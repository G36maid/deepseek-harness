# @deepseek-ai/dsh-attachment

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

持久附件服務邊界。`ctx.attachments` 校驗並以原子方式提交不可變圖片位元組，隨後返回可序列化的 `ImageAttachmentRef`；消費端絕不會在工作階段事件中持久保存瀏覽器路徑、對象 URL、提供方 URL 或 base64。

未傳送的輸入區圖片仍是由瀏覽器持有的臨時草稿。`validateImage` 執行相同的准入策略，但不執行持久化；批次寫入方會先校驗每個成員，避免某個格式錯誤的成員使較早的成員成為無引用對象。`saveImage` 會在發布任何模型可見的工作階段事件前提交每張已接受的圖片，`readImage` 則根據已記錄的元資料校驗內容尋址對象。呼叫方可以取消 `readImage`；實作會在後端讀取與校驗工作的邊界觀察取消，並保留取消語義，而不會將其轉換為儲存失敗。

## 模型體驗

該包透過角色無關的核心 `ImageBlock`，以及解析其持久引用的提供方配接器，間接影響模型。

#### KV 快取影響

新增圖片會改變提供方請求，因此會使受影響的請求後綴失效。

## 已知限制與待完成工作

- 第一版僅接受 PNG、JPEG、WebP 和 GIF。
- 保留策略與垃圾回收尚未實作，因為復原和 fork 後的工作階段可能共享不可變對象。
- 通用文件、音訊、影片和持久的未傳送草稿需要單獨的生命週期與提供方契約。
