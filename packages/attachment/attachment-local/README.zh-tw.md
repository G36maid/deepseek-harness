# @deepseek-ai/dsh-attachment-local

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

這是 [`@deepseek-ai/dsh-attachment`](../attachment) 的私有本機實作。對象存放在 `<DSH_HOME>/attachments/v1/objects/<sha256-prefix>/<sha256>`，並透過不透明的 `sha256:` 識別符號尋址。每個行程都會透過將每個祖先目錄項逐級同步到檔案系統根目錄，為某個 home 一次性證明其持久性，因此絕不會把另一個行程已經建立但尚未同步的目錄誤認為安全邊界。隨後，寫入過程使用私有暫存目錄、僅所有者可訪問的文件、經過同步的暫存檔、原子且排他的硬連結發布，並對發布路徑執行目錄同步（適用於 POSIX；Windows 相依性檔案系統中繼資料日誌），確保已報告的引用能夠在崩潰後繼續存在。寫入准入與讀取都會完整解碼光柵圖片，之後才接受其格式和尺寸；讀取還會重新校驗摘要和已記錄的中繼資料。位元組和畫素限制屬於寫入時的准入策略，因此後續收緊限制不會導致已經接納的歷史記錄變得不可讀。

`DSH_HOME` 按共享路徑策略解析：顯式設定、`$DSH_HOME`，最後是 `~/.dsh`。工作階段日誌只包含引用和經過校驗的中繼資料，絕不包含這個宿主路徑。`readImage` 會把選填取消訊號傳入檔案系統讀取、在校驗前後觀察該訊號，並保留取消語義，而不會將其包裝成 `ATTACHMENT_READ_FAILED`。

## 模型體驗

該包透過重新啟動和 fork 後對歷史使用者圖片與結構化模型圖片輸出的持久重播間接影響模型。

#### KV 快取影響

除發起請求的配接器所持有的圖片塊外，不產生其他影響。

## 已知限制與待完成工作

- 對象會無限期保留；基於引用的記憶體回收尚未實作。
- 本機後端假定宿主與提供方配接器共享同一個檔案系統服務。
- 動態 GIF 的中繼資料根據邏輯螢幕進行校驗；逐幀解碼策略由提供方持有。
