# @deepseek-ai/dsh-subprocess-e2b

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

[`@deepseek-ai/dsh-subprocess`](../../subprocess/subprocess/README.md) seam 的 E2B 實作。先載入 [`@deepseek-ai/dsh-e2b`](../e2b/README.md)，再用本服務取代 `dsh-subprocess-local`。現有的 Bash、PTY 和 LSP 消費端隨後會在共享遠端沙盒中執行，無需 E2B 專用的能力包。

## 設定

| 鍵 | 預設值 | 含義 |
| --- | --- | --- |
| `pollMs` | `20` | 遠端狀態／存活輪詢間隔（毫秒）；每個 tick 是一次控制面請求，調大該值以犧牲結束觀察延遲換取更少的請求。 |

## 行為

- **非同步遠端啟動**：同步 seam 會立即返回一個控制代碼，同時由 `Sandbox.commands.run(..., { background: true })` 在遠端啟動行程。包裝層發布行程組 ID 並由配接器完成驗證之前，`pid` 為 `-1`；stdin 和常規觀察會等待該發布。自有啟動訊號會在分配前中止環境和私有狀態準備；分配開始後，取消會等待可清理的臨時 SDK 控制代碼。
- **執行世界坐標**：`cwd` 和私有 `runtimeRoot` 來自共享所有者；可執行文件尋找會驗證絕對路徑，或根據沙盒 PATH 加顯式覆蓋來解析裸名稱，並與所有 subprocess 提供方一致地拒絕含分隔符的相對路徑。
- **Linux 行程組**：帶引號保護的包裝層會在 `exec setsid --wait` 下啟動每組 argv，並在 `ctx.e2b.runtimeRoot/processes` 下記錄實際行程組 ID 和私有狀態文件。控制代碼會等待該文件，而不會把 SDK 命令 PID 當作已發布的身份。終止操作以記錄的負數 ID 傳送 `SIGTERM`，等待呼叫方的 `graceMs`，再升級到 `SIGKILL` 和 SDK kill 回退；TERM 訊號傳送或探測失敗也會強制觸發該升級。行程表探測會把僅含殭屍或已死亡條目的行程組視為完全靜止。強制清理只有在有界探測發現行程組為空後纔算成功；否則 `waitForExit()` 會公開可重試的失敗，而已證明的完全靜止會讓後續終止操作不再執行任何動作。發布失敗與監控失敗都會在拒絕前執行同一清理交易。服務 dispose（資源釋放）會拒絕新的啟動請求、終止並等待每個保留行程組結束，再等待 SDK 結帳和私有清理完成，之後沙盒所有者才會釋放沙盒。
- **環境邊界**：一次受信任的控制 shell 探測會從 passwd 條目解析沙盒使用者的登入主目錄，以 base64 ASCII 傳輸沙盒環境，再進行一次嚴格 UTF-8 解碼；隨後包裝層移除環境中的 `DSH_*` 和形似憑據的名稱（`*KEY*`、`*SECRET*`、`*TOKEN*`），並把每個有效的 `spec.env` 條目復原為呼叫方顯式選擇。空名稱、`=` 和違反 NUL 分幀規則的條目會在啟動前被拒絕。在使用者 profile 指令碼執行前，此後的 E2B 命令 shell 與 PTY 登入 shell 會獲得位於根目錄下、全新隨機生成的 `HOME`，並為每個被清理的環境變數名設定空值覆蓋；之後，請求的 argv 會在不改變沙盒使用者 umask 的前提下接收序列化環境。宿主環境變數絕不會隱式進入沙盒。私有環境文件在使用後會被刪除；命令或終端機設定失敗時，會先刪除其私有狀態再拒絕。
- **stdio 投影**：遠端包裝層先把原始位元組分流到選填的有界 spill 文件，再把每個即時區塊編碼為換行分隔的 base64 ASCII 幀；宿主會跨任意 SDK 回呼邊界增量復原位元組。pipe 模式把這些位元組寫入宿主 Node 流；inherit 模式把位元組寫入 harness 行程流；collect 模式保留有界的宿主尾部，並支援基於偏移量讀取。包裝層會在等待繼承管道的寫入方之前發布直接命令狀態。對於 collect 或 inherit 輸出，超過 `graceMs` 後，配接器會中斷連線未完成的 SDK 流，不公開其中不完整的 spill，並返回該狀態，同時保留遠端行程組供 `waitForExit()` 和終止操作使用。原始 pipe 自然完成時，會等待無損傳輸完成並保留背壓；顯式終止則會銷毀宿主 pipe，並在遠端清理前釋放受阻的輸出寫入。批次 stdin 和流式 stdin 都使用 SDK 控制代碼。
- **終端機工作階段**：`spawnTerminal()` 使用 E2B 的位元組 PTY API，以 mode 為 `0600` 的私有文件傳入原樣 argv 與清理後的環境，報告前臺行程組，傳送真實訊號，並透過一項可重試且須等待的 `terminate()` 清理遠端終端機工作階段中仍存活的每個行程組；終止會拒絕新的控制代碼操作，中止並等待運送中寫入、檢查和訊號操作結帳，並把僅含殭屍行程的行程組視為已經完全靜止。私有隨機輸出邊界會丟棄 E2B 引導 shell 的提示符和回顯的 runner 命令，同時保留請求行程的每個位元組，包括其第一個提示符。終端機輸出推入控制代碼流時不等待宿主背壓：流動的消費端（PTY 後端在構造時就掛上一個）把位元組摺疊進自身的有界狀態，而暫停的消費端會在宿主記憶體中緩衝。在控制代碼發布前會一直等待 PTY 分配完成，之後才觀察取消，以便由承擔清理責任的回滾清理已發布控制代碼。setup 與 teardown 負責私有狀態交易，在服務 dispose 期間中止待處理的 setup 並阻止發布；若 setup 回滾也失敗，則由沙盒 dispose 或逾時約束其存活時間。提示符偵測、scrollback、就緒狀態與所有者策略仍歸 `dsh-terminal-bash` 所有。
- **沙盒消失**：在行程或終端機的存活探測、終止、回滾或中斷連線連線期間出現 `SandboxNotFoundError`，證明遠端執行環境無法保留工作，因此清理會將其視為完全靜止；其他故障仍可觀察。

E2B 預設基礎映像檔提供該配接器呼叫的執行時期和 Bash/GNU 工具：`node`、`bash`、`setsid`、`ps`、`awk`、`tr`、`env`、`base64`、`chmod`、`tee`、`head`、`rm`、`kill`、`id` 和 `getent`。

## 模型體驗

透過 Consumer 間接影響模型，例如 `dsh-tool-bash` 背後的 Bash 執行器；這些 Consumer 會算繪遠端輸出、結束事實、後臺增量和 spill 路徑。

#### KV Cache 影響

不會直接失效；請求前綴變更由具名消費端負責。

## 已知限制與延後工作

- **SDK 仍會在宿主記憶體中保留完整命令輸出**：即使本配接器公開的是有界原始位元組尾部，E2B `CommandHandle.stdout` 和 `.stderr` 仍會累積 base64 傳輸內容，因此無法達到行程管理 seam 通常提供的宿主記憶體邊界，而且傳輸保留量大於源資料流。
- **不支援需要同步 PID 的消費端**：遠端啟動期間，`pid` 保持為 `-1`；包括 ACP（Agent Client Protocol）子行程後端在內，要求立即獲得正 PID 的消費端無法原樣使用本提供方。
- **私有狀態隨沙盒生命週期存在**：行程目錄和有效的 spill 文件會留在 `.dsh-e2b` 下，直到所有者刪除沙盒；本 POC 不提供沙盒內清理。
- **控制狀態與沙盒使用者同 UID**：E2B 以同一預設使用者執行每條命令，因此 `0700`/`0600` 權限無法把 `.dsh-e2b` 控制文件與並行執行的沙盒行程隔離開。後臺行程可以改寫 `pid`/`exit-code`，或讀取尚未被消費的 `environment` 文件。配接器會驗證已發布的值，並拒絕取負後不安全的行程組 ID（`<= 1`），但真正的隔離需要 E2B 提供按命令使用者或帶外控制通道。
- **數值行程身份沒有複用圍欄**：E2B 公開基於數值 PID/PGID 的 PTY 輸入、訊號傳送和清理操作，卻沒有與身份原子綁定的替代方案。配接器會盡量減少宿主往返，真實環境測試會覆蓋可復現的過時中斷重疊；在 E2B 新增身份原語，或實際故障證明需要更窄的協定之前，替代方案會繼續延後。
- **初始環境探測會繼承沙盒預設值**：E2B 會把命令覆蓋與預設環境條目合併，因此探測無法在枚舉未知且形似憑據的名稱之前將它們置空。一個已在沙盒內執行的同 UID 不可信行程可以檢查該短時存在的控制 shell；因此，該 POC 不支援把 secret 放入沙盒預設環境變數，需要 E2B 的替換環境原語才能彌合該缺口。
- **E2B 不公開訊號事實**：配接器請求的 `SIGTERM` 或 `SIGKILL` 只有在包裝層發布的直接結束碼沒有勝出時才報告為訊號；其他未請求的 SDK 結束始終保留為結束碼，包括等於 `128 + signal` 的值。
- **無法精確檢查終端機 stdin 等待狀態**：E2B 會公開前臺行程組，但不提供證明其正在等待 fd 0 所需的 syscall 證據，因此通用 PTY 後端會回退到受控提示符標記與有界靜默機制。
- **相依性 Linux 工具與 E2B 傳輸語義**：沒有 Windows、逃逸工作階段復原或網路分區的保真層。
