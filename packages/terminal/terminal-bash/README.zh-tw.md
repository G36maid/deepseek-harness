# @deepseek-ai/dsh-terminal-bash

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

這是一個基於 `ctx.subprocess.spawnTerminal`、為 `ctx.terminals` 提供的持久 shell 後端。它在共享 `ctx.sandboxPolicy` 下啟動互動式 shell，保留有界的逐行輸出並偵測就緒狀態；行程管理提供方則負責 PTY 分配、環境清理、前臺行程組、訊號傳送和完整終端機工作階段清理。因此，同一個 PTY 後端可以與本機或遠端執行世界提供方組合。

## 外掛程式（`terminal-bash`）

該外掛程式注入 `pty`、`sandboxPolicy` 和 `subprocess`，然後註冊所設定的後端類型（`shell`）。`danger-full-access` 無需沙盒提供方即可直接啟動 shell；受限模式要求同一執行世界中存在 `ctx.sandbox`，並透過它包裝確切的 shell argv，未掛載時會在 spawn 前失敗。spawn 時，一次 `ctx.sandboxPolicy.resolve({ session })` 呼叫會同時給出實際模式與工作階段工作區根目錄；呼叫方省略 cwd 時，同一根目錄也是 shell 的預設 cwd。當某個所有者存在開放的 PTY 或正在進行 spawn 時，如果設定變更會得到不同的實際模式，系統會在對應 `sandbox/mode` 事件提交前拒絕該變更。該限制綁定到確切所有者，因此即使提供方重新載入並保留現有工作階段，它仍然有效。更改模式前，請等待建立完成並關閉工作階段，避免以更寬權限打開的終端機在權限降級後繼續存在。

就緒偵測結合以下機制：由前臺狀態驗證的私有 bash 提示符標記、提供方報告的前臺 stdin 等待事實、靜默回退和絕對逾時。只有最新自有標記之後的可列印尾部與受控 `PS1` 完全相等，標記纔算就緒；即使 OSC 標記和提示符被拆到多個數據回呼中也一樣。因此，較早提示符之後的回顯輸入或輸出無法使當前 send 完成。提供方寫入前收集的提示符與靜默證據，包括寫入前前臺檢查仍在等待時收集的證據，都會在寫入邊界丟棄。如果 bash 在終端機提供方發布其重新取得前臺行程組的狀態前列印標記，輪詢會在普通靜默上限之後再保留該候選狀態 `handoffGraceMs`，使恰好同時發生的前臺交接有機會勝出。因此，繼承 `PROMPT_COMMAND` 的互動式子行程無法一直抑制推斷空閒就緒直至絕對逾時。未知的前臺狀態絕不會作為精確空閒的正向訊號。同樣，一次 send 之前就已存在的前臺行程組 stdin 等待並不代表寫入後就緒：必須先觀察到同一行程組脫離該等待，之後再次進入等待才能使該次 send 完成；前臺行程組發生變化則構成新的證據。尚未發布的啟動過程中，回退路徑要求已經觀察到輸出；零輸出靜默不能發布空工作階段，逾時則拒絕 spawn。取消操作會關閉尚未發布的 shell，並以呼叫方提供的確切中止原因拒絕；`TerminalBackendCleanupError` 會單獨保留清理失敗。呼叫方的 signal 會轉發給終端機分配與就緒初始化；發布後，控制代碼負責其生命週期。未完成的終端機控制序列受 `maxReadBytes` 限制；超過上限後，系統會丟棄內容直到其終止符。格式錯誤的 UTF-8 終端機輸出使用替換字元；末尾的回車會跨回呼保留，使拆分的 CRLF 合併為一個換行。

取消傳送時，系統會先把排隊輸入標記為已取消，再要求終端機控制代碼向當前前臺行程組傳送真正的 `SIGINT`；非同步寫入前檢查即使隨後結帳，也無法執行該輸入。如果提供方寫入已運送中，訊號傳送會等待其結帳；寫入被拒絕時不會發送訊號。已取消的 send 會保留其位置，直到寫入與前臺訊號傳送都結帳，因此後繼 send 不會收到延遲位元組或該訊號。因此，永不結帳的提供方寫入或訊號會無限期保留該位置；復原手段是關閉工作階段（`terminal_close`）。取消等待期間，絕對 deadline 仍保持啟用。訊號傳送失敗是終端機傳輸失敗，會拒絕活躍 send。取消絕不會透過寫入 `\x03` 模擬中斷，因此，即使程序執行在 raw 模式下，也仍可取消。關閉操作會拒絕新的公開訊號、停止就緒輪詢，並等待由控制代碼提供方負責的完整工作階段終止，然後才把活躍 send 結帳為 `session_exit`。

## 模型體驗

### 當前文件策略與間接消費端

#### 模型看到的內容

策略歸屬方會貢獻與具體能力無關的 `sandbox:policy` 上下文。模型透過 `@deepseek-ai/dsh-tool-terminal` 或其他 PTY 消費端還可能收到有界的 MOTD、傳送增量、scrollback 頁、就緒原因和清理錯誤。

#### Token 影響

裝載該後端期間，當前策略子句會一直存在。消費端返回有界輸出前，保留的 PTY scrollback 不會進入模型歷史。

#### KV Cache 影響

常駐策略發生變化時，會在保留的歷史之後追加一份由歸屬方算繪、取代先前狀態的執行時期上下文快照；消費端結果保持僅附加。

## 已知限制與暫緩事項

- 輸出按行規範化；不支援全屏備用緩衝區互動。
- 精確 stdin 等待偵測取決於已掛載的行程管理提供方；無法證明該狀態的提供方使用提示符標記和靜默／逾時就緒機制。
- 清理保證以 `SubprocessTerminalHandle` 的保證為準；提供方特定的缺口屬於該實作的約定，而非這個 PTY 消費端。
- harness 行程結束後，工作階段無法繼續存在。
