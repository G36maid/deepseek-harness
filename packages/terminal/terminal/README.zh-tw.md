# @deepseek-ai/dsh-terminal

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

限定所有者範圍的持久 PTY seam。`TerminalSessionService` 註冊為 `ctx.terminals`，生成不透明的工作階段 id，透過具名後端路由建立操作，將每個操作限制在完全相同的活躍 `Agent` 內，並在該 agent（代理）或服務 dispose（資源釋放）時等待後端完全靜止。

## 約定

- 後端註冊一個穩定的 `type`，並返回尚未發布的 `TerminalBackendSession`；失敗或取消的設定程序必須清理部分資源。若清理失敗，則以 `TerminalBackendCleanupError` 拒絕，使登錄檔能在取消後繼續保留該清理失敗。
- spawn 取消會保留呼叫方提供的確切中止原因。後端設定完成後，服務 dispose 與所有者消失仍分別對應可供機器路由的不同失敗。
- 所有者與服務的 dispose 會透過服務持有的訊號中止尚未發布的設定，並等待後端結帳和回滾後才返回。
- 如果回滾關閉失敗，或後端報告啟動清理失敗，dispose 生命週期會以拒絕結束，不會聲稱已經完全靜止。呼叫方觸發的取消仍收到其確切原因；生命週期觸發的回滾失敗也會拒絕待完成的 spawn。
- 呼叫方取消後發生的後端清理失敗仍算作所有者活動，直到所有者或服務 dispose 並消費、報告該失敗，避免生命週期策略把失敗的清理誤判為完全靜止。
- `hasOwnerActivity(owner)` 覆蓋從尚未發布的設定到最終關閉的全程序，使生命週期策略能精確限制對應所有者，不受發布競態影響。
- 成功的 spawn 會發布一個 `TerminalSessionId`。選填的 `name` 只是所有者本機的顯示中繼資料，絕不代表權限。
- 一個工作階段最多接受一個活躍的傳送操作。讀取和訊號操作可以觀察該傳送；在當前操作結帳前，另一項傳送會失敗。
- `TerminalSendResult.waitReason` 與 `sessionStatus` 相互獨立。`session_exit` 描述頂層 PTY 行程，而不是任意前臺命令。
- `kill()` 與 dispose 只會在後端捕獲的行程樹完全靜止後完成。清理失敗會以拒絕結束，而非聲稱成功；同時它會清除匹配的後端和登錄檔限制，使後續關閉能夠重試，且不會幹擾較新的嘗試。

該 seam 不包含 `node-pty`、沙盒、工具 schema、提示詞、任務或終端機算繪策略。實作負責終端機機制；消費端負責模型呈現和選填的背景工作註冊。

## 模型體驗

### 間接消費端

#### 模型看到的內容

沒有直接可見內容。此包不註冊提示詞或工具；可見 schema 和結果文字由 `@deepseek-ai/dsh-tool-terminal` 負責。

#### Token 影響

沒有直接影響。活躍工作階段狀態會保留在行程本機，直到消費端返回有界結果。

#### KV Cache 影響

不會直接失效；請求前綴變更由上述消費端負責。

## 已知限制與暫緩事項

- 工作階段只存在於行程本機，harness 重新啟動後不會復原。
- 系統有意不支援跨 agent 共享；未來的共享工作階段設計需要獨立的權限約定。
