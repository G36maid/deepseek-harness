# @deepseek-ai/dsh-settings-file

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

基於文件的設定提供方。一個 YAML 或 JSON 文件承載全部 namespace 分節；外部編輯經 `ctx.settings` 熱發布，`update()` 在寫鎖下先重讀文件再原子寫回，保留使用者的 YAML 註解、當前未載入外掛程式所擁有的分節，以及任何本行程尚未觀察到的磁碟變更。

## 設定

| 欄位 | 含義 | 預設 |
|---|---|---|
| `path` | 設定文件路徑；擴充名決定格式（`.yaml`/`.yml`/`.json`） | harness home 下的 `settings.yaml` |
| `dshHome` | `path` 省略時使用的 harness home | `$DSH_HOME` 或 `~/.dsh` |
| `watch` | 監聽文件並熱發布外部編輯 | `true` |
| `debounceMs` | watcher 寫入穩定視窗（毫秒） | `100` |

預設值解析是一步顯式的 `resolveSpec(config)`；不支援的擴充名在載入時報錯。

## 行為

- **啟動失敗並明確報錯，重載保留最後可用值。** 存在但非法的文件使外掛程式載入失敗；執行中不可讀或不可解析的編輯只告警並保留最後可用分節。文件缺失時所有 namespace 按預設值與 `base` 解析；刪除文件發布同樣的空狀態。
- **每次寫入都是一次讀-改-寫。** persist 先重讀文件並把任何差異發布進 seam——無論是仍在 watcher 防抖視窗內的外部編輯、watcher 漏掉的變更，還是另一個行程的寫入——再基於這份新鮮文字算繪，因此寫入絕不會復活過時文件，也不會丟掉未觀察到的同級分節。若磁碟上的文件已變為非法，寫入會明確報錯並拒絕執行，而不是覆蓋使用者的手工編輯。
- **寫入持有跨行程寫鎖。** 讀-算繪-rename 流程在以 `wx` 建立的同級鎖定檔 `<file>.lock` 保護下執行，帶指數退避與 2 s 的取得期限。競爭者會逾時，但不會移除現有鎖，因為鎖齡無法區分已經崩潰的所有者與被暫停但仍存活的寫入方；殘留鎖復原須由操作者執行。讀取方從不取鎖：rename 提交是原子的，重載因此始終一致。
- **寫回原子、僅屬主可訪問、抗符號連結。** 算繪以 `0600` 權限獨佔建立隨機後綴臨時同級文件（`wx` 拒絕跟隨預埋符號連結）後 rename 覆蓋目標，失敗時清理暫存檔。
- **YAML 編輯是葉子級 diff。** 寫入只設置發生變化的值、只刪除被移除的鍵，因此註解、錨點與排版在每個未觸碰的節點上以及每個被改鍵值對的鍵上都得以保留；被改的陣列（或其他非 map 值）整體替換，其中的註解隨之一同被換掉。JSON 重新序列化，無註解。
- **重載與寫入共享一條操作鏈。** watcher 刷新與來自各 namespace 佇列的 persist 按佇列順序逐個執行；每次算繪都基於上一次操作提交後的文字。
- **watcher 的 ready 訊號做一次對帳。** 初始載入與 watcher 自身的建立存在競態，因此其間寫入的變更絕不會觸發事件；ready 時的對帳補上這個啟動缺口。
- **原生 watcher 接收規範化路徑。** 在 Chokidar 打開目標之前，提供方會對層級最深的現有祖先路徑執行 realpath 解析，再拼回缺失的後綴。文件訪問和麵向使用者的診斷仍使用設定路徑，從而避免 Windows 在 libuv 內部混用 8.3 別名與長格式事件路徑。
- **dispose（資源釋放）在每種 watch 模式下都保證完全靜止。** 解除安裝先把提供方標記為已關閉，在 watcher 存在時將其關閉，再等待所有已排隊或進行中的文件操作完成，之後不再有任何發布。
- **按內容抑制自寫。** 提供方快取最後可用文字；watcher 事件內容與快取相同（含自己的寫入）即為 no-op。
- **Host 設定配接器會收到解析後的路徑。** `ctx.settings.documentPath` 是 `resolveSpec()` 得出的絕對檔名，包括自訂 YAML/JSON 路徑；`prepareDocument()` 會保留現有文件，或在 Host 打開文件前，以僅屬主可訪問的權限獨佔建立缺失的空文件。瀏覽器只收到可用性標志，絕不重建 `$DSH_HOME`，也絕不提交檔案系統目標。

## 模型體驗

間接生效：本提供方只儲存並行布 namespace 分節，任何模型效果都經由 `ctx.settings` 的消費端產生，並由各消費端自己的介面文件說明。

#### KV Cache 影響

無直接失效；請求前綴的任何變更均由消費端外掛程式負責。

## 已知限制與暫緩事項

- **同 namespace 衝突仍是後寫勝出** — 寫鎖加讀-改-寫讓並行寫入者不會丟掉彼此的 namespace，但兩個寫入者編輯同一個 namespace 時仍以較後的寫入為準；沒有按值合併，也沒有修訂檢查。
- **漏掉的 watcher 事件在下一個訊號前保持不可見** — 讀取從不重新 stat 文件，因此 watcher 漏報的變更只會在下一個事件、下一次寫入或重新啟動時被並入。
- **註解保留僅限 YAML 且僅限 map 形狀** — JSON 文件重新序列化，無註解（JSON 本身沒有），且被改陣列內部的註解（或行內附著在被改標量值上的註解）隨其所描述的值一同被換掉。
- **無值間接引用** — 分節存字面值；面向金鑰的 `${env:VAR}` 式引用是暫緩實作的 seam 層功能。
