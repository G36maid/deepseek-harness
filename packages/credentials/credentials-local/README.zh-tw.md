# dsh-credentials-local

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

文件型[憑據](../credentials/README.md)提供方：四層來源，一套明確的優先級。

| 層 | 來源 id | 可寫 | 優先 |
|---|---|---|---|
| 繼承的行程環境 | `env` | 否 | 始終優先 |
| `$DSH_HOME/.credentials.yaml` 文件 | `file` | 是（`set`/`unset`） | 高於兩個 `.env` 層 |
| `<invocation cwd>/.env` | `project-env` | 不在此處 | 高於使用者 `.env` |
| `$DSH_HOME/.env` | `user-env` | 不在此處 | 其餘情況 |

啟動環境優先，因為按次覆蓋（`DEEPSEEK_API_KEY=… dsh`、CI 機密、容器 `-e`）代表本次執行的操作者意圖——而它無法從行程內部修改，就必須*可見地*只讀：`describe()` 報告 `source: 'env', writable: false`，`set`/`unset` 直接拒絕，而不是寫下一個讀取方永遠看不到的變更。

它之下的所有來源優先級都低於受管儲存，因此 Models 頁寫入的金鑰會立即生效，即使某個 `.env` 裡還留著更舊的金鑰。沒有儲存任何東西時這兩層仍會參與解析，`describe()` 會把來源報告為 `project-env` 或 `user-env` 且 `writable: true`——存入一個金鑰就會取代它們成為生效來源。

在產品 CLI（命令列介面）下，解析讀取的是啟動器凍結的[環境快照](../../util/launch-environment/README.md)而不是 `process.env`：只有快照才說得清某個值來自啟動 shell 還是來自某個文件。並非由產品 CLI 啟動的組合只有繼承環境這一層，這讓嵌入方保持它們原有的語義。

## 設定

| 欄位 | 預設值 | 含義 |
|---|---|---|
| `path` | `<harness home>/.credentials.yaml` | 憑據文件位置。 |
| `dshHome` | `$DSH_HOME` 或 `~/.dsh` | `path` 預設時使用的 harness home。 |
| `watch` | `true` | 熱發布外部編輯。 |
| `debounceMs` | `100` | watcher 寫入穩定視窗。 |

## 文件本身

一個從憑據引用到值的 YAML mapping，除此之外別無他物：

```yaml
DEEPSEEK_API_KEY: sk-…
OPENAI_API_KEY: sk-…
```

該文件只存放憑據，因此任何偏離都是拒絕，而不是跳過某個條目——被靜默忽略的鍵讀起來就是「我存進去的金鑰沒有生效」。非 mapping 的根、非 POSIX 識別符號的鍵、非字串值、空字串、重複鍵以及格式錯誤的 YAML 全部失敗：啟動時明確報錯，執行期熱重新載入則告警並保留最後可用快照。沒有 `version` 欄位，也沒有包裝層；格式就是這個 mapping。

寫入是對已解析文件打修補程式而不是重建，因此註解與所有未觸及條目的排版都會保留。直接位於某條目上方的註解屬於該條目的註解，會隨它一起刪除。每次寫入都先在 [`dsh-atomic-write`](../../util/atomic-write/README.md) 的跨行程寫鎖下重讀文件、把此前未觀察到的一切發布出去，再在僅屬主可訪問（`0700`）的目錄下以 `0600` 權限原子提交——因此並行寫入者、或落在 watcher 防抖視窗內的外部編輯會被並入，而不是被覆蓋。磁碟上已經無法解析的文件會讓寫入失敗，而不是覆蓋提供方讀不懂的內容。

任何字串值都能往返，包括多行值，因此不會再有條目因為缺少可用引號樣式而不可寫。空的儲存值等於不存在（seam 規則）——這也正是文件中的空字串被直接拒絕的原因：`unset` 刪除鍵，而不是把它置空。

## 權限

提供方以 `0700` 建立目錄，以 `0600` 建立或原子替換文件。它對*讀取*同樣守住這條界線：在 POSIX 上，只要文件帶有任何 group 或 other 權限位，就會在解析其內容之前失敗——啟動時與每次 reload 都檢查——並在錯誤裡給出 `chmod 600` 的修復命令。Windows 沒有可檢查的 mode，因此在那裡跳過該檢查而不是偽造它。

## 熱重新載入

外部編輯在快照**整體替換**後按變更引用逐個發布 `credentials/updated`——磁碟上刪掉的條目絕不在記憶體滯留。在 Chokidar 打開目標之前，提供方會對層級最深的現有祖先路徑執行 realpath 解析，再拼回缺失的後綴；文件訪問和診斷仍使用設定路徑，從而避免 Windows 混用 8.3 別名與 libuv 的長格式事件路徑。提供方自己的寫入按內容識別，只發布屬於該次提交的一個事件。執行期文件不可讀或無效時保留最後可用快照並告警；文件不存在即空儲存；啟動時不可讀或無效則明確報錯。

## 安全邊界

文件在 `0700` 目錄下以 `0600` 權限存放，這擋得住其他 OS 使用者，**擋不住**模型。工具行程（bash、檔案系統工具）以同一使用者身份執行，而已交付的 `workspace-write` 文件策略限制的是修改而非讀取，因此它們讀這個文件與讀該使用者擁有的任何其他文件毫無二致；也沒有任何沙盒模式會把它單獨挑出來。harness 真正守住的更窄：它絕不把該文件的解析後路徑交給模型，也絕不把它載入行程環境——這與使用者的普通環境層 `$DSH_HOME/.env` 不同（見 [app-boot 的 Harness home 各層](../../boot/app-boot/README.md#profiles)）——因此要拿到這個值，需要刻意去讀一條並未交給 agent（代理）的路徑。

這是審慎，不是邊界。必須讓提供方金鑰遠離自身 agent 的部署無法靠文件權限做到；OS 鑰匙串提供方——一種模型執行所在行程根本無法讀取的儲存——纔是延後的答案，它應當作為平級包與本提供方並列。

## 模型體驗

經由消費它的 LLM（大型語言模型）配接器間接生效：儲存的值為配接器向提供方寄出的請求授權，所有模型可見內容均由配接器負責。

#### KV Cache 影響

無直接失效；憑據絕不進入請求前綴。

## 已知限制與暫緩事項

- **同一引用的並行寫入是後寫勝出**——寫鎖加讀-改-寫讓並行寫入者不會丟掉彼此的條目，但兩個寫入者編輯同一個引用時仍以較後的寫入為準；沒有修訂檢查。
- **同 UID 行程可以讀取該文件**——見[安全邊界](#security-boundary)：文件效果沙盒模式不會拒絕讀取，OS 鑰匙串提供方仍是延後項。
- **環境變化不可見**：快照在啟動時凍結，因此啟動之後 export 的變數既不會進入解析，也不會進入 `describe`；要更換來自環境的憑據需要重新啟動。
- **原子但不具備崩潰持久性**——繼承自 `dsh-atomic-write`；儲存在啟動時重新讀取。
