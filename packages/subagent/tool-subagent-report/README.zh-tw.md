# @deepseek-ai/dsh-tool-subagent-report

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

選填的子級作用域 `report` 工具是 `ctx.subagents.reportFrom()` 之上的輕量配接器。它為每個可繼續的行程內子級提供一條返回通道，指向啟動該子級的 Agent（代理），並安裝指示子級使用該通道的提示詞 section。本包註冊的是可繼續子級設定貢獻，而不是全域性工具，因此該工具及其指引只存在於這些子級內部。根 Agent、一次性 subagent、遠端 subagent 提供方、同級作用域以及不關聯 Agent 的工具執行都不會提供或執行它。安裝本包只授予這項子級作用域能力；父到子方向仍由獨立的 [`@deepseek-ai/dsh-tool-subagent-control`](../tool-subagent-control/README.md) 負責，可繼續模式不相依性這兩個包中的任一個。

子級作用域的 `tool:report` 提示詞 section 要求子級在結束前呼叫一次 `report` 並給出自足的答案，並在部分發現會改變父級下一步動作時提前上報。該指令是引導而非強制：機制本身仍接受一個輪次中呼叫零次或多次，也沒有任何執行時期路徑會拒絕從不上報的子級。呼叫成功既不會結束輪次或結帳 Activation，也不會阻止父級後續訊息；輪次結束也絕不會自動上報。該工具不接受接收方參數：`exec.agent` 是傳送方確切線上的 Agent，也是權限憑據；服務根據該子級持久化的 `parentSession` 推導唯一接收方。成功時返回父級已接受訊息的穩定 `MessageId`，不表示已讀回執、inbox 中該次出現的 id、父級日誌確認、輪次完成回執或持久化刷盤。父級解析由登錄檔中的存在性決定：父級不在登錄檔時，呼叫失敗並返回 `direct parent is not live; report was not delivered`；已開始由宿主管理的 dispose（資源釋放）但仍在登錄檔中的父級在其日誌仍接受追加時仍會接受。服務不會執行注入、父級冷復原或離線 mailbox 寫入；持久化子級 transcript（文字記錄）仍是復原依據，且工具呼叫失敗不能證明未送達（後續 `tools/post-execute` 否決可能讓報告已被接受的呼叫以失敗結束）。

`reportDelivery` 為每條已接受的報告選擇父級調度方式。`wakeup`（預設值）使用 `parent.followup()`，恰好建立一個普通的後續父級輪次，並喚醒停駐的父級驅動；它絕不會對正在執行的輪次進行 steering（中途引導）。之所以作為預設值：已經停駐的父級沒有別的理由再去查看，靜默投遞會讓一條已被接受的報告一直無人閱讀，直到別的事件把父級喚醒。`quiet` 使用 `parent.inject()`，在不啟動父級模型請求的情況下新增面向模型的上下文：父級空閒時，追加操作會在呼叫返回前完成；報告到達正在准入或執行的父級時，則會暫存到下一個安全日誌位置。這是部署調度策略，因此面向模型的 schema 不能在單次呼叫中選擇或覆蓋該策略。

作用域區域性註冊有意不受子級全域性 `toolFilter` 影響，因此委派允許清單無法移除唯一的返回通道。需要子級不具備返回通道的部署應省略本包。

貢獻體以 `installReportTool(childCtx, ctx, delivery)` 匯出，以便檢查類消費端把 `report` 及其指引安裝到新建立的子級作用域中，並返回同時撤銷兩者的唯一 disposer。全域性登錄檔無法公開作用域區域性 schema，因此生成的工具目錄會使用這條路徑。生產組合仍透過 `apply()` 進入；subagent seam 的貢獻登錄檔保持私有。

## 模型體驗

### 工具 schema

#### 模型看到的內容

已生成的 [`report` schema](../../../docs/tool-catalog.md#deepseek-aidsh-tool-subagent-report)：包含一個必填 `output` 字串。其描述說明子級必須在結束前上報一次，上報只會到達啟動該子級的 Agent，並且不會結束輪次。它不包含接收方或投遞模式參數。獨立的 `tool:report` 提示詞 section 在 schema 之外重申該義務，使忽略工具描述的子級仍能讀到。

#### Token 影響

每個可繼續子級請求付款固定的 schema 與提示詞 section 成本，其他任何 Agent 的請求均無此成本。

#### KV Cache 影響

子級中的前綴保持穩定；schema 與該 section 都不會在執行時期改變。移除本包會從駐留子級中撤銷兩者，從而改變其下一次請求前綴。

### 上報結果

#### 模型看到的內容

接受時返回 `report accepted by the agent that started you as message <messageId>`；規範輸出攜帶穩定的 `messageId`。傳送方未授權、父級不可用或生命週期正在關閉時，會返回錯誤結果。描述中會說明，失敗的呼叫仍可能已經送達，因為 `reportFrom()` 接受訊息後，後續 `tools/post-execute` 失敗可能替換工具結果。

#### Token 影響

每次呼叫都會在執行上報的子級中產生一條簡短確認訊息。父級還會為上報內容付款 token 成本：喚醒投遞會使該內容成為一個新父級輪次中唯一的普通訊息，靜默投遞則把內容加入父級的下一次請求。

#### KV Cache 影響

在子級中僅附加。在父級中，帶前綴的報告位於現有歷史之後，並保留可複用前綴。

### 父級可見的報告

#### 模型看到的內容

一條使用者角色的父級訊息，以 `Background subagent <child-id> reported:` 開頭，後接子級未經改動的 `output`，並帶有指明該子級的持久化來源 `{ kind: 'subagent-report', senderSessionId: <child-id> }`。

#### Token 影響

子級的完整 `output` 加上一行前綴；本包不設上限。

#### KV Cache 影響

僅附加；報告位於父級可複用請求前綴之後。喚醒投遞會啟動一次獨立的父級模型請求，靜默投遞則不會。

## 已知限制與暫緩事項

- **父級可能在宿主啟動 dispose 後繼續接受報告**：`AgentHandle.dispose()` 會先取消並等待完全靜止，然後才撤銷作用域並離開登錄檔；它不公開「dispose 已開始」訊號。在該視窗內接受的報告會追加到父級 transcript，但該父級不會在本行程中處理它。對於由繼續執行管理器擁有的父級，管理器的准入邊界會在整片森林拆卸期間拒絕該上報。
- **接受弱於持久投遞**：沒有持久化 mailbox、冪等鍵、投遞回執、重試協議，也不保證恰好一次。任一側記錄接受後若行程失敗，結果都不明確；外部重試可能產生重複上報。
- **暫存的靜默報告無法立即重建**：接受時會返回其穩定 `MessageId`，但只有當待處理上下文到達普通日誌邊界後，父級工作階段才能重建帶前綴的內容。
- **授權須等到下一個 Activation，撤銷則立即生效**：子級駐留後再安裝本包，只會在該子級的下一個 Activation 中授予 `report` 及其指引；移除本包則會立即從駐留子級撤銷兩者。
- **巢狀上報只向上到達一條直接邊**：孫級只向作為其直接父級的子級上報，不會直接到達頂層協調器；該直接父級必須隨後顯式寄出一條衍生更新。
- **沒有速率限制**：巢狀子級頻繁上報時，默認的 `wakeup` 模式會放大模型工作量；寧可接受報告無人閱讀也要避免這種放大的部署應選擇 `quiet`。
