# dsh-session-checkpoint-policy

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

已持久化的 agent（代理）的語義持久性策略。它會在模型配接器收到請求前、頂層工具正文可產生外部副作用前，以及每個 `agent/pre-step` 邊界為事件溯源工作階段建立檢查點，使前一回應與有序工具結果在下一個請求前已持久化。

## 外掛程式（命名空間：`session-checkpoint-policy`）

該零設定函式外掛程式消費 `ctx.sessions`、`ctx.llm`、`ctx.tools` 以及 `ctx.sessionPersistence` 的存在性。將其與一個持久化後端一起載入：

```yaml
- id: session-persistence
  name: '@deepseek-ai/dsh-session-persistence-jsonl'

- id: session-checkpoints
  name: '@deepseek-ai/dsh-session-checkpoint-policy'
```

持久化與檢查點調度刻意拆分為獨立 Cordis 外掛程式。持久化後端會為追加的 `session/event` 啟動有界後臺批次，並把每個已請求的 `session/flush` 變成即時完全靜止屏障；該策略選擇請求、工具分派和下一步驟屏障。不帶此策略載入後端是有效的，但崩潰可能丟失仍位於已設定批次處理視窗內的事件，或尚未完成的寫入。第一方持久化應用和執行時期顯式掛載兩個外掛程式；專用部署可以刻意省略或替換策略。

策略延遲包裝 `llm/stream`，因此下游流只會在活動工作階段中緩衝的請求事件已持久化後構造。它在預執行策略和防護機制之後包裝 `tools/execute`；只有在已記錄呼叫已持久化後，頂層工具正文才會執行。如果取消在 flush 等待期間到達，包裝層會返回規範的 `ABORTED_BEFORE_DISPATCH` 結果，不進入工具正文。巢狀工具分派重用外層模型可見呼叫的檢查點。`agent/pre-step` 在派生請求前持久化前一回應/結果批次。

在模型和工具邊界，檢查點被拒絕時會按失敗即阻止原則處理：配接器和頂層工具正文都不執行。步驟邊界處的檢查點被拒絕會在另一個請求開始前使輪次失敗。並行工具檢查點共享工作階段儲存的序列持久化排空流程，不會產生重複的序列號。

## 模型體驗

### 中斷呼叫

#### 模型看到的內容

外掛程式不新增提示詞或工具 schema。工具檢查點後、結果前的硬崩潰會留下持久的未匹配呼叫；工作階段復原會提供模型可見的 `TOOL_OUTCOME_UNKNOWN` 結果，該結果由 `dsh-session` 負責。該訊息允許重試只讀或冪等工作，並要求對可能有副作用的呼叫驗證狀態或請求使用者確認。

#### Token 影響

成功檢查點不新增 token，也不改變請求。復原會新增一條短工具結果訊息，以平衡中斷的 transcript（文字記錄）。

#### KV Cache 影響

修復結果追加在可重用前綴之後，因此不會使較早的快取條目失效。

## 已知限制與暫緩事項

- 該策略以持久方式記錄執行意圖，而非為通用副作用提供恰好一次保證。當提供方支援時，有副作用的工具應將 `exec.callId` 作為冪等鍵轉發。
- 流式 `assistant/chunk` 事件沒有逐區塊檢查點。有界後臺批次通常會在下一個語義檢查點之前將其持久化，但硬崩潰可能丟失當前記憶體批次或尚未完成的寫入。
- 已持久化的呼叫沒有結果時，無法證明其外部副作用是否完成。因此，復原會記錄未知結果，而不是自動重試。
