# dsh-client-ui-agent-preset

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

agent preset 的各個表層：General 設定中的一行，用於選擇新建工作階段據以組裝的 [preset](../../preset/agent-presets/README.md)；新建工作階段介面上的一枚 chip，用於選擇**下一個工作階段**的 preset；工作階段標題旁的一個只讀標籤；以及一個設定頁分區，用於管理名單——複製、刪除、預設值，以及通往 preset 自身文件的入口。

## 為什麼它是"新建工作階段"的偏好設定

工作階段的 preset 在建立時即固定——宿主拒絕以不同 preset 接管已存在的工作階段，因為該工作階段的歷史是在最初那份 preset 的工具下產生的。因此本行不可能是即時切換，它也如實說明瞭這一點：更改只對此後開啟的工作階段生效，而執行中的工作階段保持它們開始時的組裝。

## 新建工作階段 chip

第二個表層，位於新建工作階段介面上、工作區選擇器旁邊。它落在這裡而非 composer，是因為這裡纔是選擇仍然成立的地方：一個大部分時間處於停用狀態的控制元件，屬於它仍然可用的那個介面。

chip 以部署預設值打開，其選擇是**暫存**的——該介面先於它要應用到的工作階段存在。暫存值會在某個工作階段成為當前工作階段且仍為空白時抵達該工作階段；這既覆蓋工作區連線新建的工作階段，也覆蓋它複用的那個空白工作階段，而搭 `sessions.create` 的便車會漏掉後者。暫存值一經使用即被清空，因此下一個新工作階段重新以預設值打開——與它旁邊的工作區選擇器完全一致。

已經開始的工作階段會被直接拒絕而非排隊：宿主返回 `agent-preset-locked`，暫存值隨之丟棄，而不是去等一個永遠不會接受它的工作階段。

## 工作階段標題旁的標籤

第三個表層，位於工作階段標題旁：**本工作階段**所執行的 preset，作為靜態裝飾呈現。在那裡放一個控制元件，等於承諾一次宿主會斷然拒絕的切換。它從工作階段自身的摘要讀取 preset，並在 General 行所讀的同一份名單上解析顯示名稱。轉發的 owner 事件 `agent-preset/selected` 會在每個分頁標籤中把已經提交的空工作階段切換折進這份共享摘要；發起方分頁標籤可能已經採用 RPC 回執，而合併是冪等的。

## 它讀什麼、寫什麼

選項與當前預設值都來自同一次 `agentPreset.list` 呼叫。名單本身已經報告了"未顯式選擇的工作階段會得到哪個 id"，因此本行無需對 settings schema 做內省；寫入目標是 `agent-presets` settings 命名空間的 `default` 欄位，也正是宿主在建立時解析的那個欄位。

本機創作的 preset 的權限恰好等於它所引用的外掛程式，因此清單會標注 `user` 行，而不是把每個 preset 都呈現為隨附且已審核的。

preset 文件提供一套未國際化的 `name` 與 `description`，Web 將其用於所有 `user` 行和未知的 `system` 行。對於四個隨附 id（`standard`、`code`、`minimal` 與 `cordis`），只有名單將該行標記為 `system` 時，Web 才會從當前 locale 解析這兩個欄位；同名的 `user` preset 仍使用其文件元資料。

本行在自身命名空間的 `settings/changed` 以及 `connection/reset` 時重新讀取：名單是一個活動目錄，預設值是一項設定，外部編輯與重新連線都可能改變它。

## 管理分區

第四個表層，獨立的設定頁（`settings.section`，id 為 `agent-presets`，排在「模型」之後——選模型是日常操作，而組裝 agent 是它背後那件塑造部署形態的事）：名單以卡片呈現，複製對話框是建立 preset 的唯一入口，隨附組裝則在只讀查看器中展示。

瀏覽器不再編輯任何組裝文字。在網頁文字域裡編 YAML 是弱功能（無補全、無高亮、無 diff），因此新 preset 是宿主端對既有 preset 的一次複製——對話框只收集一個 id（它將成為目錄名，所以必須當場取好、事後無法更改）與一個選填顯示名，跨越傳輸層的只有 `{ from, id, name? }`。其餘一切——描述、組裝、skills——都在 preset 自己的文件裡編輯，而本頁的另一職責正是把使用者送到那些文件面前：複製以打開新目錄作為收尾，每張自訂卡片也保有一個位置操作。宿主沒有桌面打開器時（名單上的 `hasDocument: false`；遠端與容器部署），同樣的操作改為把目錄以文字顯示在卡片上，而不是提供一個點了沒反應的按鈕。

preset 自行發布描述，長度不限，而網格讓每一行卡片等高——因此不加約束的描述會決定整份名單的高度。卡片把描述截斷為四行，其餘內容由 tooltip 承載，且僅在文字確實被裁切時才掛載。截斷由 CSS 完成，因此無論卡片顯示多少，完整描述始終留在無障礙樹中。

隨附 preset 在只讀查看器中打開。它是副本據以出發的已知良好組裝，因此能讀到它正是意義所在；它不提供位置也不提供刪除——它的安裝目錄會被升級覆蓋，不歸使用者管理。開篇引導語承擔了從前建立按鈕所暗示的資訊：複製一份既有預設改成自己的，或用「創造模式」讓 Agent 幫你建立。

複製旁邊是對話式入口：名單攜帶自指的 `cordis` preset 時，一張虛線新增卡（模型頁的同款樣式）會暫存它並開啟新工作階段——分區經外殼的 owner-prop `close` 關閉設定面板，新工作階段 chip 自己的應用器負責組裝工作區流程產出的空白工作階段。seat 會防止晚到的名單載入回退顯示：暫存選擇優先，其次是當前工作階段已攜帶的組裝，最後纔是部署預設值。

對話框復刻宿主自身的約束規則（`[a-z0-9][a-z0-9-]*`），並拒絕已被佔用的名稱——複製從不覆寫。這兩項檢查只是便利：宿主會重新校驗，失敗時對話框報告的正是宿主的答覆。

刪除會移除整個 preset 目錄。已據其組裝的工作階段繼續執行——組裝在工作階段建立時掛載一次，此後沒有任何東西會重新讀取該文件。

名單行攜帶 `broken`（宿主的形狀檢查發現組裝缺失或不可載入）時渲染為標記卡片：紅色邊框、「載入失敗」徽記（discovery 觀察到的事實，而非斷言文件已損壞——常見起因是使用者剛編輯或刪除了組裝文件）、原樣展示的原因、卡片主體停用——它不能成為默認——複製也停用，因為損壞 preset 的副本只是又一個損壞的 preset。損壞的自訂行保留位置與刪除動作：文件正是修復它的地方，而刪除正是清掉幽靈目錄（組裝文件被手動刪除、目錄仍佔著 id）的方式；損壞的內建行連查看器也不提供——沒有可讀的組裝可展示。兩個選擇器（通用設定行與新工作階段 chip）則完全不列出損壞的 preset：它們選的是下一個工作階段的組裝，列出無法組裝的選項只會把失敗推遲到工作階段啟動。

設定預設值寫入的是 `agent-presets` settings 命名空間，宿主需將其暴露給設定用戶端（[`dsh-apiproxy`](../../host/apiproxy/README.md) 維護一份顯式白名單——不在其中的命名空間會讓選擇器動一下然後悄悄忘記）。

`agentPreset.read`、`copy`、`openDocument` 與 `remove` 被固定在環回地址（見 [`dsh-client-connection`](../connection/README.md)）：組裝指明瞭一個工作階段所執行的外掛程式，因此讀取它是偵察，其餘幾個則管理名單並驅動宿主桌面。`agentPreset.list` 不在其中——它攜帶 id、信任等級與兩個不含路徑的能力標志，而局域網用戶端的選擇器需要它。

## 何時不顯示這些表層

未組裝任何 preset 的部署返回空名單，本行、chip、標籤與分區都不渲染任何內容——此時每個工作階段共用宿主組裝，也就無從選擇或管理。未設定可寫根目錄的部署返回 `authorable: false`，分區隨之退化為只讀瀏覽：隨附組裝仍可在查看器中打開，但每個複製操作都被停用並以原因作提示，而不是給出一個建立必然失敗的對話框。

## 模型體驗

Indirectly, through the preset a later session is composed from; [`dsh-agent-presets`](../../preset/agent-presets/README.md) owns what that composition puts in front of the model.

#### KV Cache effect

沒有直接的失效影響。更改預設值絕不觸及執行中工作階段的前綴；此後建立的工作階段依據它自己的組裝建立自己的前綴。

## 已知限制與暫緩事項

- **沒有元資料的 preset 按 id 列出** —— 展示文字是選填的，未取名的副本刻意回退到目錄名，而不是與其來源呈現得一模一樣。
- **展示的路徑是文字，不是連結** —— 宿主沒有桌面打開器時，卡片顯示目錄供手工複製；瀏覽器自身無法打開宿主檔案系統上的位置。
- **組裝編輯對頁面不可見** —— 文件在瀏覽器之外編輯，傳輸層不廣播文件變動，因此名單只在自身操作、`settings/changed` 與 `connection/reset` 時重讀，而非每次磁碟編輯。
