# @deepseek-ai/dsh-client-ui-user-questions

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

Web 提問功能外掛程式：其瀏覽器側把 `question` 條目註冊到工作階段擁有的 `conversation.composer` 鍵控 slot 中。其主機側刻意為空——在那裡掛載 `dsh-tool-ask-user` 會把工具放進登錄檔的**全域性層**，而全域性層會並入每一個 agent（代理），無論它由哪個 preset 組裝，於是一個「兩工具」的 benchmark preset 實際會呈現三個。算繪提問是宿主的 UI 能力，擁有該工具則是 agent 的能力，因此 `tool-ask-user` 行屬於需要它的各個 preset（以及沒有 preset 的 TUI 組裝）。

元件每次算繪一個問題，提供進度導覽、單選和多選選項、由標籤後綴派生的推薦徽標，以及自訂答案。使用者打開或編輯自訂答案時，多選題草稿會保留已選中的標籤，因此提交項可以同時攜帶 `selected` 與 `custom`；單選題的自訂答案仍保持互斥。問題詳情複用助手輸出的 `MarkdownText` 原語，包括其 GFM 算繪與不受信任內容策略。限高卡片保持標題、導覽與提交動作固定，超長的詳情與選項共享內部捲動區。選擇單選選項後會立即前進；所有問題均已回答或跳過後，Enter 會提交；IME 組合輸入期間按 Enter 只會確認輸入候選，不會前進。元件為整個請求提交一批結構化答案：「跳過此問題」會保留其他草稿，並為該項寄出既有的空 `{ selected: [] }` 形狀；關閉則以 `ASK_CANCELLED` 拒絕整個等待。

若某個請求的唯一問題聲明瞭呈現意圖，則改為算繪該意圖自己的介面。`plan-review`——由 `dsh-plan-mode` 在 `exit_plan_mode` 審閱上設定——採用等待審批卡片的形狀：一條 `Plan review` 條帶、計畫作為可捲動的 markdown 主體、問題文字作為卡片的無障礙名稱，以及一行 `Chat about it` / `Refuse` / `Approve` 的決定操作。Approve 與 Refuse 用提問方自己的選項標籤回答（意圖指名哪個標籤表示批准，因此裁決絕不相依性選項順序），並把提問方的描述保留為 tooltip；`Chat about it` 以 `ASK_CANCELLED` 拒絕該等待，讓編輯器歸位，使用者可以直接說出他想說的話。卡片只在能夠寄出該請求允許的每一個答案時才接管：只有一個問題、聲明瞭意圖、計畫以 `detail` 存在、提供了被指名的批准標籤，且是二元單選（除批准外最多一個選項，且非多選）。其他任何情形——沒有意圖、一批含多個問題、缺少計畫、批准標籤未命中任何選項、出現第三個選項、多選決定——都留在能夠表達它的通用流程上。意圖改變的只是版面配置，從不改變可達的答案。

選擇狀態只存在於以請求 rpcId 為 key 的元件本機。使用相同 id 重播時，只要元件仍掛載，就會保留草稿；主機發出的 `question/resolved` 則會移除編輯器。主機仍具有最終決定權：HTTP 交付成功不會在本機移除待處理狀態。

編輯器外框文案（翻頁器、按鈕、預留位置、校驗提示）是雙語的：外掛程式在 `dsh-client-locale` 的 `question` 命名空間下註冊 zh/en 詞典，並透過 inject face 把綁定的翻譯函式和 locale 快照源交給該條目，因此切換語言會重新算繪已掛載的編輯器。問題與選項文字來自模型並原樣算繪；載體失敗訊息也不經翻譯直接顯示。

## 模型體驗

透過 `dsh-tool-ask-user` 間接影響；該包擁有模型可見的工具 schema 和結構化結果。

#### KV Cache 影響

不會直接失效；模型可見的工具呼叫與結果由 `dsh-tool-ask-user` 擁有。

## 已知限制與暫緩事項

- **未提交的草稿不持久**：重新連線再同步或完整重新整理頁面時，會復原主機擁有且 rpcId 相同的待處理請求，但編輯器解除安裝會重設本機選項和自訂文字草稿。
- **每次只有一個請求擁有編輯器**：後續待處理請求仍留在工作階段快照中，並在較早請求落定後顯示。
