# @deepseek-ai/dsh-client-ui-workspace

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

共享 Workspace 瀏覽器與選擇器外掛程式。`WorkspaceBrowser` 填充側邊欄的 `sidebar.workspaces` slot，`WorkspacePicker` 則填充頁面區域性 Session Intent 主視覺區的 `conversation.hero.workspace` slot；兩個介面使用同一套 Workspace 選單和新增流程。

該瀏覽器透過全域性執行時期掛鉤將 Session 行算繪為分組或扁平形式，並負責 Workspace 新增／重新命名／重排序以及 Session 重排序。每個 Workspace 會記住自身是關閉還是顯示 Session；打開後預設顯示五條 Session，其餘條目透過臨時的**展開其餘**控制元件顯示，而關閉並重新打開整個 Workspace 後會復原為五條。從 Workspace 行建立 Session 時會先打開該分組，使 Session 狀態到達後新行保持可見。Workspace 清單基線就緒後，瀏覽器持久化的展開狀態與 Session 順序記錄只保留當前 Workspace id、Ungrouped 和單清單記帳。檢視表選項把分組方式和每個記帳各自的一份瀏覽器持久化 Session 順序放在一起：真實 Workspace 從 `WorkspaceView.sessionIds` 初始化，Ungrouped 和跨 Workspace 的單清單則從最近更新時間順序初始化。**手動排序**和**最近更新**在兩種呈現方式下都可用。進入最近更新時會執行一次完整的時間排序，後續 user prompt 或 steer 會將對應 Session 置頂一次；進入手動排序則保留所有當前位置並停用後續置頂。兩種模式下的拖曳都會編輯當前順序；真實 Workspace 在手動模式下的拖曳還會更新 Host Session 記帳，而 Ungrouped 和單清單因沒有單一 Workspace 記帳，其順序始終只保存在瀏覽器本機。單清單沒有父級層次，因此不顯示空的左側狀態槽；Session 存在可見狀態時仍保留該槽。無論採用哪種 Session 順序，Workspace 拖曳順序都由 Host 持久化。

摺疊搜尋是檢視表和新增操作旁的一枚區頭按鈕。在軌道中，新增和搜尋會算繪為沿外殼共用橫向進入路徑移動的 36px 控制元件。啟用搜尋後，輸入框會擴充並佔據區頭；點擊外部只會收起經清除首尾空白後為空的查詢，而清除控制元件總會重設並收起搜尋。非空白查詢會以單一扁平結果清單替代任一瀏覽模式：不區分大小寫的標題和 Workspace 子串匹配項會立即顯示，經 250 ms 防抖的 Host 請求則會加入經過排序的當前對話內容匹配項及其摘要片段。英文搜尋輸入框及其防禦性請求路徑會移除 NUL，將查詢限制在傳輸 schema 規定的 500 個 UTF-16 程式碼單元內且不會拆分代理項對，並保留現有的防抖與取消行為。每次新查詢都會中止前一個請求；內容搜尋失敗時，中繼資料匹配項仍會顯示，同時給出警告。清單最多顯示 20 條結果，並會在查詢過寬時提示使用者縮小範圍；打開所選 Session 時既不會清除查詢，也不會跳轉至特定事件。

該選擇器透過全域性 `useWorkspaces` hook 列出真實的 Host Workspace 實體。選擇 Workspace 會呼叫 slot owner 的 `onPick` 回呼，重新定位前端 Session 對象。不同的規範化路徑即使 basename 和顯示標題相同，仍會作為由 id 區分的獨立 Workspace；側邊欄的懸停詳情會顯示完整路徑。每個註冊各自聲明一個**目錄流子 slot**（`single` kind：`conversation.hero.workspace.directoryFlow`／`sidebar.workspaces.directoryFlow`），由組合的選擇器包 client half 填入其選取互動——今天是 [`-native`](../../host/directory-picker-native/README.md) 後端的無算繪 OS 選擇器驅動，`-browse` 組合下則是應用內瀏覽對話框。平鋪顯示的 **新增工作區…** 操作僅在當前介面的 slot 被佔用時算繪（每次選單算繪讀取佔用狀態；slot 為空意味著該組合沒有目錄選擇能力——seam 文件化的無流程預設行為，此時側邊欄區頭直接不算繪新增按鈕，而非留下一個點了沒反應的按鈕）。本包持有觸發與接納：佔用方透過 slot 的屬主互動約定（`open`/`busy`/`onPicked`/`onCancel`/`onError`）每次打開上報一個所選路徑，owner 透過對象層接納它，並等待 Workspace 清單投影刷新後才選中已提交的 Workspace；取消操作不會顯示提示，錯誤落入可重試的資料夾對話框，其 **重新選擇** 會重新打開流程。新增只有一條路徑：佔用者自帶的新建資料夾能力已經覆蓋了全新目錄，因此不再單設按名稱建立的對話框。選單只在確有多個目標選填時出現——沒有 Workspace 可列時，錨點手勢直接拉起流程，而不是彈出只有一行的浮層；在清單基線落地前，空清單不算最終結果。執行時期 Session 與 Workspace 服務負責物化。Workspace 行內的 Delete 操作會打開確認框，說明保留邊界、阻止重複提交，並在失敗時保持打開；成功後，該分組會被移除，其 Session 則留在 Ungrouped 下。Session 行內的 Rename 操作打開同款瀏覽器持有的對話框，並以該行的顯示標題預填：用戶端不設名稱衝突規則（host 負責規範化，可能以 `title-invalid` 拒絕，錯誤算繪在對話框告警區）；確認未修改的標題是有意允許的——這正是把當前自動標題釘住、不再被重新生成覆蓋的手勢。Session 行內的 Archive 操作不經確認對話框直接提交（非破壞性：日誌和 workspace 記帳席位保持不變），透過 `ctx.workspaces.archiveSession` 封存；封存集合回聲落地後，該行從所有分組檢視表——workspace 分組、Ungrouped、內容搜尋和平鋪清單——中消失，失敗只作為控制台診斷輸出，樹保持不變。空白的「新工作階段」行只是預留位置：不算繪行選單和時間標籤（其中還沒有發生任何事），重新命名、fork 和封存都從首條提示詞落地後纔可用。

Workspace 和 Session 懸浮卡片會複製對應行被截斷的值：啟用 Workspace 卡片會寫入其完整目錄路徑，啟用非空白 Session 卡片則會寫入其完整顯示標題。臨時的空白「新工作階段」卡片保持只讀，因為其本機化標籤是佔位文案，並非工作階段內容。只有瀏覽器接受剪貼簿寫入後，卡片才會顯示由字典提供的已複製狀態。

Session 行內的 fork 操作在源工作階段最後一個已完成輪次處 fork，在用戶端遞增繼承的持久化標題後再打開子工作階段；尾部半形或全形括號編號會原樣式遞增，無編號標題追加 ` (1)`。源工作階段與子工作階段在 workspace 組內始終作為同級行展示，譜系只保留為 session 資料。Fork 或改名失敗都不會改變當前選中項，改名失敗時已建立的子工作階段仍會留在清單中。

Session 行算繪執行時期的即時 `pendingInteraction` 分類：審批顯示**等待審批**，計畫審閱顯示**計畫待審**，普通問題顯示**等待回答**。每個待處理互動都使用一枚琥珀色警告點，優先級高於執行指示器；普通行的懸浮卡片重複顯示本機化狀態，普通行和搜尋結果行則都以相同文字提供面向輔助技術的視覺隱藏標籤。執行狀態使用藍色指示器及其隱藏標籤；空閒行會保留空的狀態槽位。

兩個目標 slot 都由其他外掛程式聲明，因此 `apply` 使用 `slots.inject()` 在各自的聲明生命週期內完成註冊，並在目標 slot 的聲明復原後重新註冊。

共享側邊欄投影會隱藏持久化 Session 摘要中帶有 `origin: 'subagent'` 的行；使用者從所選父級的 subagent 頁頭目錄進入這些對話。每個可見的普通行都會在經不間斷的 subagent 譜系可達的任一後代執行時期繼承藍色活動指示器；其懸停與無障礙文字會報告確切的執行中後代數量，同時不會把空閒 parent 描述為正在執行。普通 fork 仍然可見，並會終止此聚合，因為僅有譜系不會設定該 origin。待處理的使用者互動優先於工作階段自身的執行中狀態，二者無論哪一項存在都會保持為行的主要狀態，而後代活動仍作為獨立的懸停與無障礙狀態保留。兩者均不存在時，後代活動優先於綠色的未查看完成提醒；最後一個執行中的後代停止後，該提醒會重新出現。執行時期仍保留隱藏行，供對話、標題與已尋址傳輸狀態使用。

## 模型體驗

無。選擇器屬於瀏覽器介面；這裡沒有任何內容進入模型請求。

#### KV Cache 影響

無；該包既不組裝也不傳送提供方請求。

## 已知限制與暫緩事項

- **沒有模糊內容搜尋或事件深連結**：內容後端採用字面 token／短語匹配，選擇結果會打開 Session，而不是匹配的事件。
- **沒有 Session 刪除與取消封存控制元件**：工作階段可以封存，但已封存工作階段沒有查看或取消封存入口；刪除 Workspace 註冊記錄不會刪除 Session。
- **待處理的使用者互動不會聚合到摺疊的分組上**：摺疊分組內正在等待的行不會點亮分組頭指示，只有展開該分組後纔可見。
- **原生資料夾選擇相依性本機 Host 載體**：在 `-native` 組合下，行程內部署或遠端瀏覽器部署無法打開本機作業系統對話框；模態對話框會顯示平臺故障，並允許重試。可遠端的選取是 `-browse` 組合的應用內流程。
