# @deepseek-ai/dsh-host-directory-picker-browse

[English](README.md) | [简体中文](README.zh.md) | 繁體中文

[目錄選擇 seam](../directory-picker/README.md) 的**應用內瀏覽後端**：`BrowseDirectoryPicker` 以 `browse` 能力註冊 `ctx.directoryPicker`——基於 Node 標準庫（跨 OS 適配本就由它承擔）提供單層目錄列舉與子目錄建立。宿主螢幕上不渲染任何東西，因此該後端能服務原生後端無法觸及的遠端用戶端。

行為事實：列舉**只返回目錄**、按名稱排序，指向目錄的符號連結會被跟隨（斷鏈／迴圈連結被跳過——探測 `stat` 失敗即「不可進入」），並攜帶宿主判定的 `hidden` 標志（POSIX 點前綴約定），展示決策留給用戶端；`crumbs` 是從根到目標的祖先鏈，根 crumb 以完整路徑標注（`/`、`C:\`）；`list` 不帶路徑即列舉宿主帳戶的家目錄。`createDirectory` 不遞迴（父目錄缺失是真實失敗，不是要補造的層級），且即便被直接呼叫也把名稱校驗為單個非空白段，與協議 schema 的柵欄一致。兩個原語都拒絕非完全限定的顯式路徑——相對形態，以及 Windows 上 `isAbsolute` 會放行的無盤符有根形態（`\foo`、`/foo`）與不完整的 UNC 前綴（`\\`、`\\server`）——報 `directory-unreadable`／`directory-create-failed`，而不是任由 `resolve` 把它重定位到宿主行程 cwd 或當前盤符之下。單次 `list` 至多返回 `maxEntries` 行（設定項，默認 1000——GitHub 網頁端對目錄列舉採用的同一上限），且層級以流式方式經過一個有界視窗，無論目錄有多少子項記憶體都保持 O(maxEntries)：被截斷的層級保留按名排序的頭部、隱藏行計入上限、只探測視窗內候選，並報告 `truncated: true`，供用戶端提示層級不完整（視窗內的斷鏈符號連結不會從視窗外回填——發生過驅逐本身已把層級標記為截斷）；視窗插入為二分尋找、滿窗尾部單次比較即拒絕，且 `list` 透傳呼叫方的 `AbortSignal`，斷連或逾時會停止掃描而不是讓它在呼叫方離開後繼續。失敗拋出 seam 的類型化 `DirectoryPickerError`。策略依據：[目錄選擇能力 seam Agent Note](../../../.agents/notes/implemented/architecture/2026-07-28-directory-picker-capability-seam.md)。

**雙麪包**：瀏覽器側（`./client`）以應用內 **選擇工作區目錄** 對話框（figma `Harness` 813-23126 家族——Miller 雙列檢視表，其導覽以選中項為錨、安靜落地：掃描 crumb 跳轉或提交的路徑期間，先前檢視表持續渲染（「Loading…」膠囊僅在掃描超出 300ms 靜默視窗後才浮於其上，絕不挪動各列），隨後目標與父層級兩程以單個雙欄幀落地，目標被重新選中為其在父層級中的實際條目——因此後退絕不塌縮，也沒有中間幀閃現（父層級這一程超出其 200ms 等待上限時，目標單獨落地，隨後就地升級；父層級這一程失敗或被截斷時保持單欄落地；展示根保持單個寬層級）；帶點擊即編輯路徑區的麵包屑導覽，該區由欄右端的鉛筆圖示點明，懸停時整條欄——也就是編輯器自身的那隻框——亮起，其編輯器預填尾隨分隔符，隨後讓下方各欄跟隨草稿：當最後一欄正是目錄部分所指的層級時，末段對這一欄做前綴過濾（不區分大小寫，且僅作用於已列出、可能被截斷的行；無一匹配的末段會解除過濾，而不是把該欄清空），而其餘任何目錄部分都會在停頓 250ms 後被掃描，並像其他任何一次導覽那樣落地——以選中項為錨，在展示根之外即雙欄，且兩程都等齊，於是一次按鍵只讓檢視表移動一次——繼續鍵入即下潛、刪掉末段即上退，全程不必離開編輯器；分欄個數是這裡的不變數：最後一欄永遠是路徑所指的那一層，其上一層在它旁邊（只有這一層自己的末段不觸發掃描，也只有展示根會獨佔一欄），而宿主規範化過路徑之後（`..` 段、Windows 的正斜槓），該層級仍然應答產生它的那段文字——推測性掃描失敗時保持沉默，而 Enter 仍按確切文字導覽，並在落地前獨佔檢視表；編輯器按 Escape 或焦點離開對話框卡片即取消（視窗／分頁標籤切換與卡片內焦點移動保留草稿），而草稿走到的層級會留在原地——麵包屑導覽指明該層級、Open 的兜底目標隨之而動，因此取消只是關閉編輯器，並不回退這段行走；基於宿主 `hidden` 標志、標籤固定的「顯示隱藏」footer 開關，鍵入以點開頭的前綴會顯出其匹配項，且當前選中項不受任何過濾影響；巢狀新建資料夾對話框）填入 [ui-workspace](../../client/ui-workspace/README.md) 的兩個目錄流程擴充位，驅動程式 `host.listDirectory`／`host.createDirectory`，並註冊自己的 locale 命名空間（`directory-browser`，zh 默認／en）。兩個目錄流程聲明必須同時處於 live 狀態，任一貢獻才會安裝。因此一行 cordis.yml 同時組合瀏覽互動的兩側；client 側不含任何能力 kind 分支，掛載第二個流程包會在載入期失敗（洞為 `single` kind）。

## 模型體驗

無。該後端服務於 GUI 宿主的目錄選擇；這裡沒有任何內容進入模型請求。

#### KV Cache 影響

無；該包既不組裝也不傳送提供方請求。

## 已知限制與暫緩事項

- **不讀取 Windows 隱藏屬性**——Node 的 dirent 不暴露 `FILE_ATTRIBUTE_HIDDEN`，因此在所有平臺上 `hidden` 都意味著點前綴，直到原生探測值得付出相應成本為止。
- **不枚舉盤符根**——Windows 上祖先鏈止於盤符根；跨盤相依性瀏覽器 UI 的路徑輸入入口，而不是這裡的枚舉原語。
- **全盤可瀏覽**——沒有按部署限定的瀏覽根。`workspace.create` 接受任意路徑，因此這裡的根會限定 UX 範圍，而不是安全邊界。
