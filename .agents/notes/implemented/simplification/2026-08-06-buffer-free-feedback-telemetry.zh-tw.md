# Agent Note: 無緩衝回饋遙測

Status: implemented

[English](2026-08-06-buffer-free-feedback-telemetry.md) | [简体中文](2026-08-06-buffer-free-feedback-telemetry.zh.md) | 繁體中文

## 問題

僅回饋遙測必須只在記錄回饋後上傳工作階段日誌前綴。若在觸發前為每個已投影事件保留一份已深拷貝、已脫敏的記錄，就會複製權威工作階段日誌；對於長期執行但從不記錄回饋的工作階段，這份副本會無限成長。

## 決策

遙測協調器提供 `live` 與 `on-demand` 捕獲。按需捕獲不註冊工作階段、flush 或運維事件監聽器，也不保留投影記錄。`captureSession(session, throughSeq?)` 從 handoff 遊標之後讀取權威工作階段日誌，直至選填的序列號邊界（含邊界），應用固定期定額影、深拷貝每個已接受事件、執行當前的 `session-telemetry/record` waterfall（瀑布式事件），並將結果交給後端。

`FEEDBACK_ONLY` 以 `feedback/record` 事件的序列號呼叫該方法。`session/event` 監聽器執行時期，追加已經提交，因此重播包含該回饋事件，且無法包含後續後綴。現有 handoff 遊標可區分後續重播，無需另一個待處理記錄索引。

按需捕獲只讀取權威日誌，因此不會發出 `agent-error` 或 `shutdown` 運維記錄。脫敏在回饋時而非追加時求值。[回饋模式決策](../feature/2026-08-05-feedback-gated-session-telemetry.md)規定公開的共享行為；本記錄規定其無緩衝實作。

## 考慮過的替代方案

**保留捕獲時的已脫敏記錄。** 該方案會保留每個事件發生時觀察到的確切脫敏策略與運維記錄，但也會複製無上限的工作階段前綴。該模式承諾在回饋觸發後上傳工作階段日誌，而非保留捕獲時策略快照或回饋前運維遙測。

**保留工作階段事件引用或序列號。** 已否決，因為權威日誌已同時提供順序與身份。第二個索引可以省去載荷副本，但會增加生命週期狀態，且無法實作任何必需行為。

**寫入持久化的回饋前 spool。** 推遲到有部署要求回饋前的當機復原時再實作。該方案會為一個預期在行程於回饋前退出時不上傳任何內容的模式增加儲存、清理與保密策略。

## 後果

沒有回饋的工作階段不會消耗隨事件數量成長的遙測自有記憶體；權威工作階段日誌仍是回饋前的唯一副本。回饋處理會在後端非阻塞入隊前同步執行投影、深拷貝與脫敏，因此其開銷隨未釋放前綴成長。回饋前的脫敏策略變更會影響該次重播，而回饋前發生崩潰時什麼都不上傳。後續回饋只處理 handoff 遊標之後的事件。
