# Agent Note: 移除純日誌事件的合成輪次

Status: implemented

[English](2026-07-28-remove-synthetic-log-only-turns.md) | [简体中文](2026-07-28-remove-synthetic-log-only-turns.zh.md) | 繁體中文

## 問題

工作階段儲存曾暴露 `appendOutOfBand()`，讓外掛程式可以在沒有 agent（代理）輪次執行時期發布延遲到達的純日誌事件。該方法會用 `turn/start` 和 `turn/end` 包住事件，再將其刷寫。這保留了「每個持久事件都必須位於輪次內」的舊規則，卻讓同一個識別符號既表示模型迴圈執行，又表示僅持久化更新。

引入該規則時，持久化復原曾將最後一個 `turn/end` 視為唯一的已提交邊界。如今，持久化掃描器會保留每個合法且連續的事件，崩潰修復也只處理確實處於開放狀態的輪次。因此，為標題更新保留合成輪次會誇大輪次計數、為從未執行模型的工作產生執行結果，還會讓延遲到達的元資料寫入佔用下一個輪次編號。

通用輔助函式還重複了領域策略。它的標記對映說明哪些外掛程式事件符合條件，而標題能力本就擁有取消、活躍性和過時結果處理規則。改用另一個通用或標題專屬追加包裝層，仍會為兩個字面量事件類型保留同一層類型間接性。

## 決策

`SessionStore.appendOutOfBand()`、`OutOfBandSessionEventMap` 和 `OutOfBandSessionEventType` 均不再存在。擁有純日誌事件的外掛程式透過 `Session` 追加該事件；當操作承諾持久性時，外掛程式會顯式等待 `ctx.sessions.flush(session)`。系統不會僅為獲得該檢查點而打開輪次。

核心工作階段不變數繼續強制核心所屬的執行關係：輪次與步驟編號、steering（中途引導）、助手、工具、待辦和請求標頭事件的封閉，以及同一步驟內的工具呼叫／結果配對。核心允許可合併擴充事件位於輪次之間，因為只有聲明它們的外掛程式知道這些事件受執行作用域約束，還是可以獨立存在。外掛程式的不變數配套元件仍負責其自身的事件關係。

標題服務會在完成既有的服務狀態、修訂、取消和活躍工作階段檢查後，直接追加 `session/title`。隨附模型輔助函式會在發起呼叫前追加其字面量 `session/title-llm-request` 記錄。持久化透過有界 `session/event` 路徑接納兩者，並在常規檢查點與生命週期結束時排空；二者都不會僅因為位於輪次之間就強制刷寫。因此，回退標題、輔助請求記錄或已接受的提供方標題可以出現在 `turn/end` 之後、下一個 `turn/start` 之前。手動壓縮（compaction）利用同一項輪次間能力記錄 `compaction/* { turn: null }` 標記對，但會顯式刷寫已閉合的嘗試，因為 `/compact` 承諾在放行排隊中的提示詞前完成持久化。

工作階段 fork 可以結束於開放輪次之外的任意穩定事件位置，而不限於 `turn/end`。這樣，默認 fork 會保留獨立標題和其他外掛程式所屬的純日誌記錄，同時仍拒絕在活躍執行過程中截斷前綴。

歷史上的[通用輪次封閉決策](../../archived/architecture/2026-06-15-turn-enclosure-invariant.md)如今只適合用於解釋為何曾引入合成機制。[上下文注入決策](../architecture/2026-07-24-separate-context-injection-from-turn-execution.md)確立了當前語義：一個輪次表示一次模型迴圈執行。[排隊手動壓縮決策](../feature/2026-07-30-queued-manual-compaction.md)將該規則應用於持久多事件標記對，並擁有其標記與接納語義。

## 曾考慮的替代方案

**保留合成的零步驟輪次。** 這可以讓日誌在形式上保持統一，並複用 `turn/end` 作為刷寫點，但會報告從未發生的執行、擾動輪次編號，還會迫使每個輪次消費端過濾僅持久化記錄。持久性已有獨立的 `session/flush` 邊界。

**保留不使用合成輪次的通用核心持久追加輔助函式。** 執行 `append()` 再執行 `flush()` 的方法本身很小，但其准入標記和並行承諾仍會將外掛程式策略集中到工作階段儲存中。事件所有方已經擁有直接、類型化的字面量追加點；真正需要持久性屏障的呼叫方可以在該邊界等待既有的 `session/flush` 操作。

**將標題儲存為可變工作階段元資料。** 這可以避免輪次間事件，卻會在僅附加日誌之外建立第二套變更、重播、持久化和 fork 協議。標題仍採用可重播、後寫覆蓋的事件。

**要求每個外掛程式事件向核心聲明可獨立存在的資格。** 這可以保留中心准入清單，但會讓缺少聲明意味著一種核心無法驗證的執行關係。可合併擴充聯合類型已經將語義所有權賦予聲明事件的外掛程式；該外掛程式的不變數配套元件纔是正確的強制位置。

## 驗證

核心不變數測試會接受輪次之間的未知外掛程式事件，同時繼續拒絕位於該處的內建執行事件。掛鉤、plan-mode、Code Mode 分發和審批的不變數配套元件會在沒有開放輪次時拒絕其執行作用域事件；壓縮配套元件則另外接受輪次之間平衡的 `turn: null` 手動標記對，並要求數字 owner匹配一個開放輪次。工作階段標題服務測試會在並行刷新、拒絕已脫離工作階段和接受最新修訂的場景下，固定一個直接追加的回退事件。JSONL 和 SQLite 往返測試會透過持久化生命週期排空保留追加在 `turn/end` 之後的標題；fork 測試會保留獨立純日誌尾部，同時拒絕位於開放輪次內的邊界。一個無金鑰、經完整組裝的 ACP（Agent Client Protocol）快照會將模型生成的標題延遲到 `turn/end` 之後，並固定一個不含合成輪次的獨立提供方標題。生成的 API 和類型等價性目錄不含任何已移除符號。

## 後果

輪次計數和結果重新只描述模型迴圈執行。獨立事件和手動壓縮標記對會佔用工作階段 seq，但不佔用輪次編號；它們像其他追加一樣進入有界持久化，並且僅當操作承諾持久性時，纔要求事件所有方請求顯式持久性屏障。通用外掛程式錯誤不再因核心默認的封閉規則而失敗，因此每個需要執行關係的外掛程式都必須自行聲明並測試該關係。標題能力保留修訂排序和生命週期持久化，同時減少了核心狀態；手動壓縮則獲得持久控制，不產生合成輪次或輪次編號衝突。
