# Agent Note: 簡化 Web 圖片輸入第一版

Status: implemented

[English](2026-07-29-simplify-web-image-input-v1.md) | [简体中文](2026-07-29-simplify-web-image-input-v1.zh.md) | 繁體中文

## 問題

首個持久化 Web 圖片輸入切片在引入按順序接收多張圖片的必需能力時，也引入了由 CLI（命令列介面）掛載任意提供方、輸出模態發現、替代文字、提供方無關的視覺 token 定價，以及沒有跨包（package）消費端的瀏覽器生命週期 API 等推測性表面。保留這些推測性表面會把尚未選擇的未來行為變成公共契約，並使初始能力更難評審和維護。

## 決策

第一版接受有序圖片批次，並以可設定的每則訊息圖片數量與圖片總位元組數上限，以及單張圖片位元組數與畫素上限約束批次。瀏覽器會在分配預覽前拒絕聲明不支持的格式，而宿主會以權威方式解碼完整批次、檢查當前部署上限、在不寫入儲存的情況下校驗每張圖片，之後才保存每張圖片，並在生成的持久圖片塊中保留提交順序。請求緩衝上限直接由附件服務的圖片總位元組數上限派生。這樣無需新增批次交易、回滾協議或 `host.describe` 中的策略快照，就能保持校驗的原子性。

提供方／模型選擇仍屬於設定和 profile 狀態。啟動組合會註冊交付的 DeepSeek、OpenAI 和 Anthropic 路由；CLI 不會新增圖片專用選擇標志、檢查 yml 提供方清單或動態掛載配接器。

確切模型元資料只攜帶當前准入決策會消費的輸入模態。`ImageBlock` 攜帶持久附件引用；其選填顯示名稱提供無障礙 UI 文字，因此核心塊沒有單獨的替代文字欄位。與提供方無關的 token 估算不會把某一提供方的視覺定價公式應用於其他路由。

附件 seam 公開其限制、不觸碰儲存的 `validateImage`，以及 `saveImage` 和 `readImage`。宿主相依性該 seam，而不是實作層重新匯出的內容。瀏覽器草稿和歷史圖片操作仍是具體工作階段外掛程式的內部實作；公開的 `IConversation` 表面只包含輸入登錄檔，以及跨包邊界使用的按作用域傳送、取消和歷史記錄操作。

## 曾考慮的替代方案

**只接受一張圖片。** 比較或組合多張圖片是當前產品要求。圖片數量和總位元組數上限使這條路徑保持有界，而無需將其縮減為單張圖片。

**新增儲存交易或回滾協議。** 不觸碰儲存的校驗能防止後面的畸形成員使前面有效的成員成為無引用對象。若要在獨立的內容尋址對象之間實作更強的全有或全無儲存保證，就需要當前產品路徑並不需要的所有權或回收語義。

**將面向未來的欄位和方法保留為佔位符。** 輸出模態、塊替代文字和活躍模型握手資料目前都沒有決策消費端。等到第一個消費端出現時再加入這些內容，可以保留選擇正確契約的自由。

**使用一種圖塊公式估算每張圖片。** 視覺定價因提供方、模型、細節模式和預處理而異。一項硬編碼且與提供方無關的估算會看似權威，實際卻是錯誤的；提供方用量纔是權威覈算來源。

**新增 CLI 提供方／模型選擇或動態掛載。** 設定已經負責路由選擇、外掛程式組合和憑據。在圖片輸入標志中重複這些選擇，會要求在 loader 之外解析或修改設定樹。

## 後果

該功能保留了多圖片提示詞所需的兩個批次上限和一個不觸碰儲存的校驗方法，同時移除了無關的公開欄位、生命週期操作、策略快照和路由組裝分支。提供方／模型選擇仍屬於組合或 profile 設定。在設計出提供方感知型估算器之前，請求前的 token 壓力計算可能少計視覺輸入，而上報的用量仍保持精確。

重新引入任何已移除表面時，都必須有具體消費端，並為其定義失敗、生命週期、重播和測試契約，而不是為了相容這一預發布形態。
