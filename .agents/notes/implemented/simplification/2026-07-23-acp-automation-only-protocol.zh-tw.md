# Agent Note: ACP 作為僅面向自動化的協議

Status: implemented

[English](2026-07-23-acp-automation-only-protocol.md) | [简体中文](2026-07-23-acp-automation-only-protocol.zh.md) | 繁體中文

## 問題

ACP（Agent Client Protocol）橋接層已經變成第二套互動式產品 UI。它將持久事件轉換為編輯器卡片、終端機元資料、diff、計畫、標題、推理（reasoning）、命令、模式、模型和權限選擇器、工作階段導覽以及面向人類的詢問。這些職責與 TUI 和 Web 用戶端重複，同時將自動化傳輸層與 UI 服務、持久化查詢、展示策略和編輯器特定約定耦合在一起。

ACP 仍有一個有用的職責：另一個 agent（代理）或自動化控制器可以啟動 harness 行程、建立隔離工作階段、傳送文字、接收已提交的回答、取消工作並回答權限請求。跨行程 ACP subagent 後端相依性這個標準協議邊界。

快照套件使移除工作更複雜。大多數 ACP 場景測試的是組裝後的 agent 後端，而不是 ACP 展示層；如果隨編輯器橋接層一起刪除整個套件，就會丟失大量無金鑰行為測試。

## 決策

`@deepseek-ai/dsh-acp` 是位於 [`packages/acp/acp`](../../../../packages/acp/acp/README.md) 下、獨立於 `ui` 包組的自動化傳輸層。其公開協議特意保持精簡：版本協商、全新文字工作階段（每個工作階段最多允許一個進行中的提示詞）、已提交的助手文字更新、按工作階段取消、並行工作階段，以及由連線負責的資源清理。提示詞只承載規範要求的基線內容——文字，加上被展平為方括號文字引用的資源連結；橋接層會拒絕附加目錄、MCP 伺服器、超出基線的提示詞內容（圖片、音訊、內嵌資源）、空提示詞、未知工作階段和重疊提示詞。

橋接層只發出已提交的 `assistant/message` 文字。推理、原始區塊、工具活動、待辦事項、計畫、標題、重試標記、終端機元資料、diff、位置和資源連結仍保留在持久工作階段日誌或 UI 專用傳輸層中。它不提供工作階段載入、列出與刪除、命令、模式、設定選擇器、模型切換、plan 評審或面向人類的詢問。

保留一次性 `session/request_permission`。它是為橋接層擁有的 agent 提供的機器策略通道，而不是面向人類的審批 UI：應答者只接受橋接層當前工作階段對映中登記的同一 agent 對象；不屬於橋接層當前 agent 的請求或未關聯具體呼叫的請求會繼續委派；RPC 失敗則對映為故障時默認拒絕的 `unavailable` 結果。用戶端選填擇允許一次、拒絕一次或取消，橋接層絕不會將該回應轉換為持久授權。詢問策略仍歸審批 seam 及其生產者所有；[`dsh-subagent-acp`](../../../../packages/subagent/subagent-acp/README.md) 會以程序化方式使用該通道。

應用組裝包含 agent 主幹、持久化、檢查點策略和 ACP 傳輸層。它不會為 ACP 掛載命令、工作階段查詢、工作階段引用、plan mode、權限選擇器或使用者互動服務。

傳輸層呼叫 agent、工作階段和審批的介面服務，而不相依性具體的 agent loop（代理循環）。工具執行仍留在 harness 內；ACP 絕不會把 shell 執行委派給編輯器。stdout 只承載分幀 JSON-RPC，因此 app 不掛載 stdout logger，橋接層也不會 monkey-patch 行程輸出。

中斷連線連線與外掛程式 dispose（資源釋放）共享同一個經記憶化的完全靜止邊界。傳輸關閉無論成功還是失敗，都會將待處理提示詞以已取消狀態結帳，dispose 每個由橋接層擁有的 agent，並等待 agent loop 和工作階段清理完成。建立流程如果在與關閉的競態中落敗，就會 dispose 其尚未發布的 handle。

## 快照邊界

ACP 快照套件仍會啟動組裝後的 ACP 示例，並保留用於鎖定後端行為的場景。從該套件移出的只有透過已刪除的 UI 方法驅動程式的場景；由於 ACP 不再載入工作階段，語義檢查點復原透過 headless `stream-json` 示例執行。

協議與生命週期測試會鎖定停止原因編解碼器和提示詞編解碼器、版本協商、新工作階段建立、文字與資源連結展平、拒絕空提示詞或不受支持的提示詞、基於同一 agent 對象的權限歸屬、多工作階段隔離、提示詞結帳、按工作階段取消、傳輸關閉失敗、ACP 專屬重載清理，以及拆卸完全靜止。建置產物冒煙測試與真實 stdio 冒煙測試會拒絕混入 stdout 的額外輸出。`session/new` 中在真實 stdio 關閉競態中落敗的分支仍豁免覆蓋率要求，因為記憶體傳輸層無法復現這一順序；該分支會 dispose 尚未發布的 handle，而周邊 dispose 測試會鎖定無殘留資源不變式。

## 考慮過的替代方案

**在 Web 達到同等能力前，繼續將 ACP 作為編輯器 UI。** 不予採用，因為這會留下兩套需要演進的互動約定，並使編輯器約定繼續存在於自動化邊界中。

**透過嚴格的服務邊界保留早期編輯器橋接層。** 不予採用，儘管該橋接層正確使用了介面服務、工具自有的 render intent、審批與使用者互動應答者、harness 自有執行，以及保持 stdout 純淨的組裝。其終端機卡片是經過能力門控、僅用於展示的 Zed `_meta` 投影，並提供文字回退，而非使用 ACP `terminal/create`，因此 shell 執行從未離開 harness。該投影從穩定的逐呼叫 id 派生每個展示用終端機 id，以避免衝突；由於純結果展示器接收的是內容區塊，而不是結構化退出資訊，它會從渲染後的狀態標記中復原退出碼或訊號。標記往返測試和顯式的無能力 `console` 回退測試鎖定了這兩項約定。這些邊界保持一致，卻無法讓編輯器卡片、工作階段導覽、設定選擇器和麵向人類的詢問成為自動化協議應有的職責。

**用私有 subagent RPC 替換 ACP。** 不予採用，因為 ACP 已經提供類型化、可互操作的行程協議，並由跨行程 subagent 後端使用。

**隨其他互動功能一起移除機器權限請求。** 不予採用，因為自動化父 agent 必須回答子 agent 的一次性策略決策；這是 agent 之間的控制流，而不是展示層。

**刪除 ACP 快照套件，或在本次變更中遷移每個場景。** 不予採用，因為大多數場景測試後端且仍有價值，而完整的 harness 遷移是一項獨立的測試變更。只有透過已刪除的 UI 方法驅動程式的場景才離開該套件。

## 結果

ACP 具有適合 agent 與自動化的精簡約定，而 TUI 和 Web 擁有面向人類的互動與展示。該包注入的服務、相依性、協議分支和生命週期狀態更少，也不再將自身定位為通用編輯器入口。

自動化用戶端收到完整的已提交文字，而不是 token 增量或結構化工具 UI。當它們需要推理、工具跟蹤資訊、標題或更豐富的狀態時，需要查看持久日誌或其他 API。只支持全新工作階段也意味著，需要瀏覽持久工作階段或復原工作階段的呼叫方必須使用 host API，而不是 ACP。

因此，後端快照測試仍與 ACP 傳輸層耦合，儘管對於受測行為而言，該傳輸層只是附帶因素。
