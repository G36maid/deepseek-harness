# Agent Note: 移除空的實驗性包分組

Status: implemented

[English](2026-08-11-remove-empty-experimental-package-group.md) | [简体中文](2026-08-11-remove-empty-experimental-package-group.zh.md) | 繁體中文

## 問題

包層級結構預留 `packages/experimental/` 用於原型和內部專用外掛程式，但從未有包使用該分組。這個空分組新增了放置、相依性、提升和發布規則，卻沒有需要這些規則的現有包或發布機制。

原分組旨在讓團隊基於真實外掛程式圖共享原型，同時不暗示產品會提供支持。這項需求將來可能出現，但在具體包出現前，不足以支持一個永久的倉庫類別。

## 決策

包層級結構不再預留實驗性或內部專用分組。包繼續按照當前產品職責放入對應分組。

如果具體包需要不同的發布、穩定性或相依性處理，必須根據其實際消費端和發布機製做出決策。只要該決策同時定義並強制執行排除規則，就可以重新引入專用分組。

本 Agent Note 整合併取代實驗性包分組決策；該舊決策的活躍三文件組隨空目錄一並移除。

## 考慮過的替代方案

**保留空分組。** 它為未來孵化工作提供明確位置，但也會保留沒有當前負責人、包或強制執行機制的倉庫規則。

**將實驗性規則移入通用包指令。** 這可以在不保留空目錄的情況下延續政策，但會讓每次包變更都攜帶針對假設包類別的規則。

**將具體實驗性包放入產品職責分組，並用 README 標注。** 這會保持產品職責共置，但僅靠標注無法強制執行發布和執行時期相依性規則。未來的包可以根據實際發布機制評估此選項。

**在首個帶標籤的版本發布前，將每個包都視為實驗性。** 這會施加寬泛的臨時狀態，卻無法為發布開始後仍處於實驗狀態的包提供持久處理方式。

**要求原型留在倉庫外。** 這會失去真實外掛程式圖、示例、快照和生命週期檢查。移除預留分組並不施加這項限制；具體原型可以建立自身所需的放置規則。

## 後果

包層級結構移除了未使用的分組及其特殊發布和相依性政策，同時也放棄了預先聲明的團隊發現位置和現成的提升路徑。

第一個需要實驗性或內部專用處理的包必須定義其存放位置、發布版本如何排除它、允許哪些執行時期相依性，以及包在何種條件下獲得提升或被移除。當這些規則具有當前消費端和可強制執行的機制時，可以復原專用分組。
