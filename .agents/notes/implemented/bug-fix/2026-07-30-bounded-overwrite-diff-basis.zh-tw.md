# Agent Note: 在提供方限制覆寫上下文 diff 基礎

Status: implemented

[English](2026-07-30-bounded-overwrite-diff-basis.md) | [简体中文](2026-07-30-bounded-overwrite-diff-basis.zh.md) | 繁體中文

## 問題

`dsh-fs-local` 會在 `FsWriteOutcome.before` 中返回完整舊文件，供消費端生成覆寫上下文 diff。這個僅用於展示的預讀沒有上限：大文件覆寫可能分配整個舊文件；而僅檢查較早的路徑 stat 也無法真正實施上限，因為外部行程可以在 stat 與讀取之間替換文件或擴大文件。即使舊文件很小，大替換內容也會使上下文 hunk 接近替換內容本身的大小。本改動關閉了 [result-time applied-hunk diff](../../archived/architecture/2026-07-02-result-time-applied-hunk-diffs.md) 中記錄的暫緩上限事項。

## 決策

`LocalFileSystem.Config.diffBasisMaxBytes` 是一個不超過執行時期 Buffer 分配和字串解碼上限的正安全整數部署設定，默認 10 MiB。只有當 UTF-8 替換內容嚴格低於該上限，且為生成基礎而打開的舊文件最終也低於該上限時，覆寫才提供 `before`。舊文件讀取會開啟檔案描述符、檢查該描述符，並按可回應取消的分塊最多讀取設定的位元組數；一旦到達邊界便返回 `null`。描述符 stat 後發生大小變化時同樣返回 `null`，即使最終大小仍低於上限，因為部分前綴會成為錯誤的 diff 基礎。舊內容為二進位或無效 UTF-8 時也返回 `null`；描述符階段的任何 errno 同樣如此——舊文件在呼叫方預檢之後、基礎讀取打開之前被刪除或變得不可讀，不能讓呼叫方已經提交的寫入失敗；只有取消和非 errno 故障會繼續向上傳播。這些結果都不會阻止原子寫入。

本機提供方擁有該決策，因為 `before` 是它提供的選填、盡力而為的基礎：當設定的成對上限已使替換內容不合格時，它可以避免取得舊內容。`tool-fs` 繼續擁有 diff 計算、保留與展示。該設定獨立於 `tool-fs.readStreamMinSize`；讀取路由與覆寫展示是不同策略，無需共享數值。

`before: null` 要求消費端使用既有的整文件回退。該上限只限制額外取得舊內容的成本，以及上下文內容對是否合格；它不限制呼叫方持有的替換內容、返回的 `after` 值或消費端的回退渲染。

## 考慮過的替代方案

**保留一個與讀取工具流式閾值相等的硬編碼閾值。** 否決，因為讀取閾值可由部署設定，且歸消費端所有。兩個同值常數會形成無法強制的一致性耦合，而覆寫基礎本身也是部署層面的記憶體與展示選擇。

**提供方只限制舊內容一側，並在 `tool-fs` 中限制新內容 diff。** 否決，因為當提供方設定的成對上限已經排除替換內容時，這仍會取得舊文字；同時會把同一條 `before` 合格規則拆到兩個外掛程式中。消費端仍可自由施加額外的輸出限制。

**信任初次 `probe()` 的大小，再執行普通整文件讀取。** 否決，因為該大小可能在學取前變舊；描述符讀取必須對它真正讀取的對象實施上限。

**為任意大的內容對流式生成上下文 diff。** 本次缺陷修復不採用，因為當前檔案系統 seam 返回完整的 `before`/`after` 字串，當前 diff 實作也消費這兩個字串。流式 diff 需要獨立的跨包協議與展示設計。

## 後果

部署可以調整額外的覆寫基礎成本，而不改變讀取路由。達到或超過排他上限時，覆寫仍會成功，並透過整文件回退保持可見，但不再提供上下文 hunk。低於上限時，除呼叫方的替換內容外，提供方仍可能持有接近 `diffBasisMaxBytes` 的舊文字。對於合格覆寫，有上限的描述符讀取會增加一次 open/stat/read 序列，同時防止過時路徑探測把該序列變成無上限分配。
