# Agent Note: Web 圖片准入的原子性

Status: implemented

[English](2026-07-29-atomic-web-image-admission.md) | [简体中文](2026-07-29-atomic-web-image-admission.zh.md) | 繁體中文

## 問題

包含圖片的提示詞准入與 `session.selectModel` 都會在跨越非同步模型查詢與附件查詢的過程中讀取工作階段模態狀態。如果沒有統一的順序邊界，包含圖片的提示詞可能在支持圖片的目標上透過校驗，並行的選擇操作卻設定了純文字目標；選擇操作也可能在提示詞已從 inbox 出隊、但其持久訊息事件尚未發布時漏掉該提示詞。掃描不可變事件日誌可以避免第二種競態，但即使壓縮（compaction）已經從當前模型歷史中移除圖片，仍會永久阻止選擇純文字目標。

## 決策

每個活躍 Web agent（代理）都有一條私有 promise 鏈，由包含圖片的提示詞准入與模型選擇共享。操作失敗會照常傳遞給呼叫方，且不會使該鏈失效。純文字提示詞繞過該鏈，因為它們不會改變模態約束。

待發布集合會在排隊條目出隊時記錄它，而 steering 條目在入隊時即被記錄（steering 條目從不進入排隊 UI 映像檔），並各自保留到匹配的 `user/message` 或 `steering/message` 事件發布。若准入結束時未發布事件，轉為空閒狀態會移除這些條目；inbox 丟棄會移除列出的工作項，工作階段 dispose（資源釋放）則會移除所有剩餘條目。模型選擇會檢查該集合、排隊 UI 映像檔以及 `Session.deriveMessages()`；後者表示壓縮後模型當前可見的歷史。

提供方配接器仍是最終的強制檢查邊界。宿主的順序控制僅用於避免其可變路由與待發布圖片狀態在請求組裝前彼此矛盾。

## 曾考慮的替代方案

**掃描每個不可變工作階段事件。** 這能捕獲已發布的圖片，但會把經壓縮移除的內容視為永久對模型可見，從而阻止之後合法切換到純文字路由。

**在 inbox 出隊時退役待處理映像檔。** 出隊早於持久訊息追加，因此恰好會留下一個時間區間，讓模型選擇既看不到待處理狀態，也看不到已發布狀態。

**序列化每個提示詞和工作階段變更。** 純文字提示詞和無關的工作階段操作無法引入圖片要求。更寬的鎖會增加延遲與所有權複雜度，卻不會再消除任何模態競態。

## 後果

包含圖片的提示詞准入與並行模型選擇之間具有確定的先後順序，純文字目標無法使已獲准入但尚未發布的圖片擱淺。模型選擇可能等待正在進行的圖片准入完成，而無關提示詞仍按現有方式並行處理。當沒有圖片等待發布，且派生歷史經過壓縮後也不再含圖片時，純文字目標可以變得有效。
