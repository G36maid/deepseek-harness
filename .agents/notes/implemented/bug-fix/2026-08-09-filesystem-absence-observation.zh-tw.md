# Agent Note: 檔案系統中的缺失是一種觀測，帶防護的建立絕不執行替換

Status: implemented

[English](2026-08-09-filesystem-absence-observation.md) | [简体中文](2026-08-09-filesystem-absence-observation.zh.md) | 繁體中文

## 問題

事件門控的檔案系統策略最初只把成功讀取和變更記錄成目標版本。如果某個工作階段讀取文件後，外部命令將其刪除，第一次帶防護的變更會正確地因過時而失敗，但按指示執行的重新讀取會在寄出 `fs/observed` 前返回 `FS_NOT_FOUND`。因此，舊的存在版本會一直保留：寫入仍不斷選擇 `replaceIfVersion`，提供方仍不斷拒絕缺失目標，而面向模型的「re-read the file, then retry」指令則形成無法復原的迴圈。

把一次失敗的讀取視作建立授權，還會暴露第二個邊界。本機與 E2B 提供方都會先探測再暫存，此前隨後透過 rename 發布；另一行程可能在兩步之間建立目標，即使呼叫方提供了 `createIfAbsent`，該目標仍會被覆蓋。行程內目標鎖無法防範這種跨行程發布競態。

## 決策

`dsh-fs` 擁有一個顯式觀測聯合類型：`{ kind: 'present', version: FsVersion } | { kind: 'absent' }`。`fs/observed` 事件攜帶該聯合類型。成功的讀取與變更寄出存在觀測；`read` 的元資料未命中，或 `str_replace_editor` 的 `view`、`str_replace`、`insert` 命令發生元資料未命中時，都會在返回 `FS_NOT_FOUND` 前同步寄出缺失觀測。其他讀取失敗不會產生缺失觀測。

`dsh-fs-observation-policy` 按所有者與目標儲存三種邏輯狀態，既不注入也不呼叫 `ctx.fs`：對映中無條目即未見，`absent` 表示確認缺失，`present(version)` 是替換/編輯基準。寫入把未見和缺失對映到現有 `createIfAbsent` 意圖，把存在對映到 `replaceIfVersion`。編輯把未見對映到 `FS_NOT_OBSERVED`，把缺失對映到 `FS_NOT_FOUND`，把存在對映到其版本守衛。成功建立或變更後，系統會用其產生的存在版本取代缺失狀態。

每個提供方都必須在發布點執行 `createIfAbsent`，不能只在初始探測時執行。`dsh-fs-local` 在私有同級目錄中暫存並執行 fsync，再透過硬連結把暫存文件發布到目標位置；連結失敗後，它會檢查目標條目：與普通文件衝突時返回 `FS_NOT_OBSERVED`，條目非普通時返回 `FS_NOT_REGULAR_FILE`，目標仍然缺失時返回 `FS_IO_ERROR`。`dsh-fs-e2b` 使用遠端 `ln -T` 返回明確的已建立/已存在結果，並根據不可取消提交前取得的元資料推導已提交目標的版本。替換操作和裸無條件寫入仍沿用現有發布路徑。

本決策不宣稱 `replaceIfVersion` 具有跨行程線性一致性：提供方的版本檢查與替換仍只能防範被其自身鎖納入協調的寫入方，以及能透過元資料偵測到的寫入方。更窄的保證邊界準確且足以支持缺失復原：帶防護的建立絕不會覆蓋在發布前出現的目標。本機帶防護的建立要求支持硬連結；任何本機發布一旦成功，暫存清理便採用盡力而為語義，因為私有殘留無法否定已提交寫入的成功。

## 曾考慮的替代方案

- **讀取返回未找到時刪除快取版本。** 不予採用，因為這會混淆未見與確認缺失，無法讓 edit 返回正確的 `FS_NOT_FOUND` 結果，還會抹去該事件本應傳達的狀態轉換。
- **讓 `dsh-fs-observation-policy` 在選擇意圖前呼叫 `stat`。** 不予採用，因為這會讓只相依性事件的策略轉而相依性提供方，為每次決策增加 I/O，並且在發布前仍留下 TOCTOU 間隙。
- **允許 `replaceIfVersion` 在目標消失後執行建立。** 不予採用，因為存在觀測是執行替換而非建立的依據；靜默改變該提供方意圖會繞過必須針對缺失目標執行的重新讀取，並削弱過時保護。
- **讓刪除目標後的死路繼續保持 fail-closed。** 不予採用，因為這樣會使面向模型的復原指令失實，而且正常的外部清理操作無法在工作階段內復原。

## 影響

尚未觀測到外部刪除時，第一次變更仍以 `FS_STALE_VERSION` 失敗；使用者或模型必須遵循現有的重新讀取復原指令。該次針對缺失目標的重新讀取會返回 `FS_NOT_FOUND` 並同時改變策略狀態，此後 edit 仍被禁止，而 write 可以重新建立該路徑。如果另一個寫入方贏得建立競態，本次重試會返回 `FS_NOT_OBSERVED`，並保留獲勝方寫入的文件；若競態目標是目錄、特殊條目或懸空符號連結，則改為返回 `FS_NOT_REGULAR_FILE`，且不會要求再次讀取。

觀測載荷是由包擁有的事件約定變更，因此所有生產方、監聽器、不變式、生成的 Cordis 目錄、子系統文件以及兩套檔案系統工具都必須同步更新。策略保留[事件閘門決策](../architecture/2026-06-26-file-context-as-event-gate.md)確立的 read 一次 `stat`、write/edit 零次 `stat` 預算、所有者隔離、dispose 行為和選填部署邊界。

組裝後的檔案系統快照固定面向模型的復原鏈；提供方測試則在暫存後注入一個建立者，以證明發布不會覆蓋競爭目標。[帶防護變更復原指令決策](../feature/2026-08-03-fs-tool-error-remedy.md)仍然擁有面向模型的復原措辭；本 Agent Note 使其中的刪除路徑能夠生效。
