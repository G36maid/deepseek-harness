# Agent Note: Web GUI 改動在現有 URL 上閉環

Status: implemented

[English](2026-07-28-web-gui-feedback-loop.md) | [简体中文](2026-07-28-web-gui-feedback-loop.zh.md) | 繁體中文

## 問題

Web agent（代理）既無法識別承載當前工作階段的 GUI，也不知道使用者正在查看哪個 URL。[執行時期上下文決策](2026-07-28-web-agent-runtime-context.md)提供前一項事實，但 GUI 編輯仍然沒有可執行的驗收目標：原始碼編輯、產物建置、監聽中的行程與使用者已打開的頁面只是互不關聯的觀察結果。倉庫提供的入口讓錯誤的替代方案顯得合理，因為 `apps/web/package.json` 將 `vite` 暴露為 `dev` 指令碼，而裸 Vite 即使無法注入 `window.__DSH_BOOT__`，仍會返回 HTTP 200。

[事後檢討](../../../../docs/postmortem/0003-web-agent-gui-feedback-loop.md)集中記錄事件日誌時間線，並解釋原有檢查為何會接受錯誤的頁面、行程和埠。

## 決策

常規 `dsh web` 組合會掛載 Web 組合包的 `web-runtime` 外掛程式，由它發布一個規範的回環 URL，同時將其作為模型可見的介面定位資訊和受管 shell 事實。`app:web-surface` 提示詞段說明：未加限定的指代指向此 GUI，並給出 URL；`DSH_WEB_URL` 會把同樣的事實傳入每次前臺或受管後臺 bash 呼叫。該段保留「不會隱式獲得 DOM、路由或截圖」這一邊界，也不聲稱局域網別名等於瀏覽器中的實際地址。擁有完整提示詞的 profile 會把該設定行的 `surfaceContext` 設為 false，並且不會收到該提示詞段和該受管變數；Web 啟動器也會使用同一項設定來抑制其原始碼 checkout 提示詞段。

提示詞讓 agent 而非使用者負責隱藏的啟動約定。HMR（熱模組替換）接收端始終掛載，但用戶端外掛程式要自動重新載入，還需要在同一檢出中執行 `pnpm run dev:web` 監聽行程，agent 會在承諾無需刷新即可更新前驗證這一點。外殼和其他普通包的變更仍然需要重新建置受影響的產物並刷新現有 URL。除非使用者要求，agent 不會啟動替代 GUI。

`apps/web` 開發指令碼和 Vite 設定都會在打開埠前阻斷服務模式。診斷資訊會指出 `apps/web` 只是一個僅供建置的外殼，說明只有 `dsh web` 才會注入 `window.__DSH_BOOT__`，並給出生產入口與 HMR 入口路徑。Vite 建置模式保持不變。

靜態產物發生變化時，不需要僅為此重新啟動或替換伺服器。宿主會在每次請求時讀取 `index.html` 和靜態資源，用戶端 bundle 也會從當前文件提供，並設定 `no-cache`；因此，重新建置相關外殼與外掛程式 bundle 後，刷新現有 URL 就是驗收路徑。啟動另一個伺服器只能證明另一個伺服器可用。如果使用者明確要求再啟動一個長期執行的伺服器，則現有受管背景工作約定負責其生命週期和完成通知；shell `&` 不能替代這套生命週期機制。

## 驗證

無金鑰的 fresh-round-trip 瀏覽器場景會啟動已交付的 Web 組合，驅動真實的重播工作階段，對包含 URL 的系統提示詞前綴生成快照，並呼叫組裝後的 bash 工具，證明 `$DSH_WEB_URL` 與實際綁定的執行時期一致。真實 CLI 冒煙測試會啟動 `dsh web` 並捕獲模型提供方請求，從而固定完整的雙命令開發約定。`dev:web` watcher 測試會在原始碼發生變化後重新建置隔離的用戶端 bundle；瀏覽器 HMR 場景會啟動 `dsh web`，修改初始 roster 中的 bundle，並在頁面 identity 不變的情況下觀察新 DOM。真實 Vite 子行程測試要求服務模式在給出改用完整宿主的糾正資訊後自然退出，並透過插樁 `Server.listen()` 證明它從未被呼叫。真實 loader Web 伺服器測試會在行程完成綁定後改寫靜態資源，並證明同一埠返回新的位元組。這些斷言檢查提示詞狀態、行程退出狀態、shell 輸出、DOM identity 和 HTTP 位元組，而不是 agent 的成功聲明。

## 考慮過的替代方案

**僅擴充系統提示詞。** 不予採納，因為這樣會讓工具仍然無法獲得目標，保留具有誤導性的裸 Vite 路徑，並且無法證明現有行程如何觀察重新建置的產物。

**刪除 `apps/web` 開發指令碼，但不為 Vite 新增防護。** 不予採納，因為事故中實際使用的命令 `npx vite` 會繞過包指令碼。服務模式本身必須失敗。

**每次編輯後自動重新啟動或替換當前 Web 行程。** 不予採納，因為靜態伺服器本就會在每次請求時讀取當前產物，重新啟動還會中斷發起編輯請求的工作階段，而用戶端外掛程式重載由始終掛載的 HMR 鏈路加 `pnpm run dev:web` watcher 負責。

**每次請求都發送 DOM、路由或截圖。** 推遲到另行設計的已記錄輸入機制。穩定的 URL 身份足以閉合本次回饋迴圈，同時不會聲稱宿主掌握其未接收的瀏覽器狀態。

## 影響

常規 Web 提示詞會增加一個動態 URL 段落，因此模型提供方的前綴複用會隨綁定埠變化。相應的 Bash 行程會增加一個非敏感的受管環境變數。裸 Vite 不再能用作只相依性 shell 的視覺沙盒；開發者應改用完整宿主或建置模式。作為交換，GUI 工作有了一個可由機制觀察的唯一目標，agent 可以向使用者說明實際承載其工作階段的行程究竟如何更新，不受支持的啟動路徑也會在出現白屏前失敗。URL 約定會引導 agent 避免使用替代埠，但不會禁止任意 shell 命令啟動替代服務。停用 `surfaceContext` 的 profile 也會放棄這項回饋閉環指引與 shell 上下文。
