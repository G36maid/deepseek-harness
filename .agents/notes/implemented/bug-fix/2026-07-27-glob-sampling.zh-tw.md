# Agent Note: 跨目錄樹取樣超出上限的 glob 結果

Status: implemented

[English](2026-07-27-glob-sampling.md) | [简体中文](2026-07-27-glob-sampling.zh.md) | 繁體中文

## 問題

使用者詢問工作區包含什麼內容時，一個 agent（代理）把某個子資料夾描述成了整個項目。該工作區有 22 個頂層條目和 11,485 個文件。`glob {"pattern":"*"}` 匹配到 10,030 條路徑，但內聯顯示的 100 條路徑全部位於一棵近期解壓縮的子樹中，因此模型完全沒有看到其餘 21 個條目。

三個單獨看都合理的行為疊加後造成了錯誤印象。不含 `/` 的 glob 會匹配任意深度的檔名，因此 `*` 表示目錄樹中的每個文件，而不是 shell 對當前目錄執行的展開。Ripgrep 的 `--sort=modified` 按升序排列，因此歸檔包還原出的舊時間戳會讓該子樹排在最前。隨後，內聯頁面直接擷取這一順序的前部，卻沒有說明它只代表集中於一處的切片。

## 決策

未超過 `globMaxResults` 的結果仍保持完整，且按修改時間排序的內容逐位元組不變。必填的 `sampleOverCapGlobResults` 設定沒有回退值：`false` 會為超過上限的結果保留按修改時間排序的前部，`true` 則會在完整結果的頂層條目之間按輪轉方式取樣。取樣模式下，每個條目都先獲得一個位置，之後纔有條目獲得第二個位置；已經用盡的分組會退出輪轉；各組內部的相對順序保持穩定；分組以實際搜尋根為基準，顯式指定 `path` 時也如此。

取樣模式下，footer 會說明當前頁面是跨條目的樣本，而不是按修改時間排序的前部；當觸達的頂層條目數能提供額外資訊時，還會報告該數量。若頂層條目數量超過內聯位置數，footer 會要求模型縮小 `path`。保留前部的模式沿用達到上限時的普通 footer。spill 成功時，兩種模式都會在該產物中保留完整排序清單。

提示詞與 schema 會說明設定所指定的超限結果排序方式、不含 `/` 的模式會匹配任意深度，以及 glob 只返迴文件而絕不返回目錄條目。隨產品交付的 CLI（命令列介面）組合顯式選擇保留前部的模式；希望達到上限的頁面具有代表性的部署則選擇取樣模式。在向模型暴露 bash 工具的部署中，目錄定位仍由普通 shell 操作完成：查看一個目錄使用 `ls`，跨目錄樹按指定檔案路徑模式尋找則使用 glob。skill（技能）發現流程仍將 `ctx.fs.listDir` 作為內部提供方原語使用；本決策不會新增面向模型的 `list` 工具。

## 考慮過的替代方案

**只保留按修改時間排序的前部。** 測量實際故障形態後否決。某些部署需要這種穩定排序；但重視工作區定位的部署可以顯式選擇具有代表性的資料，而不必要求模型懷疑自己拿到的唯一一批路徑。

**為取樣選項提供預設值。** 否決。沒有全產品範圍的證據支持把任一排序作為隱式約定，因此每個組合都必須選擇一種，設定錯誤則在載入時失敗。

**對所有結果取樣。** 否決。完整結果沒有因截斷損失任何資訊，因此按修改時間排序仍有助於回答關注新舊時間的問題。只有當擷取前部已經無法描述整體時，才開始取樣。

**改為最新優先排序。** 否決。這只會改變哪一棵結果集中的子樹可能佔據主導；既取消了現有的最舊優先約定，也沒有讓受限頁面更具代表性。

**僅在偏斜超過閾值時取樣。** 否決。目前沒有證據支持適用於所有部署的統一閾值，模型也無法判斷當前採用的是哪一種排序約定。現有上限是可以清楚解釋的切換點。

**在頂層以下遞迴平衡。** 暫緩。按第一路徑段做平衡已經修復觀測到的故障；更深層的平衡需要一套尚無依據的深度與廣度取捨策略。

**新增面向模型的 `list` 工具。** 實作評審後否決。默認程式設計組合已經提供通用 bash，模型也理解 `ls`；重複工具會永久增加 schema 與提示詞所佔的 token，並引入排序、分頁、符號連結、轉義、UI 與快照約定，卻沒有獨立的安全或策略收益。不向模型提供 bash 工具的精簡部署也不會因本次改動獲得目錄定位能力。

**拒絕 `*`，或在不含分隔符的模式前靜默加上根目錄錨點。** 否決。同樣的「在任意深度匹配檔名」行為使 `*.ts` 可以有效地跨目錄樹搜尋。記錄這條規則能夠保留正常工作的 Ripgrep 語義。

## 影響

取樣模式下，超過上限的 glob 頁面無法再根據內聯路徑回答按時間判斷新舊的問題；footer 會明確說明這一點，spill 產物仍保留完整的排序檢視表。取樣只平衡搜尋根下的第一路徑段，因此某個頂層條目內部較深處、結果密集的子樹仍可能佔據主導。保留前部的模式則把集中風險作為顯式部署取捨保留下來。

工具介面不會擴大。每個組合都必須設定 `sampleOverCapGlobResults`；更改該值會改變 glob 的提示詞、schema 描述以及超過上限時的 Native 渲染。規範輸出保留 `root`，以便取樣模式復原其分組基準；未超過上限的結果保持不變。

## 測試

包測試鎖定了必填設定、兩種超過上限模式及其提示詞和 schema 描述、結果集中與扁平兩種情況、顯式根目錄、分組數超過 JavaScript 參數個數上限、分組耗盡、位置數少於分組數，以及工作目錄以外的路徑。`fs-glob-sampling` ACP（Agent Client Protocol）場景會顯式啟用取樣，啟動最小化的真實 Loader/app/local-bash 組合，並讓真實搜尋外掛程式對接確定性的 `rg` 行程 fixture（測試前置資料）；其結果覆蓋 4 個頂層條目，而不是隻返回某棵子樹的前部。
