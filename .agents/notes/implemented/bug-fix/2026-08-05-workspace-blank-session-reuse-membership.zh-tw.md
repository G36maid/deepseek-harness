# Agent Note: 工作區新建工作階段複用了 cwd 匹配但未入帳的空白工作階段

Status: implemented

[English](2026-08-05-workspace-blank-session-reuse-membership.md) | 繁體中文

## 問題

在側邊欄某個工作區分組的 `+` 上建立工作階段時，有時會進入一個新工作階段，但側邊欄把它顯示在「未分組」而不是點擊的那個工作區下——「進入了新工作階段，但工作區沒有被選中」。故障只出現在註冊在 CLI（命令列介面）執行目錄（即 `defaults.cwd = process.cwd()`，實際場景裡就是 harness 檢出目錄本身）上的工作區，並且一旦該目錄下存在 CLI 建立的空白工作階段就會出現。

根因：`connectWorkspace` 的空白工作階段複用掃描只按 `cwd` 相等匹配工作階段清單映像檔。host 自己的成員規則要求**同時**滿足：工作階段 id 在工作區帳戶（`sessionIds`）中，**且**工作階段 header 的規範化 cwd 等於工作區路徑（[Workspace UI product flow](../feature/2026-07-25-workspace-ui-product-flow.md)）；只有 cwd 匹配而沒有帳戶槽位的恰恰就是「未分組」的情形。複用掃描忽略了帳戶槽位，因此任何 cwd 匹配的**線上空白**工作階段都會被選中——包括 CLI/TUI/headless 入口在 host cwd 建立的 `main-session-*` 工作階段（`session.create({})` 回退到 `defaults.cwd`，從不掛到任何工作區）。當這樣的工作階段線上且空白（尚無 `turn/start`）時，下一次在該路徑註冊的工作區上點擊 `+` 就會複用它，導覽打開的是一個任何分組介面都無法顯示在該工作區下的工作階段。其他路徑的工作區不受影響，因為那裡不會積累未入帳的空白工作階段；而 host-cwd 工作區每次 CLI 執行都會積累一個。

## 決策

複用掃描現在要求工作區成員關係：`blank` 且 `summary.cwd === workspace.path` 且 `workspace.sessionIds.includes(summary.id)` 且未歸檔。僅 cwd 匹配的情況落到 `session.create({ workspaceId })`，建立並掛接新工作階段，使工作區擁有它——這與流程中「不存在空白工作階段」時的既有分支完全相同。

## 曾考慮的替代方案

**收養遊離工作階段而不是新建。** 讓 `session.create({ workspaceId })` 掛接一個 cwd 匹配但未入帳的空白工作階段。否決：靜默地把 CLI 建立的工作階段掛到工作區上，越過了帳戶邊界，令人意外；而且用戶端沒有成員檢視表就無法區分「遊離工作階段」與「工作區自己的空白工作階段」——而成員檢視表本身就是本次修復。

**複用時就地掛接，新增一條 wire 操作。** 需要在導覽熱路徑上新增 `workspace.attachSession` RPC，並且工作階段仍會有一幀顯示在「未分組」；沒有產品需求值得新增這個介面。

## 後果

遊離空白工作階段仍顯示在「未分組」（使用者仍可手動打開），但不再被某個工作區的新建工作階段流程劫持。成員校驗是複用掃描的新增條件，有一個可觀察的映像檔滯後邊界：在工作階段映像檔已是最新而工作區帳戶幀滯後的視窗裡，工作區自己的成員空白工作階段可能因成員校驗失敗而錯過複用，多建立一個空白——表現為該工作區下出現第二個「新工作階段」行，與舊故障形態（打開一個任何分組介面都無法顯示的工作階段）不同。兩個視窗都是瞬態的，按工作區的合併邏輯仍然防止並行建立互相競爭。無 host、wire 或持久化格式變更。

## 測試

`packages/client/runtime/tests/workspaces-service.client.spec.ts` 覆蓋四種結果：成員空白工作階段被複用（無 create RPC）；cwd 匹配但非成員的遊離空白工作階段**不被**複用、改為建立全新入帳工作階段（回歸用例）；已歸檔空白工作階段不被複用；首次提示詞被拒後成員空白工作階段仍可複用。完整用戶端套件（`pnpm run test:gui`）保持綠色。
