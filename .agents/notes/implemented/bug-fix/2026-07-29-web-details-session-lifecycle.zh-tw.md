# Agent Note: Web 詳情欄遵循當前工作階段生命週期

Status: implemented

[English](2026-07-29-web-details-session-lifecycle.md) | [简体中文](2026-07-29-web-details-session-lifecycle.zh.md) | 繁體中文

## 問題

詳情入口由工作階段作用域擁有，而其首選網格寬度由根作用域擁有。選擇不同工作階段時，系統會替換詳情內容，卻不會關閉根作用域的該首選寬度，因此新 owner 會繼承過時的查看幾何資訊。hero 和其他未選中狀態不會渲染工作階段作用域的詳情；其軌道需派生為零寬度，但不能因此在比較中成為偽 owner。

## 決策

`AppFrame` 從權威工作階段投影讀取當前工作階段 id 及其摘要中的 `blank` 標志。它只在該工作階段能夠擁有詳情時記錄最後一個選中的非 blank 工作階段 id，因此 hero 和其他未選中狀態既不會觸發關閉，也不會替換最後一個工作階段 owner；這些狀態下，詳情欄軌道的渲染寬度派生為零，但儲存的首選寬度不變。首個工作階段保留版面配置 store 的初始首選值，其[已歸檔的可見性預設值決策](../../archived/bug-fix/2026-07-30-web-details-default-closed.md)選擇關閉；返回同一工作階段時復原其當前寬度；選擇不同工作階段時，系統會先透過版面配置 store 關閉根作用域儲存的詳情欄首選寬度，再進行繪製。逐工作階段的聊天選中項繼續由 [slot 體系標準](../architecture/2026-07-22-slot-type-chain-implementation.md)所述的工作階段作用域 store 擁有。

版面配置 store 是瞬時狀態，詳情欄在啟動時保持關閉。它既不讀取也不寫入 `localStorage`，因此重新載入會復原側邊欄預設值，並使詳情欄保持關閉，無需工作階段基線例外。在同一個未變化的工作階段內手動關閉和重新打開詳情欄，仍保持原有行為。該生命週期 effect 不改變 [Workspace 擁有的 New Session 動線](../feature/2026-07-25-workspace-ui-product-flow.md)、composer 草稿、工作階段導覽或讓步鏈縮放。

## 考慮過的替代方案

**在 New Session 點擊處理器中關閉詳情欄。** 之所以否決：未選中表面沒有工作階段作用域的詳情，不得修改幾何資訊。詳情欄是否關閉，應由隨後對兩個已定義工作階段 owner 的比較決定。

**按工作階段持久化面板幾何資訊。** 之所以否決：產品約定需要移除過時上下文，而不是新增一張保存各寬度的對映。按工作階段保存幾何資訊還會在使用者返回時重新打開詳情欄，與選定的離開即關閉行為相悖。

**在工作階段基線就緒後保留持久化版面配置。** 之所以否決：這會僅為驗證過時的查看狀態，在呈現元件中重複實作啟動生命週期。瞬時預設值無需就緒標志即可使重新載入具有確定性。

**將當前投影的每次變化都視為工作階段切換。** 之所以否決：啟動時的物化、hero、清除選中項和選中狀態失效都不是兩個工作階段 owner 之間的過渡。

## 後果

詳情欄在啟動時保持關閉，首次工作階段物化時亦然。顯式打開操作會使用約定默認寬度。切換到不同工作階段會忘記拖動後的詳情寬度，因為關閉操作會寫入零值，重新打開時則使用該預設值。未選中狀態會將軌道的渲染寬度派生為零，同時保持首選幾何資訊不變；經由這些狀態返回同一工作階段時，會復原其寬度。重新載入會忘記側邊欄幾何資訊，並使詳情欄復原關閉狀態。版面配置行為測試覆蓋初始預設值、首次物化、直接及經 hero 中轉的工作階段切換、返回同一工作階段，以及不存在版面配置儲存的情況；無金鑰瀏覽器 e2e 則透過已交付的組合驅動相同的 owner 過渡，同時檢查完整網格軌道和瀏覽器錯誤。
