# Agent Note: 穩定快照刷新中的易變值

Status: implemented

[English](2026-07-27-stable-snapshot-refresh-volatiles.md) | [简体中文](2026-07-27-stable-snapshot-refresh-volatiles.zh.md) | 繁體中文

## 問題

ACP（Agent Client Protocol）快照比較會歸一化生成的 UUID、cwd 別名、spill locator、嵌入的事件時間和省略位元組數，但刷新寫回會持久化本次生成的原始值。因此，即使比較約定將兩份日誌視為相等，一次行為未發生變化的刷新仍會用新的隨機值或宿主特有的路徑寫法改寫 fixture（測試前置資料）。

訊息身份所需的結構前提比記錄對齊更弱：無關的日誌事件可能破壞記錄對齊，但繼承而來的訊息去除身份後的值在父級和子級日誌之間仍保持不變。錄制模式在替換現有 fixture 時也會從新生成的訊息 UUID 開始。

## 決策

在錄制或刷新寫入工作階段 fixture 前，共享快照支持層會將可寫入 fixture 的日誌交給一個負責結構化處理訊息 ID 的元件。該元件透過工作階段包的權威 surface 類型謂詞識別 surface 載體，並識別 `agent/inbox/spliced` 中與這些載體關聯的已排隊訊息副本；隨後移除每條完整訊息的頂層 `id` 並計算指紋，同時記錄所有父級/子級日誌中每條 ID 與指紋之間的關聯邊。僅當該 ID 與指紋在本次生成圖和現有圖中的度均為 1 時，才會複用現有 UUID，隨後僅改寫這些載體中透過驗證的訊息 `id` 欄位。具有相同 ID、重複出現的繼承訊息仍算作一個候選項；新增、發生變化、內容重複、格式錯誤和存在衝突的訊息則保留本次生成的 ID。ACP、JSON-RPC 和 Web 錄制器會在擦除 header 並對 cwd 進行 token 化後執行這一步，因此訊息身份取決於 fixture 中的寫法，而非宿主機原始路徑。

刷新寫回以 `normalizeSessionLog` 作為已對齊葉值的易變值判定依據。系統使用本次執行的 id、cwd 及全部 cwd 別名歸一化原始收集記錄，並使用 fixture 頭部上下文歸一化 fixture 記錄；字面量替換僅限於本次執行生成的工作階段 ID、cwd 值和 spill 路徑。現有記錄完成對齊後，系統基於這些歸一化記錄，遞迴比較本次生成記錄與現有記錄的葉節點：歸一化後等價的葉節點保留現有原始值，歸一化後不同的葉節點則保留本次生成的語義值。surface 或 inbox 載體中的完整訊息 ID 不參與這一路徑，以免按位置複用與結構複用各自獨立分配同一個已提交 UUID。

複用前必須確保完整邏輯記錄版面配置對齊，現有的打包區塊與插入標題等價情形除外。歸一化後等價但發生變化的字串在整份日誌範圍內形成雙射：一個本次生成的字串只對映到一個現有字串，反向亦然，因此跨記錄重複出現的 ID 仍保持關聯。出現無法解釋的記錄不匹配或對映衝突時，該日誌會停用歸一化字串複用。

對象欄位按鍵對齊。只有所有對應陣列長度相同時，才對齊其元素；否則以本次生成的陣列為準。字串始終作為不可拆分的葉節點。現有的打包區塊計時對齊與插入標題處理仍保持獨立，因為它們對齊的是邏輯事件，而非單條記錄內的值。

## 考慮過的替代方案

**在快照部署中使用確定性的 UUID 和 spill 檔名。** 替換生產環境使用的隨機性會削弱測試所要驗證的安全屬性，或者要求儲存與審批實作引入僅用於測試的行為。

**提交歸一化後的 fixture。** token 化的工作階段日誌將不再是原始重播輸入，並會引發與寫回缺陷無關的大範圍 fixture 遷移。

**當整條記錄的歸一化形式未變時保留整條記錄。** 這種做法更簡單，但同一記錄中的另一個欄位發生語義變化時，也會改寫其中的隨機欄位。按葉節點保留可使這些決策彼此獨立。

## 後果

錄制和刷新不再僅僅因為另一個事件改變了周邊記錄版面配置，就改寫未變化且唯一的訊息 UUID，無論該錄制由 ACP、JSON-RPC 還是 Web 負責。重複刷新也會保留規範化器歸類為易變值的已對齊 fixture 值；以後加入規範化器的新易變值類別也會自動繼承該寫回行為。結構有歧義時仍採取保守策略：記錄無法匹配、字串對映衝突、陣列尺寸發生變化、字串同時包含語義變化與易變變化、訊息格式錯誤，或訊息圖中的 ID 或指紋不唯一時，均使用本次生成的值，避免冒險複用未對齊的資料。

聚焦的單元測試固定了工作階段包權威謂詞識別的所有 surface 訊息形態、持久 inbox/surface 關聯、場景範圍內的父級/子級訊息關聯、帶 cwd 的可寫入 fixture 訊息匹配、無關事件插入、格式錯誤訊息隔離、訊息圖在 ID 與指紋兩條軸上的歧義、由單一處理方負責的寫回、遞迴處理對象與陣列的行為、對映衝突、本次執行的 cwd 別名、易變字串以及本次生成的語義欄位。無金鑰刷新測試證明，審批 UUID、cwd 別名、spill 路徑和事件讀取中的易變值不會改變已提交 fixture 的任何位元組。
