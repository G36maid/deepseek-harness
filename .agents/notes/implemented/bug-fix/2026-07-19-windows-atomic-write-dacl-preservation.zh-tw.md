# Agent Note: Windows 原子文件替換期間保留 DACL

Status: implemented

[English](2026-07-19-windows-atomic-write-dacl-preservation.md) | 繁體中文

## 問題

原子寫入在 POSIX 上以 `0o700` 保護暫存目錄、以 `0o600` 保護暫存檔，但 Windows mode 位只呈現實際 DACL 的合成只讀檢視表。在目標文件的父目錄下建立暫存目錄和暫存檔，並且只相依性繼承的 DACL，足以滿足新建文件的需要，但無法安全替換顯式或受保護 DACL 比父目錄更嚴格的現有文件：內容會在權限更寬鬆的父目錄 DACL 下寫入，而重新命名又會把這個暫存安全描述符帶到替換後的文件上。

## 決策

`dsh-fs-local` 透過 `GetFileSecurityW` 讀取現有目標文件的 DACL，在寫入內容前將其以禁止繼承的形式應用到空暫存檔，並透過 `ReplaceFileW` 發布已關閉的暫存檔。受保護的暫存安全描述符可防止暫存目錄中的繼承條目擴大訪問權限；`ReplaceFileW` 會保留原目標文件的訪問策略及其他替換元資料。其 ACL 合併過程可能重新序列化自動繼承狀態或複製等價 ACE，因此不能把自相對安全描述符緩衝區的逐位元組相等作為穩定約定。新的 Windows 文件沒有既有描述符需要保留，因此仍繼承目標目錄的 DACL；其暫存目錄也因此位於目標文件旁。POSIX 繼續使用僅所有者可訪問的暫存 mode，並保留現有目標文件的 mode。

Windows 原生覆蓋率測試會保護目標文件的 DACL、檢查寫入完成的暫存文件，並對比最終替換文件中保持順序且去重後的 ACE 策略。與宿主平臺無關的綁定測試覆蓋 Win32 錯誤轉換以及每個原生呼叫邊界。mode 位斷言仍僅適用於 POSIX；新文件的 DACL 繼承由作業系統約定規定，不應透過特定機器的帳戶允許清單來斷言。

## 備選方案

**替換文件時相依性目錄繼承。** 不予採用，因為目標文件可能帶有比父目錄更嚴格的顯式或受保護 DACL；目錄繼承既無法保護暫存內容，也無法保留目標文件的訪問策略。

**使用 `ReplaceFileW`，但不保護暫存檔。** 不予採用，因為這只能在內容已經按暫存文件繼承的 DACL 寫入之後修復最終描述符。

**每次寫入都設定僅所有者可訪問的 DACL。** 不予採用，因為這會破壞項目有意設定的共享權限。複製目標文件的 DACL 可以保留部署中已有的訪問策略，無需另行創設策略。

**使用 `Get-Acl` 或 `icacls` 斷言繼承帳戶。** 不予採用，因為這類測試驗證的是機器策略，而不是包行為；系統內建帳戶名會本機化，使輸出在不同宿主上不穩定。

**在 Windows 上跳過現有 `chmod` 呼叫。** 不予採用，因為 Node 會把這些可寫 mode 對映為無害的空操作；平臺條件判斷只會增加分支，不會改變 DACL 行為。

## 影響

替換 Windows 文件現在要求呼叫方有權讀取目標 DACL 並設定暫存檔 DACL；如果權限不足，系統會在寫入內容前明確失敗。該包引入 Koffi 以執行少量 Win32 呼叫，並且只在 Windows 替換路徑上載入。新的 Windows 文件會在目錄按設計開放較寬訪問權限時繼承該權限，而 POSIX 臨時內容仍僅允許所有者訪問；只讀 Windows 目標文件仍會在發布時失敗，早於重放合成 mode 可能產生影響的時點。
