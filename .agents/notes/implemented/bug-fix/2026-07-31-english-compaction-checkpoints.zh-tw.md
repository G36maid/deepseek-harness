# Agent Note: 壓縮檢查點使用英語工程文體

Status: implemented

[English](2026-07-31-english-compaction-checkpoints.md) | 繁體中文

## 問題

壓縮（compaction）檢查點會成為下一次模型請求中持久存在的前綴。當多語言對話使壓縮器以對話語言保留敘述性材料時，檢查點可能引入大量程式碼、工具輸出和既有推理（reasoning）前綴中均未出現的語言內容。該語言隨後會在後續壓縮週期中持續存在，並影響對話模型的推理文體。

## 決策

`COMPACTION_INSTRUCTION` 要求生成英語的內部工程檢查點。它要求模型在必要時翻譯敘述性源材料，同時保留精確的字面量；這包括路徑、命令、錯誤、識別符號、簽名，以及精確性重要時的引用措辭。檢查點的標題及簡潔的工程項目符號仍沿用既有的結構化格式。

這項要求被整合到尾部壓縮指令的第一句話中。重播的系統提示詞、工具和對話歷史與已路由請求保持位元組級一致，因此該變更保留 [壓縮摘要前綴快取說明](2026-07-21-compaction-summary-prefix-cache-reuse.md) 所確立的前綴快取複用。

## 考慮過的替代方案

- **讓重播的對話決定檢查點語言**——不採納：檢查點是持久的提示詞前綴，保留短暫的對話文體可能在後續壓縮中放大這種影響。
- **約束對話模型的語言**——不採納：該策略針對內部檢查點，而不是使用者可見的對話；對整個對話施加規則會不必要地改變正常互動。
- **要求僅輸出 ASCII**——不採納：ASCII 是字元集約束，而非工程文體約束，並會不必要地扭曲合法的字面量和技術材料。
- **在末尾追加一句獨立的僅限英語要求**——不採納：在指令開頭的輸出約定中說明該要求更簡潔，也直接將其與所請求的檢查點綁定。

## 後果

- 新檢查點會將敘述性上下文規範化為英語，同時保留未來工具使用和程式碼工作所相依性的精確字串。
- 既有檢查點結構、壓縮路由和快取對齊保持不變；只有最後一條 user 指令不同。
- 直接摘要呼叫仍不納入 transcript（文字記錄）快照，因為它不會發出 `assistant/chunk` 事件。真實迴圈回歸改為斷言摘要請求收到的精確最終指令。
