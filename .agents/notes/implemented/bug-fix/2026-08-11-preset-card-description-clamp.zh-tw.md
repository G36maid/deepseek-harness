# Agent Note: 預設卡片截斷自身描述，而不是由描述決定整份名單的高度

Status: implemented

[English](2026-08-11-preset-card-description-clamp.md) | [简体中文](2026-08-11-preset-card-description-clamp.zh.md) | 繁體中文

## 問題

preset 自行發布 `description`，長度不限，而設定分區把名單渲染為卡片網格。描述只有 `min-height` 沒有上限，網格則以 `grid-auto-rows: 1fr` 排布行——該取值讓每一個隱式行等高，而不只是承載高卡片的那一行。因此一條長描述決定了整份名單的高度：自訂組裡放入一條 250 字的描述後，四張卡片全部量得 421px，短描述卡片被大片空白填滿。

描述同時又是區分各個 preset 的欄位，因此不能藏起來；卡片必須既給它設上限，又讓全文仍然可達。

## 決定

描述截斷為四行，其餘內容透過共享的 `Tooltip` 呈現，且僅在元素確實溢位時才掛載（`scrollHeight > clientHeight`，並經 ResizeObserver 重新測量，因為設定面板寬度跟隨視窗）。這與聊天統計行一致：它按同樣的「先測量再掛載」規則截斷為一行。

卡片高度仍是推導得出而非固定。描述有了上限之後，`grid-auto-rows: 1fr` 本身就讓網格等高，而承載損壞原因或已展示目錄的卡片仍能按自身內容定高——寫死畫素高度會把兩者一並裁掉。

隨之而來三個更小的決定：

- `.cardId` 以 `margin-top: auto` 喫掉卡片的空餘空間，描述不再拉伸。被 flex 拉伸的盒子會讓截斷高度與盒子高度不一致；讓截斷盒子只按內容定高，行為便不相依性這層互動。
- 描述帶有 `title=""`。空 `title` 表示該元素沒有提示資訊，尋找就此停止，因此卡片主體的原生 tooltip 不會向上找到描述，被裁切的描述只回應一個氣泡而不是兩個。
- `Tooltip` 新增選填的 `maxWidth`。它默認的半視口上限會把描述渲染成比所屬設定彈出視窗還寬的一整塊，溢位到背後的應用介面上。
- `Tooltip` 同時在視口放不下時把 `top` 或 `bottom` 氣泡翻到另一側，此前它只做水準收斂。自訂 preset 位於名單末尾、又恰恰承載最長的描述，因此常見情形正是讓一個高氣泡掛在頁面靠下的錨點之下。翻轉只會移向確實放得下的一側，兩側都放不下時保持請求的位置而不來回擺動；改為垂直滑動則會蓋住正在閱讀的文字。

形狀檢查未透過的名單行，徽記從 `Broken`（`已损坏`）改為 `Failed to load`（`加载失败`）。discovery 在組裝文件缺失、讀不出或格式錯誤時置位 `broken`——最常見的是使用者剛編輯或刪除的文件——因此斷言損壞超出了觀察到的事實，而徽記下方原樣展示的原因本就點名了文件與修法。

## 備選方案

- **寫死卡片高度。** 它直接表達了意圖，卻會裁掉兩處高度本就可變的行：損壞預設的原因行和已展示的預設目錄。
- **用原生 `title` 屬性承載完整描述。** 無需測量也無需元件，代價是約一秒的延遲、作業系統的樣式，以及在卡片大部分區域內頂替掉「設為默認」的提示。
- **無條件掛載 tooltip。** 省掉 ResizeObserver，代價是把滑鼠停在短描述上時，彈出一個重複卡片已有內容的氣泡。
- **hover 時展開截斷。** 它就地展示文字，同時讓網格在指針下方發生位移。

## 後果

分區多了一個帶測量的小元件，共享基元多了一個選填 prop。換來的是：任何卡片的高度都不再跟隨名單中最長的那條描述；而且截斷由 CSS 完成而非截短文字，完整描述始終留在無障礙樹中。

`title=""` 的抑制作用由一條 DOM 斷言釘住，而非透過觀察原生 tooltip：瀏覽器 tooltip 畫在頁面之外，無法被捕獲。若某個瀏覽器日後重新越過空 `title` 繼續向上尋找，退路是去掉卡片主體的 `title`——它的內容已經在主體的 `aria-label` 裡。
