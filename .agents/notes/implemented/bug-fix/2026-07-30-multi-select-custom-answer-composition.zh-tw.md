# Agent Note: 多選題自訂答案組合

Status: implemented

[English](2026-07-30-multi-select-custom-answer-composition.md) | [简体中文](2026-07-30-multi-select-custom-answer-composition.zh.md) | 繁體中文

## 問題

使用者互動結果的詞彙分別透過不同欄位攜帶選中的選項標籤和選填的自訂文字，但最初的語義要求每個問題的這兩個欄位互斥。對於多選題，打開自訂答案或輸入文字會丟棄使用者已選中的標籤。TUI 只返回自訂文字，而 Web 宿主會拒絕同時保留兩個欄位的用戶端回應。

## 決策

對於 `multiSelect: true` 的問題，一個回答項可以同時包含非空 `selected` 陣列與非空 `custom` 文字。無論使用者先選擇選項還是先輸入自訂文字，Web 草稿都會保留兩個值；TUI 在選項與自訂模式之間切換時會保留待提交的自訂文字，並在任一模式提交時將其與已勾選的標籤一同投影；Web 宿主則在應用現有的 id、標籤、唯一性、批次和非空文字校驗後接受組合回應。

單選題和無選項問題仍保持互斥語義：自訂文字會覆蓋任何已選中的選項。結果形狀仍為 `{ id, selected, custom? }`，因此協議或工具輸出 schema 均無需變更。

## 考慮過的替代方案

**把自訂文字編碼為另一個 `selected` 標籤。** 不予採納，因為這樣會抹去呼叫方提供的選項標籤與使用者填寫文字之間的區別，削弱校驗，並迫使消費端推斷哪個值屬於自訂內容。

**允許所有問題同時使用 `selected` 與 `custom`。** 不予採納，因為單選題只表示一個回答；允許選中選項與自訂文字並存會使其基數含義模糊。組合形式僅適用於顯式啟用多回答的問題。

## 後果

多選 UI 可以完整表達使用者的回答，不會丟棄任一來源。提供方和消費端繼續使用現有 DTO，而請求感知的校驗器會根據 `multiSelect` 判斷是否允許組合。Web 元件與組裝瀏覽器的測試覆蓋、TUI 測試覆蓋、宿主回應測試覆蓋和工具投影測試覆蓋共同固定組合結果。Web、TUI 與工具投影測試覆蓋還固定了僅含標籤的回答形態；組裝後的無金鑰 TUI 測試覆蓋固定終端機中的組合回答流程，單選題的宿主測試覆蓋則固定其餘的互斥規則。
