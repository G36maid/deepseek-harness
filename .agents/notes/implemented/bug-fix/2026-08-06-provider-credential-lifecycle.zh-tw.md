# Agent Note: 可復原的提供方憑據生命週期

Status: implemented

[English](2026-08-06-provider-credential-lifecycle.md) | 繁體中文

## 問題

Models 編輯器橫跨互相獨立的 settings 與憑據 RPC 領域。之前它先提交提供方 settings，再儲存 API 金鑰，卻一直保留卡片打開時的 revision 和原始子樹。如果憑據寫入失敗，重試會用過時 revision 重放已提交的 settings 變更，並產生衝突，導致使用者無法從同一張卡片完成第二個階段。空的 pi-ai 金鑰還會寫入派生的 `apiKeyEnv`，卻不寫入憑據，從而阻止 pi-ai 使用提供方原生憑據發現。刪除時則存在相反的殘留問題：profile 消失了，頁面儲存的金鑰卻保留在 `.env` 中，並在重新新增提供方時靜默地復原作用。籠統的行操作與確認文案也沒有標明要更改哪個提供方。

## 決策

提供方保存仍在現有 wire 領域上按先 settings、後憑據的兩階段順序執行，但卡片會把成功的 settings 回應視為提交檢查點。它會在嘗試 `credentials.set` 之前，用返回的脫敏 descriptor 替換比較基準子樹與預期 revision；如果第二階段失敗，草稿金鑰與卡片會繼續顯示，重試不會產生 settings op，只會再次寫入憑據。首次 settings 提交之前發生的真實並行變更仍會以 `settings-conflict` 失敗。UI 與 DeepSeek 直連 resolver 邊界均會去除所輸金鑰的首尾空白，且只有標準化金鑰非空時，pi-ai 才會記錄派生引用；留空金鑰會具化一個空的、不帶引用的 profile，以便使用提供方原生憑據發現。

只有當聯接所得的行識別出該頁面派生的精確 `<ROUTE>_API_KEY` 引用，並將其報告為已設定且可寫時，刪除操作才會清除該憑據。它會先取消設定該憑據，再取消設定使用者層 profile；如果 settings 階段失敗，該行及其已凍結的目標仍可見，便於重試。兩項 unset 都具備冪等性。自訂引用、環境憑據、缺失的憑據，以及聯接無法識別目標的憑據均會保留。行的無障礙 Edit/Delete 名稱以及破壞性對話框的標題、說明和最終操作都使用同一個穩定的 `Display Name (route-id)` 標識；當兩個字串相同時，標識會簡化為路由 id。對話框會說明是否一並刪除已存金鑰，並在自身內顯示操作失敗，而不是用載入錯誤橫幅替換整個頁面。行只根據不含值的聯接結果展示 API 金鑰狀態：確認已設定的引用憑據顯示為綠色實心點，確認缺失的具名引用顯示為紅色實心點，無引用的提供方原生認證或無法取得憑據補充資訊時則不顯示狀態點。每個狀態點都有無障礙文案和工具提示；「應用」成功後的本機狀態訊息會使用同一個提供方標識，且絕不回顯任何機密內容。

## 曾考慮的替代方案

**新增跨領域交易 RPC。**settings 與憑據分屬不同的主管服務與持久儲存；引入新的 Host 交易會擴大公開 wire 面，而且仍需要補償提供方特定的持久化失敗。UI 檢查點讓當前的有序階段變得可復原，無需新增第四項設定約定。

**刪除被移除 profile 所指定的每一個憑據引用。**自訂引用可能被共享、由外部管理，或有意在 profile 反覆增刪時存留。與該頁面派生目標精確相等，再加上已設定且可寫的狀態，是頁面所能獲得的最小範圍證據；比這更弱的判定都有可能刪除不屬於它的憑據。

**先刪除 settings，再重建 profile 以作補償。**瀏覽器只持有脫敏後的子樹，無法忠實重建並行編輯。先刪除憑據可以讓權威 profile 在部分失敗時仍然可見，並且無需合成設定就能安全重試。

## 後果

Models 頁可以從任一第二階段失敗中復原，無需重新載入，也不會洩露機密或產生虛假的並行衝突；空金鑰的 pi-ai profile 會保留 Bedrock、Vertex 與其他提供方原生認證。已確認的狀態清晰可見，同時不會把路由存活狀態、原生認證或憑據查詢失敗誤報為錯誤；即使該行繼續顯示綠色，金鑰替換成功也仍然可觀察。刪除由頁面管理的提供方不再殘留可重用的本機金鑰，而存在歧義的憑據會有意保留，交由手動管理。保存與刪除在跨持久儲存時仍非原子操作：行程可能在兩個階段之間崩潰，但它們的順序與冪等性會留下可觀察、可重試的狀態。元件測試固定了部分成功後的重試、空金鑰原生認證、金鑰首尾空白處理、狀態可見性、目標標識、清理所有權，以及憑據／settings 拒絕順序；無金鑰的瀏覽器場景固定了雙語無障礙文案，並驗證確認刪除會同時清除 `settings.yaml` profile 與 `.credentials.yaml` 條目。此決策細化了 [web 設定平面 note](../architecture/2026-07-30-web-config-plane.md) 中記錄的 Models 應用語義。
