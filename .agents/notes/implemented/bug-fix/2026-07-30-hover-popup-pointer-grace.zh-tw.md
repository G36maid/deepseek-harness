# Agent Note: 懸浮彈層的指針寬限期

Status: implemented

[English](2026-07-30-hover-popup-pointer-grace.md) | [简体中文](2026-07-30-hover-popup-pointer-grace.zh.md) | 繁體中文

## 問題

工作區瀏覽器行彈出的兩種彈層都處於指針無法抵達的位置。`HoverCard` 在指針離開錨點的第一個 `pointerleave` 上就關閉，其卡片還設定了 `pointer-events: none`；但卡片位於錨點右邊緣外 8px 處，因此通往卡片的每條路徑都要穿過既不屬於錨點也不屬於卡片的區域，卡片在指針抵達之前就已被銷毀——它本應展示的完整工作區路徑和工作階段標題只能匆匆一瞥。行操作選單傳入了 `closeOnPointerLeave`，而其處理器掛在傳送後的清單上：把指針移回打開該清單的 `...` 觸發按鈕會關閉清單，指針越過清單邊緣同樣會將其關閉，且沒有任何折返視窗。

## 決策

`usePointerGrace`（[packages/client/ui-primitives/src/pointer-grace.ts](../../../../packages/client/ui-primitives/src/pointer-grace.ts)）持有唯一一個可取消的延遲關閉，由兩個原子元件共享，`POINTER_GRACE_MS` 為 200。離開會啟動關閉，折返則取消它。因此指針可以安全穿越錨點與彈層之間的間隙，而真正移開的指針仍會關閉彈層。

`HoverCard` 在離開時啟動寬限期而不再立即關閉，其卡片也不再設定 `pointer-events: none`，因此指針停在卡片上即可讓它保持打開。在已打開狀態下重新進入只取消待執行的關閉，而不重新啟動停留計時，從而避免指針穿越間隙時卡片閃爍。在卡片上按下指針用於開始文字選擇，不會關閉卡片；只有在錨點區域內發生按下操作，或所有者將 `disabled` 置真時，才會搶在寬限期之前立即關閉卡片。

`Menu` 把指針離開關閉的處理從傳送後的清單移到包裹 span 上。React 的 enter/leave 遍歷基於 React 樹進行，因此觸發按鈕與傳送後的清單在這裡屬於同一區域：穿越兩者之間 4px 的間隙、或把指針移回觸發按鈕，都不再算作離開。只有在清單打開時才會啟動離開關閉；由所有者驅動程式的關閉（選擇、Escape、外部點擊）會在一個僅以 `open` 為相依性的 effect 中解除待執行的寬限關閉——若把它摺疊進外部點擊的 effect，則每次重新渲染都會取消寬限期，因為所有者每次都傳入新的 `onClose` 閉包。

## 考慮過的替代方案

**僅透過外部點擊和 Escape 關閉這兩種彈層。** 之所以否決：兩者都由懸停喚起，且沒有可見的關閉標識；在指針已移到其他行之後仍讓它們停留，會把卡片殘留在無關內容之上。

**擴大錨點的命中區域，使其與彈層相接。** 之所以否決：8px 與 4px 的偏移來自設計稿，而一個不可見的橋接元素還必須跟隨這兩個固定定位彈層已經在滾動和調整視窗大小時執行的每一次重新定位。

**保留懸浮卡片的 `pointer-events: none`，只加入寬限期。** 之所以否決：那樣指針停在卡片上時命中的是卡片背後的元素，寬限期仍會到期，並關閉使用者剛剛夠到的卡片。

**讓兩個原子元件各自持有計時器。** 之所以否決：這兩處關閉是同一種行為、同一套調參；共享 hook 可以防止它們各自漂移。

## 後果

懸浮卡片現在可被命中，顯示期間會遮擋其覆蓋區域的 244px——這是可抵達性的代價；它依然只在指針位於行或卡片上時存在。行選單現在能承受觸發按鈕與清單之間的往返，而因自身原因關閉的選單重新打開後，也不會被殘留的待執行關閉關掉。未設定 `closeOnPointerLeave` 的選單不受影響——只有設定該屬性時才會掛上包裹層處理器。

## 測試

`packages/client/ui-primitives/tests/hover-card.client.spec.tsx` 與 `tests/atoms.spec.tsx` 固定驗證寬限期邊界、折返取消、不重新啟動停留計時、所有者關閉時解除待執行關閉，以及清單關閉時不啟動關閉。可抵達性手勢本身——把指針移到卡片上，以及在打開的清單與其觸發按鈕之間移動——由 `apps/web/tests/workspace-management.e2e.ts` 在真實瀏覽器中固定驗證，因為它們相依性 jsdom 無法建模的命中測試與版面配置。
