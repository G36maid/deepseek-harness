# Agent Note: 產品 subagent 提供方位於共享 profile 宿主

Status: implemented

[English](2026-08-10-product-subagent-providers-in-shared-host.md) | [简体中文](2026-08-10-product-subagent-providers-in-shared-host.zh.md) | 繁體中文

## 問題

[Codex 與 Claude Code 提供方約定](../feature/2026-08-04-claude-code-and-codex-subagent-backends.md)最初以可獨立安裝的包交付，由部署環境在通用 subagent 工具旁載入。Agent Preset 後來成為單個 agent（代理）的模型可見工具的常規責任方，但 preset 不能安全地擁有這些產品提供方：`ctx.subagents` 是行程級登錄檔，提供方名稱唯一，而宿主消費端會跨工作階段解析同一個登錄檔。如果要求使用者同時編輯 Profile 和 Preset，也會使通用 preset 行本身不完整。

歸屬決策必須同時保留兩個彼此獨立的事實：載入提供方不得啟動產品，也不得對產品執行身分驗證；而工具是否啟用仍須按 preset 決定，這樣兩個工作階段才能暴露不同的產品。全域性產品開關、按 agent 建立提供方實例或預先枚舉的組合 preset，都會為其中一個事實另設第二責任方。

## 決策

每個隨發行版交付的 Profile 都會透過 base 組合包的宿主平面，把固定的 `codex` 與 `claude-code` 提供方各載入一次。載入任一外掛程式只會註冊一個休眠後端；對應的 Codex 或 Claude 行程直到第一次實際委派呼叫時才啟動。Agent Preset 分別透過普通的 `dsh-tool-subagent` 行貢獻 `subagent_codex` 與 `subagent_claude_code`，因此一個 preset 可以不暴露任何工具、只暴露其中一個或同時暴露兩者，而無需更改提供方登錄檔。

本決策僅取代提供方約定說明所記錄的、原先由使用者選擇啟用的組裝位置。該說明仍負責每個產品的協議、結果對映、取消、行程樹生命週期與證據層級。[Agent Preset 架構](2026-08-03-per-session-agent-presets.md)仍負責宿主與 agent 的劃分、preset 創作，以及改動隻影響新組裝工作階段的規則。

這些提供方使用宿主環境已經選定的產品。Codex 啟動 `codex`，該命令從 `PATH` 解析；Claude Code 透過共享的子行程執行世界解析 `claude`，並把確切路徑交給官方 SDK。載入 Profile 不會安裝產品、建立產品狀態、探測版本、測試身分驗證，也不會新增產品專屬設定。命令缺失和產品故障仍侷限於發生問題的那次委派。

當前 base 相依性閉包仍包含 Claude Agent SDK 的選填平臺 CLI（命令列介面）載荷，儘管生產環境解析的是宿主提供的 `claude`。移除這份未使用載荷屬於獨立的產品安裝閉包後續項；本歸屬決策既不會動態安裝它，也不會將它當作生產可執行文件。

## 驗證

base Loader 測試證明兩個提供方名稱都恰好註冊一次，而且 Profile 啟動期間不會啟動產品行程。真實 Agent Preset 組裝覆蓋不暴露任何工具、僅暴露 Codex、僅暴露 Claude 和同時暴露兩者這四種工具集合，也覆蓋自行創作的 preset 發生改動後的代際隔離。無金鑰 ACP（Agent Client Protocol）快照固定單個產品與兩個產品同時啟用時的模型可見工具 schema，提供方測試則另行證明原生可執行文件解析、失敗、取消和行程樹完全靜止。

## 考慮過的替代方案

**將產品提供方保留為 Profile 層的按需啟用項。** 這樣可縮小默認相依性閉包，但複製或由 agent 創作的 Preset 行無法直接使用，除非使用者還發現並編輯第二個組裝層。對於這些本來與其他工具無異的工具，通用 Preset 入口仍不完整。

**儲存全域性或按 Profile 設定的產品啟用開關。** 行程級開關會與 Preset 爭奪模型可見工具的責任歸屬，也無法表示兩個工作階段使用不同組合。可用性與身分驗證屬於部署事實，並非另一份需要持久化的產品狀態。

**在每個 Agent Preset 內掛載一個提供方。** 提供方名稱屬於行程級登錄檔，因此第二個工作階段會與第一個衝突。宿主消費端也需要獨立於任何單個 agent 的生命週期使用該登錄檔。

**交付四個產品組合 preset。** 四個身份會複製完整組裝，只為表示兩條獨立的工具行。普通行已經能表達完整矩陣，無需新增名單或維護狀態。

## 後果

使用者透過與其他外掛程式相同的 Agent Preset 創作路徑管理兩個產品，每個新工作階段只會獲得其所選 preset 所貢獻的工具。每個 Profile 都攜帶兩個休眠的提供方註冊，因此未使用的產品會產生包和模組載入開銷，但不會啟動產品行程、登入、呼叫模型或建立產品主目錄。

宿主登錄檔仍是提供方的唯一權威，每個 Preset 仍是模型工具的唯一權威。代價是當前 Claude SDK 選填載荷的安裝成本繼續被明確延期處理，而不會隱藏在另一種啟用狀態或安裝程序生命週期之後。
