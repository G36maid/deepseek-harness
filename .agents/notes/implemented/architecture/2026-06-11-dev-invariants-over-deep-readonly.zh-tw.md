# Agent Note: 源端擁有的工作階段不可變性與開發模式不變式

Status: implemented

[English](2026-06-11-dev-invariants-over-deep-readonly.md) | [简体中文](2026-06-11-dev-invariants-over-deep-readonly.zh.md) | 繁體中文

## 問題

工作階段日誌需要兩種不同的保護：對每條已儲存事實的不可變所有權，以及對跨時間和服務約定的事實之間關係的檢查。如果將二者混為一個選填的開發外掛程式，生產環境的歷史記錄將失去保護；如果試圖透過 TypeScript readonly 類型同時表達兩者，既無法建立執行時期邊界，也無法描述關係規則。

工作階段日誌是重播、請求重建、持久化與使用者可見歷史的持久真源。工作階段包外部的程式碼必須能檢視歷史，但不能保留一個可在之後改寫歷史的引用；從呼叫方接受的輸入也不能繼續連線到呼叫方擁有的可變對象。

單個值的不可變性只是約定的一半。一份日誌可以包含完全不可變的記錄，但其序列、輪次/步驟巢狀、工具呼叫配對、作用域分發或重建的模型請求是錯誤的。這些規則涉及多條記錄或多個服務，無法透過凍結單個對象來建立。

TypeScript readonly 類型不是充分的執行時期邊界。它們在程序執行時期消失，類型轉換可以繞過它們，而遞迴的 `DeepReadonly<T>` 會擴散到每個日誌和訊息消費端，儘管某些下游請求處理 API 有意使用可變值。

## 決策

職責劃分給始終啟用的儲存邊界和選填的開發斷言。

### Session 擁有不可變歷史

`Session` 僅在一次遞迴遍歷完成無損 JSON 快照的物化之後才接受事件。該遍歷拒絕不支持的值，並產出進入日誌的已分離的確切記錄，因此驗證與儲存不會從有狀態的 getter 觀察到不同的值，也不會保留呼叫方擁有的巢狀引用。

被接受的事件及其所有後代在發布前被深度凍結。`append()` 返回由 Session 擁有的凍結事件，`session/event` 觀察者接收同一記錄，`session.events` 返回凍結的陣列快照。先前返回的陣列不會因後續 append 而成長。種子記錄在構造成功前經過相同的驗證、快照與凍結邊界。

此保證屬於 `Session` 而非選填監聽器，因為每種組合都相依性可信的歷史。無論是否註冊了開發支持外掛程式，生產部署、聚焦測試或自訂嵌入都獲得相同的儲存語義。

### 派生請求保持分離

`deriveMessages()` 將已記錄的表面事件投影為分離的、深度凍結的 `Message` 對象，並返回一份新的陣列快照。因此請求組裝可以將派生歷史與其他輸入組合，而不會暴露一條回到日誌的路徑。快取複用安全的不可變投影，而非為每次模型呼叫重新克隆完整歷史。

### 包擁有的不變式配套外掛程式檢查關係

`dsh-invariants` 註冊可設定的 `ctx.invariants` 服務，本身不包含產品檢查。每個包發布一個 `./invariant` 所有權配套外掛程式；`dsh-session`、`dsh-agent`、`dsh-scope` 和 `dsh-agent-loop` 目前新增需要跟蹤狀態或觀察另一個 seam 的規則：單調遞增的序列號、輪次與步驟巢狀、工具呼叫/結果配對、合法的 agent（代理）狀態轉換、主體正確的作用域分發，以及迴圈建置的請求與從其工作階段日誌前綴重建的請求之間的相等性。全域性啟用和包名 regex 過濾器歸該服務所有（見[包擁有的不變式服務](2026-07-19-package-owned-invariant-service.md)）。

當工作階段配套外掛程式附加到已有工作階段或以種子記錄初始化的工作階段時，它重播不可變日誌以重建跟蹤狀態。服務為每項貢獻提供一個可 dispose（資源釋放）的子 fiber，因此輪次中途熱重新載入是安全的，同時不賦予診斷邏輯對工作階段儲存的所有權。

## 曾考慮的替代方案

### 全面的 deep-readonly 類型

一個被否決的配套提案會在公開的日誌與訊息介面上應用遞迴 `DeepReadonly<T>` 類型，將工作階段讀取路徑（`events`、`session/event` 監聽器、`deriveMessages()`）改為深只讀，同時保持進行中的 waterfall（瀑布式事件）可變。這能提供編輯器回饋，但無法提供執行時期保證：TypeScript 類型在執行時期被擦除，外掛程式程式碼可以透過類型轉換繞過。它還會將 readonly 類型推入有意進行修改的消費端。在 `Session` 邊界處的執行時期所有權保護所有呼叫方，無需這種類型傳播。

### 僅在開發模式凍結

僅當不變式外掛程式安裝時才凍結歷史，會使核心保證相依性於組合方式。程式碼可能透過開發測試，卻在生產環境或省略了該外掛程式的聚焦組閤中破壞歷史。因此儲存不可變性始終啟用，而開銷更大的關係檢查則保持為選填的開發支持。

### 僅在派生訊息時克隆

分離 `deriveMessages()` 能保護最常見的請求路徑，但 `session.events` 的其他讀取者、append 回傳值和工作階段事件觀察者仍能修改持久歷史。日誌必須保護自身的邊界；派生投影是額外的隔離邊界，而非替代品。

## 後果

- 每個被接受的即時或種子工作階段事件在任何觀察者接收之前，都已從呼叫方擁有的輸入中分離並深度不可變。
- `session.events` 暴露穩定的不可變快照，而非持續成長的私有陣列。
- 請求側的修改無法透過派生訊息觸及已儲存的歷史。
- 開發建置可以啟用關係斷言而不改變儲存行為；dispose 或過濾一個配套外掛程式不會削弱日誌不可變性。
- `dsh-invariants` 設定全域性啟用狀態以及包名允許/阻止 regex 清單；每項檢查仍由其產品包擁有並測試。
- 執行時期邊界對每個被接受的事件產生一次遞迴快照與凍結的開銷；後續讀取者和快取投影複用已擁有的不可變記錄。
