# Agent Note: 大型工作階段 JSONL 復原管線

Status: implemented

[English](2026-08-05-large-session-jsonl-restore-pipeline.md) | [简体中文](2026-08-05-large-session-jsonl-restore-pipeline.zh.md) | 繁體中文

## 問題

復原已儲存工作階段會啟用該工作階段，並在 agent（代理）執行前物化完整且權威的事件日誌。處理大型 JSONL 產物時，這個一次性操作會產生幾項不必要的開銷：每個獨立 Zstandard 幀都會建立並關閉一個解碼上下文；解碼後的明文會彙總成整份日誌的緩衝區和字串，再進行重複掃描；剛解析出的事件還會進入面向借用值或迴圈引用值設計的通用快照與深度凍結路徑。

一份代表性效能剖析包含 61.8 MiB Zstandard 資料、97.1 MiB 明文和 1,307,073 個事件。復原路徑必須降低 CPU 與記憶體開銷，同時保持校驗和驗證、已提交區域損壞偵測、撕裂尾部復原、序列與 `surface` 校驗，以及工作階段日誌不可變性。

## 決策

復原過程是一條從持久化產物進入 `Session.fromRestore` 的所有權轉移管線。壓縮產物仍作為源緩衝區駐留，但解碼與掃描階段會增量消費上一階段的輸出，不會保留整份日誌的明文或解析副本；最終事件陣列是唯一完整的已解碼表示。

### 幀解碼

Zstandard 結構掃描器會在解碼前識別完整幀範圍。系統單獨解碼專用首幀並將其解析為工作階段頭部，後續明文幀則按順序產出並送入 JSONL 掃描器。

`ZstdFrameDecoder` 為可互換的同步實作提供統一生命週期。首選實作會探測受支持 Node 22、24 與 26 的流結構，在所有完整幀之間複用一個私有原生解碼上下文和臨時緩衝區，最後只關閉一次。如果私有結構不可用，工廠會選擇使用公共 `zstdDecompressSync` 的實作，並保持相同的迭代器和校驗和錯誤約定。迭代器產出的臨時檢視表會在進入下一次迭代前被消費。

累計幀處理時間約達 500 ms 後，非同步讀取器會在下一幀邊界讓出事件迴圈，並在繼續前觀察取消訊號。單個幀仍是不可分割的同步操作。完整幀必須透過幀結束與校驗和驗證；只有結構上不完整的最終幀才使用既有前綴解碼器進行復原。

### 增量 JSONL 掃描

`SessionLogScanner` 使用 `Buffer.indexOf(0x0A)` 在原始緩衝區中尋找換行，只把完整記錄轉換為 UTF-8 並交給 `JSON.parse`。掃描器會跨解碼寫入保留不完整記錄；由於私有解碼器可能複用輸出緩衝區，它只複製這個片段。掃描過程不會構造整份明文緩衝區或字串，也不會構造行陣列或第二份解析記錄陣列。

掃描器在遇到第一條無法解析的記錄或序列缺口後停止保留事件，但會繼續檢查後續完整記錄。後續出現 `turn/end`，說明問題位於已提交區域，系統會拒絕該日誌。處理完所有完整幀後，如果仍存在未決的解析錯誤、序列錯誤或部分記錄，Zstandard 讀取器同樣會拒絕日誌；只有結構上撕裂的最終幀才能提供可復原後綴。該撕裂幀產出的完整記錄會經過同一掃描器，並保持既有修復偏移量與復原事件語義。

### 復原准入

持久化層把剛物化的 JSON 值轉移給 `Session.fromRestore`。這些值是已分離且無環的樹，打包的區塊行也會展開成新分配的事件。因此，復原專用路徑使用一次 `for...in` 與 `switch` 校驗固定事件信封，按事件判別欄位執行當前資料形狀檢查，並透過顯式 `pending` 陣列迭代凍結所擁有的對象圖，不使用迴圈跟蹤集合。`surface` 校驗會記錄一次轉換計畫；當同一個候選事件進入日誌時，系統直接提交該計畫，不再對同一事件規劃兩次。

普通建立與 fork 路徑使用的借用 `seed` 仍會建立 JSON 快照，並使用支持迴圈偵測的通用深度凍結。因此，這項特化僅改變持久復原，不會放寬呼叫方所有值的准入要求。

## 考慮過的替代方案

- **每幀執行一次非同步原生操作**：不予採納，因為對於包含大量小型持久化批次的日誌，調度與回呼開銷佔據主要部分。協作式同步解碼只在週期性讓出邊界付款這類開銷。
- **同步處理完整日誌且不讓出事件迴圈**：不予採納，因為整個復原期間都無法回應取消或推進事件迴圈。幀邊界讓出機制無需拆分編解碼操作，就能保留有界的觀察點。
- **掃描前拼接全部明文**：不予採納，因為該方案會同時保留壓縮輸入、完整明文、整份日誌的 UTF-8 字串、行元資料和解析記錄，並會重新掃描撕裂幀前綴。
- **實作流式 JSON 解析器**：不予採納，因為 JSONL 已提供記錄邊界；使用原生換行搜尋與 `JSON.parse` 就能移除大型中間結構，無需自行維護另一套解析器或改變 JSON 語義。
- **凍結復原事件時共享一個 `WeakSet`**：不予採納，因為 JSON 物化不可能產生迴圈引用，而該集合會對每個對象增加一次尋找，並在遍歷期間保留完整對象圖。
- **跳過復原值的校驗或凍結**：不予採納，因為持久儲存屬於執行時期邊界，而 `Session.events` 承諾已接受歷史不可變。最佳化路徑利用更強的所有權事實特化這些操作，而不是將其移除。

## 後果

在代表性效能剖析中，增量掃描將 JSONL 掃描時間從約 598 ms 降至 397 ms，峯值 RSS 從約 1,494 MiB 降至 1,060 MiB。復原准入將 `Session.fromRestore` 從 604–608 ms 降至約 263 ms，其中 `assertSessionEventEnvelope` 從約 77 ms 降至 13 ms。這些資料用於描述最佳化輸入，不構成執行時期上限。

快速解碼器相依性執行時期探測的 Node 內部介面，但介面不相容時會改用公共實作，不會改變正確性。系統會在協作式幀邊界讓出點觀察取消訊號；截止時間並不是單個幀內部嚴格的掛鐘時間上限。完整事件陣列仍會駐留記憶體，因為它是活躍工作階段的權威日誌；該管線移除的是重複表示，並未對這份狀態做分頁。

測試會強制執行兩種解碼器實作，比對幀順序和損壞處理行為，覆蓋協作式取消與撕裂尾部復原，並保留既有工作階段信封、`surface` 與不可變性約定。
