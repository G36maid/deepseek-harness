# Agent Note: 將每則訊息建立為帶標識的不可變值

Status: implemented

[English](2026-07-28-identified-immutable-message-values.md) | 繁體中文

## 問題

harness 曾存在多種形似訊息的表示，各自採用不同的標識規則。agent（代理）輸入只有在 agent loop 接受後才會取得 inbox 關聯 id，而持久使用者訊息、assistant 訊息、工具結果和模型請求訊息都可能沒有標識。因此，提示詞准入介於建立訊息與建立標識之間；等價內容會在即時事件、持久事件和模型請求之間複製，卻沒有一個值能在訊息的整個生命週期中標識它。

這使標識成為路由的副作用，而不是訊息不變數。生產方無法在呼叫 agent 前引用一則訊息，提示詞掛鉤會分別接收內容和來源，後續投影則必須一邊重建訊息，一邊決定 id 是否存在。不可變性也從不同邊界開始：部分輸入由 agent loop 凍結，部分直到工作階段追加時才凍結，由提供方生成的 assistant 輸出則使用另一種攜帶提供方、模型和重播狀態的形狀。

## 決策

`@deepseek-ai/dsh-llm` 持有唯一一種 `Message` 值，其 `id`、`role`、`content` 和 `source` 均為必填。`MessageId` 是不透明標識，由使用者訊息、assistant 訊息和工具結果訊息共享。訊息在建立時就會獲得 id，早於 inbox 路由、領取、pre-step 改寫、持久追加或請求投影。同一個 id 會跨越每個表示邊界。

`createMessage(input)` 是角色通用的規範建立邊界。它會生成 `MessageId`，將傳入的角色、內容和來源與呼叫方對象解除引用關係，並在返回完整值前將其深度凍結。`createUserMessage({ content, source })` 為提示詞和上下文生產方固定 user 角色。`createAssistantMessage({ content, source })` 同時固定 assistant 角色與模型來源類別，因此模型輸出生產方只需提供內容，以及提供方、模型和選填的重播狀態。所有建立輔助函式的輸入都不包含 id，因此呼叫方不會意外地把新訊息的建立偽裝成已有訊息的匯入。`freezeMessage(message)` 是獨立的匯入或轉換邊界：它會將已有標識的訊息與呼叫方對象解除引用關係並深度凍結，不會生成替代標識。

這些輔助函式位於基礎訊息詞彙旁的 `dsh-llm` 中，因為它們的完整約定只相依性該詞彙。`createToolResultMessage()` 與其他建立輔助函式同屬此處：它將工具呼叫 id 與確切的 user-role 工具結果塊及來源耦合起來，不相依性工作階段狀態或事件。`dsh-session` 只消費完整訊息，不負責構造它們。

`Agent` 介面透過 `followup`、`steer` 和 `inject` 接收完整的 `UserMessage`。這些操作絕不會分配或返回標識；它們會凍結匯入的值，而呼叫方已經持有該值的 id。inbox 領取和 `agent/pre-step` 會直接接收該訊息。改寫內容時會建立具有相同 id 的凍結替代值，而每個附加上下文都是單獨建立的 `UserMessage`，擁有自己的 id。

產生持久訊息的事件會儲存完整訊息。`user/message` 直接儲存其 `UserMessage`；`assistant/message` 和 `tool/result` 則將各自角色專用的訊息與事件本機的位置、用量、失敗或呈現事實包裝在一起。工作階段派生會返回這些凍結值，而不是重建匿名訊息。assistant 組裝會在回應完成時建立模型來源的訊息，工具執行會在提交結果時建立工具來源的訊息。

僅改變已有語義訊息表示的操作會保留其 id，並返回另一個凍結值。建立新語義訊息的操作則會生成新 id。因此，壓縮（compaction）中的內容改寫會保留被改寫工具結果的標識，而摘要檢查點是一條新訊息。

## 考慮過的替代方案

**讓基礎訊息的 id 保持選填。** 這能減少 fixture（測試前置資料）遷移，並允許提供方或持久化形狀繼續保持匿名，但也會保留原有歧義：每個消費端都必須根據標識是否存在執行分支，且沒有任何類型能證明准入、記錄或投影保留了標識。

**讓 agent 交付分配 id。** 這會將標識限定在 inbox 關聯範圍內，卻也會讓 agent 呼叫成為生產方可以標識自身訊息的最早時機。這樣一來，在交付返回前，提示詞構造、UI 附件和同步入隊／丟棄協調都需要進行內容匹配，或使用帶外 token。

**讓每個持久事件分配新 id。** 這能為持久訊息提供標識，卻會有意切斷它與即時輸入的關聯，並讓重播請求表現得像包含了不同訊息。標識屬於語義值，而不是承載它的每個封裝。

**只在 agent 或工作階段准入時凍結。** 這能省去建立輔助函式，卻會留下一個帶標識但可變的時間區間，呼叫方程式碼可以在這段時間內改變該 id 所關聯的含義。本決策讓「擁有 id」與「是不可變快照」同時成立。

## 後果

每個訊息生產方都必須顯式選擇建立或匯入，測試也會構造完整值，而不是不完整的內容／來源記錄。UUID 的生成會前移至最初的語義建立點，因此提供已有 id 的確定性 fixture 會使用 `freezeMessage()`，而不是 `createMessage()`。

即時 inbox 事件、持久事件、派生歷史和模型請求可以關聯同一則訊息，無需比較內容或使用封裝專用 id。待處理輸入策略和 UI 附件清理可以在輪次存在之前比較 `MessageId`，領取後則會在已打開的輪次內保留該標識。深度凍結可以防止生產方、掛鉤或觀察方在標識建立後更改訊息值。

共享表示移除了舊的 `UserMessageData`/`AgentMessage` 劃分，並將提供方、模型和選填的重播狀態放入帶類型的訊息來源。事件封裝仍持有不屬於訊息語義的事實，例如輪次與步驟位置、token 用量、內部工具失敗標識和呈現元資料。

訊息和輔助函式的單元測試會鎖定即時標識、解除輸入引用、深度不可變性，以及匯入 id 的保留。agent loop 測試會鎖定標識跨越准入、inbox 生命週期、持久追加、內容改寫和取消的行為；工作階段測試會鎖定凍結派生和保留標識的替換行為。
