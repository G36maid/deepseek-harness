# Agent Note: 基於檔案系統與行程管理執行世界的可移植消費端

Status: implemented

[English](2026-07-28-portable-execution-world-consumers.md) | [简体中文](2026-07-28-portable-execution-world-consumers.zh.md) | 繁體中文

## 問題

檔案系統與行程管理 seam 使文件訪問和普通行程訪問具備可替換性，但 PTY 和 LSP 仍直接呼叫宿主 Node API。因此，即使領域行為沒有變化，遠端執行提供方看起來仍需要獨立的 PTY 與 LSP 包。這些包只會成為淺層配接器：每個包都僅為替換文件與行程操作而複製一個現有消費端。

只有文件操作、命令、終端機和語言伺服器共享同一個沙盒身份時，遠端編碼世界纔有用。若把完整 harness 移入該沙盒，還會把提供方實驗與外掛程式載入、憑據、模型傳輸、工作階段持久性、監督和部署糾纏在一起。

普通管道無法滿足其中一項要求。持久終端機需要分配 PTY、檢查前臺行程組並行送訊號，以及清理完整的終端機工作階段。如果假設可以在 `dsh-terminal-bash` 中基於普通 `spawn()` 控制代碼重建這些操作，最終不是洩漏提供方內部細節，就是削弱其生命週期約定。

## 決策

`ctx.fs` 與 `ctx.subprocess` 共同定義一個執行世界。共同掛載的提供方必須描述相同的路徑命名空間、可執行文件、行程和終端機工作階段；上層能力消費這兩個介面，而不引用具體提供方。

檔案系統介面負責其他能力需要的路徑事實，同時不公開其不透明目標身份：規範化行程路徑、規範化 `file:` URI 和包含關係。現有完整文字與流式文字操作仍歸檔案系統負責；協議消費端在消費流時執行各自的保留上限。

行程管理介面負責可執行文件尋找與行程原語：以原始或收集模式 spawn 普通行程，以及 `spawnTerminal()`。終端機操作是一項深層原語，其控制代碼負責文字 I/O、前臺行程組、訊號傳送，以及一項須等待的 TERM→KILL 操作；該操作會結帳所有運送中控制代碼呼叫，並使提供方仍可觀察到的每個工作階段成員完全靜止。其訊號只取消分配；控制代碼一經發布，便負責自身生命週期。提示符偵測、空閒推斷、scrollback、沙盒策略和所有者生命週期仍由 PTY 消費端負責。

通用消費端使用該執行世界：

- `dsh-bash-local` 繼續把 Bash 語義對映到普通的 `ctx.subprocess.spawn()`。
- `dsh-lsp-stdio` 透過 `ctx.fs` 讀取原始檔並驗證包含關係，透過 `ctx.subprocess` 解析和啟動語言伺服器，並讓由提供方負責的文件 URI 貫穿初始化與結果渲染。一個提供方生命週期訊號會在資源釋放期間中止檔案系統與協議操作，包括取得佇列所有權之前的工作區尋找；其 JSON-RPC、池化、同步和規範化保持不變。
- `dsh-terminal-bash` 把持久 shell 語義對映到 `ctx.subprocess.spawnTerminal()`。本機 `node-pty` 與行程檢查實作移入 `dsh-subprocess-local`；其他行程管理提供方則提供相同原語。`danger-full-access` 不需要 `ctx.sandbox`；受限模式要求同一執行世界中存在沙盒提供方，未掛載時會在 spawn 前失敗。提供方開始寫入時，系統會丟棄非同步寫入前檢查期間收集的提示符與靜默證據。取消會在運送中寫入結帳期間保留傳送預留，隨後向前臺行程組傳送訊號，因此延遲位元組和該訊號都無法落到後續傳送；運送中就緒檢查無法釋放該預留，寫入被拒絕時也不會發送訊號。絕對截止時間會在整個取消期間保持啟用。訊號傳送失敗會成為終結性傳輸失敗。過時檢查完成後，會針對當前傳送復原輪詢。啟動取消會立即開始終端機回滾，而不等待停滯的就緒檢查或訊號傳送呼叫。關閉操作會拒絕新的公開訊號，並把提供方可觀察工作階段成員的完全靜止委託給控制代碼上須等待的終止操作。

## E2B POC 邊界

選填啟用的 E2B 實作在 `packages/e2b/` 下恰好只有三個提供方專用包：`dsh-e2b` 建立一個沙盒，並在逾時或資源釋放時將其刪除；`dsh-fs-e2b` 實作 `ctx.fs`；`dsh-subprocess-e2b` 基於 E2B Commands、PTY 和遠端 Linux 行程組實作 `ctx.subprocess`。兩個配接器都從所有者取得唯一的 SDK 控制代碼，絕不建立私有沙盒。

E2B 負責可變檔案系統、受管命令與 Bash 行程、終端機分配與終端機工作階段組、語言伺服器行程與原始檔讀取，以及 `.dsh-e2b` 下的配接器私有文件。宿主負責 Cordis 與外掛程式對象、agent loop（代理循環）、agent 狀態、工作階段狀態與目標狀態、工作階段日誌與持久化、LLM（大型語言模型）呼叫、提示詞與工具、權限、skill（技能）、subagent 編排、PTY 緩衝區與就緒狀態、LSP 協議狀態，以及 E2B SDK／網路緩衝區。該疊加層既不上傳，也不同步宿主工作區。

配接器只保留執行基底機制。檔案系統規範化以嚴格的 base64 加 NUL 分幀穿過 SDK 已解碼的命令傳輸；流式讀取把位元組上限留給消費端執行。行程管理命令輸出與環境快照採用 ASCII/base64，避免 SDK 區塊解碼丟失位元組；私有控制 shell 隔離 profile，後續啟動會把已發現且名稱呈憑據特徵的環境變數置空。行程與終端機清理使用遠端行程組，並在結帳前證明完全靜止。

沙盒狀態有意保持短暫：逾時與資源釋放會刪除遠端文件和非託管狀態。該 POC 不提供重新連線、pause/leave 保留、工作階段持久化後端、範本建置器、卷、快照、網路策略層、沙盒目錄、工作區同步、持久遠端控制代碼，也不會在其中執行整個 harness。

## 驗證

聚焦的包測試套件鎖定了沙盒生命週期、規範化路徑分幀、檔案系統元資料與原子版本、行程管理髮布／回滾、終端機文字 I/O 與工作階段清理、輸出上限、取消、資源釋放和不變式註冊。一項受憑據門控的 Loader 組合透過原始碼匯入與建置後匯出執行同一套三包提供方組合，其中包括 FS/Bash 可見性、惡意登入 profile、跨位元組邊界拆分的 UTF-8 輸出、行程與終端機清理、LSP 查詢、宿主工作區隔離，以及最終沙盒刪除。

## 考慮過的替代方案

**為每個遠端提供方分別保留 PTY 與 LSP 包。** 不予採納，因為這會在現有 seam 之上重複實作提供方機制。刪除檢驗揭示了這一問題：刪除這些配接器不應使領域行為散落到遠端提供方中；通用消費端本已負責這些行為。

**為每項能力或工具建立獨立沙盒。** 不予採納，因為文件與行程操作將無法共享身份或狀態，從而破壞編碼用例，並增加生命週期所有者的數量。

**把終端機建模為普通的管道子行程。** 不予採納，因為管道無法分配控制終端機、確定當前前臺行程組或證明完整終端機工作階段已清理。一項終端機原語比公開特定於執行基底的逃生口更小，也更能如實表達約定。

**把 PTY 就緒判斷與工作階段策略移入行程管理服務。** 不予採納，因為這些屬於持久終端機消費端的語義，而非 OS 行程機制。行程管理提供方負責只有其執行基底才能完成的操作；`dsh-terminal-bash` 負責 Harness 終端機的語義。

**分別公開終端機終止與完全靜止操作，並提供共享生命週期控制器。** 不予採納，因為每個終端機消費端都需要相同的單一清理結果。拆分操作會把提供方簿記、有界觀察者和重試語義暴露出來，卻沒有生產消費端；由提供方提供一個須等待的操作，介面更深。

**在檔案系統 seam 中新增穩定的有界讀取原語。** 不予採納，因為只有 LSP 需要完整文件位元組上限，而它可以在消費現有文字流時執行該上限。第二項原語會迫使每個提供方實作穩定控制代碼和不跟隨符號連結的機制，遠端提供方甚至需要輔助協議，卻沒有已觀察到的並行替換缺陷。

**在遠端環境中執行整個 harness。** 不予採納，因為這是另一種部署模型。讓執行能力可移植，並不意味著移動模型呼叫、工作階段狀態、外掛程式狀態或 agent loop。

**把所有提供方操作都放進一個共享所有者包。** 不予採納，因為沙盒身份與生命週期是所有者唯一的關注點。檔案系統與行程管理保留各自獨立的約定、測試和消費端，同時避免把所有者變成無邊界的能力集合。

**只透過 shell 命令實作遠端檔案系統操作。** 不予採納，因為這會丟棄現有文件工具已消費的結構化檔案系統身份、錯誤、流式輸出、版本保護和原子變更語義。

**新增通用分散式執行時期抽象，或重新連線活躍控制代碼。** 不予採納，因為現有能力 seam 已承載經證實的約定，而僅憑遠端身份無法重建回呼、待處理 promise、權限、協議狀態或輸出遊標。新增一層只會推測 POC 邊界之外的持久化與同步問題。

## 後果

遠端執行提供方只需實作共享沙盒所有者，以及檔案系統與行程管理配接器。Bash、PTY 與 LSP 組合在這些配接器之上，因此對這些能力的修復仍與提供方無關。

基礎介面更寬，一對檔案系統／行程管理提供方必須在同一個執行世界上保持一致。新增操作僅限當前通用消費端所需的事實與生命週期機制；模型 schema、協議分幀、就緒策略和呈現不會滲入提供方。

本機實作承接 `node-pty` 和平臺行程檢查，因為它負責本機終端機機制。這種程式碼遷移不會削弱終端機拆卸：dispose（資源釋放）會在終止頂層 shell 前後清理後代行程，等待前臺檢查期間保留下來且受精確 PID 身份圍欄保護的後代行程，並繼續追蹤在頂層行程退出後仍存活的 Linux 工作階段成員。macOS 無法在 POSIX 工作階段 leader 退出後枚舉該工作階段，因此在兩次檢查快照之間重新設定父行程的子行程仍是明確的本機提供方限制，而不是把行程機制移回 PTY 消費端的理由。

E2B 組合證明，共享沙盒所有者加上檔案系統與行程管理配接器，就足以在保持上層能力與提供方無關的同時，把可變編碼世界移出宿主。其 POC 限制仍明確在案：SDK 會把完整命令傳輸內容保留在宿主記憶體中；遠端啟動無法同步發布 PID；無法獲得精確的終端機 stdin 等待狀態與獨立訊號事實；基於數值 PID/PGID 的操作沒有身份圍欄；初始環境探測無法向已在執行的同 UID 行程隱藏未知的沙盒默認 secret；配接器產物會一直保留到沙盒刪除。這些是提供方限制，不是引入相容性 shim 或更多 E2B 包的理由。
