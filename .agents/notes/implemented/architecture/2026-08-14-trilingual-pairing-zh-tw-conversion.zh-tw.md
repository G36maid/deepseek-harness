# Agent Note: 三語文件配對與 zh-TW 轉換管線

Status: implemented

[English](2026-08-14-trilingual-pairing-zh-tw-conversion.md) | [简体中文](2026-08-14-trilingual-pairing-zh-tw-conversion.zh.md) | 繁體中文

## 問題

本倉庫的文件與 Web UI 只提供英文與繁體中文，所有配對閘門、網站投影、語言登錄檔與翻譯提示詞都硬編碼為兩種語言。新增臺灣繁體中文（zh-TW）因此觸及每一層：配對記錄格式、語料發現、合併驅動、站點語言模型、用戶端語言集與機器翻譯契約。zh-TW 側無法像 zh-CN 那樣從英文人工翻譯——語料約一千篇文件，且 zh-TW 由 zh-CN 派生而非由英文派生，因此機械轉換管線加人工複核是唯一可行的生產路徑。

## 決策

**配對模型是語言對映，而非固定雙槽記錄。** `PAIRED_LANGUAGES = ['en', 'zh', 'zh-TW']`，每種語言有對應的文件後綴（`.md`、`.zh.md`、`.zh-tw.md`），`.i18n.yaml` 記錄每種語言的一個 git blob hash。閘門、合併驅動與 `--write` 流程都遍歷語言集而非硬編碼中文側；今後新增第四種語言只需改一行登錄檔。

**zh-TW 由 zh-CN 機械派生，再對照英文複核。** 轉換工具（`scripts/convert-zh-tw.ts`）執行 zhtw-js——一個約 3.1 萬詞的詞彙優先臺灣轉接器，疊加來自 `docs/i18n/terminology-zh-tw.md` 的自訂詞典——然後對 zhtw-js 遺漏的字做 OpenCC s2t 字形兜底，最後經配對閘門重新記錄。複核時對照英文源，因為純 zh→zh-TW 轉換會繼承 zh 譯文的任何漂移。術語文件的機械陷阱表記錄了必須修正的 OpenCC 輸出（權限 → 許可權 是錯的；權限 才對）。

**zh-TW 閘門報告簡體字殘留，而非詞彙偏好。** `scripts/verify-zh-tw.ts` 用 OpenCC s2t 過濾 zhtw-js 檢查結果：只有仍含簡體字的片段纔算失敗。詞彙建議（宣告 → 宣告、繫結 → 繫結）留給複核，因為兩種形式在臺灣都是合法用法。

**每個已發布層都攜帶第三語言。** 瀏覽器用戶端語言集為 `['zh', 'zh-TW', 'en']`，瀏覽器偵測使用 script 子標籤（`zh-Hant-TW` → zh-TW）；每個語言命名空間都註冊 zh-TW 字典；網站投影 `/zh-TW/` 路由，含自己的側欄與搜尋標籤；翻譯提示詞接受 `Chinese-TW` 目標用於 zh→zh-TW 轉寫。

**凍結的歸檔三件套永不新增 zh-TW 側。** `.agents/notes/archived/` 從轉換發現與配對中排除；轉接器跳過該目錄樹，歸檔驗證器繼續封存既有的 en+zh 三件套。

## 後果

配對閘門在全部 936 個範圍內配對上都已變綠，每個配對視對記錄三個 hash。轉換語料為 934 個 zh-TW 文件（docs/i18n/ 下的兩個契約文件先存在）；`verify-zh-tw --all` 報告 14 個簡體字殘留，全部集中在 麵包/遊程 這類邊界詞彙——其中 面/遊 有合法的傳統讀法，轉接器無法消歧。網站以三種語言建置（`pnpm run docs:build`），用戶端測試套件在第三語言下全綠（`pnpm run test:gui`）；基礎 tsconfig 增加了 `customConditions: ['node']`，讓 TypeScript 能解析 zhtw-js 的條件匯出（該包只有 `node`/`browser` 匯出條件，沒有頂層 `types`）。

## 考慮過的替代方案

- **以 OpenCC s2twp 作為轉換引擎**——在語料上產生 5094 個殘留發現，因為其臺灣短語表比 zhtw-js 薄，且誤轉 權限 → 許可權（術語表須再修）。zhtw-js 將同一語料轉換到 14 個殘留。其詞彙優先設計也讓倉庫術語表可充當自訂詞典，使 打包 在打包語境保持 打包 而非變成 外帶。
- **雙槽記錄加硬編碼 zh-TW 欄位**——避免泛化閘門，但每種未來語言（zh-HK、ja）都會重複同樣的改動；對映現在花費相同成本，以後免費。
- **從英文人工翻譯 zh-TW**——在約一千篇文件的規模下不可行，且與 zh 譯文重複；機械轉換加複核把人力成本放在質量上，而非轉錄上。
- **將歸檔三件套視為可轉換**——違反凍結；歸檔驗證器會拒絕第四個文件，且配對契約承諾永不重寫歸檔內容。
