# Agent Note: Skill 目錄熱刷新

Status: implemented

[English](2026-07-27-skill-catalog-hot-refresh.md) | [简体中文](2026-07-27-skill-catalog-hot-refresh.zh.md) | 繁體中文

## 問題

skill（技能）摘要是模型的路由輸入，但本機 skill 可在工作階段啟動後新增、消失或重新命名。IDE、Git 操作、shell 命令和其他行程都可以修改 `.agents/skills`，而不經過 harness 檔案系統工具。僅在啟動時建置目錄，會讓模型無法獲知新 skill，並且仍能呼叫已刪除的名稱。反之，如果把每次指令正文編輯都視為目錄修訂，就會讓漸進式載入與不必要的提示詞頻繁變化耦合。

從觀察方來看，檔案系統更新也不是原子完成的。編輯器或 Git 操作可能會短暫移除檔案，受監視的根目錄在啟動時可能不存在，發現也可能暫時失敗。把這些中間觀察結果發布為權威空目錄，比保留最後一個完整檢視表更糟。

## 決策

skill 服務將目錄成員關係與指令正文載入分離。`ctx.skills.snapshot()` 返回摘要及一個完整性位。`ctx.skills.registerProvider(factory)` 會向同步工廠提供一項註冊作用域內的 `{ signal, invalidate }` 控制能力：`invalidate()` 只會將該精確活動註冊標記為髒，並丟棄已完成目錄快取；註冊失敗或釋放時，訊號會中止。提供方返回的陣列是完整發現的簡寫形式；顯式的不完整觀測可以保留可讀候選項供直接載入，但不能快取，也不能作為面向模型消費端的權威結果。在發現期間，如果提供方或執行時期 generation 發生變化，系統會重試一次；如果這次重試也被後續修訂取代，則最新候選項會作為不完整且不快取的觀測返回。資源釋放或替換後的延遲失效操作不會執行任何操作，因為該能力已被撤銷。

`@deepseek-ai/dsh-skill-filesystem` 直接相依性 Chokidar，並觀察與目錄相關的宿主路徑。已有根目錄會監視其直屬 skill bundle 目錄、平鋪的 Markdown 條目和直屬 `SKILL.md` 條目文件。新增、移除和目錄變更會使成員關係失效；文件變更還支持刷新 frontmatter 中的 `name` 和 `description`。bundle 內更深層的資源文件會被忽略。同一微任務批次中的事件會合並為一次失效。項目 watcher 使用有界集合，並按最久未觀察順序淘汰。

系統從缺失根目錄最近的現有祖先開始，使用 `fs.watchFile` 每次跟進一層缺失路徑片段；真實根目錄出現後，再交給 Chokidar。每次發現操作都會在掃描前重新探測所保留的根目錄／祖先模式。即使子項移除在根目錄 `unlinkDir` 事件之前就觸發失效並行布權威空目錄，或者該事件根本沒有到達，這項獨立探測也會在刪除後重新建立祖先觀察。Chokidar 設定公開原生事件或輪詢模式、寫入穩定性、輪詢間隔、符號連結跟隨選項和項目 watcher 容量。第一方 `write` 和 `edit` 工具觀察會同步使相關提供方失效，因此下一個模型步驟無需等待宿主事件投遞，就能看到自身改動。watcher 啟動或執行失敗會被記錄並觸發重試；發現過程仍會返回可讀候選項供直接載入，但會報告不完整觀測。資源銷毀會關閉 watcher，並忽略延遲回呼。

`@deepseek-ai/dsh-tool-skill` 在首次觀察到非空完整目錄且返回 enter 的 `agent/pre-step` 中，貢獻一條帶來源的 `UserMessage`。每次 pre-step，它都會應用 `skill` 工具的精確可見性，對 `<available_skills>` 標籤之間精確渲染的文字計算雜湊，並從後向前掃描只讀工作階段事件且不複製，以尋找該外掛程式發布的最新一條可識別且仍可見的目錄。digest 變化時，外掛程式會向 enter 決策貢獻完整替換目錄；所有 skill 消失時也包含顯式空目錄，reject 或監聽器失敗則不記錄任何內容。如果沒有目錄仍然可見，但歷史事件中存在可識別目錄，則說明壓縮（compaction）已將其遮蔽，下一次完整且進入步驟的觀察會重新建立當前目錄，包括空 tombstone。如果當前目錄為空且歷史上從未發布目錄，則不傳送任何內容；不完整快照則保留最後一次完整的模型檢視表。反向掃描通常在最新且仍可見的目錄處停止；當壓縮遮蔽所有目錄時，它會以一次 O(session-events) 掃描的成本確認這一事實。

TUI 將同一失效通知作為介面狀態而非工作階段歷史來消費。`skills/change` 不攜帶 diff；TUI 會為活動工作階段的 cwd 重新取得 `snapshot()`，僅應用最新的完整結果，並在觀測不完整時保留先前命令。完整的空結果會清除過時補全項。pi-tui 在其提供方被替換時會關閉自動補全，因此如果目錄在使用者輸入斜槓命令名稱期間到達，還會觸發一次僅用於更新建議的當前草稿重查。

指令正文繼續採用漸進式披露。每次呼叫 `skill(name)` 時，系統都會要求提供方重新讀取並解析當前文件；不存在正文快取、雜湊、修訂或主動通知。先前記錄的工具結果保持不變。如果載入後的 frontmatter 名稱不再匹配所選候選項，登錄檔會拒絕這個過時名稱，並使該提供方失效，以便後續目錄觀察發布新名稱。

## 驗證

登錄檔測試固定了註冊作用域內的失效、能力撤銷、訊號中止、監聽器失敗隔離、不完整候選項、有界 generation 重試和過時名稱拒絕。local-provider 測試覆蓋 bundle 與平鋪文件的建立、移除和重新命名，以及根目錄建立／刪除／重建（包括未觀測到根目錄 `unlinkDir` 事件的情形）、描述變更、僅正文編輯、第一方觀察、符號連結、輪詢選項、候選項仍可載入的持續 watcher 失敗、事件合併、項目 watcher 容量上限、資源銷毀和暫時讀取。工具測試固定了完整替換訊息、空 tombstone、僅修改正文時 digest 穩定、不完整狀態保留、可見性和復原元資料。TUI 測試固定了上一份完整結果保留、權威空結果清除、刷新時以最新結果為準、資源銷毀和已打開斜槓草稿的競態；一項使用真實 Loader/PTY 的 smoke 測試會在啟動後新增本機 skill，並觀察其補全項出現，而無需重新啟動。一個無金鑰、裝配完成的 agent-spine 快照測試透過面向模型的檔案系統工具建立項目 skill，觀察下一次請求中的替換目錄，並使用真實 `skill` 工具載入當前正文。

## 考慮過的替代方案

- **將即時目錄放入 World State**：不予採納，因為目錄替換是模型可見的工作階段輸入，必須能夠從事件日誌重建。持久注入歷史已經提供重播、復原、fork 和壓縮語義，無需再引入一套可變狀態層。
- **只相依性 `fs/observed`**：不予採納，因為 IDE、Git、shell 命令和外部行程都不會經過該 seam。該事件仍作為第一方工具的低延遲快速路徑，宿主監視則補齊覆蓋。
- **為每個 `SKILL.md` 正文計算雜湊或版本**：不予採納，因為模型最初只看到名稱和描述，提供方已經在每次工具呼叫時重新讀取正文。正文修訂會產生目錄流量，卻不會改變路由，也不足以成為改寫歷史工具結果的理由。
- **監視每個 bundle 資源**：不予採納，因為參考資料、指令碼和產物都是按需載入的，不影響類別清單。寬泛的遞迴監視會增加失效、描述符壓力和平臺差異，卻不能改善路由。
- **將部分發現或失敗發現發布為新目錄**：不予採納，因為暫時讀取失敗不能證明文件已刪除。完整性位讓面向模型的消費端保留最後一次完整目錄，直到完整觀察成功。
- **保留公開的 `invalidateProvider(provider)`**：不予採納，因為這會公開一項登錄檔變更方法，並要求呼叫方重複提供登錄檔已經持有的身份。發給工廠的閉包會將失效綁定到單個註冊，並在釋放後失去作用，因此觀察方既不需要訪問登錄檔，也不需要提供方身份。
- **現在提取通用 Cordis 文件監視服務**：暫緩，直到另一個消費端確立可複用的服務約定。本機提供方標出了其 Chokidar 和缺失根目錄觀測邊界，以便後續提取；skill 路徑過濾以及對提供方失效閉包的呼叫仍屬於 skill 專用邏輯。

## 影響

- 新增、刪除和重新命名的本機 skill 會在模型步驟邊界變得可見，無需重新啟動 agent（代理），即使 skill 根目錄在啟動時不存在也一樣。
- TUI 的 `/skill:` 補全會收斂到同一份完整目錄，而不會讓每次按鍵都阻塞於發現；打開的斜槓命令名稱草稿會在目錄到達時刷新。
- 目錄訊息採用僅附加、日誌記錄和全量清單快照。它們會保留較早的可重用 token；替換目錄會顯式停用過時名稱，每次 digest 實際變化時，token 成本與當前目錄大小成正比。
- 僅修改正文不會產生目錄訊息。後續工具呼叫會看到當前內容，而先前工具結果仍準確記錄模型之前載入的內容。
- 缺失根目錄輪詢和 Chokidar 引入一個有人維護的執行時期相依性、宿主 watcher 資源、有界偵測延遲和部署可調參數。有界項目集合與資源銷毀約定會限制這些成本。
- 遠端或未來的可變提供方會保留各自註冊作用域內的失效閉包，並透過自身觀察機制呼叫它；登錄檔不會強制採用通用 watcher 或 TTL。
