# Agent Note: 持久化的同工作階段目標領域

Status: implemented

[English](2026-07-19-persisted-same-session-goal-domain.md) | [简体中文](2026-07-19-persisted-same-session-goal-domain.zh.md) | 繁體中文

## 問題

長時間執行的目標會跨越單個提示詞、輪次或模型請求。若把該目標視為記憶體中的迴圈變數，行程重新啟動時就會丟失；若只存放在 UI 狀態中，又無法重建模型行為。若把工作階段中的每個輪次都視為目標進度，與自動工作無關的人類訊息也會消耗預算。

持久化的生命週期與繼續執行的權限是兩個不同事實。工作階段在重新啟動或 fork 後可以保留活躍目標，但使用者打開工作階段時靜默啟動工作並不符合直覺。該領域需要可重播的狀態，卻不能持久化自動執行權限；它還必須作為公共 agent（代理）與工作階段服務上的外掛程式存在，而不是具體迴圈中的特例。

## 決策

位於 `packages/goal/goal/` 的 `@deepseek-ai/dsh-goal` 透過 `ctx.goals` 管理一個當前的同工作階段目標。目標包含帶品牌的 id、目標描述、持久化階段、比較並交換修訂號和 `maxGoalRounds`。`defaultMaxGoalRounds` 是經過校驗的部署設定，預設值為 `256`；`create()` 在變更前於內部將其解析為完整值，而不會把解析過程暴露為額外的服務動詞。

持久階段包括 `active`、`paused`、`blocked` 和 `complete`。阻塞快照包含由策略定義的全小寫 kebab-case 程式碼和規範化自由文字訊息，因此用量限制、Goal Round 上限、執行失敗和等待人工輸入可以共享一個生命週期狀態而不丟失原因。獨立的即時啟用態為 `armed` 或 `disarmed`。建立與顯式復原會啟用目標；暫停、完成、阻塞和清除都會解除啟用。編輯保留啟用態及阻塞原因；復原和完成會清除該原因。持久快照絕不包含啟用態。

### 持久記錄與重播

每次變更都會追加帶版本的 `goal/change` 工作階段事件，其中包含完整快照；清除時則包含帶修訂號的墓碑。工作階段日誌是唯一的持久真源，因此持久化和 fork 會繼承目標記錄，而無需另設資料庫或頭欄位。[目標自有持久事件決策](../architecture/2026-07-31-goal-owned-durable-events.md)負責將目標持久事件與收件箱狀態和模型上下文分離。

重播摺疊只從 `goal/change` 派生生命週期變更，並校驗 JSON 形狀、新 id、修訂連續性、生命週期轉換、計數器以及單個目標內單調遞增的時間戳。只有當前活躍修訂上帶正數且連續編號、已接納的 `user/message` 來源才會推進 Goal Round，且不能超過 `maxGoalRounds`；普通工作階段輪次不會影響該計數器。當前格式的畸形記錄會使重播失敗，而不會被忽略或修復。

增量重播會在每個有效事件後推進遊標，並停留在首個損壞事件處，因此後續讀取會報告同一個持久故障。重新啟動後仍以持久日誌為準。

### 生命週期與即時啟用態

最多隻有一個當前目標。建立要求不存在未完成的當前目標，並始終生成該工作階段此前未使用過、修訂號為一的 id；已完成目標可以被替換。其他每次變更都攜帶預期的 `GoalRef`，過時的 id 或修訂號會被拒絕。僅當 Goal Round 上限仍有餘量時，暫停或阻塞階段以及已解除啟用的活躍目標才能復原。領域層校驗阻塞原因的形狀，但會把原因程式碼和是否阻塞的決策留給策略消費端。

從任何種子建置的快取都以未啟用狀態開始，每次 `agent/session-start` 邊沿也會再次解除啟用。`GoalService.disarm(agent)` 還允許生命週期所有者移除行程內權限，而不寫入工作階段事件、不改變修訂號，也不寄出 `goal/changed` 通知。因此，工作階段復原、fork 和繼續執行驅動程式器替換都會保留持久化目標與歷史，但絕不會自行啟動工作。後續人類提示詞可由模型解釋，其策略 API 可以顯式呼叫復原操作並激活目標。

### 服務邊界

服務只接受在對應 id 下註冊的同一個即時 `Agent` 對象。變更提交後，它會發出帶作用域的 `goal/changed` 事件，並隔離監聽器失敗。策略消費端透過本服務、公共 `Agent` 介面和 `agent/*` 事件工作；目標領域既不匯入也不修改 `dsh-agent-loop`。

## 測試

單元測試固定建立預設值、精確即時 agent 校驗、比較並交換拒絕、所有生命週期轉換、阻塞原因校驗與保留、復原時的 Goal Round 上限約束、清除與替換、種子重播和 `SessionStore.fork()` 繼承、工作階段啟動與生命週期所有者解除啟用、活躍目標重新啟用、持久事件摺疊、收件箱獨立性、損壞事件的穩定重播、服務與監聽器銷毀、監聽器隔離、掛鐘後退鉗制、嚴格記錄解碼、生命週期連續性，以及連續 Goal Round 歸屬。無金鑰 Loader/stdio 行程測試通過測試專用 `cordis.yml` 掛載服務與生命週期消費端，再從外部讀取持久 JSONL，以驗證目標記錄以及不存在未經請求的 Goal Round。包原始碼受倉庫逐文件 100% 覆蓋率閘門約束。

## 考慮過的替代方案

- **把目標存入獨立資料庫或工作階段頭**——不予採納，因為工作階段日誌已經提供順序、持久化、fork 前綴與可重建性；第二份儲存會引入原子性和譜系問題。
- **把每次持久變更與排隊的模型上下文綁定。** 後續的 [目標自有持久事件決策](../architecture/2026-07-31-goal-owned-durable-events.md) 不採用這一方案：目標工具與已調度的繼續執行提示詞會在需要時暴露狀態，而領域持久化不相依性佇列結果。
- **持久化啟用態並自動重新啟動**——不予採納，因為打開或復原工作階段時必須等待人類輸入；持久階段記錄狀態，而不是再次消耗資源的授權。
- **把所有工作階段輪次都計為 Goal Round**——不予採納，因為同一工作階段可以包含人類澄清、檢查和無關工作；只有歸屬於目標的繼續執行輪次才消耗該預算。
- **向 `dsh-agent-loop` 新增目標狀態或通用迴圈抽象**——不予採納，因為狀態與繼續執行策略可以透過現有外掛程式、`Agent` 動詞和事件組合，而無需賦予默認迴圈實作特權。

## 後果

- 目標歷史作為普通工作階段資料，在持久化、復原、無關節點壓縮（compaction）和工作階段 fork 後繼續保留。
- 復原與 fork 會暴露同一持久階段，但在顯式復原變更啟用目標前不會執行任何操作。
- 完整快照便於檢查、嚴格重播與 last-wins 投影，且不會向模型歷史新增只用於變更的訊息。
- 修訂號與生命週期校驗會盡早拒絕遭篡改、部分寫入或生產者不一致的目標記錄。
- Goal Round 上限只約束繼續執行次數；當 Goal Round、token、費用、時間或提供方限制停止工作時，策略消費端會把它們對映為不同的阻塞原因。

## 已知限制與暫緩事項

- 本領域記錄狀態，但不調度 Goal Round、不取消活躍輪次，也不分類例外停止。
- 記錄 `complete` 或 `blocked` 的參與者具有最終權威；獨立評估器或完成憑證延期到策略消費端中實作。
- 每個工作階段只有一個當前目標；不存在平行目標圖和跨工作階段目標儲存。
- 外掛程式共享同一個受信任的行程邊界。直接寫入工作階段的外掛程式可以偽造目標記錄；嚴格重播會偵測不一致並在違規記錄處使目標訪問失敗，但不會隔離外掛程式或修復日誌。
- `GOAL_CHANGE_VERSION` 在首次發布前不承諾相容性，也不提供遷移路徑。
