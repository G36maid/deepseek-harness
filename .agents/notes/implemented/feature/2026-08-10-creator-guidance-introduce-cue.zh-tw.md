# Agent Note: 創造模式引導以介紹動效落在預設 chip 上

Status: implemented

[English](2026-08-10-creator-guidance-introduce-cue.md) | [简体中文](2026-08-10-creator-guidance-introduce-cue.zh.md) | 繁體中文

## 問題

預設的創作發生在創造模式 session 內部，但設定分區沒有把這條路徑講清楚。建立入口遊離在名冊分組之外；自訂分組在沒有成員時整個消失；點擊入口後用戶被拋到新工作階段螢幕，沒有任何標記說明發生了什麼變化：暫存的預設 chip 渲染得和使用者親手挑選時一模一樣。使用者回饋看不懂流程已經移動，也不明白即將開始的 session 正是建置預設的地方（#2184）。

## 決定

自訂分組在空的時候也常駐螢幕——分組標題加建立入口，入口移入分組內部，作為"你的預設會出現在這裡"的常設指引，而不是漂在名冊下方。

從另一螢幕暫存的選擇會經由 seat store 攜帶一次性的 `introduce` 標志（`stage(id, introduce)`），chip 據此自我介紹：預設圖示在 150ms 內緩入，落定的瞬間名稱逐字元錯峯浮現。錯峯有兩重上限——短的中文名按每字元 40ms 的節拍，同時共享一個 200ms 的整體揭示視窗（`min(40, 200/(n-1))`），讓長的拉丁名與中文名在相同時間內完成，而不是按字元數拖長整輪動畫。動效由 CSS 負責；元件只負責觸發，並在一輪結束後確認該提示，因此標志不會在後續掛載時重放。`prefers-reduced-motion` 與空顯示名會立即確認、不播放動畫。

該提示純屬呈現層：它是用戶端 seat-store 狀態，永遠不是 session 事件，因為模型可見的組合已由暫存的預設本身承載。

## 曾考慮的替代方案

**在新工作階段螢幕上彈 toast 或提示框。** 它能解釋更多，但什麼也沒指向——chip 纔是使用者之後必須再次找到的對象，可關閉的提示框教會的是提示框本身，不是控制元件。介紹動效把動作放在控制元件本體上。

**固定的每字元節拍。** 第一版實作無條件使用每字元 60ms；英文預設名的時長超過四字中文名的三倍，讀起來像卡頓而非強調。共享揭示視窗讓時長成為提示的屬性，而不是語言的屬性。

**離開前在設定對話框內播放選中動畫。** 關閉對話框本身就是這個手勢的一部分——離開設定正是流程在表達"工作發生在 session 裡"——在那裡播放的任何內容要麼被截斷，要麼會拖延它本要解釋的跳轉。

## 後果

介紹時間線存在於兩處且必須一致：元件的 `INTRO_TEXT_DELAY_MS` 與 `.introIcon` 的 CSS 動畫時長。元件常數是字元延遲與確認逾時的來源；CSS 註釋點明瞭這層耦合。seat store 多出一位 UI 狀態（`introduce`），每次暫存都顯式決定它；分區則會渲染沒有成員的分組——這一形態現由分區 golden 與單元測試釘住。

## 測試

元件測試釘住帶上限的錯峯（11 字元拉丁名走 20ms 步進、4 字中文名走 40ms 節拍、單字元無錯峯）、確認時機，以及 reduced-motion 與空名的跳過路徑。`apply.spec.ts` 端到端驅動程式跨屏暫存：創造模式草稿攜帶提示暫存，一次確認將其清除，重複確認讓快照原樣不動。`agent-preset-authoring` web e2e 在 golden 中保持空自訂分組（標題加建立入口）。
