# Agent Note: 面向模型的同工作階段目標工具

Status: implemented

[English](2026-07-19-model-facing-goal-tools.md) | [简体中文](2026-07-19-model-facing-goal-tools.zh.md) | 繁體中文

## 問題

持久目標領域有意把生命週期動詞提供給外掛程式，而不直接提供給模型。模型仍然需要一個小型控制 API，用於發現當前目標、根據人類意圖建立目標並改變其生命週期。僅靠提示詞指導無法確定是誰授權了一次變更：subagent、注入的外掛程式訊息、過時的模型輪次或復原後的工作階段都可能產生相同的工具參數。

該工具 API 還需要保持持久狀態與即時執行權限之間的分離。復原或 fork 後的工作階段可以重播活躍目標，但初始處於未啟用狀態；後續人類提出「繼續」之類的請求時，模型應能重新啟用目標，而無需使用者使用字面命令。相反，已接納的自主 Goal Round 必須能夠報告完成或持續阻塞，卻不能因此獲得編輯、暫停、復原或替換人類目標的權限。

## 決策

位於 `packages/goal/tool-goal/` 的 `@deepseek-ai/dsh-tool-goal` 在 `ctx.goals` 之上貢獻三個獨佔工具和一個系統提示詞策略段：`get_goal`、`create_goal` 與 `update_goal`。工具名稱和讀取—建立—更新形態遵循 Codex 的緊湊目標工具表面，而權限規則使用本倉庫公共的 agent（代理）、工作階段、工具與目標服務。

### 工具與模型約定

`get_goal()` 返回當前目標或 `null`。非空結果包含用於比較並交換的 id 與修訂號、目標描述、持久階段、已接納和最大 Goal Round 數、可能存在的阻塞原因，以及行程本機啟用態觀察。`create_goal(objective, max_goal_rounds?)` 建立一個長時間執行的同工作階段目標。`update_goal(goal_id, revision, action, objective?, max_goal_rounds?, blocked_reason?)` 支持 `edit`、`pause`、`resume`、`complete` 和 `blocked`；替換欄位僅對 `edit` 有效，非空的 `blocked_reason` 僅在 `blocked` 時必填，並以穩定程式碼 `model-reported` 持久化。執行器把值恰好為空字串的選填欄位和值為 0 的 `max_goal_rounds` 視為嚴格 schema 佔位值：這些值等同於省略；編輯時仍必須提供至少一個有實際意義的替換欄位；所有非佔位值仍受對應操作的限制。

提示詞告訴模型：它可以從任何措辭或語言的直接人類請求中推斷目標意圖，但不應把常規單輪工作轉換為目標。更新前必須讀取當前目標，並複製準確的 id 和修訂號。對於復原或 fork 後處於活躍但未啟用狀態的目標，人類在語義上要求繼續即可成為執行 `resume` 的依據。只有目標已經實作時才能標記完成，困難或不確定性本身不構成阻塞；阻塞報告必須說明具體條件。

三個工具都採用獨佔執行，使模型排序的批次可以觀察此前變更及其新修訂號。結果為緊湊 JSON。UI 展示是參數的純函式，使用通用讀取或變更卡片；變更卡片選擇輸入時，先取有實際意義的操作值，再取目標 id，因此允許的佔位值不會使卡片輸入留空。啟用態僅作為即時觀察返回，絕不會寫入重播狀態。

自主 Goal Round 成功報告完成或阻塞後，其工具結果會附帶一條收尾指令，模型仍會在輪次經由常規無工具呼叫停止路徑結束前向使用者發言；原先在結果處終結輪次的做法已被 [Goal Round 收尾決策](../bug-fix/2026-08-02-goal-round-wrapup-message.md)取代。直接人類發起的變更不會收到指令：agent 可以確認該變更，並且並行的人類 steering（中途引導）仍可參與普通的停止檢查。

### 執行權限

每次呼叫都要求存在 `exec.agent`，且它必須是 `AgentRegistry` 中完全相同的執行中對象、當前繼承的驅動發起者，並處於開放輪次內。這些檢查在執行時進行，不能透過提示詞注入或手寫工具參數繞過。

建立、編輯、暫停與復原還要求執行時期根 agent 的當前輪次已經接納一條使用者訊息或使用者 steering 事件。根所有權來自即時 agent 圖，而非持久的 fork 祖先關係：復原後的 fork 工作階段可以接收新的直接人類權限，即時子級則仍是 subagent，不能改變這些狀態。使用者來源是宿主的證明：每個 `Agent.followup()` 或 `steer()` 輸入都必須顯式提供來源，因此宿主把直接人類內容標為 `{ kind: 'user' }`，非人類生產者則在來源欄位中註明自己。執行時期證明當前輪次包含人類直接傳送的訊息，而不判斷人類措辭在語義上是否足以建立或復原目標；該解釋仍由模型完成。

完成與阻塞既接受直接人類權限，也接受準確的當前 Goal Round。Goal Round 權限要求存在一條來源為目標的 `user/message`，其中目標 id、修訂號和 Round 都與摺疊後的當前目標相等。它只授予這兩種終止報告權限。直接人類權限可以立即停止目標。

### 阻塞閾值

`blockedAfterConsecutiveRounds` 是經過校驗的正安全整數設定，預設值為 `3`。自主 Goal Round 呼叫 `blocked` 時，外掛程式會機械地要求至少已經接納該數量的 Round 並提供非空說明；設定值也會出現在模型指導中。執行時期無法判斷這些 Round 是否遇到了語義上相同的阻塞條件，因此語義等價性仍由模型判斷。該計數特意與目標的寬裕繼續執行上限分離。

## 測試

單元測試固定註冊與 dispose（資源釋放）、獨佔調度、生成的提示詞策略、可安全處理佔位值的通用展示、非英語輪次中的直接人類建立、精確/過時/非執行中代理與驅動檢查、即時子代理拒絕、復原後 fork 根的權限、steering、發起者不匹配、讀取/建立/部分欄位編輯/暫停/復原行為（包括嚴格 schema 佔位值）、條件式阻塞說明、工作階段啟動邊沿後的重新啟用、權限檢查先於條件參數檢查的失敗行為、準確 Goal Round 的完成、僅自主 Round 觸發終止、已設定的阻塞閾值，以及人類立即阻塞。無金鑰重播快照把目標領域和工具掛載到真實的 headless 單次執行應用中，透過隨附迴圈與持久化棧驅動一次攜帶嚴格 schema 佔位值的 `update_goal` 探測，以及對 `create_goal` 和 `get_goal` 的呼叫，固定 stream-json transcript（文字記錄），並檢查外部持久化的目標變更。這裡有意不把 echo-agent fixture（測試前置資料）當作應用 UX 的替代品。

## 考慮過的替代方案

- **相依性提示詞指令實施權限**——不予採納，因為文字可以指導模型判斷，卻不能認證即時呼叫者、輪次或來源事件。
- **把每個目標服務動詞分別暴露為工具**——不予採納，因為緊湊的讀取/建立/更新 API 可以降低 schema 成本，並保持統一的比較並交換行為。
- **要求精確命令短語**——不予採納，因為自然語言意圖（包括英語以外的語言）應由模型解釋；執行權限取決於當前輪次中人類直接傳送的訊息，而不是拼寫。
- **根據持久的根或 fork 元資料授權**——不予採納，因為作為頂層工作階段獨立復原的 fork 應接受新的人類權限，而當前仍受所有權約束的 subagent 則不應接受。
- **允許自主 Round 編輯或復原目標**——不予採納，因為繼續執行權限比重新定義或重新啟動人類目標的權限更窄。
- **把阻塞閾值當作評估器**——不予採納，因為事件計數無法證明障礙在語義上未改變或確實不可繼續。
- **拒絕所有已提供的特定操作欄位**——不予採納，因為採用嚴格 schema 的提供方可能為每個選填欄位序列化零值佔位符；只有有實際意義的欄位值才能表示與指定操作相衝突的另一項操作。

## 後果

- 模型獲得穩定而緊湊的生命週期 API，無需直接訪問目標服務。
- 改變狀態的呼叫要求即時執行時期根 agent、當前輪次中人類直接傳送的訊息，以及持久比較並交換引用。
- 人類可以透過普通自然語言請求建立和重新啟用目標，而復原後的工作階段在收到此類輸入前保持靜止。
- Goal Round 可以完成或報告重複阻塞，但不能自行擴大任務權限。
- 部署策略選擇阻塞下限；同一個解析後的值同時控制執行與提示詞指導。
- 系統可相容採用嚴格 schema 的提供方所填入的佔位值，同時不會放行有實際意義的跨操作更新。

## 已知限制與暫緩事項

- 是否屬於重大目標、是否要求繼續、目標是否完成以及阻塞條件是否相同，仍由模型進行語義分類。獨立評估器或完成憑證予以延期。
- 這些工具會改變目標狀態，但不調度 Goal Round、不分類例外驅動停止，也不取消活躍輪次；這些行為由同工作階段驅動器負責。
- 除非另行掛載的繼續執行驅動器接納了目標來源的使用者輪次，否則 Goal Round 權限路徑處於休眠狀態；本工具包本身不會製造這種權限。
- 面向人類的斜槓命令發現與渲染由獨立的 [`dsh-command-goal`](../../../../packages/goal/command-goal/README.md) 外掛程式負責。
- 若部署沒有同時設定兩個註冊項的作用域，某個作用域可能隱藏工具註冊，卻保留獨立註冊的提示詞段。
