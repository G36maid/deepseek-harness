# Agent Note: SQLite FTS5 工作階段搜尋

Status: implemented

[English](2026-07-10-sqlite-session-query-provider.md) | [简体中文](2026-07-10-sqlite-session-query-provider.zh.md) | 繁體中文

## 問題

精確讀取的 `ctx.sessionQuery` 服務有意不維護派生索引。大規模持久化的歷史記錄需要全文搜尋，而不是每次查詢都掃描全部事件；當前的活躍工作階段則需要一個包含上次持久性檢查點之後更新的覆蓋層。搜尋還需要具體的排序、摘要片段、過濾器、分頁、取消以及重建行為。

如果把這些關注點拆分到提供方協調器和資料庫實作之間，就會產生兩個耦合的對齊狀態機。第一個實作既要暴露精簡的提供方無關呼叫約定，也要在同一個生命週期內管理源觀察、提取、SQLite 交易、代際與查詢執行。

## 決策

`@deepseek-ai/dsh-session-query` 聲明一個抽象的 `ctx.sessionQuery` 服務，其精確讀取、過濾與追蹤均有具體實作，僅有兩項全文方法為抽象方法。`searchSessions(request, exec?)` 返回按遊標分頁的 `SessionSearchHit`，每個工作階段以其中匹配度最高的事件作為命中結果；`searchEvents(request, exec?)` 返回一個邏輯工作階段內的 `SessionEventSearchHit`。兩種請求都必須提供 `query`，可以接受 `limit` 和由服務擁有的品牌化 `SessionSearchCursor`，並支持選填的中止訊號。工作階段搜尋接受 `sessionFilters` 與事件元資料過濾器，事件搜尋接受事件元資料過濾器。結果會公開有界的純文字摘要片段，但不公開提供方識別符號或數值相關性分數。單一鍵拓撲由[統一服務決策](../../archived/architecture/2026-07-23-unified-session-query-service.md)定義。

`@deepseek-ai/dsh-session-query-sqlite` 擴充介面服務，並且是 `ctx.sessionQuery` 唯一的具體所有者。它相依性即時的 `ctx.sessions`，動態觀察選填的 `ctx.sessionPersistence`，並擁有一個專用的派生 SQLite 資料庫。系統沒有搜尋提供方登錄檔、協調器、持久化事件或 agent loop（代理循環）整合。

Service Definition 包還擁有共享的第一方語義提取與提供方無關的過濾。`SessionResultFilter` 涵蓋 id、可空的 cwd、建立時間範圍、可空的父工作階段與可用性；`ctx.sessionQuery.filterSessions()` 無需 FTS 提供方即可應用這些過濾器。`SessionEventResultFilter` 涵蓋 seq/時間範圍、事件類型、surface 與字面語義文字。過濾器陣列內各項按邏輯與（AND）組合，清單值按邏輯或（OR）組合。文字子句會將呼叫方輸入轉義為不區分大小寫的 Unicode 正規表達式，其中每段連續空白都匹配一個或多個空白字元；該子句透過 `ctx.sessionQuery.filterEvents()` 提供，不會委託給 FTS 提供方。

## 搜尋語義

每個語義事件對應一份 FTS 文件，其中攜帶工作階段元資料、事件元資料、surface 分類與提取文字。除非 surface 過濾器縮小範圍，否則所有 `current`、`shadowed` 與 `log-only` 文件都會參與搜尋。元資料過濾器在排序前編譯為參數化 SQL。工作階段結果按工作階段劃分匹配文件，並保留匹配度最強的文件。

排序在持久化 FTS 表與 TEMP FTS 表之間具有確定性和可比性：先按實際 FTS5 高亮匹配區段數量降序，再按已索引文件的碼點長度升序、事件時間降序、跨工作階段範圍內的工作階段 id 升序，最後按 seq 降序排列。摘要片段使用這些實際高亮位置，移除保留標記、規範化空白，並按 Unicode 碼點限制長度。不透明遊標會綁定到服務實例、範圍、規範化後的標準請求、偏移量與相關代際。語料庫發生任何變更都會使跨工作階段遊標失效；工作階段內遊標僅在其目標源或代際發生變化時失效，因此不相關的工作階段不會使其失效。重新打開服務會建立新的服務實例，並使舊遊標失效。

查詢會先去除首尾空白並規範化內部空白，再作為一個字面 FTS5 短語整體加引號。嵌入的引號在綁定前寫成兩個，因此 `OR`、`NEAR`、引號、括號與 `*` 等 MATCH 運算子會作為資料，而不是可執行的查詢文法。系統會在 SQLite 執行前拒絕 NUL。文件中的保留高亮非字元與 NUL 會在索引前規範化，因此插入的呈現標記不會與源文字衝突。短語匹配遵循分詞器 token，而不是任意子串。

## 分詞器選擇

持久化 FTS5 表與即時 FTS5 表都使用 `unicode61`。實作實驗表明，該分詞器支持由兩個字元組成的 token `AI`，生成的索引體積約為 trigram 方案的 1/2.1。系統接受的限制是 token/短語召回：`AI` 不會匹配較長的 token `BRAID`，任意子串搜尋改用提供方無關的文字掃描。

## 提取與對齊

共享提取器會提取消息文字、推理（reasoning）、巢狀的工具呼叫/結果內容、工具名稱與參數、被阻止提示詞的原因、待辦事項狀態與內容，以及錯誤或結束狀態詳情。結構性邊界、流區塊、請求標頭、成功完成標記，以及透過聲明合併擴充的未知事件/內容變體都不會產生文件。surface 分類複用 `foldSurface()`，使搜尋與模型歷史派生保持一致。

一個序列化操作會讀取提供方無關的 `SessionPersistence` 快照清單，將每個包含源身份的不透明修訂號與同已索引工作階段一並存儲的修訂號比較，只載入新增或變更的日誌，在一個事務中對齊各行，然後執行查詢。它將呼叫方傳入的原始中止訊號傳給快照清單查詢和不會修改狀態的檢查，直接等待每個已啟動的後端操作，並在每次等待結束後、啟動更多工作之前檢查取消狀態。因此，即使後端忽略該訊號，取消也只會在活躍的後端工作完全靜止後才拒絕，不會啟動後續觀察或對齊步驟；後續搜尋仍會序列等待清理完成。它絕不會呼叫後端會修改狀態的 `load()` 來處理當前由 `ctx.sessions` 擁有的 id；TEMP 覆蓋層會記錄持久化可用性，即時所有者分離後，持久化基礎層隨之刷新。修訂號同時標識其底層持久化儲存與後端本機日誌修訂版本，因此針對同一儲存重新打開服務可以複用已索引行，而切換到獨立儲存時不會因工作階段 id 與本機計數器相同而發生衝突。如果載入期間清單發生變化，系統會重複觀察；因此，會修改狀態的載入修復所產生的新修訂號會在提交前納入結果。重複查詢與針對未變更儲存的重新打開都不會載入完整的持久化日誌。新增、變更與刪除的工作階段會在下一次穩定搜尋中更新。源讀取或提取失敗時，不能將相應行標記為最新狀態，交易失敗則會回滾，使後續搜尋能夠重試。

持久化文件在重新啟動後仍然存在。即時工作階段使用連線本機的 TEMP 表，遮蔽相同 id 的持久化基礎行，並在即時所有者分離時重新顯露該基礎行。關閉資料庫會刪除即時行。解除安裝持久化服務會隱藏持久化行，但不會把缺失視為權威刪除；重新掛載後，系統會再次觀察並對齊後端。即時工作階段頭與持久化工作階段頭的不可變欄位發生衝突時，系統會失敗，而不會合並兩個來源。

派生 schema 擁有獨立的 application id 與單調遞增的 schema 版本。持久化與 TEMP 工作階段元資料均遵循 `SessionHeader.createdAt` 的整數約定，將其存入嚴格的 `INTEGER` 列。系統識別到不相容版本時，只會重設該派生資料庫。如果資料庫具有不屬於本應用的 application id 或無法識別的使用者表，系統會在修改日誌模式前拒絕該資料庫，防止意外設定的規範工作階段資料庫遭到修改。在 POSIX 檔案系統上，缺失的目錄與資料庫文件會以僅所有者可訪問的權限建立，使新的 SQLite 伴隨檔案沿用該模式；現有權限模式保持不變。一個行程中的一個服務獨佔一條派生索引路徑；代際與即時 TEMP 遮蔽狀態都歸連線所有，因此不支持跨行程寫入方。

取消會使排隊中的操作及時被拒絕。非同步源觀察一旦開始，呼叫方必須等待該後端 Promise 結帳後才會收到拒絕；系統不會提交已中止的觀察結果，也不會啟動更多源觀察或索引工作。Node 的同步 `DatabaseSync` 元資料與 MATCH 呼叫一旦開始在 JavaScript 執行緒上執行就無法中斷，因此服務會在這些呼叫前後檢查訊號，但不承諾在語句執行期間搶佔。

## 曾考慮的替代方案

- **將 FTS 表新增到規範持久化資料庫**：不予採納，因為可重建索引不應與權威日誌共享 schema、重設邊界或故障邊界。
- **新增第一階段的提供方登錄檔與協調器**：不予採納，因為單一實作無法證明註冊語義，並且會將一個對齊生命週期拆給兩個所有者。
- **立即持久化即時覆蓋層**：不予採納，因為在現有檢查點提交前，即時事件並非規範資料。
- **使用 FTS5 trigram 分詞器**：不予採納，因為它會遺漏短於三個字元的有用查詢，並且測得的索引體積約為 `unicode61` 的 2.1 倍；掃描路徑仍可提供字面子串過濾。
- **在每個表中獨立使用 FTS5 BM25**：不予採納，因為填充內容不同的持久化語料庫與 TEMP 語料庫所產生的分數不可比較；實際匹配區段與文件長度採用同一套尺度。

## 後果

搜尋只公開精簡的提供方無關 API，而唯一後端負責派生索引的全部狀態轉換。獨立資料庫增加了設定與查詢前的輕量快照讀取，但索引損壞、重設與分詞器變更都不會危及規範日誌。持久化修訂號使未變更工作階段無需讀取或重寫完整日誌；TEMP 即時覆蓋層保留當前工作階段事實，同時不會讓尚未經過檢查點的事件具有持久性。

選定的分詞器以較小的索引體積支持短 token，但不承諾子串召回。字面短語使查詢文法安全且可預測，代價是不支持布林表達式或完整 MATCH 表達式。取消在操作排隊期間會及時生效，在等待資料源期間則會等待其完全靜止；同步 SQLite 執行仍是不可搶佔區段。

單元測試將以下行為固化為約定：提取、過濾器、兩種搜尋範圍、所有默認 surface、先過濾元資料再排序、摘要片段、字面量轉義、確定性平局處理、完整分頁、按範圍的遊標失效、動態掛載/解除安裝持久化服務、重新啟動對齊、即時遮蔽、顯露與重新打開、schema 安全、回滾重試，以及排隊中或進行中的資料源等待取消。一個無需金鑰的真實 Loader 路徑測試會將該包與真實的 SQLite 持久化後端組合使用。
