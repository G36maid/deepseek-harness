# Agent Note: 工作區上下文指令文件

Status: implemented

[English](2026-06-24-workspace-context.md) | [简体中文](2026-06-24-workspace-context.zh.md) | 繁體中文

## 問題

`AGENTS.md` 等倉庫指引應當進入編碼工作階段的有效上下文，使項目約定、建置命令和評審規則無需由使用者反覆貼上即可生效。stdio 與 ACP（Agent Client Protocol）產品需要具備相同行為，並按工作階段 cwd 隔離：全域性系統提示詞章節會把一個工作區的文件洩漏到另一個仍在執行的 ACP 工作階段中。

相鄰產品形成了值得借鑑的約定，但具體做法各不相同。Codex 原生使用 `AGENTS.md`；Claude Code 使用 `CLAUDE.md`，並採用熟悉的 system-reminder 風格使用者上下文；opencode 同時支持這兩個名稱，每個目錄只選一個勝出者，並延遲發現巢狀文件。harness 需要跨工具相容，同時避免從同一作用域載入重複或互相矛盾的文件。

生命週期中有兩類截然不同的內容。初始適用文件鏈在第一次請求前一次性注入。巢狀文件、編輯、候選項切換和移除發生在其後，進入同一份持久的僅附加歷史。

## 決策

該實作在 `packages/context/agent-instructions` 中，包名為 `@deepseek-ai/dsh-agent-instructions`。它是請求上下文擴充，不是核心服務或檔案系統後端。共享 demo 主幹與 Host Runtime 根據顯式的 `{ maxBytes } | false` 部署選擇掛載它；`dsh web` 啟用 65,536 位元組預算，Host Runtime 的 headless 消費端則停用它。該外掛程式使用 `agent/pre-step`、不可變的 `tools/result` 結果、`session/event` 邊界和選填的 `ctx.fs` 功能。

外掛程式不會靜態注入 `fs`。因此，不帶提供方的產品樹仍能正常啟動；在檔案系統提供方出現之前，外掛程式保持無操作。所有生產讀取都透過該提供方完成。候選項探測會解析每個路徑並對結果執行 stat，因此會跟隨最終路徑元件的符號連結至其目標：指向普通文件的連結會被載入，缺失路徑或非文件目標則確認為不存在。允許倉庫擁有的連結跨越信任邊界，是對最初不跟隨探測方式的刻意反轉；[跟隨指令符號連結記錄](2026-07-21-follow-instruction-symlinks.md)負責說明該決策及其殘餘風險。步驟訊號與動態工具執行訊號會貫穿解析、元資料探測和流式讀取，因此取消不會等待無關的檔案系統掃描。解析或 stat 例外歸類為不可用：它只跳過該候選項，絕不被解釋為已經載入的作用域被刪除。

### 檔名與優先級

默認的逐目錄候選清單是 `['AGENTS.md', 'CLAUDE.md']`。該清單可透過 `instructionFileCandidates` 設定；`AGENTS.md` 是普通的第一候選項，而不是隱藏優先級。一個目錄中只載入第一個存在的普通文件候選項。使用預設值時，`AGENTS.md` 是原生文件，`CLAUDE.md` 是相容性回退。第二個清單 `localInstructionFileCandidates`（預設為 `['AGENTS.local.md', 'CLAUDE.local.md']`）會在同一目錄的基礎文件後加載疊加式本機覆蓋層；[默認本機覆蓋層記錄](2026-07-21-local-instruction-overlay.md)負責說明該決策。

候選條目必須是同一目錄中的檔名。空條目、`.`／`..`，以及包含 `/` 或 `\` 的條目會被忽略。其他同目錄名稱可以顯式選擇加入；規則目錄和匯入語義不屬於本約定。

使用者全域性文件固定為 `$DSH_HOME/AGENTS.md`，不受任一候選清單影響，也沒有本機覆蓋層。`$DSH_HOME` 預設為 `~/.dsh`，與 `~/.codex` 或 `~/.claude` 在 harness 層的 home 角色一致，而不會引入外掛程式專用 home。波浪號展開與預設值位於 `dsh-home-paths` 中，以便未來的 harness 功能共享同一約定。

### 基線注入

在 agent loop（代理循環）實例的第一個 `agent/pre-step`，外掛程式會組合一條帶來源的 user 角色基線。當下游決策讓非空的第一步批次進入時，外掛程式會將基線折入最終批次、緊隨已領取的直接提示詞之後，使其與直接提示詞一同成為持久記錄並抵達第一次請求。reject 或空的第一步決策會將基線留在 next-step inbox，等待後續喚醒。外掛程式先載入使用者全域性文件，再從 `agent.session.header.cwd` 向上遍歷至設定的根標記（預設為 `.git`）以確定項目根目錄，隨後從根目錄至 cwd 的每級目錄載入已設定候選項。`.git` 文件與 `.git` 目錄都是有效標記，因而能覆蓋連結 worktree 和 submodule。找不到標記時，cwd 本身就是根目錄。

該基線會成為一條持久 `user/message`，並攜帶帶類型的 `agent-instructions` 來源。其 `baseline: true` 標記將完整基線與後續增量區分開來，`baselineIdentity` 記錄規範化的發現、優先級、項目根目錄和預算語義，變更清單則持久保存已納入的作用域和內容 digest。若先前排隊的 workspace 基線仍在等待，外掛程式會刪除該確切訊息並 prepend 替代值，而不會累積副本。

復原 agent 會基於持久化歷史建立新的 loop 實例。在第一個 `agent/pre-step`，具有當前標識的可見基線仍是權威狀態；外掛程式會將其保留的 scope 與當前完整渲染進行比較。未變化和被預算省略的文件不追加任何內容；agent 離線期間新增、編輯、移除或不再屬於預算保留集的文件，會在進入步驟的批次中追加 `set`、`replace` 或 `remove` 轉換，既不改寫也不重複原始基線。不相容的可見基線會被一條按當前優先級排列的完整基線取代，並以明確措辭說明替換關係；如果當前不存在任何候選文件，一條顯式空基線會清除先前的 scope。外掛程式熱重掛遵循相同規則。如果壓縮（compaction）已遮蔽帶類型的基線，下一次進入步驟的 pre-step 會組合一條完整的當前基線，並在同一請求中攜帶它。

基線是一條 user 角色的 `<system-reminder>`，包含 `Instructions from: <path>` 章節，以及明確的權威性與優先級說明。這種熟悉的模型可見框架避免引入 harness 專用的 XML 詞彙。項目路徑相對於根目錄；使用默認 home 時，使用者全域性路徑為 `~/.dsh/AGENTS.md`，使用已設定 home 時則為 `$DSH_HOME/AGENTS.md`。最終渲染邊界會在完成位元組覈算前，轉義指令內容或模型可見的路徑、scope 與預算元資料中出現的字面量 `</system-reminder>`。包 README 負責規定當前準確的[提示詞形態](../../../../packages/context/agent-instructions/README.md#prompt-shape)。

### 動態發現與刷新

第一方 `read`、`write` 或 `edit` 呼叫成功後，不可變的 `tools/result` 觀察器會協調被觸及的後代路徑鏈，以及該工作階段已經知道的每個作用域，然後在 agent inbox 中排入一條 `Additional instructions from: <path>` system-reminder，供下一次請求使用。在 Code Mode 下，成功的子分派 touch 會沿不透明的父級執行 token 逐層上浮，直到頂層結果落定。在 agent loop 步驟內產生的 touch，須等持久 `step/end` 後才開始非同步投影；打開的步驟之外直接執行工具時，則立即投影。這兩個邊界在不讓工具管線等待檔案系統發現的前提下，保證結果／步驟的相鄰關係具有確定性。

內容編輯會追加 `Updated instructions from: <path>`，說明新內容取代先前內容，並包含當前的完整文件。如果優先級從一個候選項變為另一個，訊息還會指出先前路徑並說明它不再適用。如果沒有候選項保留，外掛程式會追加 `Instructions removed: <path>`，並說明先前載入的指令不再適用。

基線訊息和動態訊息都在 `content` 中攜帶完整的 system-reminder 框架；每條帶來源的 `user/message` 都逐字抵達模型，核心層不會再新增選填擇退出的包裝。帶類型的 `agent-instructions` 來源攜帶持久化狀態，該狀態絕不會渲染給模型。

shell 命令不會觸發發現。本機 bash 呼叫會啟動全新的 shell，而從任意命令字串推斷已到達路徑，需要實作提示詞外掛程式並不擁有的 shell 語義。

### 重複抑制與變更偵測

每個工作區上下文事件都會儲存帶版本的元資料，其形態為 `{ action, scope, path, digest? }`；`digest` 是對已載入內容計算的 SHA-1。完整基線還會額外攜帶 `baseline: true` 和 `baselineIdentity`。模型可見提示詞中沒有 HTML 註釋、隱藏標記，也沒有會被解析回狀態的標題。

協調時，外掛程式掃描帶工作區來源的 `user/message` 事件，並派生每個可見作用域的最新狀態。即使後續複合結果被攔截，成功的巢狀 touch 也會聚合到父級執行 token 下；頂層結果會將它們交給打開的工作階段步驟，或直接交給逐 agent 投影佇列。`step/end` 只會在自身邊界持久化後釋放其暫存的 touch；下一次 `agent/pre-step` 會等待序列投影完成。每次投影都會根據可見歷史和當前 inbox 進行組合，並替換唯一一條待處理工作區上下文，而不會累積中間渲染結果。

路徑和 digest 均未變化時會被抑制。日誌中的移除操作是一條墓碑記錄，因此重新出現的候選項會成為新的 `set`。復原操作從持久化元資料繼續工作：相容的可見基線會提供比較狀態，而不會導致再次追加完整基線。如果壓縮從可見表面移除某條指令事件，該狀態不再抑制後續載入，這與模型已經無法看見它的事實一致。變更只有在對應文件專屬段落保留至少一個內容位元組，或原始內容確實為空時，才會進入元資料或待處理狀態。只要任一內容位元組保留下來，部分截斷就會提交完整內容 digest；截斷到零內容仍可在後續觸碰中處理。基線可以保留位元組預算診斷而不提交任何變更。動態批次若沒有可提交變更，則整批不注入，並在後續觸碰中重試。被省略的文件仍可在之後的觸碰中載入。

只有當初始基線事件仍在可見工作階段表層中時，其類型化變更才用作比較狀態。復原會保留相容的基線，並對帳當前基線和可見的動態 scope，因此 agent 離線期間的變更會在第一次復原請求前追加為轉換。當壓縮遮蔽基線事件時，下一次進入步驟的 pre-step 會組合完整的當前基線，並在同一請求中記錄它；也可以改由一次成功的檔案系統觸碰重新新增未變化的基線 scope，或把基線編輯或移除操作追加為動態訊息。兩條路徑都不會重寫原始事件。記憶體中的 scope 標記和提供方版本 cache 只用於選擇探測對象並加速探測，因此二者都不能抑制模型已無法看見的上下文。

系統刻意不使用文件監視器。偵測發生在下一次成功的結構化檔案系統觸碰、復原時的基線對帳，或進入步驟的 pre-step 復原被遮蔽的基線時。提供方失敗不會產生移除；只有該作用域中的全部已設定候選項都成功完成探測後，系統才接受「不存在」這一結論。

### 位元組預算與有界讀取

`maxBytes` 是必填項，分別作用於渲染後的基線或單個動態協調批次；系統不存在隱式或無界的渲染預算。非正數或非有限值會停用載入。內容超過預算時，系統會先省略較寬泛的文件，再截斷最具體的文件。可見的 `Workspace instruction budget ...` 提示會指出被省略和截斷的路徑與位元組數，並且輸出絕不超過設定位元組數。

`maxSourceBytes` 是正數的逐文件上限，預設為 1 MiB。loader 會在學取前檢查報告的大小，同時仍透過 `streamText()` 消費內容並持續統計 UTF-8 位元組數，因此缺失／過時的元資料無法迫使其進行無界分配。過大的勝出候選項會被視為不可用，而不是改為同目錄中的下一個名稱。外掛程式刻意不保留行程級快取，也絕不保留指令正文。它只為每個有效作用域保存 `{ path, version, digest }`，並將這些狀態放在 `WeakMap<Session, Map<scope, state>>` 中：提供方 `FsVersion` 與有效提示詞狀態同時匹配時跳過讀取；版本變化則觸發有界讀取和 SHA-1 確認。SHA-1 仍是持久化在可見結構化元資料中的跨提供方內容標識；提供方版本只作為記憶體中的失效快速路徑。動態快取轉換發生在序列投影組合唯一一條目標 inbox 上下文時；下一次 pre-step 會等待該投影完成，再決定哪些內容進入請求。

## 考慮過的替代方案

**使用全域性 `ctx.systemPrompt.section()`。** 不予採納，因為同一個 Cordis 上下文可以承載 cwd 不同的多個工作階段，而倉庫自身擁有的文字屬於低權威使用者上下文，不是最高權威的提供方系統內容。

**始終把準備好的 workspace 上下文留在 inbox 中。** 不予採納，因為在 pre-step 中準備的上下文會因此在當前請求結束後繼續留存，並自行啟動第二個模型步驟。inbox 仍作為暫存區以及 reject 時的後備，而進入步驟的 pre-step 負責隨最終批次原子投遞。

**在一個目錄中同時載入 `AGENTS.md` 和 `CLAUDE.md`。** 不予採納，因為正在遷移的倉庫通常會在兩個文件中重複指引。按順序排列的候選項讓優先級顯式且可設定。

**解析渲染後的標題或隱藏註釋以復原已載入狀態。** 不予採納，因為指令正文可能包含相同文字，導致無提示的誤報。持久化 JSON 元資料提供明確且對模型不可見的狀態通道。

**使用模型總結文件。** 不予採納，因為指令文件本身已經是經過整理的摘要；再執行一次模型呼叫既不確定，也可能抹掉邊界情況要求。使用帶位元組預算的確定性全文更簡單。

## 後果

工作區指引按工作階段隔離，並由 demo 入口、Web Host 與每一種工具展示模式共享。初始、巢狀與變更指令都保持持久且可重播。通用的工作階段／agent 上下文約定透過先在 inbox 中暫存、再持久進入的 user 訊息攜帶帶類型的來源資料，而不會把條目展平。

倉庫文字仍是不受信任的輸入。低權威 user 角色框架、顯式優先級說明和分隔符轉義可以降低風險，但無法消除提示詞注入。跟隨候選符號連結到目標，會把該攻擊面擴大至樹外內容；因此，把 `ctx.fs` 限制在可信根目錄內的權限與沙盒層纔是真正的邊界，它們讓系統把工作區文件當作資料而不是權威（[跟隨指令符號連結記錄](2026-07-21-follow-instruction-symlinks.md)負責說明殘餘風險）。

系統由事件驅動，而不是文件監視器驅動程式。除非檔案系統變更透過結構化工具完成，否則編輯不會在確切的檔案系統變更時刻可見；外部文件變更會在下一次成功的結構化觸碰、復原對帳，或復原被遮蔽的基線時被發現。這使設計保持確定性並且與提供方無關。

## 延後事項

從 bash 派生路徑報告、遞迴啟動掃描、文件監視器、小寫默認名稱、`.claude/CLAUDE.md`、`.claude/rules/*.md`、匯入指令、ACP `additionalDirectories`、信任確認和模型生成摘要均延後處理。項目目錄中的 `.local.` 覆蓋層現已默認載入（[默認本機覆蓋層記錄](2026-07-21-local-instruction-overlay.md)負責說明該決策）；使用者全域性覆蓋層、目錄規則系統和匯入仍需要各自的優先級與信任設計。
