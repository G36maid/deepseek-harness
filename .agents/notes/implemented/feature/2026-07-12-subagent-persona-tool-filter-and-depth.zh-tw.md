# Agent Note: 設定 subagent 的人設、工具可見性與深度

Status: implemented

[English](2026-07-12-subagent-persona-tool-filter-and-depth.md) | [简体中文](2026-07-12-subagent-persona-tool-filter-and-depth.zh.md) | 繁體中文

## 問題

一個可複用的 subagent 提供方解決的是「如何執行子 agent（代理）」的問題，但不同的委派工具需要不同的子 agent 行為。某個部署可能需要評審者人設、僅限研究的工具集，或硬性遞迴上限，而不必為每種組合建立新的提供方。

這些控制影響子 agent 的第一次模型請求，因此不能在子 agent 可見之後再安裝。它們還需要提供方的誠實支持：ACP（Agent Client Protocol）後端不能默默接受一個僅限行程內的工具過濾器，而過濾器在所有外掛程式執行於同一可信行程的情況下也不應被描述為安全邊界。

## 決策

subagent 啟動有三個獨立的組合控制：`persona`、`toolFilter` 和 `maxDepth`。提供方聲明對每個控制的支持情況，服務在啟動執行之前拒絕不受支持的請求，行程內提供方在子 agent 尚未發布時安裝所請求的組合。

這些控制回答不同的問題：

| 控制 | 問題 | 結果 |
|---|---|---|
| `persona` | 什麼角色指令替換該子 agent 的部署人設？ | 一個子 agent 區域性的提示詞段落遮蔽 `deployment:persona` |
| `toolFilter` | 部署全域性工具中哪些進入該子 agent 的可見工具檢視表？ | 一個有作用域的限制在新增子 agent 區域性工具之前過濾全域性工具 |
| `maxDepth` | 這棵委派樹最深可以長到多少層？ | 子 agent 深度超過絕對上限時，啟動請求被拒絕 |

`dsh-tool-subagent` 將這些控制作為外掛程式設定暴露，並複製到它建立的每個請求中。直接呼叫 `SubagentRuntime` 的呼叫方可以按請求選擇這些控制。提供方的能力描述符仍然是後端能否兌現各欄位的真源。

### 人設是有作用域的遮蔽

人設控制改變一個子 agent 的行為，而不改變部署級的提示詞組裝。在未發布的設定階段，行程內提供方在子 agent 作用域中註冊一個名為 `deployment:persona` 的段落；普通的最具體者優先解析規則僅在該子 agent 的組裝中替換全域性段落。

其值與部署人設具有相同的嚴格範本語義。省略時透過全域性層繼承部署段落；顯式空字串則以空段落遮蔽全域性人設。父級和兄弟級的人設永遠不會進入子 agent 的扁平作用域。

這使用的是常規的系統提示詞註冊機制，而非第二條人設通道。因此第一次提示詞看到的命名貢獻與後續提示詞和提示詞檢查工具看到的一致。

### 工具過濾是一條作用於即時全域性檢視表的規則

工具過濾同時控制能力可見性和可執行尋找。行程內提供方在發布前於子 agent 作用域中安裝 `ToolRuntime.restrict()`，登錄檔的單一解析器對協定格式（wire format）的工具 schema、尋找、執行和 Code Mode SDK 生成施加相同的結果。獨立註冊的系統提示詞段落不在 `ToolRuntime` 內，因此過濾一個工具不會移除該外掛程式的獨立指導文字。

解析遵循以下規則：

1. 每條限制對活躍的部署全域性工具登錄檔先應用 `allow` 再應用 `deny`。
2. 多條限制取交集，因此一個全域性工具必須得到每條已安裝限制的放行。
3. 子 agent 作用域的工具在全域性過濾之後新增，可以遮蔽一個已放行的全域性工具。
4. 保留的 `run_code` 呈現和其他作用域區域性的協議貢獻不受全域性過濾器影響。

當過濾器既未提供 `allow` 也未提供 `deny`，或命名了當前全域性可限制集合之外的內容（包括僅存在於區域性作用域的名稱或保留名稱）時，設定會顯式失敗。`allow: []` 合法，且有意隱藏所有全域性工具。這些檢查能捕獲拼寫錯誤，並防止設定在無法影響所命名條目時看起來仍然有效。

全域性登錄檔保持活躍。僅 deny 的過濾器會放行後來註冊的全域性名稱（除非顯式 deny 該名稱）；allow 清單會排除後來註冊的全域性名稱（除非顯式 allow 該名稱）。移除一個全域性工具會將其從所有已解析檢視表中移除。這些語義在保持熱註冊的同時，使 allow 與 deny 的區別顯式化。

### 深度是絕對的樹上限

深度限制獨立於工具可見性來約束遞迴委派。頂層 agent 深度為零；行程內子 agent 的深度為其父級已驗證深度加一。`maxDepth` 是一個絕對的非負安全整數，當推匯出的子 agent 深度大於上限時，啟動在子 agent 所有權開始之前即被拒絕。

有效父級深度取持久 `SessionHeader.delegationDepth` 與執行時期 `AgentOptions.subagentDepth` 中的較大值。行程內子 agent 把推匯出的深度記錄在工作階段 header 中，復原時會重新載入該 header，因此重新啟動無法降低遞迴計數。

每個公開入口都自行驗證值域，而非相依性單一的面向模型設定路徑。負值、小數、負零、非有限值、不安全整數、格式錯誤的儲存父級深度以及推導溢位均被拒絕。直接的 `SubagentStartRequest` 可以省略上限，讓此機制不約束深度；經 loader 解析的 `dsh-tool-subagent` 設定則預設值為 `3`、接受數值覆蓋，並使用顯式的 `'provider-managed'` 來省略由行程外提供方部署擁有遞迴預算時的上限。三是一個較小的有限預設值，仍允許 root 加三代後代：[JSON-RPC 示例](../../../../examples/jsonrpc-agent/cordis.yml)採用這項通用策略，而 ACP 與 headless 示例固定為一。提供方缺少 `depthLimit` 時，數值工具上限會在提供方掛載階段失敗。

部署可以組合深度與過濾，但數值上限不會合成過濾器。委派工具在上限處仍然可見，因為授權可能相依性執行時期狀態；每次嘗試啟動都會檢查呼叫方 agent 當前的持久與執行時期深度，被拒絕的啟動返回錯誤工具結果，且不發布子 agent。可見性策略固定的部署可以另外在子 agent 中 deny 委派工具。兩種選擇都不改變提供方的對話歷史行為。

### 能力門控保持提供方誠實

能力將請求的功能與提供方實作分離。`SubagentCapabilities` 聲明 `persona`、`toolFilter` 和 `depthLimit`；`SubagentRuntime.start()` 在呼叫提供方之前，對照這些標志檢查請求中每個存在的欄位。

這使 spawn 和 fork 提供方可以共享行程內實作，而外部提供方只聲明自己能強制執行的部分。請求永遠不會靜默降級：選擇不受支持的控制會產生 `UNSUPPORTED_CAPABILITY`，不會有執行或生命週期事件存在。

### 未發布設定使第一次請求正確

所有子 agent 區域性的組合在子 agent 變得可觀察之前完成。行程內提供方向 agent 建立提供一個設定回呼；該回調在子 agent 作用域中安裝人設、工具限制和結構化輸出貢獻。只有設定成功後，建立才發布工作階段和 agent 並允許驅動器啟動。

設定失敗會回滾私有子 agent。沒有觀察者能取得到一個「第一次提示詞使用了部署人設或未過濾工具集、後續提示詞才使用所請求設定」的子 agent。

## 可見性不是授權

這些控制組合的是同一可信行程內的行為，而非授權行為。`toolFilter` 改變工具登錄檔解析出的子 agent 檢視表，但它不建立父到子的授權格，不要求子 agent 僅持有父層子集授權，不沙盒化外掛程式，也不阻止持有另一個 Cordis 上下文的程式碼直接呼叫服務。

具體而言，子 agent 區域性工具在全域性過濾之後新增，可能不在父級檢視表中。僅 deny 的子 agent 也能看到 deny 清單未命名的後來全域性工具。這些是有意的動態組合語義，並不構成非升權保證。

安全設計需要獨立的授權表示、傳播規則和執行時強制點。建立時的授權快照、父層子集授權、顯式的未來授權 API，以及通用的能力、輸出、終止標籤均不在本功能範圍內。

## 曾考慮的替代方案

**為每種人設或工具集建立一個提供方。** 這會使共享相同傳輸和生命週期實作的提供方成倍增加，使動態部署設定變得笨拙，且仍需要遞迴機制。提供方的職責是執行傳輸；請求承載每個子 agent 的組合。

**複製父級的完整工具檢視表。** 註冊作用域設計上是扁平的，生命週期所有權不意味著可見性繼承。複製已解析檢視表還會凍結動態全域性註冊，並在未完整定義任一約定的情況下混淆組合與授權。

**在子 agent 建立時快照允許的全域性工具。** 凍結的 allow 集合使未來註冊統一不可用，但它改變了熱註冊語義並開啟了授權設計。已實作的過濾器保持為活躍的登錄檔謂詞，並直接記錄 allow 與 deny 的行為。

**僅隱藏工具 schema。** 僅呈現層的過濾讓模型可以透過 Code Mode 或偽造呼叫執行一個提示詞聲稱不存在的工具。改為由一個解析器同時管控呈現和執行。

**把深度上限編碼為自動工具過濾器。** 建立時過濾器會快照一個可能相依性執行時期狀態的決策，隻影響一個已設定工具名，且不保護直接服務呼叫方或替代委派工具。提供方改為在每次啟動時強制絕對上限。

## 後果

貢獻者可以設定子 agent 的角色、可見全域性工具和遞迴深度，而無需定義新的提供方。能力檢查在所有權開始之前失敗，未發布設定使第一次請求一致，單一工具解析器防止呈現/執行漂移。

代價是部署方必須理解活躍的 allow/deny 行為以及可見性與授權的區別。當前深度策略禁止再建立子 agent 後，模型仍可能呼叫可見的委派工具並收到錯誤。提供方作者必須準確聲明每個受支持的控制，行程內提供方必須在發布前安裝所有請求的貢獻。這些控制有意不解決安全隔離或父到子的非升權問題。
