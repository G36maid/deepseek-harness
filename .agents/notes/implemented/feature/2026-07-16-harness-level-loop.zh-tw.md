# Agent Note: Harness 層目標式執行

Status: implemented

[English](2026-07-16-harness-level-loop.md) | [简体中文](2026-07-16-harness-level-loop.zh.md) | 繁體中文

## 問題

具體 agent loop（代理循環）只擁有一個輪次：它排空已接納輸入，執行一個或多個模型與工具步驟，然後停止。大型目標通常需要一項外層策略來開始另一個輪次、保留進度、在達到預算上限時停止，並讓人類能夠理解其狀態。定時提示詞、同工作階段續行和全新 agent Ralph 嘗試都會重複工作，但它們並不共享相同的狀態、權限、記憶或生命週期。

若把每種重複動作都稱為一個通用「loop」，就會掩蓋這些差異。同工作階段工作必須在現有 transcript（文字記錄）中持久化人類目標，同時保留對話上下文。Ralph 工作必須有意丟棄對話上下文，只使用工作區和一份有界交接。面向人類的狀態不能暗示重新打開工作階段就會靜默授權更多工作。完成與阻塞聲明也需要顯式信任邊界，而不能被偷渡進調度器抽象。

因此，本倉庫需要位於輪次/步驟 loop 之上的目標式執行，但不需要一個把持久化、評估、預算、調度、交接、背景工作和 UI 組合在一起的推測性通用 loop 服務。

## 決策

建置在現有 seam 之上的兩項顯式外掛程式策略：

1. **同工作階段目標**在當前工作階段中保留一個持久目標，並且只在即時啟用態已啟用時接納帶目標歸屬的續行輪次。
2. **全新 agent Ralph 執行**執行一個固定前臺工作流程，其中每個 Round 都生成一個不帶對話種子的全新結構化子 agent。

系統中沒有 `packages/loop/` 包族、`LoopDriver`、`LoopId`、通用 `StopCondition` 或面向模型的通用 `loop` 工具。兩項策略共享本倉庫普通的 agent、工作階段、工具、工作流程、subagent 與 UI 擴充點，但不會假裝一種生命週期可以同時適配兩者。

### 詞彙與策略邊界

同工作階段層級是 **Goal → Goal Round → 輪次 → 步驟**。一個 Goal Round 是為當前目標接納的一次續行週期，並實體化為一個帶目標來源的輪次。同一工作階段中的人類輪次或無關輪次不會消耗 Goal Round 上限，而一個輪次仍可包含多個模型/工具步驟。

全新 agent 層級是 **Ralph Run → Ralph Round → 全新子 agent 輪次 → 步驟**。一個 Ralph Round 建立一個子工作階段。父 transcript 和此前子 transcript 都不是種子上下文；共享工作區與一份有界結構化報告承載跨 Round 狀態。

因此，「Round」是外層策略迭代，不是每個工作階段輪次的同義詞。具體 `dsh-agent-loop` 仍是輪次/步驟引擎。同工作階段驅動器使用公開 agent 與工作階段事件；它對核心唯一的新增項是通用的取消前觀察通知 `agent/cancel-requested`，任何需要安全收斂取消的生命週期策略都可以使用它。

基於時間的 `/loop` 或定時執行是第三種策略，本決策不實作它。它應歸屬於調度器，而不是任一目標包族。

### 持久目標狀態與即時權限

一個工作階段至多有一個當前目標。每次變更都透過持久的 `goal/change` 事件提交；該事件攜帶帶版本的完整快照或帶修訂號的清除墓碑，收件箱狀態不參與其中。工作階段日誌是唯一持久真源，因此普通持久化、復原與 `SessionStore.fork()` 會攜帶目標，無需第二個資料庫或人為取消記錄。

持久階段只有 `active`、`paused`、`blocked` 與 `complete`。阻塞目標必須攜帶 `GoalBlockReason`，其中包含穩定的小寫 kebab-case `code` 與非空的人類可讀 `message`；用量限制、Round 耗盡、模型失敗與策略拒絕都是原因程式碼，而不是額外生命週期階段。獨立啟用態是 `armed` 或 `disarmed`，且永不持久化。建立與顯式復原會啟用目標；停止轉換、工作階段啟動、fork 重播、驅動器替換和驅動器拆卸都會讓目標保持未啟用。

這種分離讓工作階段復原可觀察且符合直覺。重新打開工作階段絕不會自行開始目標工作。隨後的人類提示詞，例如「繼續」、「復原目標」或任何語言中的等價請求，會給執行時期根 agent 的模型一個新輪次；模型可在其中讀取目標並呼叫 `update_goal(..., action: 'resume')`。`/goal resume` 是直接人類命令路徑。執行時期認證請求來自即時直接人類輪次；提示策略讓模型解釋措辭在語義上是否授權建立或復原。

fork 工作階段會繼承持久目標前綴，因為這是自然的重放結果。fork 從未啟用狀態開始，因此繼承不等於執行權限，歷史中也不會插入合成目標取消。

`defaultMaxGoalRounds` 可設定且預設為 `256`。該上限只計算已接納的 Goal Round。`blockedAfterConsecutiveRounds` 在模型工具策略中單獨設定且預設為 `3`；它只是在自治 Round 報告重複阻塞前的機械下限，不是對語義相同性的評估器。

### 同工作階段續行

Goal Round 驅動器為每個特定的即時 agent 至多擁有一個待定預留。只有目標處於活躍且已啟用狀態、agent 空閒、不存在競爭性人類工作、最新變更已經透過持久性檢查點、確切的目標 id／修訂號／Round 仍匹配，並且下游步驟前策略接受時，它才會接納預留。其 `agent/pre-step` 圍欄會在下游監聽器前後檢查這些事實，防止編輯、暫停、人類訊息或解除安裝競爭接納過時工作。

只有已接納、Round 為正數且帶目標來源的 `user/message` 會計入一個 Round。過時預留會結束一個阻塞的零步驟輪次，不會消耗上限。並行目標修訂會勝過舊 Round 的結帳。

普通輪次完成後，只有目標仍活躍、已啟用且低於上限時才會安排另一個 Round。取消會暫停。速率限制或配額耗盡以程式碼 `usage-limited` 阻塞；上限耗盡使用 `round-limit`；佇列失敗使用 `queue-failed`；輪次錯誤、max-token 停止、策略拒絕與未知終止結果使用各自對應的阻塞程式碼。獨立組合的請求復原外掛程式可以在同一個輪次內重試暫時性提供方失敗；目標驅動器絕不會在例外終止結果後憑空發起另一個 Round。人類隨後可以透過普通語言或 `/goal resume` 授權復原。

### 人類與模型互動

人類 UX 遵循 [OpenAI Codex 在提交 `678157a` 時的公開 TUI 分發器](https://github.com/openai/codex/blob/678157acaa819d5510adfe359abb5d0392cfe461/codex-rs/tui/src/chatwidget/slash_dispatch.rs#L750-L805)中的緊湊形態：`/goal` 顯示狀態，`/goal <objective>` 建立目標，而 `edit`、`pause`、`resume` 或 `clear` 執行直接生命週期操作。該提交永久連結讓研究所得文法在 Codex 演進時仍可驗證。狀態包含持久階段、已接納/上限 Round 數以及即時已啟用/未啟用狀態。直接狀態與命令輸出不會進入模型歷史；已接受領域變更仍可重建，因為目標服務會記錄它們。

模型只接收 `get_goal`、`create_goal` 和 `update_goal`。當直接人類請求清楚要求大量多 Round 工作時，模型可以建立目標，並且可以從任何語言推斷該意圖。它不得把日常單輪次工作變成目標。程式碼要求當前即時根 agent 輪次中有一條人類直接傳送的訊息；語義解釋仍是模型判斷。自治目標 Round 可以為確切的當前 Goal Round 報告 `complete` 或 `blocked`，但不能編輯、暫停、復原或替換人類目標。

TUI 默認掛載共享命令登錄檔和完整目標棧，並透過一個生產方暴露 `/goal`。ACP（Agent Client Protocol）掛載目標領域、模型工具和同工作階段驅動器，但有意省略人類命令平面。每條有效已註冊命令都能被每個已組合的命令配接器發現和呼叫；若外掛程式與某應用不相容，該應用組合會省略其命令生產方，而不是相依性登錄檔層面的表面掩碼。無 UI 的 agent 主幹要求顯式選擇加入，以免單次呼叫方靜默變成多 Round 操作。無頭 CLI（命令列介面）與 JSON-RPC 執行入口不消費命令平面；掛載目標棧後，普通人類文字仍可授權模型目標工具。

### 全新 agent Ralph 執行

Ralph 是位於自有外掛程式中的一等模型工具，展示了複雜固定執行策略可以在沒有新 loop 核心的情況下組合完成。該外掛程式擁有建置在 `ctx.workflowEngine` 與 `ctx.subagents` 之上的固定工作流程指令碼；它不會建立工作階段目標狀態，也不會為 `dsh-agent-loop` 增加分支。

每個 Round 都使用顯式 `WorkflowStartRequest.subagentProvider`，預設為 `spawn`。該提供方必須存在、支持結構化輸出，並聲明不繼承父上下文。Ralph 還會把解析後的 Round 上限作為 `WorkflowStartRequest.maxTotalAgents` 傳遞；工作執行緒引擎會在發布工作前驗證兩項每次執行策略，因此提供方設定錯誤或低於所請求 Ralph 規模的引擎上限會在執行建立前失敗。子 agent 繼承 cwd 與譜系，但只接收不可變目標、當前 Round/上限、以工作區為權威的指令和上一份規範化報告。

報告包含狀態、摘要、證據、下一步與阻塞文字。固定指令碼內部和消費端邊界都會驗證狀態專用不變數與序列化大小。`maxRounds` 可設定，預設為 `256`，並作為呼叫覆蓋值的上限。`maxHandoffChars` 預設為 `16384`；過大報告會失敗，而不會被靜默截斷。`maxResultChars` 單獨預設為 `16384`，並限制面向父級的完整成功文字，包括外層文字與截斷標記。

普通子 agent 失敗會結束執行且不重試。固定指令碼會報告失敗 Round，並在存在時帶回上一份成功交接；工具會把該狀態作為錯誤返回，而不會誤判為畸形報告或預算耗盡。致命工作流程基礎設施錯誤可能在指令碼返回該狀態前結帳；更豐富的原因傳輸與重試策略均予以延期。

該工具位於前臺且只存在於行程內。父工具呼叫等待終止結果，把取消傳播到工作執行緒引擎，並等待 `run.dispose()`，因此返回前子工作已完全靜止。模型只看到一次呼叫，以及一份有界成功終止結果或一個錯誤；完成與阻塞的外層文字會明確說明結果由工作者報告，而不會呈現為獨立認證。中間子 agent 對話不會進入父 transcript。

### 外部設計譜系

Codex 提供了這裡採用的最小可觀察目標 UX：一個附著於聊天的持久目標，以及設定、查看、編輯、暫停、復原與清除控制。本實作採用這種可發現性，但使用本倉庫的事件溯源目標記錄、外掛程式作用域與執行時期權限檢查。

當前 [Claude Code goals](https://code.claude.com/docs/en/goal) 進一步驗證了「前一輪次後啟動另一輪次的目標」和定時 `/loop` 之間的區別。Claude Code 還會在每個輪次後使用獨立小模型評估器。本實作採用策略區分，但有意不複製該評估器：評估器輸入、工具訪問、確定性檢查、提供方選擇、隔離與權限需要單獨設計的外掛程式約定，而不是隱式自我認證層。

外部產品只是比較對象，不是相容目標。本機原始碼研究幫助確定邊界，而交付介面遵循本倉庫「一切皆外掛程式」、模型可見內容均記入日誌、顯式解析預設值與完全靜止後拆卸規則。

### 驗證

六份所屬 Agent Note 記錄了單元、整合、行程、快照、取消、重放與建置後執行時期覆蓋率。該棧驗證嚴格目標記錄摺疊、比較並交換競爭、工作階段 fork 繼承、復原後未啟用、自然語言直接人類權限、可設定上限與阻塞閾值、確切的 Goal Round 歸屬、配接器範圍的命令發現與 transcript 隔離。已發布的無金鑰快照覆蓋透過無頭應用建立/檢查模型目標、透過 ACP 執行多 Round 同工作階段生命週期與取消，以及透過無頭應用執行兩個真實 Ralph Round；聚焦的命令測試固定了無需模型輪次的直接 `/goal` 狀態。Ralph 快照會啟動工作執行緒引擎、spawn 提供方、結構化輸出執行時期與 agent loop，隨後檢查互不相同且無種子的子日誌和精確的單向有界交接，同時固定父級事件串流。聚焦的真實棧測試還覆蓋完成、阻塞與 Round 上限結果、畸形及過大報告、保留上一份有效交接的普通子 agent 失敗、單個階段事件，以及取消後子 agent 完全靜止。包原始碼繼續受倉庫逐文件 100% 覆蓋率閘門約束，建置後二進位測試覆蓋已安裝產物解析。實作經驗已記錄進根測試策略：每項非平凡的模型或人類可見變更都必須在同一 PR（Pull Request）中攜帶真實示例無金鑰快照，而不能相依性僅包級或僅 mock fixture（測試前置資料）的覆蓋率。

## 考慮過的替代方案

- **實作原始通用 loop 能力**——不予採納，因為 `Evaluator`、`BudgetPolicy`、`RoundHandoff`、`GoalReflector`、背景工作所有權、持久化與調度並不構成一項一致的必選抽象。在出現首個具體消費端前全部建置，會產生寬泛的推測性介面，並重複現有工作階段、工作流程、subagent 與 task 機制。
- **只實作同工作階段目標**——不予採納，因為全新上下文迭代在實質上不同，也是外掛程式架構的重要示範。Ralph 應作為帶顯式上下文重設的固定工作流程消費者。
- **把 Ralph 放進 Goal Round 驅動器**——不予採納，因為同工作階段目標有意保留一段對話，而 Ralph 有意移除對話。合併兩者會讓啟用、重放、交接與 UI 狀態含糊不清。
- **把 fork 當成全新 Ralph 子 agent**——不予採納，因為 fork 會攜帶對話前綴。全新子 agent 加工作區狀態與一份顯式報告更容易限制和重放，並且無需合成取消記錄。
- **把 Claude Code 評估器複製進首個目標實作**——不予採納，因為只讀取 transcript 的模型評估器是一項有用策略，但不是普遍可信的完成憑證。系統必須仍能支持確定性評估與隔離，因此評估器延期到其權限與提供方約定完成設計之後。
- **工作階段復原後自動續行**——不予採納，因為打開工作階段是觀察行為，不是花費資源的權限。系統復原持久狀態，而啟用態等待新的人類提示詞。
- **透過模型路由 `/goal`**——不予採納，因為狀態與顯式生命週期控制應是確定性且零 token 的 UI 操作；普通自然語言提示詞仍是語義模型路徑。
- **為具體 agent loop 增加目標或 Ralph 模式**——不予採納，因為公開佇列、提示詞、工作階段、取消、工作流程與 subagent seam 已經支持兩項策略。通用 cancel-requested 觀察是唯一核心協調新增項。

## 後果

- 目標式執行在沒有單個過載「loop」對象的情況下交付：同工作階段續行與全新 agent 迭代擁有顯式、可獨立測試的約定。
- 持久目標歷史可以重放和 fork，而行程本機啟用態會防止復原時意外開始工作。
- 人類獲得小型 Codex 形態 UX；模型獲得一組緊湊工具，其中的修改操作要求當前即時根 agent 輪次中有一條人類直接傳送的訊息；部署可以獨立移除任一能力。
- Ralph 展示了非平凡固定策略可以完全作為現有工作流程與 subagent 原語之上的外掛程式實作。
- Round 上限默認寬裕，但仍由部署控制。它限制迭代次數，不限制 token、價格、耗時或外部副作用。
- 原始提案中的評估器、預算、反思器、背景工作、CLI 與通用 loop-session 架構有意不進入已實作的公開 API。

## 已知限制與暫緩事項

- **獨立評估**——同工作階段完成/阻塞和 Ralph 終止狀態都是模型或工作者聲明。獨立評估器、評估器驅動回饋 Round、完成憑證、確定性檢查器、對抗式 verifier 與標準/執行器/隔離約定均予以延期。
- **聚合預算**——`maxGoalRounds` 與 Ralph `maxRounds` 是唯一聚合工作量限制。token、貨幣、耗時、提供方用量與逐 Round 價格准入策略均不存在。
- **沒有持久自治執行器**——同工作階段目標事實會持久化，但啟用與調度只存在於行程內，並且有意在復原後等待人類輸入。Ralph 位於前臺，行程丟失後無法復原。後臺收集、重新啟動復原與無人值守常駐執行均予以延期。
- **沒有時間調度器**——間隔 `/loop`、cron、主動維護以及雲端或桌面調度不在本決策範圍內。
- **沒有通用 loop 日誌或執行世界回退**——工作階段重放會重建目標歷史，而不會復原此前文件、行程、環境、憑據或外部副作用。Ralph 把當前工作區作為權威，並且沒有跨執行日誌。
- **沒有目標反思器**——concern 事件、自動無進展啟發式、由獨立反思器執行的目標修訂、卡住模式偵測與 `loop_split` 均未實作。人類可以直接編輯、暫停、清除或復原目標。
- **Ralph 策略仍然狹窄**——一個 Round 建立一個全新子 agent；Round 內扇出、評估器/工作者角色分離、動態提供方/模型選擇與從結構上禁止遞迴呼叫 Ralph 工具都需要獨立策略 API。提示詞指導不是強制執行。
- **Ralph 不會重試失敗的子 agent**——普通失敗會保留失敗 Round 與上一份有效交接，而致命工作流程基礎設施錯誤可能在該狀態可用前結束。重試次數、退避與更豐富的失敗傳輸需要獨立的策略與邊界設計。
- **可移植 UI 仍較樸素**——TUI 渲染純文字目標狀態和通用 Ralph 卡片。ACP 只承載已提交的助手文字；系統沒有持續狀態元件、可重連命令輸出、模態目標編輯器，ACP、無頭 CLI 與 JSON-RPC 也沒有命令平面。
