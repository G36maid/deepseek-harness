# Agent Note: Web 對話輸入區的工作階段模型選擇

Status: implemented

[English](2026-07-24-web-session-model-selector.md) | [简体中文](2026-07-24-web-session-model-selector.zh.md) | 繁體中文

## 問題

Web 對話需要一項由 Host 提供、可見且可更改的工作階段模型選擇。如果照搬 TUI 的呈現方式，或在瀏覽器中硬編碼 DeepSeek 模型，就會讓模型發現邏輯和步驟邊界語義分散到不同前端中。回應執行期間發生的切換還需要一個原子邊界：提示詞變數與請求路由不能觀測到不同的選擇。

## 決策

Web Host 為每個新建或復原的 Agent 安裝 `ModelSelection`。如果工作階段已經使用過模型，提供方／模型／推理（reasoning）選擇來自最新的 `request/header`；否則來自 `ctx.agentDefaultModel`。`session.selectModel` 會賦值工作階段級選擇，提示詞組裝則將它與請求路由一並捕獲，因此執行中步驟發生的切換會應用於下一個組裝步驟。下一個實際採用的選擇透過完整的 `request/header` 快照持久化；尚未進入請求的選擇則僅保存在當前行程中。

工作階段 RPC 領域公開 `session.models` 模型目錄與 `session.selectModel`。該目錄從 LLM（大型語言模型）登錄檔動態建置，並按提供方分組；每個已列出模型的精確元資料還會加入由配接器持有的推理強度 ID、名稱、說明和選填預設值。各提供方的目錄與精確元資料會按提供方並行載入，且彼此獨立失敗，因此成功載入的分組仍可與可重試的失敗記錄一同使用。模型是否位於目錄僅供參考：`session.models.current` 獨立返回，即使不在任何分組中也仍然可以路由，但提供方停止公佈該模型後，Host 不會合成未列出行。兩個前端對這一狀態給出不同回答：TUI 把未列出的當前模型渲染為獨立一行，Web 則顯示未設定狀態的觸發器標籤並要求選擇替代模型。Web 是編輯目錄所在的前端，因此缺席的目錄行代表一項待作出的選擇；TUI 只從現有行中選擇。顯示未設定標籤的 Web composer 仍可以使用當前可路由選擇傳送訊息。精確解析決定提供方／模型組合與顯式推理強度是否可用。選擇操作透過 `resolveCallConfig` 拒絕不支持的推理強度 ID，並在賦值該選擇前具體化配接器設定的預設值。

瀏覽器中的 `ModelDirectoryResolver` 為每個即時工作階段持有一個 `ModelDirectory`。其快照包含當前完整的 `ModelSelection`、分組目錄、提供方失敗記錄、操作錯誤，以及 `idle`、`loading`、`ready`、`selecting`、`error` 狀態。掛載時會預先填充觸發器標籤，此後每次打開選單都會刷新目錄。目錄與選擇呼叫共用操作代次，防止較早回應覆蓋較新結果；連線重設會先丟棄當前行程中的投影，再復原 Host 選擇。失敗時保留先前的選擇和可用分組。

`@deepseek-ai/dsh-client-ui-conversation` 將工作階段作用域的單實例 slot `conversation.input.model` 聲明為其輸入欄 entry 的子 slot。InputBar 在尾部控制元件區將該 seat 渲染於 pending 指示器與主按鈕之前；該 seat 接收輸入欄的 `locked` owner prop 與工作階段作用域。`@deepseek-ai/dsh-client-ui-model-selection` 佔用該 seat，並在同一目錄上提供 `/model`。其緊湊型觸發器顯示目錄中的確切模型名稱與生效的推理強度標籤。當前選擇不在分組中時，觸發器顯示 `Select model`，模型清單不標記任何活動行，Effort 行也保持隱藏；選擇一個已列出的模型，會透過共享的選擇路徑賦值完整選擇。除此情形外，向上展開的選單會首先提供 Model 與 Effort；Model 可深入提供方分組，Effort 可深入配接器排序的等級。僅當配接器沒有設定模型預設值時，才顯示提供方預設值行。

生產環境的瀏覽器名冊由 `apps/cli/config/base.cordis.yml` 與 `apps/cli/config/web.cordis.yml` 共同組裝；模型功能對應其中一行 `dsh.client` 設定項，而不是 Web boot 程式碼中硬編碼的包。其包 manifest（中繼資料清單）將載入順序置於執行時期與命令功能之後；Cordis 服務注入則等待 conversation slot 可用，再註冊 composer 佔用方。

## 考慮過的替代方案

**分別使用提供方與模型下拉式方塊。** 模型清單相依性提供方，每次更改都需要經過兩階段互動。單個分組選單仍以提供方組織模型，同時不會增加觸發器或各行的顯示長度。

**在 Web 用戶端中硬編碼當前 DeepSeek 目錄。** 該目錄會與已註冊配接器發生偏離，也會排除部署自有的提供方。LLM 登錄檔繼續作為提供方與模型元資料的真源，也涵蓋部分查詢失敗資訊。

**將 `High`／`Max` 保留為用戶端本機 UI 狀態。** 靜態 DeepSeek 標籤無法覆蓋 `off`、pi-ai 的提供方詞彙、配接器預設值與校驗，也不能參與復原或下一次提供方請求。精確模型元資料擁有選填詞彙，工作階段選擇則擁有已選擇的 ID。

**只使用全域性預設值。** 預設值變更會意外改道空白對話。工作階段選擇僅屬於一個即時工作階段；對於沒有已記錄請求的工作階段，`ctx.agentDefaultModel` 提供回退值。

**Agent 執行期間拒絕更改。** 原子選擇快照將當前組裝步驟與下一次選擇分離。保持選擇器可用，可以讓使用者為下一個步驟預先選擇模型，而不會改變正在執行的請求。

**將每次點擊作為新的工作階段事件持久化。** 只有提示詞組裝採用某項選擇後，該選擇才對模型可見。持久化尚未使用的 UI 意圖，會增加一個無法重建模型請求的持久事件；現有 `request/header` 會記錄首次實際使用該路由的請求。

## 影響

任何由 Host 支撐的 Web 對話（包括空白工作階段）都可以在動態發現的提供方分組和配接器持有的推理等級之間切換，而無需顯示重複的 `provider/model` 標籤。實際採用的選擇會在復原和重連後保留；目錄名稱僅用於呈現，而選擇和持久化使用提供方／模型／推理強度 ID。某個提供方的目錄或精確元資料不可用時，只有相應分組會降級。提供方／模型變更可能降低提供方側的快取複用率，但選擇器不會新增任何提示詞內容，也不會幹擾正在執行的步驟。沒有推理元資料的模型不顯示 Effort 行。

## 測試

Host 測試固定分組發現、目錄與精確元資料失敗隔離、已記錄推理強度復原且不注入過時行、不受目錄約束的未列出模型選擇、不支持的推理強度拒絕、預設值具體化，以及切換僅影響下一次組裝。用戶端測試固定共享目錄、重連復原與完整選擇提交。元件測試固定動態推理強度標籤、說明、提供方預設值展示、推理強度提交，以及缺席模型行的 `Select model` 回退。無金鑰 built-app fixture（測試前置資料）載入生產模型外掛程式，選擇 OpenAI 的 GPT-5 及其 Max 推理強度，發起一個輪次，並驗證下一條生成的回應會報告兩個 ID；DeepSeek 設定 fixture 會省略活動目錄行，在選擇替代模型之前固定該回退。
