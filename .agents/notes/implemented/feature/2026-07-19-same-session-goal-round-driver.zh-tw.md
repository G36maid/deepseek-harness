# Agent Note: 同工作階段 Goal Round 驅動器

Status: implemented

[English](2026-07-19-same-session-goal-round-driver.md) | [简体中文](2026-07-19-same-session-goal-round-driver.zh.md) | 繁體中文

## 問題

目標領域可以保留目標，模型可見工具也可以變更其生命週期，但兩者都不應決定下一個模型輪次何時開始。繼續執行驅動器必須把活躍目標狀態橋接到普通 agent loop（代理循環），同時不能向 `dsh-agent-loop` 新增目標專用分支、建立第二段對話，也不能把每個人類輪次都視為自主迭代。

這層連線還承擔並行與持久性義務。人類輸入、取消、目標編輯、持久化失敗、工作階段重新啟動、外掛程式解除安裝以及下游提示詞策略都可能與待處理的繼續執行發生競爭。簡單的 `goal/changed -> agent.followup()` 監聽器可能接納過時工作、與人類提示詞同時執行、超出上限消耗資源，或在重播後未經新授權自行重新啟動。

## 決策

位於 `packages/goal/goal-round-driver/` 的 `@deepseek-ai/dsh-goal-round-driver` 是建置在 `ctx.goals`、公共 `Agent` 介面和持久工作階段事件之上的策略外掛程式。它不匯入具體 agent-loop 實作。它以每個即時 `Agent` 的確切對象身份為單位維護行程內調度狀態，並且最多預留一個自動 Goal Round。

層次關係為目標（Goal）→ Goal Round → 輪次（Turn）→ 步驟（Step）。Goal Round 是外層繼續執行策略的一次迭代；它會成為一個歸屬於目標的工作階段輪次，而該輪次可以包含任意數量的普通模型或工具步驟。同一工作階段中的人類輪次不是 Goal Round，也絕不會增加 `roundsStarted`。

該外掛程式沒有設定項。`maxGoalRounds` 由 `dsh-goal` 解析並持久化；「相同阻塞條件」的門檻由 `dsh-tool-goal` 解析並寫入提示詞。若驅動器重複聲明這些可調值，一個策略就會出現多個所有者。

### 預留與接納

當 agent 空閒、沒有競爭中的排隊工作，且當前目標為 `active` 加 `armed` 時，驅動器會先將待處理的目標變更持久化到檢查點，並在等待完成後重新校驗所有條件。若 `roundsStarted` 已等於 `maxGoalRounds`，它會記錄程式碼為 `round-limit` 的 `blocked`；否則，它會先預留精確身份 `{ goalId, revision, round: roundsStarted + 1 }` 和完整渲染提示詞，再以 `GoalMessageSource` 呼叫 `Agent.followup()`。提示詞用 JSON 引號編碼目標描述，使多行或類似標籤的文字在熟悉框架中仍是無歧義的資料值。

`agent/pre-step` waterfall（瀑布式事件）是進入柵欄。Round 編號為正數的目標來源只有在完全匹配驅動器待處理的身份和內容、即時目標仍具有相同 id 與修訂號、啟用態仍為 armed，並且該 Round 仍是下一個編號時才會進入。外掛程式在委託下游監聽器前檢查一次，在下游返回後再檢查一次。第二次檢查防止非同步監聽器編輯或暫停目標後，舊提示詞仍會進入。

只有最終產生的 `user/message` 纔是已進入的 Goal Round，並推進目標摺疊。過時預留會關閉一個被阻塞的零步驟輪次；驅動器會把它標記為過時，不計入 Round 數。若下游策略拒絕並非由過時狀態導致，目標會進入 blocked，而不會繞過該策略自動重試。

### 人類工作與修訂競爭

預留的 `MessageId` 會區分驅動器自己的完整記錄與其他所有提示詞。預留之前已經排隊的普通工作會阻止調度；自動提示詞待處理時進入的普通工作會使該預留過時，因此混合的已領取批次會拒絕自動提案。Goal Round 進入後到達的普通工作會保留在佇列中，成為下一個獨立輪次；只有 agent 再次空閒後才重新考慮繼續執行。

目標在 Round 內發生變更時會推進持久修訂號。舊修訂的結帳不得覆蓋該變更。驅動器會丟棄舊嘗試的結果、讀取新投影，並且只在新修訂仍為 active 與 armed 時繼續。因此，模型記錄的完成、暫停、阻塞和編輯相對於物理輪次稍後的關閉原因具有最終權威。

### 結帳

驅動器按下表分類一個已經關閉、歸屬於目標的輪次：

| 輪次結果 | 動作 |
|---|---|
| 持久化的 `completed` | 目標仍 active/armed 且未到上限時繼續 |
| 取消已預留/接納的 Goal Round，或該 Round 產生 `aborted` 結果 | 暫停並解除啟用 |
| 程式碼為 `RATE_LIMIT` 或 `QUOTA` 的 `error` | 以 `usage-limited` 程式碼阻塞 |
| 其他 `error` | 以 `turn-error` 程式碼阻塞 |
| `max-tokens` | 以 `max-tokens` 程式碼阻塞 |
| 持久化檢查點失敗 | 解除啟用，但不改變持久化階段 |
| `disposed` 或 `interrupted` | 解除啟用 |
| 外掛程式新增的未知結果 | 阻塞並等待檢查 |

例外結果都不會請求自動重試。之後的人類提示詞可以用任何語言要求繼續；模型讀取已停止目標並呼叫目標工具的 resume 動作，記錄新修訂並重新啟用繼續執行。

### 持久性與取消約定

每次 `goal/changed` 通知都會產生一個檢查點義務。驅動器在預留工作前等待 `ctx.sessions.flush(session)`，隨後檢查是否出現了更新的變更、agent 生命週期變化或競爭提示詞。輪次結束時的 flush 失敗會在 `turn/end` 之後透過現有 `agent/error` 通知報告；即使並行的一次性注入已追加後續輪次，驅動器仍會找到對應的同一個已關閉輪次，把失敗關聯到對應的同一次嘗試，並在下一次空閒決策前解除啟用。

廣義取消會清除待處理的收件箱工作，並中止活躍的迴圈階段。目標驅動器透過收件箱領取／丟棄事件和持久化的 aborted 輪次結束事件來跟蹤預留訊息。由於輪次現在會在首次領取前打開，取消可以關閉已領取的零步驟嘗試；驅動器會把該嘗試標記為已取消，並讓隨後的空閒邊沿暫停目標，與已接納嘗試的處理方式相同。沒有匹配目標嘗試的取消只會移除行程內啟用態。若暫停變更拋錯，驅動器會回退到解除啟用，避免已取消的自動工作重新啟動。

`Agent.cancel()` 仍是唯一的公共廣義取消動詞。若消費端相依性這些順序，實作該介面的自訂 `Agent` 必須遵守收件箱、輪次結束、狀態與完全靜止的順序。

### 行程生命週期

`GoalService.disarm(agent)` 只移除行程內啟用態。它不寫工作階段事件、不改變修訂號，也不寄出目標變更。驅動器在載入現有 agent、持久性存在不確定性以及解除安裝前呼叫該方法；之後的 `resume` 纔是模型可見的持久啟用邊沿。

驅動器的事件監聽器和完全靜止後關閉的流程巢狀在同一個有序 Cordis effect 中。Cordis 會並行解除安裝同級 effect；若監聽器和清理分別註冊，非同步 disposer 仍在排空時提示詞柵欄就可能已被移除。組合 effect 會先關閉接納、解除目標啟用、取消已接納嘗試，並等待 agent 與驅動器都完全靜止；之後才註銷監聽器。

緊鄰外掛程式開始解除安裝前，收件箱接納可能贏得微任務競爭。在這種情況下，輪次甚至首個請求都可能已經開始，且該 Round 仍會持久化計入額度；解除安裝一旦開始，取消就會中止它，不會再調度後續回合，目標保持 active 但 disarmed。若假裝已經觀測到的接納從未發生，就會破壞重播計數。

## 測試

單元測試使用真實 agent loop 與工作階段服務，只對模型編寫指令碼。覆蓋內容包括精確連續接納和上限執行、載入與復原的惰性、所有結果分類、限流、請求錯誤、最大 token、下游提示詞否決、接納前與執行中取消、無關人類工作取消、暫停失敗回退、人類輸入排序、排隊時與下游修訂競爭、偽造目標來源、變更與輪次檢查點失敗（包括後續一次性注入）、調度器與自訂 agent 失敗、工作階段啟動重設、精確生命週期退出，以及排隊中和執行中的外掛程式解除安裝。新驅動器原始碼達到逐文件 100% 語句、分支、函式和行覆蓋率。

無金鑰 ACP（Agent Client Protocol）快照透過 `cordis.yml` 掛載已發布的自動化應用，以及真實目標領域、目標工具、目標驅動器、agent loop、持久化和重播配接器。一個源自人類的輪次建立並檢查一個包含兩個 Round 的目標；第一個自動輪次正常停止，ACP 隨後取消刻意停滯的第二個 Round 並記錄持久暫停。規範化的協議層 transcript（文字記錄）和外部 JSONL 斷言證明只有一個工作階段、Round 來源依次為 `1, 2`、生命週期變更與重播計數精確，並且沒有把 `echo-agent` 當作應用替身。

核心取消測試固定通知順序與隔離：只有有效取消才會通知；觀察者可以在清空收件箱前排入替代工作；拋錯不能阻止後續觀察者；空閒呼叫不會發出事件。

## 考慮過的替代方案

- **在 `dsh-agent-loop` 內新增目標迴圈**——不予採納，因為公共佇列、提示詞、工作階段、取消和狀態約定已經足夠，具體迴圈分支還會賦予某種策略特權。
- **使用 `agent/turn-continuation` 把每個 Round 變成另一個步驟**——不予採納，因為 Goal Round 是外層策略迭代，必須擁有自己的持久使用者提示詞、輪次邊界、Round 計數和失敗結帳。
- **持久化待處理預留**——不予採納，因為崩潰無法證明行程內佇列已經達到接納點；只有持久 `user/message` 才計入 Round。
- **自動重試提供方或持久化錯誤**——不予採納，因為重試會消耗資源，需要顯式授權；停止階段與之後的人類復原更簡單，也可觀察。
- **每個 Round 都 fork 對話歷史或生成新 agent**——本包不採用，因為此目標明確屬於同工作階段工作。新 agent 的 Ralph 執行仍是基於 subagent 與工作流程原語的獨立工作流程外掛程式。
- **把每個工作階段輪次當作 Round 計數**——不予採納，因為人類澄清和無關工作共享工作階段，但不共享自動工作預算。

## 後果

- 目標繼續執行仍是可移除外掛程式，具體迴圈只新增一個通用的「取消前觀察」通知。
- 重播可以從精確目標來源和提示詞重建每個已接納 Round；被拒絕的預留不會產生虛假的預算消耗。
- 人類訊息和生命週期變更可以在有文件約束的競爭中勝出，而不破壞修訂號或計數器。
- 復原和 fork 會一直保持惰性，直到人類的語義意圖促使模型記錄 resume 變更。
- 保守的失敗對映可能要求在暫時性錯誤後手動繼續，但絕不會隱藏自動重試。

## 已知限制與暫緩事項

- 完成證據和阻塞條件的語義等價性仍由模型判斷。獨立評估器、完成憑證或由驗證器驅動的停止策略延期到獨立策略外掛程式。
- 本包不提供 Ralph 風格的新 agent 嘗試、上下文重設、跨 Round 評估回饋或工作流程級平行；它們屬於獨立的 Ralph 工作流程工具。
- Cordis 解除安裝非同步開始。已經被收件箱接受的條目可能先進入一個計入額度的 Round 並啟動一個請求，之後解除安裝取消才生效；關閉排空會阻止所有後續 Round。
- `maxGoalRounds` 只是已接納 Round 的上限。token、費用、掛鐘時間和提供方使用預算需要獨立策略。
- 自訂 `Agent` 實作必須產生文件規定的工作階段事件、狀態邊沿、取消通知和完全靜止語義；僅憑 TypeScript 結構相容無法驗證執行時期順序。
