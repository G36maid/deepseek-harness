# Agent Note: 面向人類的 `/goal` 命令

Status: implemented

[English](2026-07-19-human-goal-command.md) | [简体中文](2026-07-19-human-goal-command.zh.md) | 繁體中文

## 問題

同工作階段目標領域和模型工具提供了狀態機與自然語言語義路徑，但尚不足以構成面向人類的 UX。使用者需要在不詢問模型的情況下檢查準確的當前階段與 Round 預算，在不消耗模型輪次的情況下明確暫停或清除工作，並在工作階段復原後經過必要的人類決策重新啟用已復原的活躍目標。若在各 UI 中分別實作這些操作，就會重複解析邏輯、導致各介面發生偏差，還可能把未知或不可用的命令交給模型處理。

該命令還必須遵守目標設計中的兩類狀態。持久階段、目標描述、修訂號與 Round 來自工作階段日誌；行程本機啟用態決定活躍目標能否自動繼續。復原後若只顯示「活躍」，就會掩蓋目標已被有意設為未啟用、正在等待人類授權這一事實。

## 決策

位於 `packages/goal/command-goal/` 的 `@deepseek-ai/dsh-command-goal` 是建置在 `ctx.commands` 與 `ctx.goals` 之上的命令生產方。它註冊一個全域性 `goal` 定義，因此組閤中的每個命令配接器都會發現同一個命令；不相容的應用應省略該生產方，而不是在配接器處封鎖其註冊。處理器從命令分發接收準確的目標 agent（代理），透過領域服務讀取或改變該 agent 的目標，並返回直接的純文字 UI 輸出。它不匯入任何配接器或具體 agent loop（代理循環）。

該命令遵循 [OpenAI Codex 公共倉庫 `678157a` 提交中的 TUI 分發實作](https://github.com/openai/codex/blob/678157acaa819d5510adfe359abb5d0392cfe461/codex-rs/tui/src/chatwidget/slash_dispatch.rs#L750-L805)所呈現的緊湊形態：無參數狀態查詢、自由形式目標描述，以及 `clear`、`edit`、`pause` 或 `resume` 控制。固定到提交的連結使調研所得文法在 Codex 後續演進時仍可核驗。本倉庫保留自身的事件溯源狀態、Round 計數策略與復原後啟用規則，而不複製 Codex 的 SQLite、token 預算或自動復原行為。

### 文法與生命週期動詞

`/goal` 報告目標描述、面向人類的持久階段、`roundsStarted/maxGoalRounds`、行程本機 `armed` 或 `disarmed` 啟用態，以及當前狀態下有意義的命令。沒有當前目標時，它會報告該事實與完整用法。讀取狀態不會新增工作階段事件。

`/goal <objective>` 建立活躍且已啟用的目標。已完成目標可以被替換，此時透過現有領域規則建立新的目標身份。任何未完成目標都會讓命令直接失敗，並提示使用者使用行內編輯或明確清除。通用命令服務有意不提供模態確認 API；若靜默執行清除再建立兩條持久記錄，就等於憑空製造破壞性同意，並暴露一個非原子的失敗視窗。

`/goal edit <objective>` 編輯當前未完成目標，但不改變其階段或啟用態。若目標已經完成，則建立一個新的活躍目標，因為領域不允許復原已完成狀態，而新的目標描述應擁有新的目標身份。單獨使用 `edit` 會返回錯誤而不是啟動編輯器，因為可移植的非結構化命令約定沒有模態編輯器。

`/goal pause`、`/goal resume` 與 `/goal clear` 使用當前檢視表呼叫相應的比較並交換領域動詞。復原既適用於停止的持久階段，也適用於工作階段復原、fork 或驅動器替換後處於活躍但未啟用狀態的目標。領域規則仍會拒絕已耗盡的 Round 上限、對已活躍且已啟用目標的重複復原、非法階段轉換與過時身份。清除會移除當前指針，而工作階段日誌保留帶修訂號的墓碑和此前快照。

控制詞會在去除兩端空白後按 ASCII 大小寫不敏感方式匹配。只有佔據完整後綴時才被視為控制；其餘任何非空文字都是目標描述。這保持了可預測的自由形式命令規則：`/goal pause after verification` 是目標描述，而不是被部分解析的暫停命令。

### 輸出與失敗邊界

狀態輸出省略品牌化 id 與比較並交換修訂號，因為它們屬於模型/外掛程式協調細節，而不是人類控制項。輸出包含啟用態，因為該事實會改變工作是否繼續；被阻塞的目標還會包含其持久策略程式碼和麵向人類的說明。命令提示從準確狀態派生：已啟用的活躍目標提供暫停，未啟用的活躍目標或已暫停/被阻塞目標提供復原，已完成目標則提供替換或清除。

預期的 `GoalError` 失敗會變為一個穩定且不含品牌化 id 的 `CommandResult.error`，使領域診斷不會向面向人類的介面洩露比較並交換內部細節，非法操作也絕不會進入模型歷史。當前狀態負責提供針對具體狀態且可執行的復原路徑。其他例外仍是配接器可見的命令失敗；若把程序缺陷當成普通領域錯誤，就會隱藏問題。命令處理器只執行同步領域變更，因此請求取消會在變更開始前由命令登錄檔決定，不存在需要回滾的外逸非同步副作用。

通用斜槓輸入、狀態文字與錯誤不會持久化。成功的目標變更會追加領域自有的 `goal/change` 事件，而且不會將模型上下文加入佇列。該命令不會引入可能與領域事件不一致的第二份審計記錄。

### 應用組合

`agent-spine-demo` 接受選填的 `goals` 組合對象，其中包含目標領域與模型工具的所有者設定。省略或設為 `false` 時不會掛載該棧。對無頭單次呼叫方而言，明確選擇加入非常重要：它們的結果 API 會在與呼叫關聯的一個物理輪次後結束，不能靜默變成長時間執行的邏輯目標操作。

TUI 應用包作出相反的產品選擇。它默認讓 `goals` 使用所有者預設值，並掛載目標領域、模型工具、同工作階段驅動器、命令登錄檔與本生產方；`goals: false` 會一致地移除整個棧。[ACP（Agent Client Protocol）自動化應用](../simplification/2026-07-23-acp-automation-only-protocol.md)也默認掛載目標領域與模型工具，但有意省略命令服務。Python SDK 執行時期閉包交付本生產方、命令與目標棧，使外部 `cordis.yml` 能組合相同命令。

## 測試

生產方測試套件使用真實命令登錄檔、目標服務、agent 登錄檔與工作階段日誌。它覆蓋 Loader 安全匯出、登錄檔發現、dispose（資源釋放）、空狀態、目標描述解析、拒絕未完成目標替換、行內編輯、已完成目標替換、無目標狀態下的所有控制命令、暫停/復原/清除、每個持久階段、阻塞程式碼/說明展示、已啟用/未啟用展示、經淨化的領域錯誤、意外失敗與持久變更記錄。應用組合測試覆蓋顯式主幹選擇加入、TUI 預設值、一致停用、轉發的領域/工具設定、命令發現、打包執行時期閉包與擴充後的模型工具組裝。ACP 後端快照繼續固定目標工具 schema，與這項面向人類的命令無關。

## 考慮過的替代方案

- **讓模型把 `/goal` 當作普通文字處理**——不予採納，因為狀態與直接生命週期操作會消耗模型輪次、可能被重新解釋，也無法提供確定性的命令發現。
- **在各 UI 中分別實作處理器**——不予採納，因為文法、錯誤行為與目標狀態格式會發生偏差，選填部署也無法把該能力作為一個 effect 統一增刪。
- **為 `ctx.commands` 新增模態編輯與替換確認**——不予採納，因為現有跨介面約定是非結構化輸入加直接輸出；通用互動協議所需的設計遠超這一個生產方。
- **靜默替換未完成目標**——不予採納，因為這會在沒有原子性或明確破壞性意圖的情況下組合清除與建立。
- **在人類狀態中暴露目標 id 與修訂號**——不予採納，因為人類操作始終在一個同步處理器內針對確切的當前檢視表；這些欄位只會增加實作噪聲，無法避免另一處競態。
- **在無 UI 主幹中無條件啟用目標**——不予採納，因為單次 SDK/CLI 的結束約定是物理輪次 API，而不是目標操作 API。

## 後果

- TUI 暴露由可移除外掛程式提供的 Codex 形態 `/goal` 命令。
- 人類狀態會區分持久階段與即時啟用態，並報告準確的目標 Round 上限。
- 直接暫停、復原、清除、建立與編輯不消耗模型輪次，而其已接受變更仍可從工作階段日誌重建。
- 復原後的工作階段等待人類決策；`/goal resume` 是字面命令路徑，任何語言的普通提示詞則可以授權模型工具路徑。
- 無頭組合保持單輪行為，除非明確選擇加入目標並定義自己的長時間執行結束約定。

## 已知限制與暫緩事項

- 可移植命令約定沒有模態編輯器或確認互動；在出現通用跨介面互動原語之前，行內編輯與明確清除是有意選擇。
- `/goal` 不接受逐命令 Round 上限。部署設定擁有預設值；得到直接人類指示後，已授權模型工具可以編輯上限。
- TUI 渲染可移植純文字，而不是持續更新的目標狀態元件。可重連命令輸出和配接器專用狀態指示器予以延期。
- ACP 自動化伺服器、無頭 CLI 與 JSON-RPC 執行入口不消費命令登錄檔。
- 該命令觀察並改變狀態，但不認證完成或阻塞。基於評估器的認證延期到具有明確權限與隔離約定的獨立策略層。
