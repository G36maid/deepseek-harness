# Agent Note: 跨工作階段引用

Status: implemented

[English](2026-07-21-cross-session-references.md) | [简体中文](2026-07-21-cross-session-references.zh.md) | 繁體中文

## 問題

TUI 使用者需要把另一場對話中的相關工作帶入一條新訊息，但不復原、不 fork，也不讓源 transcript（文字記錄）對當前工作階段擁有權威性。harness 已經提供準確的工作階段枚舉與原始事件檢查，但若每個宿主都獨立解析日誌，就會重複實作壓縮（compaction）摺疊、按被引用來源事件 seq 過濾、大小限制、錯誤行為和持久化。把宿主標記直接編碼進 agent（代理）訊息約定，還會讓核心迴圈綁定某一種 UI 文法。

## 決策

`@deepseek-ai/dsh-session-reference` 是註冊在 `ctx.sessionReferenceResolver` 上的單一上下文消費服務。宿主先把各自的協議規範化為 `SessionReferenceInput[]`，並在交付前呼叫 `prepare()`。該服務返回分離的可讀內容和一份選填的、帶標識且凍結的 `UserMessage` 快照；核心 agent 包既不解析工作階段 URI，也不讀取其他日誌。

`dsh-session:<base64url(JSON.stringify(sessionId))>` 是與宿主無關的規範識別符號。系統先執行 JSON 字串編碼，再執行 base64url 編碼，因此引號、正斜槓、反斜槓、Unicode、換行符以及其他任意 JavaScript 字串值都能無損往返，不會因分隔符產生歧義。TUI 把該 URI 渲染到 `@[label](uri)` 中；純文字用戶端可以使用同一種行內提及標記。顯式 Markdown 提及標記會拒絕格式錯誤的 URI。裸文字只有在負載非空且形狀符合 base64url 時才會成為引用，而且解碼過程仍須透過規範性校驗；空負載或只含標點符號的用法仍按普通討論文本處理。

該服務使用 `ctx.sessionQuery.readSurface(sessionId)`：它優先從即時工作階段載入一次語料觀察結果，使用工作階段包的規範表層演算法執行摺疊，並返回與源資料分離的工作階段頭、捕獲序號和當前節點。FTS 不是相依套件：候選發現會匹配 id、cwd 或最新摺疊後的標題，而訊息主體不進入候選層。非空查詢會對可見語料中的標題觀察結果執行批次處理，以有界並行讀取持久化日誌，並支持取消；專用標題索引可以替換這條發現路徑，而無需改變引用標識或準備過程。

## 快照與投影

準備過程按首次出現的順序去重、拒絕目標工作階段自身的 id，並且執行可設定的數量限制，但引用硬上限為三個，所有讀取均平行執行。該過程不會返回部分完成的上下文：任何讀取、取消、校驗或預算錯誤都會在呼叫 `followup()` 或 `steer()` 前拒絕本次操作。取消會與進行中的候選發現和精確讀取競速，因此即使持久化後端無法中斷待處理操作，宿主也能及時結束等待；後端遲到的完成結果仍會被觀察，但不能讓訊息入隊。源工作階段在入隊前完成讀取，因此源工作階段後續新增訊息、執行壓縮、被刪除或替換持久化內容，都無法改變目標工作階段中的快照。

投影會保留直接使用者訊息與 steering（中途引導）、已完成的 assistant 文字，以及攜帶由 `dsh-compaction` 匯出的規範來源標記的檢查點使用者訊息。該標記屬於壓縮能力約定的一部分，而非某個後端包名稱。當源提示詞已包含合併寫入的前綴上下文時，投影只讀取其模型不可見的顯示內容，因此後續引用該目標不會遞迴傳播先前的快照。投影會排除壓縮前已被遮蔽的節點、工具及其結果、推理（reasoning）、注入的上下文、其他外掛程式使用者訊息、僅用於日誌的記錄，以及尚未完成的 assistant 區塊。因此，重複壓縮只會暴露當前表層仍保留的最新摺疊檢查點譜系及其尾部訊息；系統不提供 raw/current 開關，也不復原被遮蔽的內容。

系統把一個聚合上下文序列化為 JSON，並置於固定的不可信背景警告之後。該警告要求模型不要遵循被引用工作階段中的指令、權限聲明或工具請求，除非當前使用者再次提出這些內容。標籤安全序列化會把資料中的每個 `<` 無損轉義為 JSON `\u003c`；因此源字串無法拼出外圍類似 XML 的標籤，也無法逃逸資料區域。同一個序列化器會獨立覈算每個源的位元組數。AgentLoop 會把快照持久化為一條帶來源資訊的 `user/message`，緊接在直接 `user/message` 之前。因此，目標重播無需新增事件類型、放置模式或提示詞封套，也能滿足「模型可見／日誌可重建」不變數。

## 訊息所有權

TUI 負責快照／直接訊息交易，不擴充通用收件箱記錄。agent 空閒時，它會在呼叫 `followup()` 前安裝一次性的外層 `agent/pre-step` 監聽器；enter 決策會把快照作為另一則訊息接收，而 reject 或更早的普通丟棄會釋放監聽器，並且不寫入任何訊息。agent 執行時期，TUI 會依次呼叫 `inject(snapshot)` 和 `steer(prompt)`，把兩者放入 next-step inbox，等待後續同一次領取。pre-step reject 或失敗會使這對已領取消息維持已移除狀態；領取後插入的訊息繼續等待。這一通用交付邊界由[上下文分離決策](../architecture/2026-07-24-separate-context-injection-from-turn-execution.md)規定。

引用準備過程不是新的 steering 協議，本身也不會建立輪次。空閒交付使用 `followup()` 和 pre-step 進入決策；執行期間的交付使用共享 next-step inbox，並保持快照順序。

## 宿主配接器

TUI 把工作階段候選與現有 `@` 文件提供方組合在一起。候選查詢會對 session id、cwd 或最新摺疊後的標題執行不區分大小寫的子串匹配，顯示該標題，並在沒有標題觀察結果或標題觀察失敗時回退到 session id。候選查詢遵循編輯器的取消訊號；session id、cwd 和提及標籤中的外部終端機控制字元會被轉義，但規範 URI 仍保留原始 id。TUI 只準備包含結構化提及標記的提交；等待快照時停用重複提交；失敗時復原輸入；它把可讀的直接內容渲染為使用者訊息，並把工作階段引用來源元資料渲染為精簡的來源清單，不在終端機中暴露完整 JSON。

[僅面向自動化的 ACP（Agent Client Protocol）傳輸層](../simplification/2026-07-23-acp-automation-only-protocol.md)有意不掛載工作階段查詢或工作階段引用服務。

## 預算與保留策略

最多三個引用中的每一個默認獨立限制在 65,536 個 UTF-8 位元組以內。保留策略會優先保留當前壓縮檢查點和最新的對話單元，再丟棄較舊的非檢查點訊息。若保留文字過大，系統使用 `dsh-output-retention` 進行首尾切片並記錄準確的省略位元組數；若某個源的固定序列化欄位無法裝入其上限，整個準備過程會失敗，不會輸出部分上下文。

## 考慮過的替代方案

- **等待 SQLite FTS5**：不予採納，因為快照正確性相依性按準確 id 讀取和規範表層摺疊，而不是內容搜尋。FTS 只改進候選發現。
- **把提及標記文法放入 agent 投遞方法**：不予採納，因為這會迫使核心協議解析某個宿主的展示文法，並阻止帶類型的非文字宿主複用同一語義層。
- **在每個宿主中分別實作引用**：不予採納，因為投影、安全警告、保留策略和持久化會在不同宿主之間逐漸偏離。
- **把上下文附加到 `SendOptions` 和直接提示詞的收件箱記錄**：不予採納，因為通用投遞將不得不負責貫穿准入、steering、取消和觀察的領域交易。領域專用的准入包裝層和現有 next-step inbox 可以保持所需配對，而無需擴大每條直接提示詞。
- **在呼叫 `followup()` 前由宿主合併前綴**：不予採納，因為 `agent/pre-step` 必須只檢查和改寫直接提示詞。將快照保留為獨立的帶來源訊息，可以維持該邊界，並讓 TUI 從直接使用者氣泡中隱藏背景位元組。
- **重播原始源日誌或復原被遮蔽的事件**：不予採納，因為壓縮定義了當前模型表層，並且可能有意淘汰敏感或開銷高昂的歷史內容。
- **復原或 fork 源工作階段**：不予採納，因為本功能只為一條目標訊息提供只讀背景，不提供身份或生命週期連續性。
- **在請求時重新讀取源工作階段並注入**：不予採納，因為這會讓引用變得不確定，取消競態可能改變其位元組內容，目標重播也會相依性可變的外部狀態。

## 驗證

單元與整合測試覆蓋 URI 無損往返與文字邊界標點、顯式格式錯誤的引用、按 id／cwd／標題進行候選匹配與排序、標題觀察失敗時的回退、候選查詢取消、終端機控制字元轉義、投影排除規則、快照的非遞迴投影、與後端無關的壓縮檢查點、標籤安全封套、去重、自引用、數量限制、讀取的全有或全無、儲存讀取不結束時取消提示詞、逐源獨立位元組保留、提示詞阻止、准入期間的暫存、send／steer 放置方式、標題隔離、能力缺失和壓縮場景下的 TUI 重播。一個無金鑰終端機快照會在工作階段 id 不透明的情況下輸入一個只與標題匹配的子串，並固定渲染出的候選項。另一個無金鑰 TUI 快照會執行真實的 agent loop（代理循環）：源表層用一個壓縮檢查點替換舊的使用者／assistant 歷史，目標工作階段提交一個提及標記，捕獲到的模型請求包含一條帶來源的快照訊息，後面跟隨可讀的當前提示詞，並且不包含任一被遮蔽的字串。

## 後果

新外掛程式構成穩定的語義邊界，不會新增持久化 schema、事件類型、FTS 相依性、源工作階段訂閱或對壓縮所遮蔽內容的訪問。標準 TUI 演示組合包會顯式掛載它，並在自身設定中暴露引用數量和逐源位元組上限；自訂宿主在掛載該服務並適配輸入前保持不變。引用上下文會在設定的界限內增大目標歷史，隨後可由目標工作階段的普通壓縮進行摘要；完成壓縮後，源工作階段便不再相關。
