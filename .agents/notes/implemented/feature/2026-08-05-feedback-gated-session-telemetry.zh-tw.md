# Agent Note: 回饋門控的工作階段遙測

Status: implemented

[English](2026-08-05-feedback-gated-session-telemetry.md) | [简体中文](2026-08-05-feedback-gated-session-telemetry.zh.md) | 繁體中文

## 問題

工作階段遙測原本只有一種已掛載行為：每條已接受記錄都立即進入上報後端。部署方需要兩種更嚴格的策略，且不替換外掛程式：只有使用者記錄回饋時才釋放該工作階段的遙測，或停用上報並仍向使用者說明回饋的去向。該策略必須保留遙測 seam 在記錄抵達後端之前脫敏的邊界。

## 決策

`@deepseek-ai/dsh-session-telemetry-otel` 向 TypeScript 呼叫方公開以字串為值的 `SessionTelemetryMode` 枚舉，並在序列化設定中接受相同的三個大寫 `mode` 值：

- `FULL` 顯式選擇向已設定 OTel 管線即時投遞。
- `FEEDBACK_ONLY` 在追加 `feedback/record` 時讀取權威工作階段日誌，並交接截至該事件的未釋放前綴。該邊界後追加的記錄會留在本機，直到另一個回饋事件。
- `DISABLED` 是[預設值](2026-08-10-telemetry-default-off.md)，不構造匯出器、處理器或日誌提供方，並在觀察到 `feedback/record` 時輸出警告，說明什麼都不會共享，且回饋仍留在本機。

通用遙測協調器擁有 `live` 與 `on-demand` 捕獲。即時捕獲在工作階段 firehose 上投影、深拷貝、脫敏每個事件，並將其交給後端。按需捕獲不註冊持續捕獲監聽器；`captureSession(session, throughSeq)` 從 handoff 遊標起讀取權威日誌，直至含邊界的指定序列號，然後投影、深拷貝、脫敏並交接該前綴。遊標只為已交接記錄推進。[無緩衝重播決策](../simplification/2026-08-06-buffer-free-feedback-telemetry.md)說明瞭按需路徑為何使用權威日誌而非記錄副本。

模式解析採用封閉式檢查，並在設定前失敗：透過直接構造傳入未知值時，會在學取傳輸設定前失敗。只有 `FULL` 向 SDK 管線開放公共服務的 `emit()` 路徑。`FEEDBACK_ONLY` 向其按需協調器提供私有後端能力；其監聽器向 `captureSession()` 傳遞事件的唯一條件，是該事件與那個 `feedback/record` 對象身份完全相同，且該對象已儲存於 `session.events[event.seq]`。`Session.append` 在發布 `session/event` 前已提交該對象，因此重播包含該回饋，但不會越過其邊界。`DISABLED` 既不建立該能力，也不建立 SDK 管線，並且不檢查匯出器設定。

## 考慮過的替代方案

**工作階段在首次回饋後永久開放。** 已否決，因為後續工作會在使用者未再次提交回饋的情況下被共享，而且外掛程式需要額外的工作階段開放狀態。每次回饋只釋放一個待處理前綴，狀態機更小，共享邊界也更窄。

**回饋前保留捕獲時已脫敏記錄。** 已否決，因為權威日誌已擁有這些事件，該方案仍會複製無上限的工作階段前綴。它能保留捕獲時的脫敏策略與運維記錄，但對於一個定義為「回饋後上傳工作階段日誌」的模式，這些性質不足以證明該記憶體成本合理。

**在回饋重播期間臨時允許公開 `emit()` 呼叫。** 已否決，因為在標志開啟期間，脫敏監聽器或另一個可重入呼叫方可能將無關記錄入隊。私有後端能力使授權成為結構性保證，並確保公共服務在整個重播過程中保持關閉。

**以不掛載外掛程式表示停用狀態。** 這仍然是靜默退出方式，但無法在記錄回饋時輸出警告。顯式停用模式讓部署方可以保持同一種設定形態，並說明本機回饋未離開行程。

## 後果

`FULL` 作為顯式啟用模式保留原有的原始碼與協議行為。`FEEDBACK_ONLY` 在回饋前不增加遙測自有的逐事件緩衝；直接服務呼叫與非權威回饋事件均不上傳任何內容，且回饋前發生崩潰時，該前綴也不上傳任何內容。重播使用記錄回饋時掛載的脫敏策略，並排除權威日誌中不存在的運維記錄。因此，僅回饋的流既不攜帶 `agent-error` 記錄，也不攜帶 `shutdown` 記錄，而缺少 shutdown 不是崩潰訊號。每個後續回饋都會捕獲從上一個邊界起累積的後綴。`DISABLED` 可省略 `exporter.url`，不執行任何上報工作，並僅在權威工作階段日誌中保留回饋。
