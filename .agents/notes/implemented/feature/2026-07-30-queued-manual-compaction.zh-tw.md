# Agent Note: 使用單一持久鎖實作排隊手動壓縮

Status: implemented

[English](2026-07-30-queued-manual-compaction.md) | [简体中文](2026-07-30-queued-manual-compaction.zh.md) | 繁體中文

## 問題

自動壓縮（compaction）可以保護上下文視窗，但互動使用者還需要一種確定性方法，在壓力策略觸發前壓縮累積的歷史。把 `/compact` 作為提示詞文字傳送會消耗一個模型輪次，還會讓工作階段模型重新解釋一項直接控制操作。在某個 UI 內實作該功能，則會重複命令發現、生命週期日誌記錄、取消與後端策略。

面向使用者的命令在輪次之間到達，並且必須非同步生成摘要。在等待期間獲接納的提示詞必須保留普通身份、FIFO 位置與喚醒行為，但不得從即將被壓縮替換的歷史派生請求。單獨檢查狀態並不足夠，因為另一呼叫方可能在該檢查與壓縮操作認領空閒階段之間喚醒驅動器。

手動、壓力、溢位和顯式範圍入口點還需要共享同一項互斥事實。僅使用行程本機標志無法解釋一份當機復原後的日誌，而先摘要再記錄的交易在開銷較大的等待期間不會留下持久證據。反過來，把標記對視為排他容器又會禁止有效的空閒注入，儘管注入按定義不會喚醒，並且會在輪次之間立即執行。

本 Agent Note 擴充[壓縮能力 seam](2026-06-18-compaction-capability-seam.md)、[工作階段 end-seed 邊界](../architecture/2026-07-30-session-end-seed-log-boundary.md)和[移除純日誌事件的合成輪次](../simplification/2026-07-28-remove-synthetic-log-only-turns.md)。三者均保持活動狀態，並擁有各自更廣泛的決策；重疊僅是部分的。

## 決策

### `/compact` 是基於後端無關 seam 的命令

`@deepseek-ai/dsh-command-compact` 透過 `ctx.commands` 註冊一個無參數、面向使用者的命令。它呼叫第三個抽象 `CompactionEngine` 操作 `compactNow(agent, signal)`，並把封閉的 `ManualCompactionError` 分類體系（`busy | changed | summary | commit | persistence`）對映為直接 UI 結果。`command/run` 和 `command/done` 保留命令生命週期，同時不進入模型歷史，也不消耗模型迴圈輪次。

命令外掛程式會獨立跟蹤每個實際處理器 promise，不相依性命令執行器的中止感知等待。其複合生命週期 effect 先註銷 `/compact`，再非同步等待所有已開始的處理器結帳，因此根級 teardown 只有在後端的閉合與 flush 工作結帳後才會完全靜止。

該 seam 的 `ManualCompactAgentContext` 只在壓縮已需使用的工作階段與路由事實之上增加 `runMaintenance()`。保留、平衡、摘要、標記排序、替換與持久性仍由後端負責。

### 同步認領空閒維護階段

`Agent.runMaintenance(task)` 只能從空閒階段啟動，並會在呼叫任務前認領該 phase。會喚醒的傳送會在 idle 時立即啟動迴圈，因此先認領 phase 的操作會擁有該邊界。

維護階段不會建立第二個佇列。之後傳送的項保留其 `MessageId`、位置、FIFO 順序與喚醒資訊。會喚醒的輸入會保持排隊，直至維護任務結帳，再啟動既有驅動器路徑；`inject()` 仍然不會喚醒驅動器。

`whenIdle()` 會把維護任務及其結帳後釋放的所有喚醒工作視為尚未完成的活動。取消會中止 agent（代理）自有的維護訊號，生命週期 teardown 則會在 dispose（資源釋放）完成前排空同一個活動邊界。

### 一個參數化交易擁有每一對標記

`dsh-compaction-basic` 只有一個區域交易，由標記歸屬值（`number | null`）、穩定性規則（整個工作階段表層或所選區段）與選填 flush 參數化。它按同一順序執行：

1. 驗證所選位置範圍，並檢查持久日誌尾部；
2. 拒絕活動的未匹配壓縮標記；
3. 同步追加 `compaction/start`；
4. 準備並等待摘要；
5. 重新驗證所需穩定性；
6. 追加 `compaction/summary` 與替換用的 `user/message`；
7. 恰好嘗試一次 `compaction/end`；
8. 當手動呼叫方要求持久性時執行 flush。

自動和顯式區域工作使用從未閉合輪次復原的數字歸屬值，並要求整個工作階段表層保持穩定。手動工作會先預留接納，在進入交易前選擇有效範圍；選擇結果為 `null` 時不寫入任何內容。其標記對使用 `turn: null`，只要求所選區段保持穩定，並在 `finally` 中釋放接納預留前 flush 每次成功閉合的嘗試。

因此，`compaction/start` 是唯一的壓縮鎖。不存在 `WeakSet`、包裝層 mutex、locked／unlocked 方法拆分，也不存在交易外部重複的活動狀態檢查。

### 先記錄標記有意不同於調研過的實作

Codex 將手動壓縮建模為佔用其活動輪次槽位的 `CompactionTask`，自動壓縮則以內聯方式執行。Pi 使用壓縮 abort controller 是否存在作為 mutex，並僅在成功後追加壓縮。Claude Code 的自動和手動路徑共享同一個壓縮例程，但會在摘要流結束後才構造邊界。

DSH 有意在呼叫摘要器前記錄 `compaction/start`。緩慢或崩潰的嘗試因此可觀察，自動與手動路徑共享同一個持久鎖，之後的寫入方也不會把正在生成的摘要誤判為未鎖定工作階段。這是對先摘要行為的主動偏離，而不是偶然的事件順序差異。

### 標記是時間點，而不是事件容器

`compaction/start` 和 `compaction/end` 表示取得與釋放鎖。它們不聲稱排他擁有二者 seq 之間的每個事件。手動摘要等待期間，空閒的 `inject()` 可以追加 `user/message`，因此該不相關事件可能位於標記區間內。

手動穩定性只檢查所選區段：它必須仍然存在、連續、有序、計價相同且保持平衡。其外部的僅附加上下文不會使摘要過時。位置替換會把檢查點放在舊 span 的表層位置，並使注入上下文在派生模型歷史中位於其後，即使注入的日誌 seq 早於後續摘要和替換事件。

失敗的 `changed` 或 `summary` 嘗試會保持對話表層不變，但日誌並非沒有變化：其中會包含 `compaction/start` 和 `compaction/end { error }`。面向使用者的文字會明確說明這一區別。

### End-seed 區分活動與過時的未匹配標記

尾部掃描會分別尋找當前輪次、未匹配的 compaction start 與最新 `session/end-seed`。位於最新 end-seed 之後的未匹配 start 是活動鎖，會阻塞每個壓縮入口點。位於較新 end-seed 之前的未匹配 start 屬於更早的工作階段生命週期，已經過時，因此不會卡住復原或 fork 後的工作階段。

壓縮不變數在 seed 重播期間使用同一項轉換邏輯：`session/end-seed` 會清除未閉合的歷史追蹤狀態。此場景不要求構造函式即時發布該邊界；重播纔是承重路徑。

用戶端請求投影會在 `session/end-seed` 時刻將未匹配的壓縮請求以中斷狀態結束，並清除其活動索引。因此，後續 `compaction/start` 會建立一個獨立請求，而不是讓該殘留的未匹配請求永久保持執行狀態或將其覆蓋。

交易追加 start 後，每次後續失敗都會進行一次閉合嘗試。閉合失敗會有意留下可見且具有阻塞作用的未匹配 start，並且不嘗試 flush。已閉合的手動嘗試即使報告預期失敗也會 flush。完成必需的閉合與 flush 清理後，取消仍保留原始原因優先級。

### 參考實作邊界

一個未合併的參考實作為命令、預留、測試與快照結構提供了參考。它的行程本機 `WeakSet` 鎖與 locked／unlocked 方法拆分經過評估後未被採用，因為持久標記對是唯一可達的鎖。

該參考實作還包含用戶端側替換錨點機制，用於保留 transcript（文字記錄）位置。按日誌順序排列的 transcript 投影已經從事件順序消費壓縮，並且不會查詢可變表層位置，因此這些錨點經過評估後未被採用。

## 曾考慮的替代方案

**在啟動維護任務前檢查 `agent.status`。** 不予採用，因為檢查與 phase 認領會成為兩個獨立操作；會喚醒的傳送可能在二者之間啟動驅動器。

**把命令本身加入佇列。** 不予採用，因為 `/compact` 是直接控制而非模型輸入；先獲接納的提示詞必須保留優先權，不能圍繞第二個命令佇列重新排序。

**在追加 `compaction/start` 前生成摘要。** 不予採用，因為開銷較大的進行中操作將不可見，也不會參與自動壓縮共享的鎖。

**同時使用持久標記與行程本機 mutex。** 不予採用，因為兩套權威機制在重播後可能產生分歧，還會要求用包裝層分支處理標記對已經表達的狀態。

**與喚醒提示詞一起阻塞注入。** 不予採用，因為按約定，空閒注入是不會喚醒的持久上下文；延遲注入會使外掛程式排序相依性某個 UI 命令。

**要求標記區間只包含壓縮事件。** 不予採用，因為標記表示鎖的時間點。`compaction/summary` 會精確指明所選區間與被遮蔽 seq；排他性不會增加正確性，只會拒絕有效注入。

**把每個未匹配標記都永久視為 busy。** 不予採用，因為當機復原或 fork 後的工作階段會永久卡住。`session/end-seed` 是區分過時歷史與當前行程活動嘗試的顯式生命週期證據。

## 驗證

agent loop（代理循環）測試覆蓋同一 tick 內的優先權、保留 ID 與 FIFO 生命週期、會喚醒和靜默的排隊工作、冪等釋放、`whenIdle()`、取消與 teardown。壓縮測試覆蓋獨立與數字形式的不變數 owner、end-seed 重播、活動與過時未匹配標記、listener 重入、所選區段漂移、commit 與閉合失敗、flush 順序、原始取消原因、raw output 與 usage 保留，以及自動／手動互斥。

命令包固定註冊行為、Loader 組合、參數拒絕、精確的成功／失敗文字、取消、不進入模型歷史的保證，以及 dispose 在中止使執行器停止等待處理器後，仍會跨越相互獨立的閉合與 flush 邊界等待該處理器結帳。用戶端執行時期投影測試固定 end-seed 中斷，以及隨後一次獨立嘗試的完成。`queued-manual-compact` 終端機快照透過已組裝 TUI 驅動真實按鍵：`/help` 可發現該命令；被暫停的摘要會接納一個排隊提示詞和即時注入；`turn: null` 標記與 flush 先於排隊提示詞輪次；命令生命週期保持純日誌；派生順序固定為檢查點 → 注入 → 排隊提示詞。

## 後果

互動使用者無需消耗工作階段模型輪次即可壓縮有效歷史。在命令前獲接納的提示詞勝出；命令期間提交的提示詞會以原有佇列身份等待。手動壓縮會消耗工作階段 seq，但不消耗輪次編號。

日誌透過同一對標記暴露緩慢、失敗、崩潰與成功的嘗試。邊界前的過時未匹配標記不會再卡住新的生命週期，而當前未匹配 start 仍是嚴格的 busy 訊號。標記區間可以包含不相關事件，因此消費端使用 `compaction/summary` 記錄的 seq 與相對順序，而不假定存在連續且僅含壓縮事件的切片。

共享交易讓每個入口點保持同一種順序並使用同一把鎖。失敗報告會精確區分只有日誌發生變化、工作階段表層可能已部分改變，以及記憶體提交無法持久化這三種情況。
