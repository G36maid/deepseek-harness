# Agent Note: 載入全部指令候選並按目錄去重

Status: implemented

[English](2026-07-21-instruction-load-all-dedup.md) | 繁體中文

## 問題

[agent-instructions 外掛程式](2026-06-24-workspace-context.md)在每個目錄中為每個候選清單只解析出一個勝出文件：`instructionFileCandidates` 中第一個存在的名字贏得基礎槽位，[本機覆蓋層](2026-07-21-local-instruction-overlay.md)再追加一個勝出者。但 `AGENTS.md` 與 `CLAUDE.md` 經常共處同一目錄。在多數倉庫裡其中一個是另一個的符號連結，因此內容完全相同；在遷移中的倉庫裡它們則是兩個已經產生分歧的、彼此獨立的真實文件。先到先得會悄悄丟棄未勝出的已提交文件，於是一個合理地攜帶兩個不同指令文件的目錄最終只暴露其中一個——而暴露哪一個取決於候選順序，而非內容。需求是把兩者都讀取，僅在它們實質上是同一文件時纔去重。

## 決策

每個清單中每個存在的候選都會被載入——先基礎清單，再本機清單——按設定順序進行。在同一目錄內，內容在去除首尾空白後逐位元組相同的候選會合並到該順序中最靠前的候選，並渲染被保留文件的原始位元組。去重是按目錄進行的，而非全域性，並且在基礎清單與本機清單之間對稱。比較前先做去空白處理，可以容忍某文件與其近似副本之間的末尾換行或縮排差異，同時仍逐位元組渲染保留下來的文件——這正是需求所要求的「格外穩妥」的比較。

符號連結現在會統一經此流轉。指令發現會解析每個候選並對其目標做 stat，而非拒絕末段的符號連結，因此一個符號連結指向其同級 `AGENTS.md` 的 `CLAUDE.md` 會解析到相同內容，並在此像任何逐位元組相同的真實副本一樣被合併。因此內容去重會透過與真實副本相同的路徑把常見的符號連結映像檔只渲染一次。[跟隨符號連結說明](2026-07-21-follow-instruction-symlinks.md) 擁有該反轉決策及其殘餘的信任邊界風險。

## scope 鍵改為按候選劃分

現在每個 `(directory, candidateName)` 對都是各自獨立的邏輯 scope，編碼為 `directory\u0000candidateName`，其中 NUL 分隔符在真實路徑中不可能出現。`candidateScopeKey` / `decodeScopeKey` 負責這套編碼，`probeScopeInstruction` 則解碼候選名以精確讀取該文件。這取代了覆蓋層 note 引入的層級哨兵 scope 鍵：一個目錄不再有「基礎 scope」和「本機 scope」，而是每個候選名一個 scope，因此同一目錄中的 `AGENTS.md` 與 `CLAUDE.md` 是各自獨立協調的 scope。

由於一個 scope 現在只對應一個固定文件，此前的「同一 scope 內的候選切換」——即一個 `AGENTS.md` scope 回退到 `CLAUDE.md` 並把舊名字記錄在 `previousPath` 中——不再可能發生。`previousPath` 已從變更記錄、序列化的 `context/message` 元資料以及渲染文字中移除；一次變更現在要麼是 `set`、要麼是同一文件的 `replace`、要麼是 `remove`。移除某個候選會為該候選自己的 scope 寄出一個 `remove`，而把不同的同級文件留作獨立的 scope。

去重在協調過程中強制執行，而不僅僅在基線組合時。每一輪協調都會按候選順序重建一個按目錄的「已保留去空白摘要」集合，因此當更靠前的候選收斂到某文件的內容時，一個未變更的文件也會被移除，而新出現的重複同級文件會被丟棄或移除。版本快取在完整內容摘要之外還儲存一個 `trimmedDigest`，使快速路徑無需重新讀取內容即可重新判定是否重複。

## 備選方案

**每個候選清單保持先到先得。** 否決：這會悄悄丟棄一個目錄的第二個已提交指令文件，並使勝出者取決於候選順序、而非文件是否真的不同，而這恰恰是需求要消除的意外。

**全域性的、跨目錄的去重。** 否決：兩個不同目錄下相同的樣板內容對各自而言都合理地在作用域內，而更深層的文件對於該更深目錄下的工作仍必須暴露。跨目錄合併會隱藏模型本應看到的指令。

**不做去空白、直接比較原始位元組。** 否決：一個新增末尾換行的編輯器，或一個重排縮排的副本，都會讓實質相同的文件無法去重。比較前去空白正是需求所要求的寬容鍵，而保留下來的文件仍渲染其原始位元組。

**跟隨符號連結，從而讓映像檔透過內容去重。** 為本次改動否決以保留「不跟隨」不變式，隨後另行採納：[跟隨符號連結說明](2026-07-21-follow-instruction-symlinks.md) 反轉了該不變式，此後符號連結映像檔會被解析，並像真實副本一樣透過內容去重。

## 後果

一個攜帶兩個不同真實指令文件的目錄現在會把兩者都暴露；一個第二個文件僅僅是映像檔的目錄仍只渲染一次，而無處不在的符號連結場景保持不變。可見的行為差異被限定在攜帶兩個不同真實文件的遷移期倉庫中。scope 鍵的形態從層級哨兵改為按候選劃分，`previousPath` 也從持久化的變更元資料中消失；`dsh-session` 對舊工作階段不作相容承諾，因此兩者都是無成本的改動。版本快取行新增了一個 `trimmedDigest` 欄位，協調過程現在按目錄比較去空白後的內容，因此一個未變更的文件可以被同級文件的收斂所移除——這是[狀態模型](2026-06-24-workspace-context.md)此前無法產生的轉換。
