# Agent Note: 基於日誌的工作階段標題

Status: implemented

[English](2026-07-21-log-backed-session-titles.md) | [简体中文](2026-07-21-log-backed-session-titles.zh.md) | 繁體中文

## 問題

工作階段需要一個面向使用者的簡短標題，編輯器、終端機或查詢消費端纔能有效呈現它。成本最低的實作可以從第一條提示詞派生標題，質量更高的實作則可以讓模型處理第一條提示詞或整個對話。這些策略在延遲、成本、路由和重試行為上各有不同，但所有消費端都需要一個持久的真源。

工作階段身份元資料不可變，事件日誌是重播和 fork 的邊界。模型生成的標題往往在主輪次結束後才完成，因此同步寫入會延遲 agent（代理）回應，而作為可變元資料寫入則會繞過常規的持久化、重播和沿襲語義。並行提示詞、提供方 HMR（熱模組替換）、取消以及被忽略的中止訊號，還可能讓未受版本校驗約束的後臺結果覆蓋更新的標題。

## 決策

[`session-title` 能力包族](../../../../packages/session/README.md)負責標題狀態和生成策略。`@deepseek-ai/dsh-session-title` 提供 `ctx.sessionTitle`、確定性的首訊息回退方案，以及一個至多接受單個選填非同步提供方的登錄檔。`@deepseek-ai/dsh-session-title-llm` 負責通用的輔助模型請求策略；首訊息外掛程式和全部使用者訊息外掛程式分別選擇輸入調度方式。共享 agent 主幹只掛載回退服務。Web host 會掛載該服務和首訊息模型提供方，並顯式設定可覆蓋的限制，因此新建的 Web 工作階段會立即獲得回退標題，隨後在不阻塞主回應的情況下獲得模型摘要。其他組合需顯式選擇任一模型提供方。

### 事件歸屬與摺疊

每個已接受的修訂都是純日誌 `session/title` 事件。其載荷包含規範化後的非空文字、用於派生標題的所有合格且來源為人類的 `user/message` 的準確 seq，以及回退來源 kind，或已註冊的提供方 id 加選填的提供方和模型路由。輔助標題模型發起呼叫前，共享輔助元件會追加一個純日誌 `session/title-llm-request` 事件，其載荷包含標題提供方 id、準確的源 seq、路由、系統提示詞、訊息和輸出 token 上限；即使後續生成失敗，這次請求仍可審計。傳送的請求信封經過深度凍結，以確保其與該記錄精確一致，但它有意不攜帶行程本機的 agent loop（代理循環）請求身份，因此僅針對 agent loop 的重建檢查不會將它與主對話請求標頭進行比較。未進入呼叫階段的驗證失敗不會建立請求事件。`foldSessionTitle()` 選擇最新的標題事件，並將該事件的 seq 和時間戳加入 `SessionTitleSnapshot`。這兩類事件都不會進入 `session.surface` 或 `deriveMessages()`。

標題服務會在檢查當前修訂和確切的即時工作階段後，直接追加 `session/title`；隨附模型輔助函式同樣會在發起呼叫前追加其字面量 `session/title-llm-request` 記錄。兩類記錄都可以位於輪次之間，而無需虛構執行邊界。持久化會將它們接納到有界後臺批次中，並透過常規檢查點和生命週期 teardown 排空；標題發布不會強制逐事件 flush。事件所有方與 `Session.append()` 之間不存在通用標記、類型斷言或結帳佇列。這是[獨立純日誌事件決策](../simplification/2026-07-28-remove-synthetic-log-only-turns.md)在特定領域中的應用。

### 輸入與非同步時序

只有人類來源的 `user/message` 事件中的文字塊才符合條件。空提示詞、僅含控制內容的提示詞和非文字提示詞會等待下一條合格訊息。服務從提示詞路徑調度首個回退標題而不等待其完成，隨後規範化空白和控制序列，應用已設定的單詞數和 UTF-8 位元組限制且不拆分程式碼點，並記錄第一則訊息的 seq。

僅當主迴圈存在已記錄在日誌中的當前提供方/模型路由時，自動提供方工作才會啟動。`request/header` 新追加到日誌時，會直接啟動待執行工作；如果請求標頭沒有變化，則由迴圈建置並帶有標記的 `llm/stream` 請求會先與摺疊所得的路由匹配，再啟動該工作。隨後，生成工作獨立於 agent 回應執行；完成結果會追加一個獨立事件，而不改變輪次狀態。顯式呼叫 `refresh(session, signal?)` 會生成尚缺的回退標題並等待已註冊的提供方；沒有提供方時則返回回退標題。呼叫方取消不會回滾已接受的回退事件，`refresh()` 會在返回成功前重新檢查訊號。並行刷新會在提供方工作之前預留工作階段本機修訂號，因此較新的呼叫會在任何呼叫有機會造成提供方完成順序倒置之前中止並取代較早的呼叫。自動工作與並行刷新在每個工作階段內共用同一個進行中的回退 promise，因此首次回退只會建立一個標題事件。非同步壓縮（compaction）期間接受的標題仍是純日誌事件，因此壓縮器在摘要完成後執行的表層節點檢查不會因該標題而失敗；並行的表層變更仍會使替換失效。

首訊息提供方僅在新工作階段首次建立回退標題時調度一次。自動執行失敗後，後續提示詞不會重新調度；`refresh()` 是重試路徑。全部訊息提供方會在每條合格且由人類寄出的提示詞後調度，並傳入截至該修訂的所有合格訊息，包括預置歷史記錄。較新的修訂會中止並取代更早的待執行或活躍工作。

### 註冊、路由與失敗策略

`register(provider)` 會驗證一個帶品牌類型的穩定 id、執行時機和生成函式，然後返回一個可等待完成的 effect dispose（資源釋放）函式。第二個活躍註冊會立即拋出錯誤。對提供方註冊執行 dispose 時，會將註冊標記為正在關閉，中止其待執行和活躍工作，並等待所有呼叫結束後才移除註冊，因此替代提供方不會與忽略取消的舊提供方重疊執行。工作階段 dispose 會中止其活躍工作。服務解除安裝時，會阻止排隊中的回退和提供方微任務啟動，中止活躍工作，並且解除安裝完成前會等待所有已跟蹤的 promise 結帳。每項工作階段本機生成都有單調遞增的修訂號和確切的註冊身份；接受結果時會重新檢查修訂號、註冊、工作階段活躍狀態、服務活躍狀態和取消狀態，因此過時輸出無法提交。

模型提供方必須顯式設定單詞數、CJK 字元數、輸入位元組數、輸出 token 數和逾時限制。選填的 `provider` 和 `model` 覆蓋項必須成對提供；兩者均未提供時，輔助元件會使用主請求已記錄請求標頭中的準確路由。系統在一條固定且能區分語言的指令下，將選中的訊息封裝為 JSON。寄出的 `GenerateOptions` 攜帶 `purpose: 'session-title'`；DeepSeek 配接器將該用途對映為停用思考且省略推理強度設定的請求，使受限輸出成為可見的標題文字，而主對話仍沿用已設定的思考模式。輸入位元組數按最終形成的使用者提示詞計算，其中包括包裝文字、seq 欄位和 JSON 轉義；系統會在記錄請求或發起呼叫前完成這項檢查。過大輸入會被拒絕而不是截斷，因為截斷會讓記錄的源訊息 seq 錯誤地表示這些訊息已被完整使用。系統在消費每個流區塊時以及流完成後都會檢查融合後的截止時間，因此即使攔截器或配接器忽略中止訊號，逾時後返回的成功結果也不會被接受。

自動提供方故障只會寄出非致命警告，並保留最新標題。顯式刷新失敗則會使呼叫方的呼叫被拒絕。輸出必須是非空文字，並包含來自固定請求、唯一且有序的 seq；服務會在日誌接受前對其進行規範化並施加位元組限制。

### 顯式重新命名

`rename(session, title)` 同步接受使用者標題：按已接受標題的位元組上限規範化文字、取代運送中自動工作，並追加一條第三種來源 `user` 的 `session/title` 事件。最新標題來源為 user 即釘住該工作階段：只要它還在，`onUserMessage` 在任一節奏下都不再安排自動修訂。顯式 `refresh()` 仍是有意的解釘手段——只要能推匯出替代標題，它就在被釘住的標題之上追加提供方或回退事件（推導不出回退標題時，例如位元組上限過小，釘住狀態保持不變）。Web host 將其暴露為 `session.rename` unary 方法（冷工作階段先復原），並返回規範化後的標題及其事件 seq，使 client 在推送幀到達前就結帳自己的 `title` 投影格。

### Fork 與消費端

與源日誌的其他部分相同，fork 會原樣繼承作為種子的標題事件——被釘住（user 來源）的標題在子工作階段中保持釘住，直到顯式 refresh。首訊息提供方不會自動為 fork 重新生成標題。全部訊息提供方可以在子工作階段出現後續提示詞後追加一項歸子工作階段所有的修訂，並使用繼承的合格訊息和新增的合格訊息。

`ctx.sessionQuery.readTitle()` 會摺疊一份即時優先或已持久化的日誌，而不會在 `listSessions()` 期間載入標題。TUI 使用最新標題作為其標題欄副標題，並在完成終端機安全渲染後，將終端機視窗標題設定為 `<session title> — <configured product title>`。Web host 會在每個已附加工作階段的訂閱基線之後，以及轉發即時原始標題事件後立即，將同一份日誌狀態摺疊為經過校驗的 mux 控制幀。即使控制幀先於清單或工作階段實例建立抵達，瀏覽器也只保留標題事件 seq 較新的版本；側邊欄標籤、搜尋、麵包屑導覽和瀏覽器標題會隨投影后的修訂更新。`session.list` 仍只包含元資料，因此尚未打開的持久化工作階段會繼續以 cwd 基名或 id 作為回退，直至打開或復原工作階段時附加其日誌。瀏覽器僅在選中已有標題的工作階段時將標題設定為 `<session title> — <existing HTML title>`，否則保留產品標題。報告 agent 完成情況的消費端使用核心的 `foldConsumedWork()` 摺疊邏輯，因此後續的輪次間標題記錄無法取代此前由訊息觸發的結果。

## 考慮過的替代方案

- **可變 `SessionHeader` 或獨立元資料**：不予採納，因為這會建立第二套持久化變更協議，削弱不可變身份元資料，讓崩潰原子性因後端而異，並使 fork 的複製或引用行為產生歧義。僅附加日誌已經負責可重播的後寫覆蓋狀態。
- **返回 agent 回應前等待標題生成**：不予採納，因為輔助提供方的延遲和故障會進入主互動的關鍵路徑。確定性回退方案可以立即提供可用狀態，質量更高的標題則可稍後到達。
- **將標題放入派生歷史記錄或請求前綴**：不予採納，因為 UI 元資料會消耗 token、改變快取標識，並讓主模型觀察到自己的標籤。純日誌事件既保持可重建，又不會變得對模型可見。
- **允許註冊多個提供方，並在完成後解析優先級**：不予採納，因為完成順序並不等於產品優先級，而且會讓重試、HMR 和已記錄的提供方變得不確定。需要組合策略的部署可以註冊一個自行負責該策略的提供方。
- **靜默截斷過大的輔助輸入**：不予採納，因為提供方結果會引用源訊息 seq，卻沒有收到這些訊息的完整文字。保留原有標題並行出警告，可以保留準確的輸入記錄。
- **立即在 `listSessions()` 中索引標題**：不予採納，因為現有的輕量元資料清單將需要逐後端同步派生索引。精確的 `readTitle()` 建立了讀取約定，而沒有提前鎖定搜尋或索引策略。
- **讓 Web host 只使用回退標題**：不予採納，因為 UI 雖會顯示持久標題，卻始終無法將第一條提示詞的前綴改進為更好的標題。首訊息提供方在主回應路徑之外執行，並讓模型摘要成為 Web 的默認結果。

## 後果

- 標題可以在 JSONL 和 SQLite 持久化中存續、重放並遵循 fork 繼承語義，而無需單獨的可變記錄。
- Web 標題仍以增量方式從日誌交付，無需標題索引或掃描持久化清單；冷工作階段的清單項會在工作階段附加後改用標題。
- 回退標題會立即出現。每個新建的 Web 工作階段都會增加一次針對首訊息的輔助呼叫；其他組合可以自行決定更優標題是否值得模型成本，以及後續提示詞是否需要重新生成工作階段標題。
- 輔助請求記錄和延遲接受的標題會佔用事件 seq，但不會佔用輪次編號，因此持久化會同時呈現嘗試發起的呼叫與已接受的更新，儘管模型歷史和 KV Cache 標識保持不變。
- 單個提供方和每工作階段單調遞增的修訂號讓 dispose、取代和過時結果拒絕行為明確可見，但多策略優先級必須由複合提供方負責。
- 刪除（不經顯式 refresh 的解釘）、搜尋和清單索引不在此能力範圍內。
