# Agent Note: 軌跡檢查記錄表

Status: implemented

[English](2026-07-27-trajectory-inspection-ledger.md) | [简体中文](2026-07-27-trajectory-inspection-ledger.zh.md) | 繁體中文

## 問題

軌跡檢視表需要在同一視口內清晰呈現正文、機器載荷、token 用量、計時資料和巢狀工具活動。此前堆疊式的輪次與步驟卡片雖然保留了層級，卻在重複介面框架上耗費了太多垂直空間；完全扁平化的表格又會抹去因果結構，而這種結構正是軌跡檢視表的價值所在。角色配色還可能借用成功與警告語義，使視覺裝飾與執行時期狀態無法區分。

## 決策

**使用現有 DeepSeek 設計系統，渲染保留輪次結構的緊湊事件記錄表，並提供區域性記錄檢查器。**

- 記錄表在已載入視窗內按 Session Event 順序展示物化後的業務記錄。輪次邊界由稍粗的分隔線、原始輪次 id 和連續的左側豎線表示；請求邊界以融入該結構的小圓點表示，普通請求與壓縮（compaction）請求在整個時間序列中共用一套編號。
- 事件類型與內容構成兩個穩定列。角色標籤朝內容側對齊，巢狀子工具略微縮排，內容預覽使用 CSS 截斷以適應可用寬度。token 用量和耗時留在檢查器中。
- 產品正文使用現有無襯線字體棧。輪次 id、token 數、耗時、工具呼叫、原始載荷和其他機器資料使用現有程式碼字體棧。
- 現有主題 token 同時負責亮色和暗色渲染。中性邊框與表面構成整體結構；相互區分的低強調度角色色幫助掃讀而不表達成功或失敗語義，業務藍色則標識選擇狀態、連結和焦點。
- Session 統一擁有一份連續 Event 視窗、分頁狀態、即時缺口修復與重連重建。Chat 與 Trajectory 針對共享的 `ConversationNodeAssembler` 分別註冊業務 Definition；Trajectory 從 `Session.views` 讀取自己的 target snapshot，並在使用者到達已載入範圍頂部時請求一頁更早的 Session 歷史。[Trajectory Context 組裝決策](../architecture/2026-08-11-trajectory-conversation-context-assembly.md)負責其精確 ID Definition、stage Builder 與複雜度上界。
- 普通生成呼叫與壓縮呼叫形成一條按時間排序的請求投影，以用途區分而不是放入不同集合。生效的提示詞狀態及其變化附著在引入它們的請求上；壓縮和提示詞變化都不是獨立檢查實體。請求編號和累計用量覆蓋已載入的歷史視窗，並隨更早頁面到達而擴充。
- 呼叫 schema 來自當前生效且已記錄的請求標頭。無金鑰快照 fixture（測試前置資料）有意將該目錄替換為非陣列 token `{{tools}}`，持久化檢查邊界會將其視為不可用，而不是嘗試投影或虛構 schema。
- 選擇記錄或請求後，Trajectory 內部會打開檢查器，其分頁標籤和概述區域隨實體類型變化：Markdown 訊息提供渲染內容、來源欄位、提供方／模型欄位和層級檢視表；工具提供 JSON 載荷／結果和 schema 檢視表；請求提供選項、用量、計時和結果跳轉。可滾動的概述區域默認保持捲軸滑桿透明，直到懸停或 `focus-within` 時才顯示，同時保留捲軸預留空間和滾動行為。圖片以媒體形式渲染，而不是顯示為序列化資料。
- 摺疊輪次時保留其第一條記錄，並用緊湊的步驟數和工具呼叫數替換後續所有行；摺疊助手時對其工具呼叫後代應用相同操作。全域性控制元件會摺疊或展開這兩個層級。
- 長記錄表初始時將已載入尾部置於底部，只掛載視口對應的行視窗及有界的額外緩衝行。僅含請求的分隔行並入下一個具備可測高度的虛擬項，末尾分隔行則保留固定留白，因此虛擬化器不會管理零高度項。可安全用於 DOM 的語義行鍵與 ARIA 索引使標識不相依性掛載位置。只要已知尾部之前仍有更早歷史，即使當前已載入投影低於常規行數閾值，也會立即啟用虛擬化。基於穩定鍵的虛擬化器錨定會在向前補頁和尾部追加時保留當前可見項；只有分頁完成導致虛擬化停用時，才使用手動滾動高度兜底。選擇、時間線聚焦、摺疊、搜尋和末尾跟隨均按穩定的事件或工具呼叫標識定位，不要求對應 DOM 行已存在。初始定位完成前，明確的載入行會遮住真實記錄。更早的 Session 前綴仍未載入時，互動式首行位於已載入記錄之前，可請求一頁更早歷史；頁面載入期間，同一行會變為停用的載入狀態，僅在分頁完成時消失。
- 移除獨立的 waterfall（瀑布式事件）分頁標籤。固定在記錄表上方的 Overview 區域將所有 `startedAt` 已知的已載入記錄按各自耗時投影到三條語義計時軌道。仍有更早前綴尚未載入且 viewport 包含已載入時間域起點時，中性的省略號控制元件會遮住截斷邊緣並載入一頁更早歷史，而不會為未知歷史虛構耗時；懸停在該控制元件上會隱藏普通的時間線遊標。已完成的助手時間條以首個非空 token 增量為分界，用不同顏色按真實比例表示 TTFT 與解碼時間；計時不完整時退化為單一助手色。懸停 500 ms 後會顯示精確起止時刻、總耗時、TTFT 和解碼時間，而不相依性瀏覽器原生 tooltip 的延遲。向左或向右拖動會提交包含邊界的區間篩選：任何活動區間與所選區間任一邊界重疊的記錄都會保留，計時未知的記錄會從聚焦後的記錄表中移除，清除選擇則復原完整的已載入記錄表。滾輪手勢用於縮放時間域。右鍵單擊會清除區間選擇；右鍵拖動則只會平移已放大的 viewport，不會改變該選區。聚焦後，Overview 區域仍保留完整時間範圍，以便在不失去方位的情況下調整或清除選擇。
- 即時歷史更新僅在使用者已經跟隨記錄表末尾時保留底部位置。向上滾動會清除跟隨狀態，因此流式分塊和新追加的記錄不會打斷對舊記錄的檢查。末尾跟隨與虛擬化器測量僅回應行鍵和高度，而非內容標識，因此僅含文字的流式幀既不會丟棄測量快取，也不會重複執行 DOM 滾動寫入。
- token 流式輸出只更新命中的 Trajectory Assistant Context，發布則合併為每個 animation frame 最多一次。target snapshot 繼續提供既有 stage、layout、請求編號、Overview 與搜尋輸入；已完成的 Assistant State 只保留組裝後的 blocks、計時與 usage，不保留每條原始 chunk payload，而 Session 繼續保存原始 Event 視窗。
- 每個 Trajectory Definition 都從當前 Event 提取穩定 ID，共享 Assembler 只 replay 因 Match、Location 或 Reader 變化而受影響的 Context。更早 Session 頁面 prepend 到同一個引擎視窗；Trajectory target builder 再把已物化 Node 轉換為記錄表繼續消費的 stage-oriented snapshot。
- Trajectory 透過 `data-conversation-composer-overlay` 啟用由工作階段持有的 composer 浮層模式。`ConversationRoot` 負責定位 composer seat 並行布其即時高度；Trajectory 讓記錄表保持全高，並在記錄表與檢查器的縱向滾動容器內預留該高度加 16 px。這兩個窗格會根據可用寬度自適應，而不會在浮層下方暴露橫向捲軸。
- 此區域性檢查器與工作階段級 Chat 詳情欄相互獨立。在窄屏下，檢查器會覆蓋記錄表，並且仍可透過鍵盤或指針關閉。

## 曾考慮的替代方案

**照搬 Vite DevTools 的字體、顏色、玻璃表面或元件形狀。** 不予採納：這些選擇表達的是另一種產品身份。實作僅吸收可遷移的方法，即中性結構、語義強調色、機器資料排版、緊湊掃讀，以及只為浮層保留陰影。

**每個輪次和步驟保留一張卡片。** 不予採納：重複的卡片框架減少了可見記錄數量，並降低了跨步驟比較的速度。

**在表格中掛載每條投影記錄。** 不予採納：記錄投影仍可用於搜尋、計時和導覽，但把每一行及其後代都保留在 DOM 中，會使瀏覽器渲染開銷隨完整工作階段成長，而非隨可見視口成長。

**Trajectory 掛載時補齊所有歷史頁面。** 不予採納：完整工作階段指標可以立即獲得，但傳輸並反覆投影含大量區塊的舊頁面會延遲對當前尾部的檢查。按需向前分頁會讓這項成本隨使用者導覽產生。

**每收到一個流式 token 區塊就重建已載入記錄表。** 不予採納：虛擬行限制了 DOM 工作量，卻不會讓反覆摺疊歷史變得低廉。保持已完成投影穩定，可以讓普通增量的成本只隨當前未完成部分成長，而結構事件仍是顯式的完整重建邊界。

**不使用輪次或請求邊界，將所有記錄完全扁平化。** 不予採納：軌跡並非普通日誌流；這些邊界無需佔用獨立行，也能保留因果結構。

**複用全域性 Chat 詳情欄。** 不予採納：這會讓區域性檢查與工作階段導覽耦合，還會使行點擊意外改變另一個檢視表的狀態。

**由 Trajectory CSS 覆蓋 composer seat。** 不予採納：跨包選擇器會相依性生成類選擇器的優先級和樣式表順序。顯式檢視表標記讓 seat 幾何形狀和活躍階段優先級留在 `ConversationRoot` 中，而 Trajectory 只負責自身內部的避讓空間。

**將計時保留在獨立的 waterfall 分頁標籤中。** 不予採納：佔位實作彙總的是節點數而非記錄計時，並迫使使用者離開想要聚焦的記錄。保留完整時間範圍的 Overview 區域讓計時和篩選後的記錄處於同一視覺上下文中。

**修改全域性主題 token 以匹配參考設計。** 不予採納：現有主題已經提供配對的亮色與暗色語義層，區域性重新設計不足以成為修改無關表面的理由。

## 後果

軌跡檢視表在保留輪次與請求定位的同時，每個視口可以顯示更多有效記錄。上下文 `rewrite` 與壓縮會作為當前物化的業務記錄，按順序出現在周邊歷史中。浮動 composer 讓記錄表一直顯示到視口邊緣，同時不會遮住最後幾行，也不會隱藏橫向控制元件。主記錄表省略 token 用量和耗時，讓內容獲得可用寬度；區域性檢查器展示這些資料以及完整載荷、提供方／模型欄位、來源欄位、schema 和請求計時。Overview 區域使用記錄的開始時間、耗時與 token 邊界資料，而不虛構即時流逝時間，其包含邊界的聚焦行為與使用者熟悉的 Chrome DevTools Network 互動一致。尾部優先分頁限制初始傳輸工作，虛擬化限制已掛載的行元素數量，精確 ID 分發避免重新 fold 無關業務 Context，animation-frame 發布則限制流式 snapshot 頻率。保留的 stage-oriented target builder 在一次發布中仍可能執行與已載入物化 Node 數量成比例的工作；本次遷移不額外承諾更強的 Trajectory 專屬複雜度。針對性元件測試鎖定尾部優先分頁、向前補頁錨定與標識保持、虛擬視窗、末尾跟隨、僅含內容的流式輸出不會重複寫入滾動位置、計時投影、延遲展示詳情、摺疊、記錄與區間選擇、實體特定分頁標籤和執行／錯誤語義。真實瀏覽器中的長記錄表約定鎖定向前補頁時穩定的幾何位置、有界掛載、頂部／中部／底部可達性，以及按節奏進行的流式輸出中有界的滾動寫入；組裝後的 Web 快照則透過真實用戶端組合鎖定記錄表、Overview 計時詳情、composer 浮層幾何形狀與檢查器。
