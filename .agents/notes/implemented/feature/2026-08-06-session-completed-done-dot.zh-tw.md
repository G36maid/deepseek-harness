# Agent Note: 側邊欄工作階段完成提醒點

Status: implemented

[English](2026-08-06-session-completed-done-dot.md) | 繁體中文

## Problem

操作者派發任務後切換到其他工作階段，原工作階段完成時沒有任何訊號。執行指示停止後，該行與普通空閒工作階段看起來完全一樣，操作者只能反覆查看清單或很晚才發現工作已完成。等待互動的琥珀點只覆蓋需要操作者輸入的工作階段，不覆蓋「只是幹完了活」的工作階段。

## Decision

`SessionManager` 持有用戶端側的完成提醒集合，與待互動位並列：非當前工作階段發生 running→idle 邊沿時點亮其提醒；`select()`/`selectSubagent()` 消費掉提醒；重新開始一輪執行會熄滅提醒並在再次完成時重新點亮；工作階段被移除時清理提醒。該位經 `SessionListEntry` → `SessionSummary`（選填欄位，預設 = 無提醒）進入工作區瀏覽區，其工作階段行與搜尋結果行渲染現有的 `StateDot` `done` 狀態——執行中仍顯示轉圈，無提醒的空閒工作階段不顯示任何點——懸停卡片將該提醒標注為「已完成 / Completed」。

提醒僅存在於記憶體中且按瀏覽器實例隔離。它跨連線代存活——傳輸抖動不會使「你還沒回來看」失效——但頁面刷新後重置。

## Consequences

側邊欄行狀態成為三個互斥訊號：綠 = 已完成且未查看，琥珀 = 等待操作者輸入，藍 = 執行中。協定格式（wire format）、磁碟格式或設定格式均無變更：`SessionSummary.completed` 為選填欄位，現有消費端與 fixture（測試前置資料） 保持有效，只有工作區瀏覽區讀取它。完成邊沿在每次清單變更與拉取時即時偵測（僅在建快照時偵測會把連續兩個狀態幀摺疊為一次觀察，從而漏掉完成事件）。

## Alternatives considered

- **元件本機 UI 狀態。** 已拒絕：側邊欄摺疊時會解除安裝，且多個介面（分組樹、扁平清單、搜尋）需要同一狀態位；manager 本就持有執行狀態遷移與選中狀態，manager 持有的集合是所有介面都能投影的唯一真源。
- **僅從狀態幀做事件驅動點亮。** 已拒絕：清單拉取本身也可能攜帶 running→idle 遷移（刷新運送中時工作階段已完成）；提醒需對每次變更與拉取做對帳。
- **持久化提醒。** 已拒絕：提醒的含義是「此瀏覽器裡你還沒查看該工作階段」；刷新會復原選中狀態且使用者正看著清單，持久化位只會變得過時。
