# Agent Note: 持久的逐步驟時間上下文

Status: implemented

[English](2026-07-16-durable-per-step-time-context.md) | [简体中文](2026-07-16-durable-per-step-time-context.zh.md) | 繁體中文

## 問題

僅存在於請求中的時鐘可以告訴模型當前時間，但在系統提示詞中替換這個值會移除先前對時間敏感的推理所依據的證據。在包含多個步驟的輪次中，請求需要保留先前步驟使用的讀數。系統必須能在重新啟動後重建請求，自動壓縮（compaction）也必須將模型實際收到的同一份時間上下文納入考量。

行程本機刷新快取會使顯示時間相依性於無法在復原後保留的狀態。來自瀏覽器的自然語言也需要歸屬於請求的時區：伺服器端行程時區無法推斷使用者所在地，而可變的工作階段或連線預設值會讓旅行或並行分頁標籤重新解釋另一條提示詞。

## 決策

`@deepseek-ai/dsh-time-context` 是位於 `packages/context/time-context/`、需要顯式啟用的函式外掛程式。默認組合不啟用其披露內容與 token 成本；Schedule Web overlay 會掛載它，使模型能夠按附加到當前請求的瀏覽器時區解釋未明確限定時區的日期和時間。

該外掛程式會前置一個 `agent/pre-step` 監聽器，並先行委託下游。當下游決策進入步驟且需要生成讀數時，外掛程式會把該決策的最終訊息與開放輪次中已有的持久使用者訊息合併，從確切的 user-rpc 來源派生瀏覽器時區來源資訊，並向該決策追加一條讀數。決策被拒絕、監聽器失敗或訊號已經中止時，不會記錄任何內容。在當前批次之後被認領的 steering（中途引導）仍歸屬於普通的下一步驟，並在該步驟進入時獲得新讀數。

每條 Web 提示詞都會取樣瀏覽器的 IANA 時區。Host 校驗並規範化該值，再將其綁定到確切的持久使用者訊息來源。開放輪次中唯一一個時區可解析請求；多個時區會產生排序後的 `mixed` 結果；沒有時區則為 `unavailable`。解析成功的請求會告訴模型，把未限定時區的日期和時間解釋為該時區。來源資訊混雜或不可用時，模型會收到要求使用者澄清的指令。

這種與訊息綁定的來源資訊不會複製到 `SessionHeader`、連線預設值或 Schedule 狀態。Time-context 只負責模型指導。接受本機日曆欄位的工具仍必須自行定義顯式邊界；因此 Schedule 要求 `time_zone`，而不是匯入該外掛程式的讀數（[決策](../simplification/2026-08-09-explicit-schedule-time-zone.md)）。

解析後的瀏覽器時區也用於格式化讀數中的時間戳。請求來源資訊混雜或不可用時，使用設定的 `timeZone` 回退值；如果省略該設定，則使用外掛程式載入時解析一次的 Node 行程時區，同時仍保留要求澄清的策略。每個回退值都經 `Intl.DateTimeFormat` 校驗。

每個讀數都使用確切的快照來源 `{ kind: 'plugin', plugin: 'time-context', form: 'snapshot', sections: [{ name: 'time-context', text: <same text> }] }`。不變式配套模組會校驗快照形狀，從原始 user-rpc 訊息重新派生當前輪次的瀏覽器來源資訊，並校驗渲染的時間戳時區與經過時長基線。

選填設定 `refreshIntervalMs` 必須是非負安全整數。省略或設為 `0` 時，每個符合條件且已進入的步驟都會注入。設為正數時，外掛程式會掃描原始工作階段事件，尋找最新的外掛程式讀數；不存在學數、掛鐘時間倒退或事件已達到相應時長時執行注入。事件時間戳在壓縮和復原後仍是判斷依據，無需行程本機快取。Schedule Web overlay 會省略該間隔，使每個請求步驟都獲得當前瀏覽器時區指導。

### 文字與時長基線

已解析的第一步讀數為：

```text
Time sampled while preparing turn <turn>, step 1: <timestamp-in-browser-zone>
Browser time zone for this request: <iana-zone>. Interpret otherwise-unqualified dates and times in this zone.
Elapsed since the preceding model-visible message: <duration-or-unavailable>.
```

混雜和不可用的變體會把第二行替換為要求澄清的指令。基線是最新一條在其之前持久化的使用者、助手或工具結果訊息。為該步驟擬議的提示詞尚未追加，因此新工作階段可能報告 `unavailable`。

後續步驟讀數會改變第一行的步驟號，並以下行結束：

```text
Elapsed since the preceding step context: <duration-or-unavailable>.
```

其基線是開放輪次中的前一個 time-context 事件。缺少基線時報告 `unavailable`；時長採用緊湊的整秒單位，並在掛鐘時間倒退時限制為零。

### 持久性與重建

已進入的步驟會在 `step/start` 之後、請求派生之前，先追加其返回訊息，再追加時間讀數。後續準備失敗時，讀數可能留在歷史中，因為它記錄的是步驟進入，而不是成功傳輸。每個讀數都作為普通表層節點保留，直至壓縮將其遮蔽。正數間隔可以讓後續請求複用現有歷史，而不新增新讀數。

外掛程式不向系統提示詞組裝或 `request/header` 貢獻任何內容。請求重建會在每個 `step/start` 取得完整的持久表層前綴，因此歷史請求可以還原模型看到的確切時間與瀏覽器策略。

## 已考慮的替代方案

- **替換動態系統提示詞值**：不予採納，因為替換會抹去先前讀數，並改變重建後的歷史請求。
- **持久化工作階段默認時區**：不予採納，因為瀏覽器事實只屬於一條提示詞；旅行與並行分頁標籤不得修改共享含義，也不得把時區狀態擴散到工作階段、fork 與持久化約定中。
- **把瀏覽器時區複製到第二個上下文權威**：不予採納，因為原始 user-rpc 來源已經擁有該值，不變式可以直接重新派生策略。
- **讓 Schedule 隱式消費讀數**：不予採納，因為自然語言上下文不是穩定的類型化預設值，而且這會把絕對時間解析器耦合到 AgentLoop 歷史。模型會改為傳入顯式偏移量或時區。
- **只使用行程時區**：不予採納，因為部署所在地無法推斷遠端使用者的時區。請求來源資訊缺失或混雜時，它仍可作為顯示回退值。
- **只透過工具提供時間**：不予採納，因為普通時間推理會產生本可避免的往返，也無法確保每個步驟之前都有讀數。
- **默認掛載 time-context**：不予採納，因為披露內容、新鮮度與歷史成本仍屬於組合策略。

## 驗證

單元測試和真實 agent loop（代理循環）測試固定時間戳格式化、唯一／混雜／缺失瀏覽器時區的派生、回退顯示、兩種經過時長基線、間隔邊界、跨輪次與復原後的調度、掛鐘倒退行為、steering 歸屬、取消、精確快照校驗和請求重建。Host/client 測試固定瀏覽器取樣，以及提示詞進入時的校驗與規範化。無金鑰的組裝 Schedule Web 場景傳送一條真實瀏覽器提示詞，在模型請求中觀察到同一時區，並驗證模型把該時區顯式傳給 `schedule_create`。

## 後果

- 瀏覽器時區含義歸屬於請求並可持久重建，無需更改工作階段、fork、JSONL 或 SQLite schema。
- 模型在每個 Schedule Web 請求步驟中都會收到所請求的瀏覽器本機假設；來源資訊混雜或缺失時會詢問，而不是猜測。
- 工具仍保持顯式邊界：上下文幫助模型選擇欄位，但不會成為包 seam 上隱藏的預設值。
- 時間上下文僅附加並保留到壓縮為止；正數間隔會減少歷史成長，但也可能使後續請求缺少新的瀏覽器時區指導。
