# Agent Note: 基於既有 seam 的最小 read_image 工具

Status: implemented

[English](2026-08-10-minimal-read-image-tool.md) | 繁體中文

## 問題

多模態附件工作為使用者上傳建立了完整的持久路徑：位元組在所屬 `user/message` 之前提交到內容尋址的附件儲存，`ImageBlock` 只攜帶 `sha256:` 引用，pi-ai 路由在每次請求時重新讀取並校驗位元組。但模型自己沒有查看磁碟影像的手段。`read` 按約定拒絕二進位內容，因此被問到截圖或渲染圖表的 agent 要麼失敗，要麼退到有損的變通做法。第一次獨立嘗試（PR #598）把這個問題與迴圈級路由作用域一起解決：新增在組裝前發布確切模型模態的 `agent/request-ready` 擴充點、按路由控制 schema／指導可見性，以及可逆的 `image-placeholder-v1` 歷史投影讓文字路由能在佔位符上繼續。該設計可行，但讓一個工具耦合了新的 agent-loop 機制、三個新的工作階段日誌概念和每步的註冊變動，遠超這項能力本身的需要。

## 決定

只交付能把影像載入下一次請求上下文的最小工具，完全建立在既有 seam 之上；撤回的 PR #598 設計是本記錄明確保留的反例。

- **`read_image` 放在 `dsh-tool-fs`**，與 `read`/`write`/`edit` 並列。擴充名選擇聲明的 PNG/JPEG/WebP/GIF 媒體類型；附件儲存的魔數與畫素校驗保持權威。位元組沿 `ctx.fs.stat` → 有界 `ctx.fs.readBytes` → `ctx.attachments.saveImage` → `fs/observed` 流動，工具結果是元資料信封加真正的 `ImageBlock`——`ToolResultBlock.content` 本就允許影像塊，pi-ai 配接器本就會渲染它們，Web 宿主的模型切換防護本就會掃描工具結果，下游無需任何改動。
- **`FileSystem.readBytes(target, signal, maxBytes)`** 是新的必備提供方原語：位元組上限放在 seam 上，任何後端都無法無界緩衝文件；stat 大小先短路，隨後的流最多多讀一個位元組以防 stat 之後的成長（`FS_TOO_LARGE`）。
- **註冊隨組合條件掛載，執行按路由閘門。** 工具只在 `ctx.inject(['attachments'], …)` 作用域內註冊——沒有儲存就沒有工具。執行時在任何 I/O 之前，嚴格閘門透過 `ctx.llm.resolveModelInfo` 解析呼叫路由（最新 `request/header` 設定，缺失時回退到 agent 選項），要求 `inputModalities` 包含 `image`；能力未知即拒絕。拒絕是普通的 `isError` 結果，因此文字路由的持久歷史絕不會出現影像塊，工作階段不會毀掉自己的路由。
- **Code Mode 以帶外方式轉發影像**：巢狀分派返回規範值（僅限本次執行，不含影像塊），並延遲提交一條攜帶信封和影像的 `user` 角色上下文訊息，圖片仍會到達下一次請求。
- **llm-replay 模型可以聲明 `inputModalities`**，這正是兩個 keyless ACP 快照能釘住閘門兩側的原因：影像路由上以 sha256 引用的成功結果，和純文字路由上逐字的拒絕。

## 考慮過的替代方案

- **PR #598 的路由作用域設計**（request-ready 擴充點、按路由的 schema／指導可見性、可逆歷史投影）——被本記錄的形態取代後撤回。它換來的是：影像進入歷史後文本路由仍能執行，工具在註定失敗的提示詞裡消失。它付出的是：改動 agent-loop、三個新的持久概念（`agent/request-ready`、`messageProjection`、可用性通知）和每步變動的註冊。而這項能力本身——下一次請求看到影像——從不需要這些。如果按路由投影將來成為真實需求，該 PR 的歷史就是參考實作。
- **用 `agent.inject()` 代替帶影像的工具結果**——把影像繞過工具結果，作為單獨注入的使用者訊息。拒絕：影像就是工具的結果；拆開只會多一條無收益的日誌訊息，而工具結果路徑本就端到端可用。
- **用魔數嗅探代替擴充名聲明**——嗅探重複了附件儲存已擁有的偵測（基於 sharp，權威）。擴充名只是聲明；不匹配時按改名修復提示失敗關閉，而不是被靜默接受，這也讓模型對檔名與內容的對應保持誠實。
- **無條件註冊、缺儲存時執行報錯**——拒絕；沒有附件儲存的部署永遠無法滿足該工具，其 schema 會是常態謊言。相反，路由閘門是逐呼叫狀態，正確的位置就是執行邊界。

## 後果

- 純文字路由得到拒絕而不是降級：沒有佔位符投影意味著這裡沒有委託查看的方案——那有意留給下一個 PR（基於當前 subagent seam 重建的 subagent image readback）。
- 路由閘門與並行模型切換存在競態；Web 宿主的影像感知切換防護覆蓋其表面，其他前端擁有各自的等價防護。已記入 tool-fs 的已知限制。
- 重複的影像結果在壓縮之前持續累積請求 token 成本；內容尋址只去重位元組。
- 工具結果卡片渲染持久引用而非畫素；內嵌預覽延後到 UI 包處理。
