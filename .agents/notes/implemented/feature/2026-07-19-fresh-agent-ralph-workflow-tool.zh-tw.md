# Agent Note: 全新 agent Ralph 工作流程工具

Status: implemented

[English](2026-07-19-fresh-agent-ralph-workflow-tool.md) | [简体中文](2026-07-19-fresh-agent-ralph-workflow-tool.zh.md) | 繁體中文

## 問題

同工作階段目標會保留對話，讓一個 agent（代理）持續完成持久目標；通用工作流程工具則讓模型編寫扇出編排指令碼。兩者都不是 Ralph 模式：把同一目標反覆交給全新的工作者，以共享工作區作為長期記憶，並且在各 Round 之間只傳遞一份小型顯式交接，直到工作完成或觸及限制。

如果把 Ralph 行為加入 `dsh-agent-loop`、目標驅動器或面向模型的公開工作流程語言，就會讓一項策略與無關的執行機制耦合。讓每個子 agent 繼承父對話也會破壞上下文重設，並讓重放相依性不斷成長的隱式前綴。此功能需要一項由現有外掛程式原語組合而成的固定、可評審策略，同時保證取消後完全靜止、有界跨 Round 資料、寬裕且可設定的上限，並且不引入新的面向人類目標狀態。

## 決策

在 `packages/workflow/` 下新增獨立的消費端包 `@deepseek-ai/dsh-tool-ralph`。它註冊 `ralph({ objective, maxRounds? })`，擁有固定工作流程指令碼，並且只相依性 `ctx.tools`、`ctx.systemPrompt`、`ctx.workflowEngine` 和 `ctx.subagents`。Ralph 執行不是工作階段目標，不會建立目標狀態，也不要求在具體 agent loop 中增加分支。

該工具僅以前臺方式執行。呼叫 agent 作為每個子 agent 的父級以提供 cwd 和譜系，父工具呼叫等待整次執行結束，父步驟的中止訊號會取消工作流程。每條路徑都會等待 `run.dispose()`，因此呼叫返回前，取消會經過工作執行緒引擎的有界收斂並使子 agent 完全靜止。

### 每次執行的工作流程提供方路由

`WorkflowStartRequest` 新增選填的 `subagentProvider`。工作執行緒引擎先解析這個顯式的每次執行值，再回退到引擎設定的提供方；在發布執行前，它要求所選規範化路由已註冊，並把結果用於每次 `agent()` 呼叫。指令碼無法觀察或替換此路由。普通 `workflow` 工具不設定該欄位，也不暴露新的模型參數，因此通用工作流程行為和提供方策略保持不變。

Ralph 外掛程式的 `subagentProvider` 預設為 `spawn`。每次呼叫前，它要求具名提供方已存在、支持結構化輸出且報告 `inheritsParentContext: false`；類似 fork 或能力不足的提供方會在工作流程啟動前明確報錯。提供方尋找保留在呼叫期，因為效果作用域內的提供方註冊可能隨 HMR（熱模組替換）改變。

### 每次執行的工作流程子 agent 上限

`WorkflowStartRequest` 還新增選填的 `maxTotalAgents`。工作執行緒引擎要求它是正安全整數且不高於已設定的部署上限，並在發布執行前把解析值裝入該執行的工作執行緒限制。Ralph 把解析後的 `maxRounds` 作為此上限，因此固定迴圈的 Round 預算不會與通用失控子 agent 後備限制衝突。普通工作流程工具不設定該欄位並保留引擎預設值。

### Ralph Round 與交接

層級為 Ralph 執行 → Ralph Round → 全新子 agent 輪次 → 步驟。每個 Ralph Round 恰好透過所選提供方建立一個子 agent。spawn 給該子 agent 一個沒有種子的獨立工作階段，同時保留父級 cwd，因此共享工作樹是持久權威，父對話和先前子 agent 歷史都不會進入請求。

固定提示只傳遞不可變目標、當前 Round 與上限、以工作區為權威的指令，以及上一份結構化報告。`RalphRoundReport` 包含 `status: continue | complete | blocked`、`summary`、`evidence`、`nextSteps` 和 `blocker`。字串必須規範化；`continue` 要求存在下一步且沒有阻塞項，`complete` 要求存在證據且沒有下一步或阻塞項，`blocked` 要求具體阻塞項。報告成為下一次交接前，指令碼會驗證語義與序列化大小；消費端還會跨 workflow seam 再次驗證實體化的終止值。

`maxRounds` 預設為 `256`，同時也是呼叫覆蓋值的部署上限。`maxHandoffChars` 和 `maxResultChars` 均預設為 `16384`。三者都是正安全整數設定值。過大的交接會失敗，而不會被靜默截斷；`maxResultChars` 單獨限制面向父級的完整成功文字，包括外層文字和截斷標記，並且不會改變跨 Round 狀態。最後一個允許的 Round 報告 `continue` 後，固定指令碼返回 `budget-limited`；`complete` 和 `blocked` 會立即返回最終報告與已啟動的 Round 數。

工作流程語言會把正常結束但未成功的子 agent 對映為 `null`。固定指令碼會在報告驗證前偵測該值，並返回 `round-failed`，其中包含失敗的 Round，以及存在時的上一份成功交接；工具會把它轉成錯誤，而不會誤判為畸形報告或預算耗盡。Ralph 不新增重試策略。致命的提供方啟動、傳輸、工作執行緒和工作流程錯誤仍是通用工作流程失敗，因為這些路徑上的 workflow seam 不攜帶可復原的子報告。

### 模型與 UI

模型只能提供 `objective` 和選填的 `maxRounds`；提供方選擇、報告 schema、交接上限和指令碼都由部署方控制。固定提示區段說明，只有直接互動的人類明確要求 Ralph 或全新 agent 迭代時才使用 `ralph`，並將其與同工作階段目標、有界委派和通用扇出工作流程區分開。這是指導，而不是新的目標 UX 狀態機。

面向人類的展示使用通用 `ralph` 卡片，並把目標作為原始輸入；ACP（Agent Client Protocol）只承載已提交的助手文字。成功完成與阻塞的外層文字會說明結果由工作者報告，而不會把它呈現為獨立認證。父級 transcript（文字記錄）只保留原始工具呼叫，以及一份有界成功終止報告或一個錯誤，不包含中間子 agent 訊息。發布的無頭、TUI 與 ACP 組合會在現有工作流程引擎旁載入該外掛程式；JSON-RPC 保持不變，因為其默認組合不暴露工作流程。

## 測試

單元測試覆蓋設定與呼叫上限解析、提供方能力拒絕、固定啟動請求路由與子 agent 上限、全部成功終止結果、普通子 agent 失敗外層值、畸形及過大邊界值、成功結果精確截斷、中止時序、dispose（資源釋放）、渲染意圖、提示生命週期和命名空間外掛程式形狀，並達到逐文件 100% 覆蓋率。工作流程引擎測試證明提供方路由會同步驗證、每次執行的子 agent 上限可低於部署上限，並且提供方覆蓋會選擇每個子 agent 且不改變設定預設值，其中包括普通 Node 下建置後的 `lib/worker.cjs`。

一項無金鑰真實棧整合測試透過實際工作執行緒引擎、spawn 提供方、結構化輸出執行時期和 agent loop 驅動固定指令碼。它證明子 agent 標識不同、沒有 `seedLength`、繼承 cwd、兩個子請求都不含父歷史標記、上一份報告只精確出現在下一 Round 的交接中、只產生一個階段事件、終止完成以及兩個子 agent 都已 dispose。同一真實棧還覆蓋阻塞與 Round 上限結果、未規範化及語義無效報告、過大交接、保留上一份有效交接的普通子 agent 失敗，以及取消後子 agent 完全靜止。一項已發布的無金鑰無頭快照還會啟動真實的 `examples/headless-agent` 組合、呼叫 `ralph`、固定父級流式 transcript，並檢查持久化日誌中存在兩個不同且無種子的子工作階段，且 Round 1 的交接只出現在 Round 2。工具測試固定通用呼叫/結果展示，而 ACP 重放請求標頭快照固定發布的 schema 與提示指導 transcript 表面。

## 考慮過的替代方案

- **把 Ralph 放進同工作階段目標驅動器** — 拒絕，因為 Goal Round 有意保留同一段對話，而 Ralph 的定義性屬性是每個 Round 使用全新上下文；合併兩者會讓目標生命週期與子 agent 編排無法分離。
- **在通用工作流程工具上暴露 `fresh` 或迴圈標志** — 拒絕，因為模型編寫的指令碼 API 應保持通用且與提供方無關；Ralph 的固定報告協議和停止策略值得擁有一個可評審消費端。
- **為了方便重放而使用 `subagent_fork`** — 拒絕，因為繼承的已完成輪次是隱式、不斷成長的交接狀態，並違反全新上下文約定。工作區加一份結構化報告即可重放，無需插入人為取消記錄。
- **讓工具直接呼叫 subagent seam** — 拒絕，因為現有工作流程引擎已經擁有前臺編排、結構化子 agent、取消傳播、工作執行緒終止、事件和負責 dispose 並等待完全靜止。複用它可以展示外掛程式組合，而不是建置第二個迴圈執行時期。
- **靜默截斷大型報告** — 拒絕，因為截斷可能刪除狀態證據或下一步，卻仍看似權威交接。生產方必須在設定邊界內寄出有效報告。

## 後果

- 全新 agent 迭代成為一項一等模型工具，並完全以現有 seam 之上的可移除外掛程式實作。
- Goal Round 與 Ralph Round 保持不同概念：前者是一次同工作階段續行輪次，後者是前臺工作流程中的一個全新子 agent。
- 工作區成為權威跨 Round 記憶，因此工作者必須檢查和驗證工作區，而不能信任敘事性交接。
- 寬裕的 Round 上限允許大量自治工作，而部署設定仍會限制子 agent 數量，並且每次交接始終受大小約束。
- 提供方路由與可降低的每次執行子 agent 上限成為顯式的工作流程啟動關注點，但不擴充指令碼或普通工作流程工具集。

## 已知限制與暫緩事項

- 完成與阻塞狀態由工作者自行聲明。獨立評估器、評估器驅動的回饋 Round、完成憑證或對抗式 verifier 被有意推遲。
- 執行位於前臺且只存在於行程內。後臺收集、持久化/復原、調度和重新啟動復原均不存在。
- Round 數是唯一聚合預算。token、貨幣、耗時和提供方用量預算仍屬於未來的獨立策略。
- 每個 Round 建立一個子 agent。Round 內扇出、評估器/工作者角色分離、動態提供方或模型選擇，以及跨執行日誌均被推遲。
- 普通子 agent 失敗會結束執行且不重試，同時保留失敗 Round 與上一份成功交接。致命工作流程基礎設施錯誤可能在固定指令碼返回該狀態前結束；增加重試或更豐富的失敗傳輸需要獨立的策略與邊界設計。
- 提示指導模型不要遞迴呼叫 Ralph；結構化的子 agent 工具限制需要另行設計工作流程子策略 API。
