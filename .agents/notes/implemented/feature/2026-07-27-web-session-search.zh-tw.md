# Agent Note: Web 歷史工作階段搜尋

Status: implemented

[English](2026-07-27-web-session-search.md) | [简体中文](2026-07-27-web-session-search.zh.md) | 繁體中文

## 問題

Web 側邊欄會展示工作階段標題及其 Workspace 歸屬，但無法根據只出現在訊息中的詞語檢索歷史對話。在瀏覽器中掃描歷史記錄，需要附加或載入每個工作階段，重複實作現有的索引搜尋服務，也會讓冷態持久化工作階段的檢索既緩慢又容易遺漏。產品還需要一條可預測的故障路徑：派生索引不可用時，不得抹去用戶端能夠在本機計算出的標題匹配結果。

## 決策

Web 與 headless 共用的組合會使用 `openAt: first-search` 和記憶體資料庫掛載 [`@deepseek-ai/dsh-session-query-sqlite`](../../../../packages/session-query/session-query-sqlite/README.md)。服務啟動時處於 ACTIVE 狀態，而其 `node:sqlite` 模組與連線私有控制代碼分別要到首次內容查詢才會匯入和打開。這讓 Node 22 的啟動輸出在使用搜尋前不會出現 SQLite 實驗性警告，但並不承諾在首次搜尋匯入該模組時抑制警告。每個服務實例都獨佔自己的索引，因此平行 CLI 或 Web 呼叫可維持 SQLite 後端的單一所有者約定，又不會留下行程級派生文件。資料庫從空狀態啟動，並在該首次查詢時惰性對齊即時工作階段與持久化工作階段。它仍是與規範 JSONL 持久化相互獨立的可丟棄派生索引。

宿主閘道透過現有的類型化 RPC 棧公開 `session.search`。它根據 `session.list` 使用的同一組可見摘要推導授權集合，向 `ctx.sessionQuery.searchSessions` 請求全域性排序後的當前 surface `user/message` 和 `assistant/message` 匹配項，並持續消費提供方分頁，直到獲得 20 個已授權工作階段及一個前瞻項，或結果流耗盡。首個提供方頁面請求 20 個命中；如果第一頁返回 `SESSION_QUERY_INVALID_LIMIT`，頁面大小會依次折半為 10、5、2、1，並在續傳和過時世代重新啟動中沿用探測所得的大小。每個命中的工作階段 id、最佳匹配工作階段 id、surface 和事件類型都會經過重新校驗，其 snippet 才能離開宿主。寄出的 snippet 最多包含 240 個 Unicode 碼點；宿主與傳輸 schema 共用協議邊界及碼點安全的截斷輔助函式，而傳輸 schema 會在用戶端解析時獨立強制執行 snippet 上限。將可能很大的授權集合排除在 SQLite 綁定之外，可避開可移植變數上限，同時保持全域性排序。回應仍只有一個有界頁面；`hasMore` 會指示 UI 提示使用者縮小查詢範圍，而不是公開分頁能力。過時的續傳會丟棄當前嘗試的部分結果、去重條目和遊標，然後依據原始可見性快照從第一頁重新開始。上限探測與過時重試共用 100 次提供方呼叫的限制（因此最多檢查 2,000 個命中）；如果某頁命中數超過其請求的上限、續傳遊標重複，或用盡該呼叫預算後結果流仍未耗盡，都會直接返回 `internal` 業務錯誤，不返回部分結果。載體訊號會取消已被取代的工作，包括持久化清單枚舉、分批受限執行的冷工作階段元資料 stat，以及每一次提供方呼叫；即使同時收到上限拒絕或過時拒絕，也以取消為準。查詢服務缺失或索引／查詢故障無法復原時，仍作為業務錯誤處理，不會修改規範工作階段儲存。

[`WorkspaceBrowser`](../../../../packages/client/ui-workspace/README.md) 有意將元資料搜尋與內容搜尋保持獨立。其默認介面文案為英文；輸入框及防禦性請求路徑會移除 NUL，將查詢限制在請求 schema 規定的 500 個 UTF-16 code unit 內且不會拆分 surrogate pair。非空白查詢會立即從工作階段清單中計算不區分大小寫的標題和 Workspace 子串匹配，在 250 ms 防抖後發起內容請求，在查詢變化時中止前一請求，並忽略過時的完成結果。它先按新近程度排列本機匹配，再合併由後端排序且僅匹配內容的結果，按工作階段 id 去重；無論常規分組模式如何，最終都渲染為扁平清單。每一行顯示標題、Workspace，並在存在時顯示一行摘要片段。選擇某一行只會打開對應工作階段，並保留查詢條件；不會跳轉至確切事件。

結果上限是單一協議常數，而非逐連線狀態。`SESSION_SEARCH_RESULT_LIMIT` 位於 `dsh-host-apiproxy` 中強制執行它的回應 schema 旁邊，`SessionRuntime.searchResultLimit` 則把該常數重新公開給呈現外掛程式。功能包要取用它，必須顯式擴充 sessions 域的對外面：`ISessions`（即注入為 `ctx.sessions` 的那個面，也因此是測試執行時期的 sessions 替身必須實作的面）在該上限旁聲明瞭搜尋動作。連線 handle 不攜帶它：逐連線欄位會暗示該上限隨傳輸層變化或由伺服器端協商，而 schema 固定的 `max` 恰恰禁止這一點，並且會讓同一事實在同一模組內擁有兩處歸屬。

內容匹配沿用 SQLite 後端經過規範化的字面 token／短語語義。共享語義投影會排除推理（reasoning）塊，因此 UI 搜尋絕不會將模型的私有推理作為命中或 snippet 返回；派生索引的 schema 版本會隨之前進，使現有持久化索引重建並移除先前的這些文件。FTS5 運算子只作為資料處理，此搜尋介面不提供拼寫錯誤糾正、模糊匹配、前綴匹配或任意子串擴充。特別是，`unicode61` 分詞器可能將一段連續中文視作單個 token，因此不保證 `搜索` 之類的較短查詢能匹配 `会话搜索功能` 的內部片段。標題與 Workspace 匹配仍採用普通的用戶端子串匹配。

## 故障與可見性約定

搜尋絕不會擴大工作階段可見範圍：沒有可供服務的 cwd 的冷工作階段會被排除，原因與它們不出現在 `session.list` 中相同；只有 id 位於這條基線中的提供方命中才能離開宿主。被遮蔽事件和純日誌事件、訊息內容之外的工具事件、錯誤、待辦事項及其他追蹤記錄都不會產生 UI 命中結果。

首個或後續內容請求仍在處理期間，UI 會保留即時元資料匹配結果，並顯示歷史搜尋狀態。如果後端失敗，這些行會保持不變，並顯示警告說明內容搜尋不可用。合併後沒有任何行時，介面會顯示明確的空狀態。候選行超過 20 條時，介面會提示使用者縮小查詢範圍。

## 曾考慮的替代方案

- **在瀏覽器中掃描每個工作階段的歷史記錄**：不予採納，因為這會讓 UI 承擔傳輸與摺疊開銷；除非載入冷態日誌，否則還會漏掉這些日誌；並會重複實作已經由 `ctx.sessionQuery` 負責的語義提取與源對齊。
- **首版即加入 trigram 或模糊搜尋**：不予採納，因為這會改變索引大小、排序、短查詢行為與產品預期。trigram 本身也無法解決雙字查詢。首版沿用現有後端約定，將召回擴充留作另一項基於度量結果的決策。
- **返回事件地址並跳轉至確切匹配位置**：本版不予採納，因為對話虛擬化與穩定的事件導覽需要單獨的 UI 約定。工作階段級導覽本身已有價值，無需讓搜尋與這項工作耦合。
- **在側邊欄公開遊標分頁**：不予採納，改為固定顯示前 20 條結果並提示縮小查詢範圍；這樣可使互動與取消狀態保持有界。

## 後果

無需預先打開，即可檢索到歷史持久化對話，同時宿主仍只保留一條可見性邊界和一套語義索引實作。即時本機結果掩蓋了大部分請求延遲，取消機制可防止已作廢查詢重新渲染清單，後端故障則會降級為內容搜尋尚不可用時已有的行為。

首次內容查詢可能耗時更長，因為它要先匯入並打開 SQLite，再承擔惰性對齊的開銷。搜尋質量採用 token／短語召回，而不是模糊召回或任意子串召回，並受上述連續中文限制。結果粒度為工作階段，最多 20 條，不支持分頁，也不能跳轉到具體訊息。如果有效但選擇性極差或反覆過時的提供方嘗試未能在 100 次呼叫內完成，系統會進入僅保留元資料匹配的故障路徑，而不是無限制地繼續處理。

## 測試

宿主測試將請求與回應校驗、可見工作階段過濾、事件和 surface 過濾、結果與 snippet 邊界、共享呼叫預算內的自適應提供方上限、沿用探測所得上限的過時世代重新啟動、遊標與跨頁去重行為、取消優先級及故障對映固定為約定。SQLite 生命週期測試將啟動時啟用、首次搜尋時的打開與失敗、共享就緒狀態以及未打開狀態下的處置固定為約定；語義提取測試與 SQLite／fixture 搜尋測試將排除僅存在於推理中的文字固定為約定。Node 22 相容性閘門會建置 CLI 與 Web 產物，在移除環境級警告抑制並採用隔離的臨時 home／提供方環境後，以普通 Node 啟動隨產品交付的 `dsh web`／`AppCLIEntry` 組合，等待啟動完成並穩定，再沿隨產品交付的訊號路徑對其執行 dispose（資源釋放）。fixture（測試前置資料）、執行時期與 UI 測試將以匹配位置為中心的有界 snippet、無狀態委託、500 個 code unit 的查詢邊界、防抖／中止／過時回應行為、本機回退、合併順序、去重、英文文案、ARIA 樹成員關係、行渲染與導覽語義固定為約定。無金鑰的組裝層 Web 測試會在保留惰性打開設定的同時，播種一段尚未打開的持久化對話，透過 SQLite 索引按可見訊息內容找到它，捕獲側邊欄結果，打開該工作階段，並驗證查詢條件仍然保留。
