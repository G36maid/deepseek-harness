# Agent Note: Web 斜槓命令模糊發現

Status: implemented

[English](2026-08-04-web-slash-command-fuzzy-discovery.md) | [简体中文](2026-08-04-web-slash-command-fuzzy-discovery.zh.md) | 繁體中文

## 問題

Web 命令選單要求按命令名前綴匹配，因此使用者只記得關鍵字母卻不記得其準確位置時，就無法發現命令。擴大選單的匹配範圍可使命令更易發現，但命令執行仍必須保持精確匹配和確定性：近似輸入行絕不能執行相近命令。

## 決策

`/` 命令 source 將鍵入的查詢作為不區分大小寫的有序子序列，與命令名進行模糊匹配。精確前綴構成排名最高的一類匹配。在每類匹配中，對齊分數越高越優先：分隔符邊界和相鄰字元會提高分數，前導字元和間隔會降低分數；分數相同則保持 host 目錄和 client contribution 的順序。位置過濾仍會在排名前從行內選單中移除接收參數的命令。

評分器對每個候選項使用動態規劃，時間複雜度為 `O(query length × name length)`，空間複雜度為 `O(name length)`。候選項評分只在用戶端進行且只檢查命令名；命令描述不影響匹配。選單選擇仍派發所選的精確名稱，而空格鍵和 Enter 鍵的判定邏輯仍要求命令 token 精確匹配。

## 考慮過的替代方案

**保留僅前綴匹配。** 否決，因為本功能要解決的使用者無法準確回憶前綴的問題依然存在：`/cpt` 無法發現 `/compact`。

**匹配無序字元或描述。** 否決，因為無序匹配難以預測，而描述匹配可能展示命令，但命令的可見名稱無法解釋其排名。

**使用通用模糊搜尋相依性。** 否決，因為該介面只需對小型命令目錄使用一種受限的子序列規則；可設定搜尋索引會增加 bundle 體積，並引入產品未使用的排名行為。

## 後果

使用者可以憑按順序記得的字母發現命令；只要目錄相同，排名就保持穩定。評分刻意採用啟發式規則：與分隔符對齊的匹配可能排在原始跨度更短的匹配之前。包測試固定各項排名因素以及同分時的穩定順序，組裝後的 Web 重播快照固定 `/cpt` 解析為 `/compact` 的行為。精確執行語義保持不變。
