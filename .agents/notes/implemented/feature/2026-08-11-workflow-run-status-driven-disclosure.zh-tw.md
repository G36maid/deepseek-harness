# Agent Note: 工作流程執行的狀態驅動 disclosure

Status: implemented

[English](2026-08-11-workflow-run-status-driven-disclosure.md) | [简体中文](2026-08-11-workflow-run-status-driven-disclosure.zh.md) | 繁體中文

## 問題

持久工作流程 Chat 節點會在同一位置從執行前綴更新為終態記錄。只在掛載時初始化的 disclosure 選擇可能隱藏新開始執行的階段，讓已完成工作繼續佔據對話空間，或者把失敗、已取消或已中斷成員埋在兩層摺疊內容之後。若只把開合狀態作為完成狀態的純派生結果，雖然能避免這些問題，卻也會阻止使用者重新打開乾淨歷史進行復盤。

renderer 已經從工作流程 Conversation Node 收到全部所需生命週期事實。因此，可見性需要一個元件本機生命週期：讓當前執行與需注意狀態優先，同時不增加另一項持久事實，也不取得工作流程結果的所有權。

## 決策

每個階段從當前成員派生一項可見性要求。存在執行中、失敗、已取消或已中斷成員時，該階段強制展開；全部成員均已完成時，該階段處於乾淨狀態。工作流程自身狀態需要注意或任一階段強制展開時，工作流程也強制展開，因此即使工作流程結果記錄為已完成，例外成員仍保持可見。已完成的兄弟階段繼續可以獨立摺疊。

強制展開層級渲染為靜態展開行。它不提供按鈕 role、焦點目標、鍵盤切換或 `aria-expanded` 值，因為摺疊操作無法改變結果。這樣既保留視覺層級與狀態摘要，也讓互動承諾與實際可執行動作一致。

乾淨層級會以關閉狀態掛載普通受控 disclosure。它的本機選擇在同一段連續乾淨狀態的 rerender 中保持。新的執行中或例外資料會用強制展開替代該手動區間；下一次回到乾淨狀態時會掛載新的關閉 disclosure，從而讓每個活動週期只自動摺疊一次。關閉工作流程會自然解除安裝其階段控制元件；Session remount 會從當前持久狀態重建每個層級，而不復原更早的選擇。

例如，執行中的工作流程無需點擊即可展示活躍階段與成員。該階段完成時，只有階段摺疊，工作流程繼續展開；工作流程自身和全部階段均完成時，工作流程也會摺疊。使用者隨後可以重新打開兩個層級復盤。若同一階段 key 下又開始新成員，受影響的兩個層級會立即復原強制展開，並且只在新活動完成後再次摺疊。

renderer 只擁有這項可見性生命週期。它不增加 Session 事件、store、設定、確認狀態、計時器、焦點遷移、自動滾動或跨 remount 持久化。它不改變工作流程狀態派生、階段分組、成員順序、導覽准入、文案或共享 `DisclosureRow` API。pointer 遊標由共享的 `data-expandable` 樣式擁有，因此強制展開的靜態行不會提示無法執行的操作。持久記錄中的中斷前綴仍屬於需注意狀態，因此在底層事實改變前始終可見。

## 驗證

元件測試驅動同一個 keyed 工作流程與階段依次經過執行、乾淨完成、手動復盤、新活動、再次乾淨完成、零成員完成以及每種例外狀態。測試還驗證例外成員向上展開、乾淨兄弟階段獨立、滑鼠和鍵盤復盤、連續乾淨狀態中的選擇保持，以及強制展開時不存在虛假按鈕和 ARIA 語義。

shipped Web 重播觀察真實工作流程、worker、Session 日誌、瀏覽器外掛程式圖和子級導覽。它要求即時工作流程與活躍階段無需 disclosure 控制元件即可見，正常結帳的工作流程與階段會摺疊，手動復盤仍能看到不再可導覽的終態成員，並且刷新會從持久事實重建摺疊歷史。

## 曾考慮的替代方案

**保留一項從首次渲染初始化的手動狀態。** 拒絕，因為後續生命週期更新無法重新打開新活動或例外內容，也無法摺疊正常結帳的工作。

**只根據層級是否乾淨來派生 `open`。** 拒絕，因為已完成歷史會永久保持關閉，無法重新打開復盤。

**持久化展開、確認或已讀狀態。** 拒絕，因為當前生命週期事實已經決定強制可見性，而復盤選擇只屬於已掛載的展示層。持久化會增加第二個狀態歸屬方，並要求定義過時選擇、例外確認、重播和同步語義，而使用者結果不需要這些機制。

## 後果

工作流程記錄無需預備點擊即可展示當前工作與例外結果，並在正常完成後回收對話空間，同時不犧牲復盤能力。自動控制期間的互動語義保持真實，同一份持久記錄在即時渲染、刷新和歷史重建時得到相同初始狀態。

代價是有意保留的本機重設行為。父工作流程關閉或元件解除安裝時，階段選擇會消失；由於產品沒有確認狀態，例外記錄不能手動隱藏。以後若要支持任一行為，需要單獨決定所有權與持久化，而不能隱式擴充這項本機生命週期。
