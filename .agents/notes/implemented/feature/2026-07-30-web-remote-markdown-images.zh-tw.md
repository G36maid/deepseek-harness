# Agent Note: Web 中的遠端 Markdown 圖片

Status: implemented

[English](2026-07-30-web-remote-markdown-images.md) | [简体中文](2026-07-30-web-remote-markdown-images.zh.md) | 繁體中文

## 問題

assistant Markdown 可以使用標準圖片文法引用圖表和截圖，但 Web 渲染器會把每張圖片替換為斜體替代文字。因此，即使目標地址是絕對 HTTP(S) URL，也無法獲得普通的 Markdown 圖片行為。

## 決策

`MarkdownText` 將絕對 HTTP(S) 圖片目標地址渲染為延遲載入的響應式 `<img>` 元素，並使用非同步解碼與 `referrerPolicy="no-referrer"`。相對路徑、絕對本機路徑、`file:` URL 與不支持的協議繼續沿用現有的替代文字回退。原始 HTML 保持停用，因此 assistant 無法透過手寫 `<img>` 繞過 Markdown 圖片元件。

圖片元件複用渲染器的絕對 URL 策略，不新增主機代理、本機文件路由、Session 相依性、淨化器或圖片抓取器。已完成的歷史訊息、流式輸出、被中斷的部分輸出以及其他所有 `MarkdownText` 消費端均獲得同一行為。

## 考慮過的替代方案

**將所有圖片都保留為替代文字。** 這種方案維持了最小的網路邊界，但無法滿足在行內查看網路託管的視覺產物這一產品需求。

**透過主機代理遠端圖片。** 代理可以向圖片源站隱藏瀏覽器的網路地址，但這會讓主機執行任意出站請求，並且需要單獨制定重定向、DNS、大小與內容策略。直接載入 HTTP(S) 圖片可讓瀏覽器控制機制繼續觀察該請求；不傳送 referrer 可減少對話來源資訊的暴露。

**在同一變更中支持本機路徑。** Web 源無法直接載入主機文件。安全的實作需要單獨評審的權限邊界，因此相對路徑、絕對本機路徑與 `file:` URL 保持停用。

**允許 `data:` 圖片。** 大型 data URL 會將二進位內容以文字形式重複寫入持久化的 transcript（文字記錄）。僅允許 HTTP(S) 的策略足以滿足當前需求，且不會擴大工作階段日誌。

## 後果

assistant 回覆會在流式輸出與重播期間顯示遠端圖片，且不改變工作階段事件或主機協議。遠端源站仍可觀察到圖片請求、用戶端網路地址，以及瀏覽器策略允許傳送給該源站的任何憑據。本機及不支持的目標地址仍只顯示不會發起請求的替代文字。
