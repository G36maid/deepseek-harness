# Agent Note: 後臺 subagent 任務

Status: implemented

[English](2026-07-08-background-subagent-tasks.md) | [简体中文](2026-07-08-background-subagent-tasks.zh.md) | 繁體中文

## 問題

[subagent seam](2026-06-21-subagent-capability-seam.md) 會返回 `SubagentRun`，但原先面向模型的工具會同步收集每一次執行。因此，各自獨立的慢速委派要麼一直佔用父呼叫，要麼按序列方式執行。

subagent 需要與其他長時間執行的工具相同的啟動、收集、列出、停止、歸屬、通知和清理行為，但不應採用行程流語義。子工作階段仍是詳細記錄；父級只需最終答案和任務狀態。後臺子級的存活時間還會超過啟動它的工具呼叫，因此必須明確其取消和擁有者資源釋放約定。

## 決策

每個 `dsh-tool-subagent` 實例都可以公開 `run_in_background`，由 `enableRunInBackground` 控制，且預設啟用。停用該功能的實例不包含此參數，並會在執行時拒絕強制傳入的後臺參數。提供方選擇仍屬於部署設定，因此一個實例仍然只為一個提供方註冊一個名稱可區分的工具。

後臺 subagent 使用[通用背景工作執行時期](../architecture/2026-06-20-generic-long-running-tool-runtime.md)。`job_output`、`job_list` 和 `job_kill` 負責收集、列出、取消、完成通知和提示詞引導；系統不提供 subagent 專用的配套工具。

前臺呼叫保留其同步約定：等待提供方啟動和 `run.result`；僅當狀態為 `completed` 時返回最終文字；將其他終止原因對映為出錯的工具結果；並且始終在返回前釋放該執行。

對於後臺呼叫，工具會驗證父級，並在呼叫 `ctx.jobs.start()` 前拒絕已中止的執行訊號。任務執行時期會在呼叫生產者啟動器前，預檢控制 API 和擁有者清理。該啟動器建立獨立的 `AbortController` 並啟動 `ctx.subagents.start()`；返回 id 之後，工具呼叫的訊號不再擁有該子級。

任務註冊按以下方式對映 subagent seam：

- `kind` 為 `subagent`，`label` 為模型提供的描述，`owner` 為父 agent（代理）。
- `cancel(reason?)` 中止任務自有的控制器。同一個訊號同時覆蓋尚未完成的提供方啟動和已發布 run 的剩餘工作。
- `done` 等待提供方啟動、子級結果和 `run.dispose()`。已完成的執行返回最終文字，已中止的執行變為 `killed`，其他停止原因變為 `failed`。啟動、結果和資源釋放失敗會轉換為失敗結果，而不是被拒絕的任務 Promise。
- `readOutput` 不存在。任務存活期間，`job_output` 只返回狀態；結帳後，它以冪等方式返回最終輸出。中間的子級活動仍保留在子工作階段中。

## 生命週期

後臺 subagent 歸屬於其父 agent，不會在擁有者關閉後持久存續。任務執行時期將清理附加到對應擁有者的確切作用域。agent 資源釋放會取消任務，並在 `AgentHandle.dispose()` 完成前等待啟動回滾或子級資源釋放，避免洩漏子 agent 和工作階段。

完成通知會發送給啟動時捕獲的確切擁有者。如果擁有者清理過程已經釋放了注入目標，該通知將被丟棄；生命週期保證是清理，而不是通知。

## 模型引導

通用任務提示詞教會模型一套共享的做法：保留 id；繼續獨立工作，而不是忙等輪詢；在回答前收集相關任務；終止無關工作。subagent schema 只補充說明：後臺模式返回 job id，且 `job_output` 用於收集結果。無論模型是否遵循提示詞，授權和擁有者清理都會強制執行執行時期邊界。

## 備選方案

### subagent 專用的等待、輸出和停止工具

能力專用工具會重複任務協議，再教一套收集與停止習慣，並增加多個提供方實例的複雜度。通用執行時期在不改變工具「每個實例對應一個提供方」形態的前提下，提供了所需行為。

### 在擁有者關閉後存續

該方案需要持久化的任務狀態、子工作階段復原、延遲結果交付通道，以及對被遺棄擁有者的處理策略。以擁有者為作用域的清理為行程內工作界定了明確生命週期。持久作業需要單獨設計。

### 隔離用戶端不做擁有者檢查

agent 和日誌可能以工作階段為作用域，但任務登錄檔和可預測 id 屬於執行時期全域性範圍。因此，通用擁有者防線同樣適用於 subagent 和所有其他生產者。

### 增量子 transcript 輸出

將子級歷史以流式方式寫入父級，會模糊日誌邊界，並使提供方行為分化。此工具只公開最終輸出；更豐富的觀察應由工作階段或 UI 工具承擔。

## 測試

單元測試覆蓋固定了停止原因對映、在報告前釋放資源、啟動與結果失敗、對預中止的拒絕、從啟動呼叫訊號分離、在提供方發布前後取消、透過真實任務工具收集、無控制器的預檢防線、執行時期缺失失敗，以及每實例 schema 開關。快照覆蓋固定了面向模型的 schema。

## 影響

父級可以平行分派慢速委派任務，並透過與 bash 共用的任務控制來收集結果。子級工作不再佔用啟動它的工具呼叫，但在收集、終止或擁有者釋放之前可以繼續消耗資源。提示詞引導鼓勵收集；擁有者清理則提供硬性生命週期邊界。需要同步委派的部署可以按工具實例停用後臺模式。
