# Agent Note: 側邊欄的捲軸跟隨指針

Status: implemented

[English](2026-08-04-pointer-revealed-sidebar-scrollbars.md) | [简体中文](2026-08-04-pointer-revealed-sidebar-scrollbars.zh.md) | 繁體中文

## 問題

側邊欄的工作階段清單只要有幾個工作階段就會溢位，從那一刻起它的捲軸就一直畫在那裡——所處的這一列大部分時間都是靜止的，而清單行自己的操作按鈕只在懸停時纔出現。它是側邊欄裡唯一始終常駐的構件，而在有人真的伸手去操作它之前，它不提供任何可操作性。產品訴求（2026-08-04）是隻在指針位於側邊欄內時才繪製它，並留一小段拖尾，避免指針路過時它一閃而滅。

## 決策

`SidebarRoot` 跟蹤整列上的指針，只要指針不在列內就給根元素掛上 `quietBars` 類。該類選中的規則把 ui-theme 的那組間接變數——`--dsh-scrollbar-thumb` 與 `--dsh-scrollbar-thumb-hover`——重新綁定為 `transparent`，於是巢狀在這一列下的每個滾動區域都不繪製滑桿。今天這樣的區域只有工作階段清單；將來新增的區域會直接繼承這一行為，而不需要逐個接入。

拖尾是 `SCROLLBAR_LINGER_MS = 2000`：離開會啟動一個定時器，進入會取消尚未觸發的定時器，只有定時器真正觸發才會把類加回去。指針越過列邊界又折返時——繞過一個 portal 選單，或是奔向某一行時衝過了頭——不會看到滑桿閃動。

進入用的是列自身的 `pointerenter`；離開則按列的盒子判定，由一個只在捲軸可見期間存在的 `pointermove` 監聽完成。DOM 包含關係無法判定離開：ui-settings 把整屏的設定面板渲染為這一列的 fixed 定位*後代*，指針移到該面板上——或在面板關閉後移到對話區——都不會在這裡觸發 `pointerleave`，捲軸就會繼續畫在一個沒人指向的列上。元素自身的 leave 仍然保留，用於幾何判定看不到的那一種情況：指針移出視窗後不再產生任何移動事件。

承載指針的是整列，而不是清單。奔向捲軸的指針會先經過 logo 行、New Session 膠囊和搜尋框，所以只在清單上顯示，會讓捲軸等到指針已經落在行中間時纔出現。

`transparent` 正是讓這次顯示不觸發任何版面配置的原因。清單上的 `scrollbar-gutter: stable` 存在的意義就是讓行永不移動（見[空槽 Agent Note](../bug-fix/2026-07-28-themed-scrollbars-and-reserved-gutter.md)）；重新綁定的只是顏色，那份預留始終有效，所以滑桿出現在清單本就為它留出的空間裡。

選擇這組間接變數而不是給清單加規則，是因為這組變數正是 ui-theme 寫明的重新綁定約定：一次聲明同時作用於兩條渲染路徑（WebKit 偽元素與 Firefox 的 `scrollbar-color`），而自訂屬性會繼承——這正是讓整列、而不是列內每個滾動區域，成為該狀態所有者的原因。

這拓寬了重新綁定約定，因此它的閘門把新的形態明寫出來，而不是默許透過：`ui-theme/tests/scrollbar-styles.spec.ts` 只接受兩種重新綁定目標，即 l2 那一組或 `transparent`，並且判定的是**整條規則**而不是逐條聲明——混合規則（`thumb: transparent` 與 l2 的 hover 並列）會在指針一碰到捲軸時重新上色，卻能透過逐條檢查。抬升那一半按整個值與這組變數的規範寫法比對，這同時也拒絕了交叉綁定和被包在字面表達式裡的 token；綁回 l1 與裸顏色本來就在門外。

隱藏不再算作抬升：只有 l2 重綁才能讓一張樣式表免於「任何在抬升表面上滾動的樣式表都必須重新綁定」。既隱藏捲軸又在抬升表面上滾動的樣式表，仍然欠著那裡真正繪製滑桿時所需的 l2。

## 考慮過的替代方案

**只用列上的 CSS `:hover`，不引入 JavaScript 狀態。** 整套機制只需一條規則，但它表達不出拖尾：指針越過邊界的那一幀滑桿就會消失，而那恰好是指針正奔向對話區或繞行 portal 選單的時刻。訴求本身點名了拖尾，只有 hover 的版本讀起來就是閃爍。

**留在 CSS 裡、用過渡拿到這段延遲**，即透過 `@property` 註冊 `--dsh-scrollbar-thumb` 讓該自訂屬性可動畫，再用 `transition-delay` 把顏色按住。因代價與作用範圍被否決：這項註冊對每個讀取這組變數的表面都是全域性的，卻只為一列的時序服務；而且這套調色板實際渲染所走的 WebKit 捲軸偽元素並不可靠地支持過渡——延遲會被聲明在觀察不到它的地方。

**直接把捲軸藏掉**——`scrollbar-width: none`，或對 `::-webkit-scrollbar` 用 `display: none`。被否決，因為這會連帶取消那段預留：捲軸重新出現時會重新佔走 8px，使每一行都在觸發其顯示的指針下方橫向移動，而這正是當初加入空槽預留所修掉的回歸。

**在應用內自繪一個覆蓋式滑桿**，並徹底隱藏原生捲軸，這是完全自訂淡入淡出所需要的做法。它換來任意樣式，代價是命中測試、拖拽、滾輪、慣性以及兩套調色板下的 hover 狀態——在一個捲軸已由 token 統一主題化的用戶端裡，為觀感付出的是一大片自持表面。

**把顯示範圍收斂到滾動的清單而不是整列。** 涉及的元素更少，卻把顯示的邊界放錯了位置：指針最後纔到達行，捲軸會等到使用者已經在學這些行時纔出現；而且日後加入側邊欄的其他滾動區域都得手工接入。

**滾動事件也觸發顯示**，讓鍵盤或觸摸驅動的滾動同樣顯示捲軸。被否決，因為那是在為觸發它的輸入方式畫一個它用不上的可供性；行本身已經說明清單移動過了。

## 後果

- 用鍵盤或觸摸拖動滾動的清單，在拖尾結束後不顯示滑桿，因為這兩種方式都不會把指針留在列上。e2e 會釘住這一點，而不只是把它寫下來。
- 拖動滑桿本身移出列不會在拖動中途把它隱藏：捲軸會接管指針捕獲，按住按鍵期間頁面收不到 `pointermove`。已在 Chromium 實測——指針拖到列右側 900px 處、超過拖尾視窗後，捲軸依然繪製並繼續滾動。
- 冷啟動時該列處於靜默狀態，直到指針第一次移到它上面為止。頁面載入時就停在那裡的指針在移動之前不會觸發任何事件，這是瀏覽器的規則，而非這個外殼的。
- 巢狀在列內、為自身抬升層級把這組變數重新綁定到 l2 的抬升表面，會覆蓋靜默狀態並繼續繪製自己的捲軸。今天側邊欄內沒有這樣的表面。
- 外殼的 DOM 現在帶有一個狀態類，因此 ui-sidebar 的外殼快照會釘住 `quietBars`，默認狀態出現回歸時表現為快照 diff，而不是需要有人從截圖裡看出來的東西。

## 測試

`packages/client/ui-sidebar/tests/pointer-scrollbars.client.spec.tsx` 用假定時器把這個類走過各次躍遷：進入時顯示，拖尾結束前 1 毫秒仍然顯示，結束後 1 毫秒轉為靜默，以及視窗內折返會取消隱藏。另有兩條覆蓋幾何判定的離開：落在列盒子之外的 `pointermove` 會在沒有任何 DOM leave 的情況下隱藏捲軸（即設定面板那種形態），落回盒子之內的則取消待觸發的隱藏。它還在拖尾進行中解除安裝元件並斷言沒有定時器存活——待觸發的隱藏落到已銷毀的元件上，正是這種寫法容易犯的錯。事件用的是帶 `relatedTarget` 的 `pointerover`／`pointerout`，因為 React 由它們合成 enter 與 leave，而會忽略原生的那兩個事件。

`packages/client/ui-sidebar/tests/scrollbar-quiet-styles.client.spec.ts` 直接讀樣式表：該規則必須寫出這組變數的兩半——只重新綁定靜止態滑桿，會讓指針一碰到捲軸就露出 hover 顏色——並且不得出現 `scrollbar-gutter`，那屬於滾動區域自己。

`apps/web/tests/sidebar-scrollbar.e2e.ts` 是兩半在真實引擎裡匯合的地方。它在每次讀取顏色前先把指針停在清單上，因為一個從不移動滑鼠的場景全程測到的都是靜默狀態，會在未實際驗證目標行為的情況下透過。隨後它自己的用例把指針移開，斷言在 leave 當下滑桿仍在繪製，輪詢直到它解析為 `rgba(0, 0, 0, 0)`，在該狀態下重新測量幾何以證明捲軸隱藏期間那份預留依然生效，並以程式設計方式滾動清單——鍵盤或觸摸拖動所做的事——來釘住無指針滾動不繪製任何滑桿。提交的 golden 記錄了兩套調色板下、兩個指針位置上的滑桿顏色。

這條 e2e 的對照是一次 mutation，而它需要外掛程式自己的產物：把 `quietBars` 從外殼中去掉，先重新建置 `@deepseek-ai/dsh-client-ui-sidebar`、之後再跑 `build:web`，該用例會因為滑桿解析為 `rgb(229, 229, 229)`、而期望 `rgba(0, 0, 0, 0)` 而變紅。只重跑 `build:web` 用的是過時產物，即使改動已被刪除也照樣透過，這正是[空槽 Agent Note](../bug-fix/2026-07-28-themed-scrollbars-and-reserved-gutter.md)記錄過的陷阱。

拓寬後的閘門也有自己的對照，每個都是對真實樣式表的一處聲明改動：把 `transparent` 與 l2 的 hover 混用，以及把 l2 token 包進 `color-mix(…)`，都會讓這條成對斷言變紅。

演示這一行為的錄制必須用有頭瀏覽器。無頭 Chromium 會預留那條帶（`offsetWidth - clientWidth` 為 8），卻不會把滑桿畫進捕獲幀——透過統計帶內滑桿色畫素在顯示前後的變化實測：無頭一直停在噪聲水準，有頭則從 46 跳到 1466。
