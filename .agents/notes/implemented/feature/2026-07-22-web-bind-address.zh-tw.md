# Agent Note: 顯式指定 Web 綁定地址

Status: implemented

[English](2026-07-22-web-bind-address.md) | [简体中文](2026-07-22-web-bind-address.zh.md) | 繁體中文

## 問題

即便瀏覽器與伺服器執行在同一臺機器上，`dsh web` 也會綁定所有網路介面。因此，本機使用會在操作者未明確選擇的情況下暴露一個未經身分驗證的開發伺服器；另一方面，遠端容器和局域網瀏覽器場景仍需要一種受支持的方式來接受非環回連線。

HTTP 承載層還把綁定地址隱藏在 `startWebServer()` 內部，導致其他殼層無法在包邊界明確表達自己的網路策略。

## 決策

`dsh web` 默認綁定 `127.0.0.1`。CLI（命令列介面）接受 `--host 0.0.0.0` 作為顯式啟用的全介面模式，並拒絕其他取值，使網路模式保持為一份規模小、經過審慎限定的約定。全介面模式仍然輸出本機環回 URL，並在可用時輸出第一個外部 IPv4 URL。

`WebServerOptions.host` 為必填項。HTTP 承載層將該值直接傳給 `node:http`，不提供回退值，因此每個殼層負責制定自己的綁定策略。以程式設計方式使用承載層的消費端可以直接選擇其他主機名或地址。

## 曾考慮的替代方案

**保留以 `0.0.0.0` 作為預設值。** 不予採納，因為普通的同機使用不需要在全網範圍內可達，也不應隱式獲得這種可達性。

**使用布林型暴露標志。** 不予採納，因為 `--host 0.0.0.0` 直接說明最終的Socket行為，並與底層伺服器選項一致，無需再引入第二套術語。

**在 `startWebServer()` 內設定預設值。** 不予採納，因為承載層可能由多種殼層呼叫，沒有依據替它們選擇部署策略。要求傳入 `host`，可使每次裝配呼叫都明確作出這一選擇。

## 後果

`dsh web` 的本機啟動仍可透過 `http://127.0.0.1:3080` 訪問；其他機器上的瀏覽器必須使用 `dsh web --host 0.0.0.0` 顯式啟用。CLI 尚未開放自訂介面地址或 IPv6 模式，而以程式設計方式使用承載層的消費端仍保留這種靈活性。伺服器測試將環回模式和全介面模式向 Node 監聽邊界的傳遞固定為約定，Web 冒煙測試繼續覆蓋默認 CLI 路徑。
