# Agent Note: 面向模型的工作階段查詢工具

Status: implemented

[English](2026-07-24-model-facing-session-query-tools.md) | [简体中文](2026-07-24-model-facing-session-query-tools.zh.md) | 繁體中文

## 問題

統一的 `ctx.sessionQuery` 服務對優先使用即時資料的工作階段日誌提供精確讀取、過濾、關係追蹤與全文搜尋，但模型無法直接使用該服務。若把提供方請求類型交給模型，還會暴露不穩定的分頁遊標、受信任的語料範圍、儲存形態的時間值，以及更適合程序化消費端而非模型推理的結果記錄。大型追蹤與事件負載另有輸出大小問題，但若在該消費端內部解決，就會重複 harness 的通用 spill 機制，並使工作階段查詢工具與其他工具的行為不一致。

## 決策

`@deepseek-ai/dsh-tool-session-query` 是 `ctx.sessionQuery` 面向模型的消費端。它註冊五個職責單一的只讀工具：`session_search`、`session_event_search`、`session_trace`、`session_event_trace` 和 `session_event_read`。該包相依性介面而非 SQLite 實作，負責模型參數校驗與易讀文字渲染，並貢獻一個精簡的提示詞段，說明歷史搜尋以及從搜尋轉向追蹤／讀取的工作流程。

該包入口僅作為設定、提示詞註冊與工具註冊的公開組合根。內部模組沿執行邊界劃分：`input.ts` 負責模型 schema、規範化與過濾條件構造；`service-boundary.ts` 包含提供方呼叫與面向模型的安全錯誤轉換；`workspace-access.ts` 負責呼叫者身份、工作區授權、標題訪問與譜系投影；`operations.ts` 編排五個服務工作流程；`presentation.ts` 渲染工具結果與呼叫卡片。這樣可讓策略留在其所屬層，同時不改變包約定。

`session_search` 按工作階段聚合全文匹配，並公開帶類型的工作階段與事件元資料過濾條件。`session_event_search` 搜尋一個工作階段，默認目標為呼叫者的當前工作階段。`session_trace` 返回完整的已授權祖先鏈與遞迴後代樹。`session_event_trace` 返回一個事件所有已知的位置替換關係與直接引用來源事件的關係。`session_event_read` 以未刪節的 JSON 原樣返回目標事件，並可選擇彙總一個有界的原始事件視窗；省略 `before` 與 `after` 時只返回目標。

面向模型的過濾條件使用扁平的 snake-case 欄位。工具邊界上的時間戳採用帶時區的 ISO 8601 字串，轉換為服務使用的閉區間毫秒時間戳，並以 UTC ISO 8601 渲染。同一個過濾條件中的清單值按 OR 組合，不同過濾條件按 AND 組合。請求的父工作階段 id 會在 FTS 之前去重並按權限過濾，因此只有呼叫者工作區中的父工作階段會進入提供方條件；缺失與跨工作區的猜測具有相同行為，而根工作階段標記仍會獨立按 OR 加入該條件。由於 `SessionEventMap` 可透過聲明合併擴充，事件類型字串保持開放；可用性與面向模型公開的事件欄位採用封閉取值。

## 工作區權限

每個執行器都從不可變的 `ToolExecution.exec.agent` 身份推導呼叫者，絕不接受模型提供的工作區。只有當目標觀測中的 `cwd` 與呼叫者工作階段的 `cwd` 完全相同時，目標才獲授權。跨工作階段搜尋始終附加該工作區過濾條件。直接操作先預檢目標，然後在渲染負載前，校驗與每一頁事件搜尋結果、事件追蹤、事件讀取、譜系目標或摺疊標題來自同一服務觀測的工作階段頭。這樣，即使即時或持久化目標在檢查與使用之間被替換，也無法跨越工作區邊界。譜系渲染在遇到未授權的祖先或後代子樹時停止，且不洩露被隱藏的工作階段 id。呼叫者工作階段沒有 `cwd` 時只能檢查自身工作階段；缺少 agent（代理）身份時按失敗關閉處理。

每個受信任的 `ctx.sessionQuery` 呼叫都會經過同一個模型邊界淨化器。它首先檢查執行訊號，原樣保留呼叫者的取消原因。對於其他失敗，它會盡力把可獲得的語料或提供方診斷鏈寫入內部日誌；當值無法安全檢查時，則改用固定佔位符。診斷格式化與錯誤分類各自受到保護，因此無法列印的巢狀 cause 既不會逃逸，也不會阻止對外層錯誤進行安全分類；分類不安全或日誌記錄失敗時，則返回固定的通用錯誤碼 `SESSION_QUERY_TOOL_FAILED` 及其訊息。逐標題失敗也會先經過同一個淨化器，再轉為不可用標記。工具自身的輸入校驗與授權錯誤在該服務邊界之外建立，因此仍保留精確訊息。

搜尋工具公開的是既往工作，而不是正在執行搜尋的操作本身。`session_search` 排除呼叫者工作階段。`session_event_search` 以呼叫者工作階段為目標時，會把請求的序號範圍與當前 `step/start` 之前的最後一個事件取交集，從而排除當前 assistant 訊息、工具呼叫，以及從該次呼叫中建立索引的查詢參數。

## 無遊標結果與 spill

兩個搜尋工具都不向模型公開遊標、偏移量、頁大小或模型可控的結果限制。一次執行會在觀察到的代保持有效時持續跟隨提供方遊標，並收集不超過設定項 `maxSearchResults` 的結果，其預設值為 100。達到上限的結果會要求模型縮小查詢或過濾範圍；代發生變化時會報告必須重試完整搜尋。搜尋執行透過工具截止時間與服務中止訊號傳遞可設定的 `searchTimeoutMs`，預設值為 30 秒。由於內部頁面共享與代綁定的遊標，兩個搜尋工具在 agent loop（代理循環）調度器中都以獨佔方式執行；精確追蹤與讀取工具則允許和兄弟工具平行執行，因為其觀測可以容忍期間發生的提交。

追蹤與讀取工具同樣不公開譜系分頁或字元分頁。規範結果採用純文字，並在服務已有的事件視窗與搜尋數量資源邊界內保持完整。每個精確執行器都會將未經替換的工具執行訊號傳遞給目標授權與服務追蹤或讀取。在服務解析過程中，已知即時事件追蹤、事件讀取與標題讀取在遵循預中止的同時仍不訪問持久化。工作階段譜系追蹤會將該訊號傳遞給全語料持久化列舉操作；持久化事件追蹤與讀取則將其傳遞給目標列舉與檢查操作。每個已啟動的後端呼叫都會等待清理完成後再原樣保留中止原因，即使該後端忽略了取消也不例外。通用的 `tools/post-execute` spill 策略負責行內位元組保留：當已設定的部署收到過大的文字時，該策略會用有界預覽、不透明定位符與讀取提示替換文字，同時在 spill 儲存中保留完整結果。工作階段查詢消費端既不匯入 `ctx.spillStore`，也不實作第二套截斷格式。

工作階段級結果在可用時包含最新摺疊標題。每次工具執行都會透過一次優先使用即時資料的語料觀測批次讀取唯一標題 id，最多使用服務透過 `persistedInspectConcurrency` 設定的持久化檢查 worker，其預設值為 4，並將工具執行訊號原樣傳遞給持久化列舉與檢查操作。即時來源會直接摺疊；每個持久化 worker 都會把已完成的來源摺疊為分離的工作階段頭／標題觀測，並在取出下一個 id 前釋放完整日誌，因此批次只保留小型投影值。對於搜尋工具，該執行訊號攜帶已設定的搜尋截止時間。取消不會啟動排隊中的標題檢查，並會在已經啟動的檢查全部完成後拒絕完整的工具執行；標題缺失、格式錯誤或發生操作性失敗時，錯誤隻影響對應 id，同時保留基礎結果、渲染不可用標記並記錄底層錯誤，而授權不匹配則按失敗關閉處理。搜尋結果包含匹配度最高的事件與提供方摘錄，追蹤包含完整的已授權關係，事件讀取保持鄰近事件呈現易讀，同時只為被請求的目標保留精確 JSON。

## 宿主組合

該消費端是一個需顯式啟用的外掛程式。已交付的宿主組合不掛載它：已交付的 TUI、Web 與無頭介面保留 `ctx.sessionQuery` 索引（即 `/resume` 與 Web 內容搜尋背後的 SQLite 服務），但不掛載面向模型的消費端，因此其默認請求既不攜帶查詢提示詞，也不攜帶五個 schema；僅用於自動化的 ACP 組合也兩者均不掛載（[session-search-not-shipped-default](2026-08-02-session-search-not-shipped-default.md)）。這些組合還提供通用的逾時與 spill 策略。專用的 ACP 快照 fixture（測試前置資料）顯式掛載該消費端與這兩項策略，並使用私有的本機 spill 儲存。通用工具呈現無需工作階段查詢專用用戶端外掛程式。

## 考慮過的替代方案

- **向模型公開提供方遊標**：不予採納，因為記錄工具結果或開始下一個模型步驟會改變相關工作階段或全域性代，導致遊標通常在模型能夠複用前就已過期。
- **增加工具本機截斷、偏移量或 spill 文件**：不予採納，因為執行後 spill 策略已經統一負責各工具的完整結果保留與讀取。
- **允許訪問所有持久化工作階段或由模型提供工作區過濾條件**：不予採納，因為 `ctx.sessionQuery` 是受信任服務，面向模型的消費端必須執行呼叫者權限邊界。
- **把搜尋、追蹤與精確讀取合併為一個帶操作選擇器的工具**：不予採納，因為職責單一的名稱能為模型提供更清晰的 schema、預設值、呈現意圖與後續選擇。
- **只返回一層譜系**：不予採納，因為 spill 已消除行內大小方面的理由，而單層輸出會遺漏關係且沒有繼續讀取路徑。

## 驗證

包級測試固定參數校驗、過濾條件轉換、時間戳規範化、精確工作區授權、父級過濾預授權與抵禦預言機探測、變更觀測拒絕、普通值與對抗性未知值的服務診斷脫敏、盡力記錄迴圈 cause、日誌失敗隔離、身份缺失行為、隱藏邊界裁剪、當前步驟排除、內部提供方翻頁、搜尋獨佔與精確讀取平行分類、數量上限、訊號原樣傳遞、中止原因保留、持久化清理完全靜止、單次掃描且並行有界的批次標題擴充、先投影再取出下一個任務的順序、抑制排隊工作、等待已啟動 worker 完全靜止、逐工作階段頭校驗、標題回退、代表性搜尋／追蹤／讀取渲染、通用呈現與可釋放註冊。整合覆蓋使用真實 SQLite FTS 提供方查詢即時與持久化工作階段。發布設定與 TUI/Web 組合測試證明面向模型的消費端不存在於 TUI、Web 與無頭介面，而組裝後的 ACP 請求標頭快照證明自動化介面默認不包含它。包自身的 Loader 冒煙測試與專用無金鑰 ACP 快照顯式掛載該消費端，並配套啟用逾時與 spill 支持，固定其提示詞指引、schema 以及與路徑無關的精確事件讀取保留行為。

## 後果

模型無需獲得儲存權限或繼續狀態，即可透過提供方無關的方式訪問既往工作階段工作。搜尋具有有限的單次呼叫工作邊界，若要命中前 100 條以後的結果，可能需要縮小查詢；搜尋呼叫不能與兄弟工具重疊執行，而精確觀測仍可平行調度。完整追蹤與事件負載可能表現為 spill 引用而不是行內文字。嚴格的 `cwd` 字串相等選擇了保守安全邊界，而不解析透過符號連結等價的路徑。自訂組合可以在不掛載 spill 的情況下使用該工具，但這表示它們明確接受完整追蹤與讀取結果直接出現在行內。
