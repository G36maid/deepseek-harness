# Agent Note: 當前沙盒策略上下文

Status: implemented

[English](2026-07-30-current-sandbox-policy-context.md) | [简体中文](2026-07-30-current-sandbox-policy-context.zh.md) | 繁體中文

## 問題

沙盒策略已經強制執行並記錄每個工作階段的文件操作模式，但新的模型請求並不包含這一狀態。在 `read-only` 下的 Web 工作階段中，write 與 edit schema 仍然可見，因此模型會聲稱自己能夠寫入，直到一次被拒絕的呼叫後才發現事實並非如此。執行 `/permission danger-full-access` 後，下一個請求帶有批准策略變更，卻仍省略沙盒模式。因此，即使使用者在任何操作前詢問能力，拒絕結果也是模型可見的首個策略來源。

## 決策

`dsh-sandbox-policy` 負責解析模式與工作區根目錄，並註冊一項快取安全的 `sandbox:policy` 上下文貢獻。每次 agent（代理）請求都透過 `ctx.sandboxPolicy.resolve({ session })` 直接解析當前工作階段；不存在拒絕歷史掃描或行程本機的「上次告知」狀態。

該策略貢獻不相依性具體能力，並默認可用於每個 agent 工作階段。當模型介面有意排除動態上下文時，組合可以抑制完整的 runtime-context 通道；這不會停用策略強制機制。該貢獻不會另行維護一份已掛載後端或工具清單；模型可見的 schema 仍是可用操作的權威來源，而上下文會將其聲明限定在 DSH 文件沙盒所強制執行的任何可用操作上。[不相依性具體能力的策略上下文決策](../simplification/2026-07-31-capability-neutral-sandbox-policy-context.md)取代了較早的家族註冊機制，同時保留本 Agent Note 的快取安全交付與持久快照設計。

該貢獻只說明所有強制執行方言所共有的事實。`read-only` 表明受沙盒強制執行的可用操作在常駐模式下無法修改文件，並指示模型正常嘗試可用工具，隨後遵循該工具返回的任何拒絕與升權引導。`workspace-write` 用非排他措辭說明規範化的工作階段工作區，並概述某些平臺臨時區域可能也可寫，而不逐一列舉。`danger-full-access` 表明 DSH 文件沙盒不會限制可用操作修改文件。後端選擇的臨時路徑、`/dev/null`、runner 就緒狀態、確切的工具可用情況和其他策略領域都不會出現，因為 `resolve()` 無法在請求組裝時確定它們。

現有 `dsh-system-prompt` 組裝在穩定系統段與工具 schema 之外，還包含有序的動態上下文。組裝一個步驟後，agent loop（代理循環）會將所有活動上下文渲染成一份帶顯式取代聲明的完整快照。僅當不存在保留快照、位元組發生變化、壓縮（compaction）移除了保留訊息，或最後一項貢獻消失而需要一份清除快照時，它才會追加一條帶來源的 `user/message`。快照追加在現有歷史之後、`step/start` 之前，因此策略變化時仍會保留此前的系統與對話快取前綴。工作階段事件本身可以重建確切的模型輸入；當變化的只有策略上下文時，`request/header` 仍保持逐位元組相同。

歸屬範圍仍然有限。批准策略會將其完整的當前 `ask` 或 `never` 事實貢獻給同一份完整快照；只遷移沙盒無法保留快取，因為 `/permission` 會同時改變兩方。計畫模式仍由 `plan:policy` 負責，工具外掛程式也繼續負責各自的 schema，以及嘗試、拒絕與升權引導。上下文負責說明常駐策略；檔案系統、一次性 bash 與終端機後端仍是強制執行邊界。

快取決策依據當前原始碼，而不只依靠類比。Codex 將權限建模為 developer 角色的 `WorldState` 段並保存其指紋；只有狀態變化或保留的歷史丟失該片段時才寄出它，同時記錄快照轉換。Hermes 在工作階段期間保持系統提示詞不變，並明確將不斷變化的 skill（技能）、模型與語音通知前置到下一條使用者訊息，以擴音示詞快取失效。Pi 沒有可比的內建沙盒狀態，Claude Code 當前的原生實作也無法公開檢視；不過，Anthropic 的公開快取指南仍將不斷變化的逐請求上下文放在穩定快取前綴之後。

先前接入真實提供方的 Web fixture（測試前置資料）量化了系統段版本的缺陷。首次 `danger-full-access` 和 `workspace-write` 請求分別只有 256 個快取讀取 token，而未快取輸入 token 為 14,691 和 14,782 個。相同策略下的後續步驟報告約 14.7k–15.5k 個快取讀取 token。只移動沙盒語句無法修復這些未命中，因為同一次 preset 切換還會改寫批准策略系統段。

## 措辭證據

措辭實驗預先登記「預防性拒絕」為主要終點，並要求舊常駐句子在十二個新工作階段中至少產生一次拒絕，之後才能評判任何替代措辭。2026-07-30，commit `2bf41990401b194bd8637f07bbd90c67a9eeac75` 透過已交付的 Web 組合執行 `deepseek-v4-flash`，使用精確的陽性對照句子 `Bash commands run under the "read-only" file sandbox.` 與當前工具歸屬方的嘗試引導。對照組產生零次預防性拒絕和零次推測性升權；十二個工作階段全部先發起普通 bash 呼叫、觀察到拒絕、在同一輪次升權、獲得批准，並讓所請求文件實際落盤。沒有樣本被排除。

快取安全交付變更後，commit `10d4e0ff7b68d38fc4403403b644aac442b97a00` 透過新的尾部上下文通道重複了同一項十二工作階段陽性對照。結果再次為零次預防性拒絕和零次推測性升權；十二個工作階段的首次呼叫均為普通呼叫，隨後觀察到拒絕、在同一輪次升權並獲得批准。其中八個工作階段讓所請求文件按確切要求落盤，沒有樣本被排除。

因此，兩項陽性對照均未透過預先登記的靈敏度門檻。Candidate A 與 B 的正式十二工作階段實驗組均未執行，這些實驗不選擇也不驗證當前措辭。它們說明先前十二次中五次的結果無法在本任務與當前工具引導下復現；在聲明模型行為率之前，需要更強的陽性對照或不同的任務分佈。下述確定性測試只能證明請求構造如實反映狀態，並驗證其可重播性。

隨後，快取安全交付重做針對中性 Web 任務 `Create the relative path policy-neutral.txt ...` 提供了一次獨立的非統計驗收對比；它不取代預先登記的十二工作階段實驗。Candidate A 的絕對化只讀聲明導致模型以純文字拒絕，工具呼叫為零。Candidate B 只針對受強制執行、且其工具公開升權能力的家族增加一句按組合條件化的文案。隨後一次全新的真實提供方執行先發出普通 `write`，觀察到只讀拒絕，再在同一輪次用 `sandbox_permissions: "workspace-write"` 重試同一操作，獲得批准、讀迴文件並核驗確切內容。它沒有進行推測性升權。在權限切換和四個變更步驟中，每個請求的快取讀取為 14,848–15,872 個 token，未快取輸入為 59–306 個 token，直接證明瞭穩定前綴的收益。

## 曾考慮的替代方案

**僅敘述模式變更。** 不予採用，因為這會讓新工作階段不瞭解策略，並把首次被拒絕的操作變成策略發現機制。如果可以直接渲染當前狀態，也就無需額外定義基線。

**掃描拒絕歷史或記住上次敘述的模式。** 不予採用，因為拒絕事件描述的是嘗試過的操作，而不是權威的當前狀態；行程本機的簿記也無法跨復原保留。歸屬方可以在每次請求時直接摺疊持久策略。

**把當前策略放入動態系統段。** 不予採用，因為真實提供方證據顯示，首次權限切換後快取讀取降至 256 個 token，而約 14.7k 個輸入 token 未命中快取。DeepSeek 匹配完整前綴；改變第一條協議訊息會阻止複用更長的系統與歷史前綴。

**由每個策略歸屬方獨立呼叫 `agent.inject()`。** 不予採用，因為同級監聽器的順序會決定模型所見順序，分開的訊息可能暴露不匹配的中間快照，並且每個歸屬方都需要各自掃描壓縮後的保留狀態。現有組裝歸屬方可以對貢獻排序，並生成一份原子化的完整快照。

**通用執行時期事實包。** 不予採用，因為現有系統提示詞組裝已經擁有段、schema、變數、作用域和權威的逐步驟 waterfall（瀑布式事件）。為該歸屬方增加有序上下文，無需新增包或第二個登錄檔服務。

**在上下文中重複工具 schema 或計畫引導。** 不予採用，因為這些介面已有各自歸屬方和獨立生命週期。批准的當前狀態加入快照，僅僅是因為同一個 `/permission` 切換會改變它，而把它留在系統段會保留快取缺陷。

**快取安全遷移後仍保留 Candidate A。** 不予採用，因為中性的真實提供方任務中，儘管已有 bash 嘗試引導，模型仍以純文字拒絕，且沒有呼叫工具。保留下來的反預防性拒絕原則本身不說明任何升權機制；它告訴模型不要從常駐標籤推斷操作不可能完成，然後把拒絕與升權行為交還給可用工具。

**繼續省略沙盒模式，因為常駐模式標籤曾引發預防性拒絕。** 不予採用，因為新的 Web 請求否則會暴露變更工具，卻隱去這些工具的常駐策略，導致模型在首次操作前錯誤聲稱自身能力。先前的線上測量仍是必須執行的反證測試：使用 `Bash commands run under the "read-only" file sandbox.` 時，十二個輪次中有五個沒有呼叫工具。已提交的工具歸屬方嘗試引導晚於該測量，因此應透過當前工具約定下的新陽性對照實驗選擇替代文案，而不能假設舊條件與當前條件相同。

**獨立的模型上下文包。** 不予採用，因為策略歸屬方可以直接解析當前工作階段狀態，現有組裝服務也可以對其排序。新包只會圍繞同一個請求邊界引入淺層組合層，並增加額外的文件與閘門維護工作。

**枚舉可寫臨時根目錄。** 不予採用，因為後端要到稍後的 `confine()` 才會選定：bwrap、Landlock、Seatbelt 和行程內檔案系統圍欄並不授予一套共同的臨時路徑。常駐請求中的主機特定路徑既不穩定，也會作出過度承諾。

## 後果

模型在試探工具前就會收到常駐文件策略，且 `/permission` 後的下一個請求會反映已提交的模式。穩定的系統提示詞不再隨沙盒或批准狀態變化；變化後的完整上下文快照會在保留的歷史之後僅附加，狀態不變時不增加訊息。較舊的快照仍保留在歷史中，但最新的完整快照會明確取代它們。該聲明是引導，而不是強制執行護欄：執行時期安全仍來自檔案系統、一次性 bash 與終端機後端消費同一項解析完成的策略。

聚焦測試固定了所有模式、規範化根目錄、切換時機、服務 dispose（資源釋放）、上下文順序、清除、穩定的請求 header、復原，以及不同 `TMPDIR` 值下的位元組穩定性。無金鑰的組裝快照透過真實 Loader 組合固定持久上下文訊息。無金鑰重播負責固定中性的拒絕到升權軌跡；它是結構回歸證明，而不是措辭選型證據。
