# Agent Note: 行內程式碼文件提及可打開其命名的文件

Status: implemented

[English](2026-08-07-web-inline-file-mentions.md) | 繁體中文

> 範圍：引導最終回覆以行內程式碼點名主要輸出文件，再把這些 token 連結到本輪變更的文件。不在範圍內：識別普通正文中的路徑、連結成功修改位置中不存在的文件，以及流式或輪次中途訊息裡的提及。

## 問題

產物行列出了一輪的輸出，但收尾訊息通常也會在正文裡*點名*文件——以行內程式碼形式，如 `` `deepseek-homepage.html` ``——而這個提及是死文字。讀者的視線先落在句子上；可點擊的互動卻在下面一行。模型並不知道這種精確的行內程式碼寫法會啟用 Web 文件打開器，因此能否產生有用引用取決於模型習慣。

## 決定

**正文提及只在與產出文件對得上時才成為連結。**[產物行的決定](2026-07-31-web-workspace-file-links.md)否決過「把收尾訊息連結化」，理由是渲染不能相依性模型把路徑寫得可識別；這一點不變。產物行仍是權威的、不相依性正文的記錄。本特性只是給同一份 `locations` 詞表增加第二個消費者：`producedFileMentions` 按精確路徑解析行內程式碼 token，或當 token 恰好是且僅是一條產出路徑的 basename 時解析。兩條路徑共享的 basename 保持死文字而不猜測，命名了本輪沒寫過的文件的 token 同樣保持死文字——提及連結永遠不會 404。

**渲染器不持有詞表，提供方是 deliverables 外掛程式。**`MarkdownText` 接受選填的 `MarkdownFileMentions` 解析器，對行內程式碼 token 詢問它——URL 提升優先於解析器，且絕不在錨點內部（按鈕不能巢狀在連結裡）。什麼算檔名的決定藏在 ui-conversation 經 `ctx.get` 觸達的選填 `chatFileMentions` 服務背後：ui-deliverables 在其 turn-tail chain 註冊項旁提供該服務，因此 cordis.yml 中的一行同時把產物行和正文連結組合進來或去掉，ui-primitives 不引入任何工作階段概念。提及只作用於已定稿的渲染——流式快取不能固化可能過期的 handler，而且詞表在輪次收尾前並不最終。消費端按收尾 seq 而非不斷成長的 transcript（文字記錄）記憶化解析器，因此已定稿訊息的快取解析在流式追加中得以保留。

**提供方也擁有其所接受文法的模型指引。**ui-deliverables 的 Node 側註冊靜態段落 `ui:deliverable-file-references`，要求模型在最終回覆中點名來自成功建立或修改呼叫的主要文件，並將這些文件以及正文中提到的其他本輪變更文件寫成 Markdown 行內程式碼：使用文件工具採用的精確路徑，或僅在 basename 能唯一指代本輪文件時使用 basename。該指引刻意不涉及無關的本機路徑格式。正式提供的組閤中只有 Web patch 載入 ui-deliverables，因此提示詞只存在於渲染器存在的地方；移除該包會同時移除兩者。模型遺漏提及時，文件行仍承擔正確性兜底；匹配詞表仍拒絕成功修改記錄之外的所有文件。

## 考慮過的替代方案

- **對全部正文跑路徑形狀的正則**——會把隨口提到的 `package.json` 和從未寫過的示例都連結上；每個誤報都會帶來一次點擊，結果要麼什麼也沒打開，要麼打開了錯誤文件。詞表方案不可能產生死鏈。
- **連結後綴匹配（子目錄清單裡把 `out/index.html` 寫作 `index.html`）**——暫緩；精確路徑加唯一 basename 已覆蓋觀察到的收尾訊息形態，之後放寬匹配器不會破壞這道 seam。
- **在 ui-primitives 裡對傳入的路徑清單做解析**——把匹配策略放進通用渲染器，其他消費端會被動繼承。解析器約定讓策略留在持有者手裡。
- **經由 turn-tail chain 傳遞詞表**——chain 是訊息下方的渲染派發；提及要裝飾的是訊息內部的 markdown，只有抵達 MarkdownText 的資料才做得到。選填服務就是那條資料通路，它的缺席即關閉態。
- **在 dsh-web-app 中註冊指引**——會讓應用組合包描述某個功能特有的渲染文法，也允許渲染器與提示詞分別組合或產生漂移。該功能包現有的 Node 側讓 cordis.yml 中的一項可以共同持有兩者。
- **增加一次輪次結束後的模型呼叫來識別輸出**——即使最終回覆已經擁有所需的文件工具歷史，仍會增加延遲和一次生成。一個靜態提示詞段落可以留在可複用前綴中，並要求現有的最終生成輸出渲染器接受的寫法。

## 後果

提及與產物行是同一事實的兩個互動面（兩者都以完整路徑作 `title`）；提及本身採用 markdown 樣式表的錨點語言——靜止為連結藍、懸停出底線——因為靜止底線在 code 膠囊裡會壓住等寬字的下伸部。提示詞段落在本包載入期間保持不變，因此可跨 Turn 複用快取。無金鑰的正式 Web 組合快照釘住模型可見段落的精確文字，`apps/web/tests/produced-file-mentions.e2e.ts` 則用構造的寫入輪次 seed 釘住組裝後的渲染行為：唯一 basename 成鏈，歧義與未知 token 保持死文字。終端機命令間接建立的文件即使被模型點名，仍不在詞表中。輪次中途敘述裡的提及即使命名了本輪後來產出的文件也保持死文字，因為詞表只掛在收尾訊息上。視窗前插的邊界——從輪次中途開始的視窗後來補入了同輪更早的寫入——只會讓提及在重掛載前暫不成鏈，絕不會錯鏈。
