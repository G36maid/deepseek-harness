# Agent Note: 將中文 contract 術語統一為「約定」

Status: implemented

[English](2026-08-09-chinese-contract-terminology.md) | [简体中文](2026-08-09-chinese-contract-terminology.zh.md) | 繁體中文

## 問題

中文文件對英文 `contract` 的譯法在「契約」與「約定」之間不一致，有時甚至出現在同一文件或段落中。術語表規定使用「契約」，而經過評審的增量覆校選擇了更符合工程語境的「約定」。若術語表與語料繼續分裂，無論選擇哪一種譯法都會違反倉庫術語規則，後續翻譯也會再次引入分歧。

英文 `convention` 也常譯為「約定」。這種重合是有意保留的：普通中文工程文體會用「約定」表達這兩個概念，通常可由上下文判斷它描述的是慣常做法還是有約束力的介面規則。如果英文句子明確對比 convention 與 contract，中文必須透過「慣例」與「約定」等措辭保留這種區分，而不能機械地把每個 `convention` 都譯成同一個詞。

## 決策

術語真源規定 `contract` 譯為「約定」，`adapter contract` 首次出現時寫作「配接器約定（adapter contract）」。所有活躍中文文件配對均遵循該裁決；歸檔 Agent Note 保持凍結。未參與配對的雙語校準資產和翻譯提示詞說明文字也採用相同術語，避免繼續教授已被取代的譯法。

這次遷移只維護語義正文，不重新命名識別符號。行內程式碼、檔案路徑、連結、API 名稱、檔名中包含的英文 `contract` 以及機器可讀值均保持不變。`convention` 不新增全域性術語行，也不做全語料改寫：翻譯時保留自然中文，只在源文明確對比兩個概念時消歧。[具體行文決策](2026-08-09-concrete-prose-names-actors-and-recorded-facts.md)另行規定：如果英文正文中的 `contract` 含糊不清，應在翻譯前將其改為確切的規則、API 或行為。

## 考慮過的替代方案

**繼續把 `contract` 譯為「契約」。** 否決，因為經過評審的語料在技術介面、生命週期保證和行為邊界中一致傾向使用「約定」；保留舊術語意味著回退大量已接受的覆校結果。

**為 `convention` 規定強制的全域性譯法。** 否決，因為它既可表示命名慣例，也可表示協議約定。強制一種譯法會帶來另一輪大規模遷移，卻無法改善普通行文；只有源文明示對比時才需要使用不同措辭。

**允許 `contract` 同時使用「契約」與「約定」。** 否決，因為這會保留導致包家族乃至同一段落互相矛盾的原始問題。

## 後果

活躍中文文件對 `contract` 只有一種有約束力的譯法，後續翻譯提示詞會直接從術語表獲得該決定。歸檔記錄保留歷史文字。源文若對比 convention 與 contract，仍需在區域性使用語義化措辭，因此相同的常用中文譯法不會抹去源文真正表達的區別。

## 驗證

遷移掃描每一組活躍雙語配對，更新受影響的中文文件並重新記錄對應的伴隨記錄，使活躍正文不再出現「契約」。配對閘門、完整 `doc-sync`、網站建置、翻譯提示詞測試與快照，以及 `git diff --check` 共同驗證最終語料和管線資產。
