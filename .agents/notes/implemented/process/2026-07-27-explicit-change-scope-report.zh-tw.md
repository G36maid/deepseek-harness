# Agent Note: 顯式報告倉庫變更範圍

Status: implemented

[English](2026-07-27-explicit-change-scope-report.md) | [简体中文](2026-07-27-explicit-change-scope-report.zh.md) | 繁體中文

## 問題

[pre-push 工作流程](../../../skills/dsh-pre-push-checks/SKILL.md)需要取得相對於實際基準的 diff，但按 `origin/<current-branch>` 構造引用存在兩類問題：對於第一次推送前跟蹤 `origin/master`、尚無同名遠端分支的新 worktree 分支，該引用無法解析；對於 PR（Pull Request）以另一功能分支為基準的堆疊分支，該引用會錯誤描述基準。[程式碼評審](../../../skills/dsh-code-review/SKILL.md)與[文件審計](../../../skills/dsh-doc-standards/SKILL.md)工作流程同樣需要判斷當前基準。

錯誤的範圍可能遺漏受影響的路徑，從而削弱證據選擇。三點範圍產生的已提交 diff 也完全無法說明 Git 中彼此獨立的已暫存、未暫存與未跟蹤層。

## 決策

根目錄的 `change-scope` 命令要求提供 `--base <ref>`，接受選填的 `--head <ref>`（預設為 `HEAD`），並寫出一份帶版本號的 JSON 報告。該命令會偵測歧義，將兩個輸入解析為 commit，並要求二者恰好有一個合併基點，之後才會呈現報告。報告記錄倉庫根目錄（不對路徑中的合法空白字元作規範化處理）、輸入引用、解析後的基準、頭部與合併基點 commit ID，以及排序後的已提交、已暫存、未暫存和未跟蹤路徑集合。路徑記錄先按原始 NUL 位元組切分；倉庫根目錄和每條路徑都以嚴格 UTF-8 解碼。遇到無效值時，報告會中止，不會用替換字元代替無效位元組或把不同值合併為一條。

已提交路徑由解析後的合併基點與頭部之間的比較得出。即使 `--head` 指定其他 commit，各類未提交路徑集合仍始終描述當前 worktree 與索引。每次 Git 探測都會停用設定的檔案系統監視器和選填加鎖；diff 設定不能隱藏子模組，也不能呼叫外部 diff 或文字轉換驅動；系統停用重新命名偵測，因此重新命名前後的路徑都會保留在結果中。

該命令從不猜測或取得基準，不查詢程式碼託管提供方，也不選擇測試。呼叫該命令的每個工作流程都會驗證當前遠端或堆疊狀態、顯式提供基準，並將這份事實報告作為語義評審或證據選擇的輸入。

聚焦的臨時倉庫測試覆蓋顯式引用與堆疊引用、所有未提交改動層、合法路徑空白、嚴格路徑解碼、無副作用的探測、無效引用、確定性 schema，以及報告前後不變的引用、索引、設定與狀態。

## 考慮過的替代方案

**繼續使用臨時拼裝的 diff 命令，輔以文字化回退說明。** 這種方式無需新增倉庫指令碼，但不同工作流程對常見的新 worktree 與堆疊基準拓撲仍會作出不一致處理，而且無法涵蓋未提交改動層。

**根據設定的上游推斷基準。** 第一次推送前，上游可能是 `origin/master`；推送後，它可能是同一功能分支；也可能是一個頭部分支，而其 PR 以另一功能分支為基準。沒有一種推斷能夠適用於所有拓撲。

**在命令內查詢 GitHub 以確定基準。** 這會把本機只讀報告綁定到單一程式碼託管平臺與網路憑證，卻仍然無法解析尚無 PR 的分支。

**根據變更路徑生成必需的測試。** 變更路徑無法揭示經由設定、動態載入、子行程、worker、建置產物或提供方觸達的行為。pre-push 工作流程仍須透過判斷來選擇證據。

**報告當前分支與上游，並維護平行的人類可讀渲染器。** 呼叫方在呼叫前已經驗證分支和基準狀態，沒有消費端使用這些欄位，而格式化文字只會重複 JSON schema，並不能提高路徑完整性。

## 後果

顯式輸入仍可能指定錯誤的基準，但這種錯誤是可見的：報告中會顯示輸入引用與解析出的三個 commit ID。呼叫方需要付出少量成本，在執行該命令前驗證即時基準並從遠端取得它。

字串 schema 有意不表示非 UTF-8 路徑位元組。含有這類路徑的倉庫必須先重新命名這些路徑才能生成報告，以此保持範圍精確，而非返回有損結果。

倉庫需要維護一個 Git 拓撲輔助工具及相應的聚焦測試。由此，pre-push 證據選擇、程式碼評審與文件審計可以共享一份關於已提交變更和本機變更的確定性只讀說明，而不必混入程式碼託管平臺或策略職責。
