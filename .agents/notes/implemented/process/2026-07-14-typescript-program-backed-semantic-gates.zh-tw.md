# Agent Note: 基於 TypeScript Program 的語義閘門

Status: implemented

[English](2026-07-14-typescript-program-backed-semantic-gates.md) | [简体中文](2026-07-14-typescript-program-backed-semantic-gates.zh.md) | 繁體中文

## 問題

倉庫閘門有時需要判斷 TypeScript 文法本身不攜帶的事實：接收者是否為 Cordis `Context`、哪些具體事件名會進入轉發輔助函式、聲明合併是否改變了事件簽名。

當前的閘門基於 TypeScript 單文件文法解析能力，使用命名約定、手寫的表格、JSDoc 等方式來維護這類資訊。

倉庫需要一個語義真源，同時不能引入執行時期包之間的迴圈相依性、寬泛的兜底啟發式邏輯，或重複描述 TypeScript 已有資訊的機器可讀標注。

## 決策

倉庫閘門可以透過 `ts.Program` 匯集項目級類型資訊，並使用 `TypeChecker` 提取**強類型**事實，從而減少對命名約定、手寫表格和 JSDoc 元資料的相依性。

倉庫將這一模型應用於以下兩個閘門。

### 一個項目模型展開根項目設定

[`TypeScriptProject`](../../../../scripts/ts-project.ts) 解析根 `tsconfig.json`，遞迴展開每個項目引用，並將各引用項目的原始碼根合併為一個不輸出文件的語義 Program。直接從根項目設定建立普通 Program 時，TypeScript 可能將引用項目重定向到建置後的聲明文件；顯式展開可以讓閘門繼續遍歷各包的 `src` 文件，並保留符號同一性。

該封裝統一負責設定診斷、語義編譯選項、倉庫相對路徑、原始碼尋找和共享 TypeChecker。各閘門不再自行按文件通配模式掃描包原始碼，也不再分別建置不完整的 Program。

### A. 事件關係由接收者類型和值類型決定

[`gen-doc-graphs`](../../../../scripts/gen-doc-graphs.ts) 根據呼叫接收者與倉庫中真實 `Context`、`AgentEventDispatch` 和 Cordis `EventsService` 類型之間的可賦值關係進行分類。變數名和屬性拼寫不再決定某次呼叫是否屬於事件操作。

Context 與 AgentEventDispatch 呼叫只貢獻由字串字面量構成的有限事件集合。對於直接呼叫 `EventsService.dispatch()` 的路徑，生成器會沿陣列字面量、常數別名、條件分支和未匯出本機輔助函式的已解析呼叫點復原事件槽位。泛型轉發參數不算作具體生產方：事件仍歸屬於傳入封閉事件值的呼叫點。

語義查詢只在存在消費分支的位置執行：呼叫先經過封閉的事件 API 方法名集合預過濾，再做接收者分類；輔助函式呼叫點索引按需建置，而不是預先對全部包原始碼的每個呼叫求解簽名。需求式索引對每個輔助函式逐一證明區域性性——未匯出、位於真正的 ES 模組文件中、且同文件所有引用都是直接呼叫位的輔助函式，按模組作用域規則其全部呼叫必在本文件內，此時只索引該文件。任一前提無法證明（帶匯出修飾符、位於全域性 script 文件、存在別名化或無法歸類的引用）即回退到原全部包原始碼索引，回退路徑就是原語義本身：證明隻影響開銷，不影響結果。惰性單一全域性索引方案被否決，因為當前原始碼樹確實會走到輔助函式參數路徑，該方案仍需付款幾乎全額的 `getResolvedSignature` 掃描成本。

每個已聲明的 harness 事件都必須存在掃描得到的生產方。找不到生產方時，生成過程會將其視為沒有生產方的事件詞彙或尚不支持的語義 dispatch 形態，並明確失敗；沒有監聽方的擴充點仍然合法。`internal/dispatch` 插樁不會被當作它所觀察的每個事件的訂閱，因此關係矩陣只記錄直接的產品監聽方，不再手工補充間接關係。

### B. 帶作用域的事件路由生成一份強類型解析函式表

[`gen-scoped-events`](../../../../scripts/gen-scoped-events.ts) 掃描真實的 `scopeTarget(base, key)` 呼叫，為每種 scoped 基礎對象確定路由鍵類型。隨後，它尋找帶有 `this: Scoped<Base>` 的 Cordis `Events` 成員，並在每個事件參數及其第一層公開屬性中搜尋與該鍵匹配的類型；移除 `null` 和 `undefined` 後，候選類型必須與路由鍵類型完全相同。

恰好一個匹配項會生成解析函式。存在多個匹配項時，含義不明確，生成器會失敗。沒有匹配項時，事件必須標記 `@dshScopeScan unsupported`；該標記只用於路由鍵有意留在事件參數之外的情況，例如按所屬 agent（代理）路由的工作階段事件和按父 agent 路由的 subagent 生命週期事件。此標記只表示掃描不受支持，不編碼事件名、參數下標、屬性路徑或替代類型。

提交到倉庫的 [`scoped-events.generated.ts`](../../../../packages/core/scope/src/scoped-events.generated.ts) 是位於 scoped dispatch 所屬包中的純執行時期對映，不匯入任何事件聲明方包。語義完整性由生成器自身保證：根 Program 枚舉所有 scoped `Events` 聲明與真實 `scopeTarget` 約定，透過 checker 解析唯一的 payload 路徑，並在渲染 `unknown[]` 執行時期邊界前拒絕缺失、過時或含義不明確的條目。

`dsh-scope/invariant` companion 消費這份對映，不再維護手寫事件表。Program 分析發生在倉庫閘門內，而不是相依性生成的類型匯入，因此 `dsh-scope` 和 `dsh-invariants` 都不需要相依性所有事件聲明方。

### 語義缺口必須顯式失敗

遇到聲明缺失、設定診斷、事件名被拓寬或保持泛型、路由鍵類型不一致、事件參數匹配不唯一、不必要的 unsupported 標記，或生成產物過時時，生成器都會拒絕繼續。透過本機輔助函式呼叫點復原資訊的能力被刻意限制在窄範圍內：如果資料流經過匯出或無法解析的邊界，應新增通用語義規則，而不是新增特定包的覆蓋項。

## 驗證

`verify-doc-graphs` 對語義生產方/監聽方掃描執行新鮮度檢查；`verify-scoped-events` 會重新執行 Program 分析，並檢查生成對映的新鮮度。根 TypeScript 建置會編譯該執行時期配接器；workspace 約束與執行時期相依性閉包檢查確保事件聲明方聚合不會進入部署相依性。

## 考慮過的替代方案

- **保留文法掃描、接收者白名單和手寫覆蓋項。** 每個例外都容易單獨處理，但重新命名和新增輔助函式形態時還必須更新第二份表示。完整性檢查能夠發現生產方缺失，卻無法證明覆蓋項仍與原始碼一致。

## 後果

- 事件關係生成依據語義接收者身份和封閉事件值，不再相依性區域性命名約定；
- 帶作用域的事件成員關係、主體提取和執行時期不變式覆蓋來自事件聲明與真實 dispatch 約定，不再來自手寫表；
- 修改事件名、參數位置、主體屬性或路由鍵類型時，會在其所屬約定處觸發生成失敗；
- 建置扁平化 Program 比解析孤立文件消耗更多啟動時間和記憶體，語義閘門也相依性有效的根項目圖；
- 生成的 TypeScript 仍屬於提交到倉庫的原始碼：事件聲明方或 dispatch 形態發生變化後，必須重新生成該文件和受影響的文件。
