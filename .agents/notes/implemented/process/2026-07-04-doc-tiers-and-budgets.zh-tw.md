# Agent Note: 文件結構、層級與預算

Status: implemented

[English](2026-07-04-doc-tiers-and-budgets.md) | [简体中文](2026-07-04-doc-tiers-and-budgets.zh.md) | 繁體中文

## 問題

儘管已有寫作指導，常設文件仍不斷累積重複規則、反覆講述的事故、重複的包對映，以及過時的 Agent Note 摘要。該指導也未明確文件在層級中的位置如何限定其內容範圍，以及按順序引導讀者學習的內容與面向查閱的材料有何不同。僅靠評審無法阻止這種成長，因此倉庫需要在文件分類體系之外再配一套可自動執行的預算。

## 決策

- **結構遵循文件樹。**[docs/AGENTS.md](../../../../docs/AGENTS.md) 是文件標準：文件負責承載其主題的詳細內容，僅概述直接子項的目的、職責和高層行為，並連結到更深層內容的歸屬文件。[Agent Note](../../README.md) 仍不受這一結構約定約束。每份面向人的文件要麼是按順序引導讀者達成結果的教程（tutorial），要麼是查閱範圍明確的參考文件（reference）；[事後檢討（postmortem）](../../../../docs/postmortem/README.md) 是範圍限定於單起事故的參考文件，其時間線記錄證據。教程結合讀者的起始知識，按前置相依性順序介紹概念。
- **每項事實只歸屬一處的層級分類。**文件標準為每種 Markdown 層級分配單一職責，禁止在事實歸屬層級之外重複陳述，並包含編寫或評審任何文件時使用的贅餘檢查清單。
- **單一產品入門路徑。**根 README 負責推薦的包執行路徑、從原始碼執行的備選路徑和簡要的 `dsh plugin --profile` 用法。已發布的使用者指南從執行中的 Web UI 內部任務開始，再連結到其他介面的獨立教程或外掛程式開發與進階設定的參考文件歸屬處，而不會重複介紹 Web 啟動步驟。
- **範圍窄且嚴格的預算閘門。**[scripts/verify-doc-budgets.ts](../../../../scripts/verify-doc-budgets.ts) 接入 `doc-sync`：[scripts/doc-budgets.manifest.json](../../../../scripts/doc-budgets.manifest.json) 列出的每份文件都必須低於其詞數上限（採用 `wc -w` 語義，統計整個文件）；預算內文件缺失也會使閘門失敗，使重新命名無法悄然遺落其預算。範圍刻意只涵蓋容易膨脹的常設文件——根目錄和子樹中的 `AGENTS.md` 文件、`architecture.md`、`packages/README.md`，以及它們將內容移入的常設策略文件（`docs/testing.md`、`docs/defensive-patterns.md`）。參考文件、Agent Note 和包 README 不設預算：只要每一行都是事實，長度在這些位置就是合理的；評審和贅餘檢查清單負責約束它們。
- **上限是隻進不退的執行紅線。** 達到或低於目標的文件在上限逐步下調時保留至少 5% 的餘量；高於目標的文件則維持凍結的上限，在達到目標之前不得成長（根 `AGENTS.md` ≤ 1,600 詞；`architecture.md` ≤ 1,800；子樹 `AGENTS.md` ≤ 600，但 `packages/AGENTS.md` ≤ 650、`docs/AGENTS.md` ≤ 1,250；`packages/README.md` ≤ 600）。閘門變紅時，遷移或壓縮內容；只有在 PR（Pull Request）描述中給出明確理由時才提高上限。
- **精簡的工作流程 skill（技能），約定歸文件。**[.agents/skills/dsh-doc-standards](../../../skills/dsh-doc-standards/SKILL.md) 承載文件放置、審計和閘門失敗處理工作流程，並以文件標準為真源，與 [dsh-translate-docs](../../../skills/dsh-translate-docs/SKILL.md) 和 i18n 約定之間的分工相同。

## 曾考慮的替代方案

- **僅靠 skill 和評審紀律，不設閘門**：否決。上述膨脹正是在現行規則和評審注意力已經存在的情況下發生的；一條沒有自動化保障的行文規則在此處已被證明無法維持，而本倉庫自身的[品質閘門立場](2026-06-11-quality-gates.md)認為值得保持的不變式就值得編碼。
- **對所有文件層級全面設限**：否決。一刀切的上限恰好懲罰了那些正當的長文件（如功能矩陣或類型目錄，每一行都是事實），並產生逐文件的例外變更，訓練貢獻者機械地批准提限。
- **為每個文件入口維護獨立入門教程**：否決。重複的設定步驟會在命令順序、首個結果和產品定位上產生分歧。簡短的 README 路徑接上面向任務的指南，可明確銜接兩者，且不需要維護相互競爭的教程。
- **將標準放在 skill 內部**：否決。約定歸文件，工作流程歸 skill；如果標準被塞進 SKILL.md，那些不呼叫該 skill 而直接編輯文件的 agent（代理）就看不到它，而 `docs/AGENTS.md` 已經作為子樹指令被任何在 `docs/` 下工作的人載入。

## 後果

- 向受預算約束的文件新增內容需要騰挪空間：將新增內容遷移到其分類體系歸屬地並留下連結，或壓縮現有行文來騰出空間。只增不減會導致 CI 失敗。
- 結構評審先檢查歸屬關係和文件形式，再進行句子層面的編輯，使較低層級的細節遷移到其歸屬文件，而不是在錯誤的位置加以潤色。
- 讀者會先進入可執行的 Web UI，再遇到 headless 執行、SDK 嵌入、自訂 profile 或直接 settings 文件；這些入口仍可從各自的參考文件歸屬處訪問。
- 仍高於目標的受預算約束文件不得成長；達到目標後，將復原 5% 的工作餘量。
- 詞數是一個粗糙的代理指標，這是有意接受的：它無法判斷質量，但它在內容被新增的那一刻強制觸發遷移決策，而那正是作者擁有足夠上下文來正確放置內容的時刻。
