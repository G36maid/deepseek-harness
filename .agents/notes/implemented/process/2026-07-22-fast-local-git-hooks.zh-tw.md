# Agent Note: 快速本機 Git 掛鉤

Status: implemented

[English](2026-07-22-fast-local-git-hooks.md) | 繁體中文

## 問題

agent（代理）已經會執行能夠覆蓋自身改動的測試和檢查，而提交、推送與 CI 可能分別重複其中範圍越來越廣的子集。因此，全量 pre-push 套件會拖慢每次推送，放大與當前改動無關的本機偶發失敗，而且 CI 緊接著再次執行完整矩陣時不會提供新訊號。

快速掛鉤仍需在工作離開本機之前攔下檢查成本低且把握高的缺陷。暫存檔案格式問題、空白錯誤、vendor 原始碼元資料缺失與倉庫類型錯誤符合這條邊界；單元測試套件、快照、文件檢查、建置與包的 `hygiene` 檢查則隨改動範圍而異，不符合這條邊界。

## 決策

[lefthook.yml](../../../../lefthook.yml) 將兩個掛鉤都保留為有界的本機檢查點。Pre-commit 按順序執行：不載入項目的 [Oxlint](2026-07-29-oxlint-linter.md) 設定驗證改動過的 JavaScript 和 TypeScript 文件，應用帶[一次有界重試](2026-08-09-oxlint-only-fix-workflow.md)的安全修復，並重新暫存這些文件；`git diff --cached --check` 拒絕暫存 diff 中的空白錯誤，vendor manifest（中繼資料清單）守衛檢查 vendor 原始碼元資料。Pre-push 執行 `pnpm run typecheck`；該命令會先準備好生成的 Host Typert 約定，再執行 Client 增量型別檢查。

Pre-commit 不執行類型分析、測試、快照、文件檢查、建置、`hygiene` 或閘門調度器。Pre-push 只增加倉庫型別檢查所需的 Host 約定建置。選填執行的 `check:all` 包指令碼獨立於這些掛鉤，從 [scripts/run-gates.ts](../../../../scripts/run-gates.ts) 中選擇 `check-all` 調度器清單；它是貢獻者命令，而非對 agent 的指令。

agent 檢查待推送的 diff，並僅執行一次能夠覆蓋其行為的最小範圍測試和檢查。CI 負責全量覆蓋率閘門、建置產物檢查與平臺矩陣。只有在明確要求、診斷 CI，或涉及全倉庫的改動無法由範圍更窄的證據得到可信驗證時，才完整執行一遍本機檢查矩陣。

## 取代關係

本決策取代[平行 pre-push 閘門](2026-07-06-parallel-pre-push-gates.md)中涉及本機掛鉤的部分，以及[以機械品質閘門代替文字規範](2026-06-11-quality-gates.md)中關於掛鉤與 CI 對稱性的部分。上述記錄中關於 CI 調度器、包閘門與機械化強制執行的決策繼續有效。

## 考慮過的替代方案

- **保留全量 pre-push 套件並最佳化其調度器**——能夠最早提供全面訊號，但仍會重複 agent 已選取的證據和 CI，且無關失敗仍會阻塞推送。
- **完全移除 pre-push**——推送成本最低，但會失去 TypeScript 在多個提交之後提供的快速跨文件保證。
- **在 pre-commit 中保留型別檢查**——更早捕獲類型錯誤，但每次中間提交都要承擔開銷，而不是隻在推送時執行一次；暫存文件 lint 已經覆蓋提交本身的文法與風格邊界。
- **將暫存文件 lint 設為僅檢查模式**——避免掛鉤修改文件，但貢獻者有意保留自動修復工作流程；Oxlint 的一次有界重試和 Lefthook 的 `stage_fixed` 會保留該工作流程，無需單獨的格式化器，也無需重複執行 `git add`。

## 結果

普通提交的關鍵路徑是不載入項目的暫存文件 Oxlint 修復與驗證，快取已預熱時推送的關鍵路徑是經過準備的增量型別檢查。貢獻者仍選填擇用一條命令完整演練，且不會擴充掛鉤關鍵路徑或 agent 必須執行的驗證集合。掛鉤耗時只作為開發觀察資料和 PR（Pull Request）證據記錄，不設定會受主機負載與快取狀態影響的計時測試。

從本機推送成功不再能證明倉庫完整矩陣已透過。agent 必須選擇相關的行為證據，評審人必須判斷該選擇是否與 diff 相符，CI 則對每個推送版本提供一次全面訊號。
