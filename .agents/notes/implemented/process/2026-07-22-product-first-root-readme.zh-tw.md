# Agent Note: 產品優先的根 README

Status: implemented

[English](2026-07-22-product-first-root-readme.md) | [简体中文](2026-07-22-product-first-root-readme.zh.md) | 繁體中文

## 問題

根 README 是倉庫的產品入口。其產品優先的結構和既有語氣仍然有效，但隨著執行時期不斷擴充，具體入口和能力聲明會逐漸過時。重寫事實仍然正確的章節，會擴大評審範圍，也會丟棄已經行之有效的措辭。

## 決策

只要背後的事實仍然正確，根 README 就保留既有結構、順序和措辭。刷新時只修正過時聲明，並補充呈現已交付內容所需的資訊；不會因為倉庫規模成長就重構整篇敘事。

安裝說明之前的一則文字感謝內測使用者，說明功能和體驗仍待完善，並邀請大家透過企業微信羣直接回饋失敗、困惑和不順手之處。既有的開發階段聲明明確說明 DeepSeek Harness 處於內測階段。

使用者入口章節在已有的 Web、TUI 和 Headless 入口旁補充 ACP（Agent Client Protocol）自動化伺服器和 Python/JSON-RPC SDK。安裝後的 TUI 仍只需執行一條 `dsh` 命令；Web 說明要求先建置當前檢出，再執行 `dsh web`，並明確處理自訂或複用的檢出路徑。這兩條啟動路徑必須分別能在真實 PTY 與生產建置／HTTP 冒煙中原樣執行。能力段落沿用簡潔清單的寫法，補充已經交付的 PTY、LSP、Web、目標、規劃、任務、沙盒、審批、設定、憑據、工作階段查詢和遙測等能力類別，並說明不同組合只選用其中一部分。相鄰的一條清單項說明權威工作階段日誌規則，因為持久化、重播、查詢、遙測和各類介面都相依性它。

包與服務的完整清單仍由各自的歸屬文件維護。中英文 README 採用相同的技術結構，但社區章節仍分別指向各自語言受眾的主要交流渠道。文件網站保留獨立的[快速開始入口路由](../simplification/2026-08-11-quickstart-documentation-home.md)，不另行呈現產品首頁。

## 考慮過的替代方案

**圍繞新的產品敘事重寫 README。** 完整重寫能夠突出所有現有入口和能力，但也會替換準確且已經過評審的文案，造成不必要的變動。現有事實能夠納入既有的產品優先結構。

**將倉庫呈現為 SDK 和包清單。** 這樣能立即展現實現廣度，卻會迫使新讀者從包名反推出產品。包索引與生成的能力圖仍是權威清單。

**使用包含截圖、徽章和重複教程的長篇行銷頁面。** 富媒體能夠展示穩定的產品使用路徑，但其內容會獨立於命令和原始碼約定而逐漸過時。根 README 保持緊湊，並連結到可執行示例和各自維護的指南。

**將根 README 投影為文件網站首頁。** 使用同一個首頁可以避免兩套敘事，但文件網站的使用者指南與倉庫面向產品和開發者的入口在導覽和維護需求上並不相同。文件根路由則將讀者引導至快速開始。

## 結果

評審者可以區分事實更新與編輯性重寫；今後的更新會保留既有措辭，除非其含義已經不再正確或完整。受影響的命令、入口、發布階段聲明或高層能力類別發生變化時，README 仍須同步更新；完整細節則繼續以連結方式提供，而不是複製到正文。
