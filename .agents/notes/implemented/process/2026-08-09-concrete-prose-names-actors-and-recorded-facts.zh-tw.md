# Agent Note: 具體表述說明執行者和記錄的事實

Status: implemented

[English](2026-08-09-concrete-prose-names-actors-and-recorded-facts.md) | [简体中文](2026-08-09-concrete-prose-names-actors-and-recorded-facts.zh.md) | 繁體中文

## 問題

倉庫行文使用了抽象的類別名稱，但讀者需要知道的具體事實各不相同。同一個名稱可能指替換操作引用的早期事件 seq、生成訊息的提供方和模型、提供上下文的呼叫方、提供某行設定的文件，或建置某個二進位檔案的 CI 任務。讀者必須查看程式碼，才能知道句子承諾的是哪項事實。

用另一個寬泛名稱替換原名稱，仍會保留這種歧義。在行文整理中重新命名類型、欄位和協議成員，反而會改變與行文問題無關的約定。

## 決策

倉庫維護的行文直接寫明當前語境下的約定需要的執行者、動作、來源、事件、欄位、文件或行程。句子說明記錄了什麼，以及由誰或什麼記錄。寫作者還要檢查自己是否會在向同事解釋同一個問題時使用這些詞；如果不會，就替換它們。

該規則適用於 Markdown、README、活躍 Agent Note、JSDoc 與註釋、提示詞、診斷資訊和使用者可見字串。審查會分別判斷每個句子，不會在整個倉庫中用一個偏好的近義詞統一替換某個術語。編輯後的句子保留執行者、動作、條件、順序、情態、例外、歸屬、失敗行為和後果。

除非另一項獨立需求明確要求協調重新命名約定，否則確切的程式碼識別符號、公開 API、持久欄位、協議成員、類型名、帶有外部引用的標題和檔名均保持不變。它們周圍的行文直接說明其欄位或行為。生成的文件和目錄在維護它們的原始檔修改後更新。

使用 `contract`、`boundary` 或 `shape` 之前，寫作者要確認句子是否實際指更具體的規則、操作、資料結構、欄位集合、校驗點、時間點、API、類型或失敗條件。呼叫方、被呼叫方、實作方、提供方、生產方或消費端相依性的前置條件、後置條件、不變數、相容性承諾及其他義務仍可準確稱為 `contract`。真實的安全、信任、wire、行程、序列化、交易或生命週期分界仍可準確稱為 `boundary`。當結構形式本身就是主題，且欄位、schema、類型、聯合變體、文件版面配置或匯出形式等更窄的詞無法說明事實時，仍可使用 `shape`。除非另一項獨立需求要求協調重新命名，否則包含這些詞的程式碼和 API 名稱保持不變。

該決策補充了[文件層級與字數預算](2026-07-04-doc-tiers-and-budgets.md)決策；後者繼續規定內容位置、文件形式和字數預算。

## 曾考慮的替代方案

**禁止一份固定詞表中的所有詞。** 不予採納：某個詞可能是確切的識別符號，也可能是另一項約定中最清楚的用詞。例如，呼叫方與被呼叫方相依性的不變數屬於真實的約定，行程邊界或協議邊界也表示真實分界。逐句審查可以找出歧義，且不會拒絕有效名稱。

**將每個抽象名稱都替換為“來源”、“起源”或“元資料”。** 不予採納：另一個寬泛名稱仍會讓讀者自行推測句子指的是文件、呼叫方、事件 seq、提供方／模型組合、commit 還是建置任務。

**在修改行文時重新命名所有匹配的識別符號。** 不予採納：讓行文更清楚，不能作為進行無關 API、協議、持久格式、類型或文件遷移的理由。這些改動需要各自的消費端審查和決策。

## 後果

文件和診斷資訊可能會多用幾個詞，但每條說明都會告訴讀者哪個值或哪個執行過程有關，無需查看原始碼。全倉庫行文審查必須根據句子的具體含義分類，不能盲目替換。雙語對側檔案保留相同的具體事實；生成的副本只會在其歸屬原始檔更改後刷新。
