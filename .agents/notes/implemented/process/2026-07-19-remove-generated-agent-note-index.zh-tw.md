# Agent Note: 無需生成索引即可發現 Agent Note

Status: implemented

[English](2026-07-19-remove-generated-agent-note-index.md) | 繁體中文

## 問題

提交到倉庫的 Agent Note 索引，會重複記錄每個文件的生命週期／類別路徑、檔名日期和 H1 已經編碼的事實。任何分支只要新增、移動或重新命名彼此無關的 Agent Note，都會重寫同一個生成文件，因此該產物會成為可預見的合併衝突熱點。

與瀏覽生命週期／類別目錄樹或搜尋倉庫相比，這份集中式時間順序清單提供的發現價值有限；但其生成器、渲染器、命令和新鮮度檢查仍然構成維護負擔。

## 決策

按生命週期／類別組織的檔案系統目錄樹就是 Agent Note 清單。[README.md](../../README.md) 繼續作為人工維護的入口和約定，普通的目錄樹瀏覽與倉庫搜尋負責內容發現。

`scripts/agent-note-tree.ts` 持有封閉的生命週期／類別集合與結構遍歷器。`verify-agent-note-classification` 校驗該目錄樹，並拒絕舊目錄和根目錄中的 `INDEX.md`，但不會渲染集中式清單或檢查其新鮮度。

## 備選方案

**保留提交到倉庫的生成索引，並透過重新生成解決衝突。** 重新生成能讓衝突解決過程機械化，但無法阻止無關分支修改同一產物，也不會減少由此產生的評審噪音。

**提供不提交到倉庫的按需索引命令。** 這可以避免已提交文件的衝突，但仍需維護渲染器和命令，而目錄樹瀏覽與倉庫搜尋已經覆蓋該發現路徑。

**復原人工維護的索引。** 它同樣會造成共享文件爭用，還會重新引入生成機制已經避免的完整性和排序錯誤。

## 影響

- 新增、移動或重新命名 Agent Note 時，不再改動覆蓋整個語料庫的生成文件。
- 分類閘門執行的工作更少，文件閘門拓撲也無需增加行程或階段。
- 讀者不再獲得單一的時間順序頁面，改用生命週期／類別目錄樹或倉庫搜尋。
