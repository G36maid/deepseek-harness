# Agent Note: 包的模型體驗約定

Status: implemented

[English](2026-07-12-package-model-experience-contract.md) | [简体中文](2026-07-12-package-model-experience-contract.zh.md) | 繁體中文

## 問題

包 README 可以解釋 API 和執行時期機制，卻不回答主導 agent harness（代理框架）行為與成本的問題：該包的哪些內容會進入模型請求、在什麼條件下進入、這些 token 會保留多久，以及後續請求是否會保留可複用的 KV Cache 前綴。在外掛程式架構中，這種遺漏尤其難以審計。消費端可能把後端結果轉為工具訊息，策略外掛程式可能以錯誤取代成功結果，壓縮可能移除舊歷史，而 agent 範圍的註冊可能改變某個 agent 的提示詞或 schema，卻不影響其他 agent。因此，只閱讀名義上面向模型的包會遺漏真實的上下文效應，而在每次常規評審中跨所有相依性閱讀原始碼又成本過高。

## 決策

每個具有面向模型或鄰近模型約定的 workspace 包 README 都以規範的[模型體驗章節](../../../../docs/cookbook/adding-a-package.md#4-write-the-package-readme)收尾，位置緊鄰 `## Known Limitations and Deferred Work` 之前；位於“無已知限制”允許清單中的包則以模型體驗章節本身結尾。經審計確認與模型無關的通用包透過 `NO_MODEL_EXPERIENCE_SECTION` 省略該章節。

具有直接、條件式、有上限、生命週期、多表面或輔助模型效應的包，為每個上下文表面使用一個 H3。每個表面包含三個有序 H4 欄位——`What the model sees`、`Token effect` 和 `KV Cache effect`——每個欄位都以一個正文段落開頭。快取欄位區分僅附加成長、穩定重複前綴、替換先前 token，以及獨立模型請求；它點明由包擁有、且能在新內容追加前改變請求的每項設定、作用域、生命週期、壓縮或路由變化。“Does not invalidate”表示該包保留一個已經可複用的前綴，並非承諾提供方一定能命中快取或將其保留特定時長。由包擁有的穩定文字按原文精確引用：系統提示詞正文和其他長字面量在引入它們的欄位下使用帶標題的 H5 加 `markdown` 圍欄，通常位於 `What the model sees`；短字面量則以內聯形式保留，並點名插值佔位符。工具 schema 連結生成的[工具目錄](../../../../docs/tool-catalog.md)中帶錨點的章節，並且只陳述組合或設定增量；僅執行時期定義解釋目錄為何省略它們。相依性資料和由提供方擁有的文字採用摘要。agent 範圍的可見性須顯式說明；當範圍可隱藏提示詞與 schema 中的一者而不影響另一者時，兩種表面保持分離。

沒有模型上下文效應的包，或某條路徑完全由另一個包渲染的包，使用驗證器審計過的短格式：一句以 `None, as ` 或 `Indirectly, through ` 開頭的句子，隨後是一個 `KV Cache effect` H4 和一個正文段落。純傳輸包和無金鑰測試支持包若不建立任何進入模型的內容，就使用 none 格式。提供方後端即使會限制或過濾資料，也使用間接格式；具名子項擁有全部效應時，接線 bundle 也使用該格式。這些章節會指出貢獻所在，並聲明不會直接導致 KV Cache 失效，同時不重複陳述消費端。結構化章節同樣只記錄由包擁有的輸入、變換和增量。

`verify-package-readme-model-experience` 發現各包的 manifest（中繼資料清單），並驗證三種分類、規範末尾章節順序、確切欄位標題深度與順序、非空欄位段落、逐字塊的 H5 歸屬、具體字面量證據，以及帶錨點的工具目錄連結。它在 `doc-sync` 和平行閘門 runner 中執行。評審仍負責覆蓋面、連結相關性和事實準確性。

## 曾考慮的替代方案

- **只記錄註冊提示詞或工具的包**：否決。後端、策略外掛程式、配接器、持久化、作用域和壓縮都會改變 token 的內容或生命週期，卻不擁有面向模型的 schema。
- **從原始碼生成一份集中式上下文成本目錄**：否決。AST 能找到註冊點，但無法推斷語義條件，如歷史保留、輸出截斷、父子可見性或輔助模型邊界。包 README 是實作本機的約定；集中副本會增加又一個漂移點。
- **要求給出精確 token 數**：否決。精確數量取決於所選模型的 tokenizer、配接器序列化方式、設定和執行時期資料。穩定的約定是成長形狀：每請求固定、每呼叫條件性、保留、替換、有上限或零直接影響。
- **使用表格**：否決。精確原始碼文字和條件式結果形狀會使單元格密集而難以掃讀。重複的小節在保留相同欄位的同時，為每個上下文表面提供易讀的縱向空間。
- **允許所有零影響包省略該章節**：否決。無約束的缺失在「經審計的零影響」和「忘記寫文件」之間有歧義。省略僅限於在驗證器中以理由命名的模型無關通用包；模型相鄰的零影響包保留一句顯式說明。
- **要求經審計的零效應包或簡單間接包使用完整結構化格式**：否決。它會圍繞一個事實重複標籤。受閘門約束的句子加 cache 欄位既保留顯式覆蓋，又沒有多餘儀式。
- **只有慣例而無閘門**：否決。倉庫級約定必須覆蓋未來的每個包；評審者的記憶無法可靠地偵測到遺漏的 README 章節。

## 後果

評審者可以從任何面向模型或鄰近模型的包開始，看到它對對話模型、子模型和輔助呼叫的貢獻，無需重建完整外掛程式圖。token 預算工作可以區分重複請求開銷和相依性資料的歷史，而 cache 敏感工作可以識別僅附加路徑，以及最早由包引起請求前綴變化的位置。agent 範圍變更有明確的文件檢查點。每當模型可見行為發生變化時，包作者都要維護一個或多個緊湊的上下文條目塊，或一種已分類的短格式；經審計的通用包不攜帶無關的模型樣板。結構化欄位不承諾由提供方給出的精確 token 數或 cache 命中；測量仍取決於具體模型、提供方和工作負載，而所記錄的成長、可見性和前綴穩定性約定保持穩定。
