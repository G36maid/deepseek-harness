# Agent Note: 每項實質性變更都必須附帶 Agent Note

Status: implemented

[English](2026-07-19-require-agent-notes-for-non-trivial-changes.md) | [简体中文](2026-07-19-require-agent-notes-for-non-trivial-changes.zh.md) | 繁體中文

## 問題

如果只在決策被認為持久、有爭議且出人意料時才記錄 Agent Note，實質性變更就可能在沒有保存決策依據的情況下落地。程式碼和測試能展示改動內容，卻無法穩定保留某種方案勝出的原因、被放棄的備選方案，以及維護者接受的成本。

## 決策

每項實質性變更都在同一個 PR（Pull Request）中新增或更新至少一份 Agent Note。實質性變更包括行為、架構、跨文件或跨包約定、流程或工具、測試策略、磁碟格式、協定格式（wire format）或設定格式，以及維護者可能合理重審的其他決策。

更新已經持有該決策的 Agent Note 即滿足規則；僅當沒有 Agent Note 持有該決策時才新增記錄。完全機械或區域性、且不改變行為、約定、結構、流程或決策依據的編輯可豁免。[Agent Notes README](../../README.md#when-to-write-one) 持有這條邊界，根目錄 `AGENTS.md` 則攜帶常駐指令。

只有在當前持有該決策的記錄保存了所有獨有的決策依據、備選方案、影響、驗證約定和明確指出的覆蓋缺口後，纔可將被完全取代的 implemented Agent Note 合併到該記錄中並刪除。同一變更還要修復入站連結，並刪除中文對側檔案和伴隨記錄。僅部分被取代時，兩個記錄仍需互相連結並保持與現狀一致；合併既不將舊決策改寫成與其相反的決策，也不讓 git 歷史成為決策依據的唯一副本。

後續決策完全移除較早的功能時，只有該功能已從生產程式碼、設定、schema、持久化格式或協定格式、遷移和相容行為中消失，當前文件不再將其描述為可用，且沒有測試把它作為受支持行為來執行，移除記錄才會成為當前持有記錄。移除決策的依據和驗證該功能已不存在的測試可以保留。它必須保留該功能的最初動機、為什麼該動機已不足以證明繼續保留該功能、完全移除之外的備選方案、放棄的能力、重新引入的條件，以及證明已徹底移除的驗證。只描述已刪除行為的實作清單和測試已經過時，不屬於當前驗證約定。僅移除一種傳輸、預設值、實作或展示仍屬於部分取代。

評審負責執行這條語義邊界。自動化閘門不嘗試把差異分類為平凡或實質性變更，因此這項政策不會增加閘門階段或執行時期間。

## 備選方案

**只為被判斷為持久、有爭議且出人意料的決策要求 Agent Note。** 這條門檻過於主觀，實質性變更可能被視為顯而易見或區域性改動，從而丟失 Agent Note 本應保存的決策依據。

**每項變更都必須新增 Agent Note。** 當現有 Agent Note 已經持有該決策時，這會產生重複記錄，也會讓純機械編輯承擔空洞的流程負擔。

**永久保留每份被完全取代的 Agent Note。** 只要舊決策仍有部分適用，就需要保留互相連結的記錄；但完全失效的 implemented Agent Note 與記錄當前狀態的約定相矛盾，並重複保存本可由一個記錄持有的決策依據。

**新增 `superseded/` 生命週期。** 新增生命週期仍會保留過時記錄並擴張目錄樹、格式閘門和維護規則，卻無法減少重複內容。

**將舊 Agent Note 改寫為替代它的決策。** 這樣會抹去決策邊界及其否決的備選方案。合併做法是在刪除過時文件前，先由當前持有決策的記錄保存這些事實。

**保留已移除功能的每一項實作與測試細節。** 這會在替代記錄中重建過時記錄。移除決策的持有記錄只保留理解或重新審視當前已移除狀態所需的決策依據與驗證，已刪除機制仍可從 git 歷史查看。

**新增 CI 差異分類閘門。** 機械檢查無法可靠判斷語義變更是否平凡，額外閘門還會增加執行時期間，並引入誤報或表面合規。

## 影響

- 每項實質性變更都會在實作旁保留其決策依據和被放棄的備選方案。
- 貢獻者維護現有的決策持有記錄，而不是建立重複記錄。
- 被完全取代的記錄可以歸並到一個當前持有記錄中，同時不丟失其獨有的決策依據或驗證約定。
- 後來被移除的功能可以只有一個當前持有記錄，而無需繼續保留過時的實作與測試清單。
- 僅部分被取代的情況仍需明確記錄並互相連結；刪除記錄則必須在同一變更中清理連結和雙語配對。
- 機械編輯仍保持輕量，閘門拓撲和執行時期間也保持不變。
