# Agent Note: 僅使用 Oxlint 的修復工作流程

Status: implemented

[English](2026-08-09-oxlint-only-fix-workflow.md) | 繁體中文

## 問題

[倉庫 linter 遷移](2026-07-29-oxlint-linter.md)保留了一次僅用於格式化的 ESLint 呼叫，因為當時認為 Oxlint 的 JavaScript 外掛程式橋接層只能用於校驗。固定版本的 Oxlint 工具鏈能夠執行 `@stylistic/eslint-plugin` 提供的安全修復，因此單獨的格式化器重複引入了設定邊界、命令啟動過程，以及對 `eslint` 和 `@typescript-eslint/parser` 的直接相依性。

單次呼叫 Oxlint 並不能實作等價替代。相互重疊的外掛程式修復可能先應用一項變更，卻留下由此新暴露的診斷；倉庫中包含 `semi` 和 `object-curly-spacing` 違規的 fixture（測試前置資料）需要執行第二輪才能完全修復。工作流程必須重試這種情況，同時不得列印第一輪中已經失效的診斷。

## 決策

倉庫的所有 lint 與修復工作流程都透過 [`scripts/run-oxlint.ts`](../../../../scripts/run-oxlint.ts) 呼叫 Oxlint。普通校驗仍由單個行程執行，並直接繼承輸出。包含 `--fix`、`--fix-suggestions` 或 `--fix-dangerously` 的呼叫會捕獲第一次 Oxlint 的執行結果；如果成功，就透過原有通道輸出其 stdout 和 stderr；如果行程正常結束但狀態非零，則丟棄其中可能已經失效的診斷，隨後以繼承輸出的方式再執行一次相同命令。子行程被訊號終止時，執行器會重新觸發該訊號，而不會重試或將其轉換為退出碼；第二個行程的結束結果作為最終結果。

`lint:fix` 包指令碼和處理暫存文件的 lefthook 作業直接使用該執行器。類型感知的根設定仍會忽略 `oxlint-tsgolint` 無法分析、需要保留原始形態的 TypeGraph fixture；不載入項目的暫存設定會重新納入該目錄，保留其中有意設定的 `any` 與引號規則例外，並在完整的類型感知修復輪次之前應用其樣式修復。倉庫中不存在僅用於格式化的 ESLint 設定，也不直接相依性 `eslint` 和 `@typescript-eslint/parser` 這兩個開發相依性。`@stylistic/eslint-plugin` 和 `eslint-plugin-sonarjs` 仍作為 Oxlint 的 JavaScript 外掛程式保留，因為它們承載了已強制執行的規則；pnpm 仍會將 ESLint 作為這些外掛程式聲明的對等相依性（peer dependency）進行安裝，但倉庫中的設定和工作流程均不會呼叫它。

## 驗證

可執行 lint 約定將一項特意構造、會觸發重疊修復的樣式違規交給倉庫執行器處理，並要求執行器成功退出且最終位元組完全一致。同一約定還會固定完整的 Stylistic 規則集、不載入項目時對 TypeGraph fixture 的覆蓋、包指令碼、暫存文件掛鉤命令、已刪除的格式化器設定，以及 ESLint 解析器和執行器不存在直接相依性這一事實。現有的可執行探針繼續覆蓋 Stylistic 和 SonarJS 相容外掛程式、不載入項目的暫存文件校驗，以及類型感知的項目發現。

## 考慮過的替代方案

**保留僅用於格式化的 ESLint 輪次。** 這會保留 ESLint 內建的多輪修復行為，但在 Oxlint 已能執行相同外掛程式修復的情況下，仍需維護第二個執行器、重複的格式化設定和直接相依性。

**僅執行一次帶 `--fix` 的 Oxlint。** 這樣更簡單，但相互重疊的安全修復可能使命令只完成部分格式化並以非零狀態退出，即使再次執行同一命令就能完成修復。

**採用 Oxfmt。** 遷移格式化器會改變倉庫的輸出約定，並產生無關的格式化 diff。它與移除冗餘 ESLint 執行路徑是兩項獨立決策。

**移除 JavaScript 相容外掛程式。** 這會消除這些外掛程式引入的 ESLint 對等相依性圖，但也會移除強制執行的 Stylistic 和 SonarJS 規則。追求相依性樹純淨不能成為削弱質量約定的理由。

## 結果

貢獻者、包指令碼、掛鉤和 CI 統一使用一個 lint 執行器和一份規則設定。暫存設定會重複根設定的忽略清單，以便重新納入僅用於格式化的 fixture，同時避免將 vendor 或生成文件納入檢查。修復行程正常結束但狀態非零時，始終會額外執行一次重試；穩定存在且無法修復的錯誤也不例外。第一輪的每條輸出流最多緩衝 64 MiB，因此重試成功時不會列印已經失效的診斷；行程建立或輸出捕獲失敗（包括超出該上限）時會立即報告錯誤，不會重試。

相依性鎖中仍可能因外掛程式的對等相依性解析而包含 ESLint。要移除這個傳遞相依性，需要使用原生替代方案，或另行決定採用能夠同時取代相容外掛程式的格式化器；這不屬於本次工作流程簡化的範圍。
