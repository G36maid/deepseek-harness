# Agent Note: 工具可達能力 seam 中的必填取消

Status: proposed

[English](2026-07-19-required-cancellation-through-tool-capability-seams.md) | [简体中文](2026-07-19-required-cancellation-through-tool-capability-seams.zh.md) | 繁體中文

## 問題

已經實作的[工具登錄檔取消約定](../../implemented/architecture/2026-07-19-cooperative-tool-cancellation.md)讓每個工具主體中的 `exec.signal` 成為必填值，但許多從這些工具主體可達的非同步能力介面仍接受選填訊號。因此，工具可以滿足自身類型，卻在下一次同進程呼叫時意外丟失取消。

這一缺口會沿呼叫鏈傳遞。檔案系統工具可能呼叫路徑解析和 I/O，Web 工具可能呼叫提供方，Bash 工具可能呼叫執行器，組合工具可能啟動或等待任務、subagent 或工作流程。只要某個控制工具所持有的工作且會被工具等待的操作允許省略訊號，TypeScript 就無法證明取消仍能到達擁有副作用的邊界。

要求倉庫中所有非同步函式都攜帶訊號會過度擴張。有些操作無法從工具到達，有些同步查詢無法等待或持有持續工作，而明確分離的工作在刻意交接後已經擁有新的所有者。

## 提議

所有能從工具主體到達、且在工具仍持有或等待該操作期間執行的非同步同進程能力操作，都必須接收 `AbortSignal`。根據所屬 seam 的既有形態，這項要求可以表現為位置參數，也可以表現為必填的只讀請求欄位，但省略訊號必須導致 TypeScript 編譯失敗。

每個直接呼叫方提供自己持有的訊號，或從自身必填的操作上下文繼續傳遞訊號。實作可以派生子截止時間或取消作用域，但派生訊號在委託期間仍須與上游訊號關聯。能力實作不得生成永不中止訊號、使用環境式非同步本機取消，也不得僅為重複類型化同進程約定而在執行時期校驗 `AbortSignal`。

遷移首先從每個第一方 `ToolDefinition.execute()` 出發，沿其等待的能力呼叫進行清點；隨後按內聚的 Service Definition／Service Provider／Consumer seam，將測試與生成的 API 文件一並修改。檔案系統、Bash 與任務、Web 與提供方、工作流程與 subagent、程式碼執行時期等能力族可以透過獨立 PR（Pull Request）遷移，以保持每項變更可審查；但根據倉庫的預發布原則，已經遷移的介面不得保留選填相容重載。

### 範圍邊界

本提議包含完成或取消仍屬於當前工具生命週期的非同步能力操作，包括所有權交接前的啟動操作、前臺執行、讀寫、提供方請求、等待，以及工具會等待的清理或釋放操作。

本提議不包含同步登錄檔查詢、可用性檢查、schema 渲染、參數分類，以及其他無法保留非同步工作的操作。明確交接所有權後的分離工作也不在範圍內：任務、工作流程、worker 或 subagent 成功發布給新的生命週期所有者後，其分離生命週期由新所有者的控制器管理。發起啟動的操作在交接提交前仍須接收呼叫方訊號；之後若另一次工具呼叫等待該分離工作，則必須使用該次呼叫自己的訊號。

若外部協議本身允許省略取消，解析器、設定、模型與工具 JSON、持久化與檔案格式、worker、行程或協議輸入仍可保留選填取消。所屬邊界必須先把該輸入解析為必填的同進程訊號，再呼叫已經遷移的能力 seam。

## 考慮過的替代方案

**因為工具主體已經收到訊號，所以繼續讓下游訊號保持選填。** 不予採納，因為外層回呼中存在訊號並不能讓傳遞過程具備類型安全；每個選填能力呼叫仍可合法省略它。

**透過 lint 規則或回呼檢查強制傳遞。** 不予採納，因為文法檢查無法可靠識別所有權、派生訊號、抽象層或正確的完全靜止行為。必填介面參數可以在 TypeScript 能檢查每個呼叫方的位置表達約定。

**把 `ToolRunContext` 傳入所有能力。** 不予採納，因為能力需要的是取消，而不是工具身份、agent（代理）狀態或上下文延後功能。傳遞更大的上下文會讓可複用服務耦合到工具登錄檔，也會掩蓋狹窄的 seam。

**使用環境式非同步本機訊號。** 不予採納，因為隱藏傳遞會讓所有權和分離交接難以審計，使測試複雜化，並可能讓呼叫靜默綁定到錯誤的生命週期。

**在能力實作中加入默認或永不中止訊號。** 不予採納，因為預設值會抹去缺失的所有者，而不是在編譯期暴露問題。

**在已經實作的工具登錄檔變更中遷移所有能力。** 不予採納，因為傳遞性的介面修改橫跨獨立能力族。單獨保留這項提議既能維持已實作的登錄檔決策，也能讓每個深層 seam 透過聚焦測試完成遷移。

## 驗收標準

- 清單把每個第一方工具主體對映到所有權交接前可以到達的非同步能力操作。
- 每個範圍內的能力介面都要求 `AbortSignal`，並由編譯期約定測試證明省略訊號會失敗。
- 介面、實作、直接消費端、測試輔助函式、示例和生成的 API 引用必須一起遷移，不保留相容重載或生產環境永不中止哨兵。
- 派生截止時間和包裝層作用域仍與呼叫方訊號關聯，整合測試證明取消到達副作用所有者，且等待的工作完全靜止。
- 同步查詢和明確交接後的分離工作不受這項要求約束；存在歧義時，需要記錄並測試所有權轉換。
- 只有真實的無類型邊界才新增執行時期校驗，不得重複校驗 TypeScript 已要求的欄位或參數。
- 每次內聚遷移後，頂層型別檢查、覆蓋率、快照、文件、模組圖、建置、hygiene、演示和建置產物閘門全部透過。

## 風險

**傳遞性影響範圍較大。** 一個必填參數可能同時暴露大量直接呼叫方。應按內聚能力族遷移，並把型別檢查失敗作為完整的呼叫方清單。

**錯誤劃分分離工作。** 過早排除啟動操作可能在發布提交前就讓工作脫離控制；永久要求父訊號又可能讓已完成工具取消合法分離的工作。每次交接都需要明確提交點、新所有者、回滾行為和完全靜止的失敗路徑。

**訊號所有權混淆。** 能力若在委託生命週期之外保存借用訊號，可能讓工作綁定到過時的呼叫方。介面和測試必須區分借用的操作訊號與長生命週期服務所持有的控制器。

**只有機械合規而沒有協作行為。** 必填參數只能證明訊號可用，不能證明實作會觀察或轉發它。行程、worker、Socket、提供方和任務邊界仍需整合測試證明實際行為。

**把同步或無關 API 納入範圍。** 在不存在非同步工作的地方要求取消只會增加噪聲，並削弱約定的辨識度。修改前，清單需要記錄每項操作為何可由工具到達並承載其生命週期。
