# Agent Note: 互動式側工作階段與合併回寫

Status: proposed

[English](2026-07-08-interactive-side-sessions.md) | [简体中文](2026-07-08-interactive-side-sessions.zh.md) | 繁體中文

## 問題

使用者可能希望在不改變當前工作階段主上下文的前提下，探索一個來自活躍工作階段的問題。現有原語無法提供這種產品形態：[工作階段儲存 fork](../../implemented/feature/2026-06-30-session-store-fork-api.md) 建立的是一個未綁定的工作階段，而 [fork subagent](../../implemented/feature/2026-06-21-subagent-capability-seam.md) 是模型驅動的任務，其 transcript（文字記錄）會摺疊為一條工具結果。兩者都不能給使用者一個獨立的對話，也都不能在父工作階段中同時記錄結論和產生該結論的側工作階段。

## 提案

**側工作階段（side session）**是一個普通的活躍工作階段，從源工作階段的最後一個已完成輪次 fork 而來，綁定到自己的 agent（代理），定位為只讀顧問，並能**合併回寫**一條精簡筆記。

- **Fork 並綁定：**以父工作階段的平衡已完成輪次前綴建立子工作階段，並在其元資料中標記 `parentSession` 與 `seedLength`。這組合了 `ctx.agents.create({ seed, meta })`；不新增核心服務或工作階段儲存方法。
- **顧問定位：**建立後注入一條外掛程式來源的 `context/message`，告知子工作階段只做解釋，不執行變更或繼續任務。保持系統提示詞逐位元組一致，可在繼承的歷史上保留提供方的前綴快取。
- **合併回寫：**向子工作階段請求一條有長度上限的 handback，然後向父工作階段注入一條外掛程式來源的 `context/message`。父工作階段的下一次請求在日誌所記錄的位置看到該訊息，保持重播與[請求可重建性](../../implemented/architecture/2026-07-05-reconstructable-requests.md)，無需新增工作階段事件。
- **呈現：**呼叫方式、工作階段切換與 handback 渲染屬於首個用戶端擁有的介面。本 Agent Note 僅規定與介面無關的機制。

回退產品化、工作階段樹檢視表、面向模型的側工作階段工具，以及 `forkName`/`mergedInto` 元資料均不在本 Agent Note 範圍內。一次真實配接器 spike 已驗證了源日誌隔離、繼承上下文、多輪子工作階段互動，以及合併回寫在父工作階段下一輪次中的可見性。

## 曾考慮的替代方案

- **使用 subagent seam：**否決。側工作階段是使用者驅動的、用戶端可見的，且可能存活超過父工作階段的一個輪次；subagent 是模型驅動的執行，返回一條工具結果。
- **修改子工作階段的系統提示詞：**默認否決，因為任何位元組變化都會從第零個 token 起使前綴快取失效。部署方仍選填擇這種更強的隔離方式。
- **新增 `sidechat/*` 事件：**延後。已標注來源的 `context/message` 已經持久記錄內容、生產方和重播輸入；只有當某個介面需要差異化渲染時，專用事件纔有正當理由。
- **現在就綁定一個協議介面：**否決。當前 UI 由用戶端擁有。即時呈現最終必須從持久訊息派生，以使重播渲染出相同的記錄。

## 驗收標準

- Fork 不改變源工作階段，建立的子工作階段具有平衡的已完成輪次前綴、`parentSession`、`seedLength`，以及逐位元組一致的系統提示詞。
- 顧問定位在子工作階段追加歷史的頭部恰好新增一條外掛程式來源的 `context/message`，而非修改其系統提示詞。
- 合併回寫恰好新增一條有長度上限的 `context/message`，來源為 `plugin: sidechat`；父工作階段的下一次請求與重播在相同位置看到它。
- 父工作階段與子工作階段並行執行，日誌和流之間無串擾。
- 單元測試覆蓋 fork/attach 與合併回寫；快照覆蓋隨首個綁定介面一起落地。

## 風險

- 只讀行為在 `tools/pre-execute` 拒絕閘門強制執行之前僅為建議性質；[攔截點](../../implemented/feature/2026-06-30-interception-extension-points.md)可在不改變本機制的前提下新增該閘門。
- 經過壓縮（compaction）的源工作階段 fork 出的是其壓縮檢視表，因此綁定的介面應當告知使用者子工作階段繼承的是摘要而非被替換的輪次。
- 反覆的 handback 會消耗父工作階段上下文。每次合併的長度上限約束了單條筆記的大小；後續的合併整理屬於上下文壓縮的職責。
